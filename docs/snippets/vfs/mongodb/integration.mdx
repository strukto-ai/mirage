## Integration

MongoDB answers these commands through its own API, so fewer documents are
read. See [Integration](/home/integration/overview).

- `grep` and `rg` on one file: a filter on the server sends only the documents
  that may match. `grep -r` on a folder does the same for each
  `documents.jsonl` under it.
- `tail -n N`: the last N documents by `_id`, sorted on the server.
- `wc -l`: `countDocuments()` on the server.
- `tail -f`: a change stream yields each new insert.

For one plain text, the filter matches it in any case against every key and
string of a document, eight levels deep, in the `_id` order a plain read takes.
A document nested deeper, or holding a value the filter cannot look into
(binary, a regex, code), is always sent. MongoDB still scans the collection,
but only those documents are sent. The file is read as usual when the text
holds anything but ASCII letters and spaces, or could match an Extended JSON
key (`$oid`, `$date`, `$numberLong`), a JSON literal (`true`, `null`) or an id
(a word of hex letters only, such as `ada`). `schema.json` and `database.json`
are always read, and `-m` stops the cursor early.
