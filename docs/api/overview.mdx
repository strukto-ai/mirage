Mirage has two HTTP APIs. **Cloud** runs on infrastructure managed by Strukto.
**OSS Server** runs on infrastructure you operate, using Python or TypeScript.
Both provide workspaces and shell execution.

## Deployments

| Deployment | Base URL | Authentication |
| --- | --- | --- |
| Cloud | `https://api.strukto.ai` | A bearer token for your account |
| OSS Server | `http://127.0.0.1:8765` for a local server | A server token or JWT, depending on server configuration |

For an OSS Server on another machine, use that server's URL. Local mode accepts
requests without a bearer token when no token is configured.

Cloud and OSS Server share workspace concepts, but endpoint availability,
parameters, and response fields can differ. Use the contract for your deployment.

## Make a request

<Tabs>
  <Tab title="Cloud" icon="cloud">
    List the workspaces available to your account. Set `MIRAGE_AUTH_TOKEN`
    to your Cloud access token.

    ```bash cURL
    curl --request GET \
      --url 'https://api.strukto.ai/v1/workspaces' \
      --header "Authorization: Bearer $MIRAGE_AUTH_TOKEN"
    ```

    See [Authentication](/api/authentication) for credentials and
    [Quickstart](/api/quickstart) to create a workspace and run a command.
  </Tab>
  <Tab title="OSS Server" icon="server">
    [Launch a server](/home/access/http#launch-a-server), then list its
    workspaces. Set `MIRAGE_AUTH_TOKEN` to the token configured on your server.

    ```bash cURL
    curl --request GET \
      --url 'http://127.0.0.1:8765/v1/workspaces' \
      --header "Authorization: Bearer $MIRAGE_AUTH_TOKEN"
    ```

    Omit the authorization header if your local server has no token configured.
    See [Server authentication](/home/access/http#configure-authentication)
    for token and JWT settings.
  </Tab>
</Tabs>

## Endpoint availability

<Note>
Workspace VFS endpoints describe the planned Cloud contract. They are available
in OSS Server; the Cloud implementation is pending. Shell is already available in Cloud.
</Note>

Choose **Cloud** or **OSS Server** with the filter above the sidebar.
Shared content is generated from one source. Deployment differences are called out
on the endpoint page. cURL examples
use the selected deployment's base URL.

Server administration, such as readiness checks, metrics, and shutdown,
belongs to OSS Server. See [HTTP](/home/access/http) for server setup and configuration.

## Resource groups

**Workspaces** contains workspace lifecycle operations, command execution, path
matching, direct VFS operations, and [command logs](/api/operations/workspaces/list-workspace-logs).

**Saved configurations** contains reusable VFS, CLI, and runtime definitions.
These configure workspace backends and commands. Templates describe workspace
configurations. Policies manage reusable rules.

## OpenAPI contracts

Download the [Cloud contract](/api/deployments/cloud.json) or the
[OSS Server contract](/api/deployments/server.json) for schemas and all documented
status codes. The right pane shows successful responses; errors appear in each
endpoint's collapsed **Errors** section.
