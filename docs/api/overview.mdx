The Mirage HTTP API creates workspaces, runs shell commands, and reads or writes
files. Run the Python or TypeScript server on your own machine or infrastructure.
Both implementations follow the same [OpenAPI contract](https://github.com/strukto-ai/mirage/blob/main/docs/openapi.yaml).

## Base URL

A local server uses `http://127.0.0.1:8765` by default. Examples in this reference
use that address. For a server on another machine, replace it with your server's
base URL. Routes are under `/v1`.

## Make a request

[Launch a server](/home/access/http#launch-a-server), then list its workspaces.
Set `MIRAGE_AUTH_TOKEN` to the token configured on your server:

```bash
curl --request GET \
  --url 'http://127.0.0.1:8765/v1/workspaces' \
  --header "Authorization: Bearer $MIRAGE_AUTH_TOKEN"
```

Local mode without a configured token accepts requests without the authorization
header. See [Authentication](/api/authentication) for token and JWT settings.

## Resource groups

**Workspaces** groups lifecycle operations, Shell, VFS, Agent Instructions, Approval requests,
Commands, Jobs, Processes, and Machines. Each operation acts on a workspace.

**Configuration** groups reusable templates, policies, and saved VFS, CLI, runtime,
and machine configurations.
Service and Daemon contain health checks and server administration.

## OpenAPI contract

[`openapi.yaml`](https://github.com/strukto-ai/mirage/blob/main/docs/openapi.yaml) defines the endpoints, request and response schemas,
and examples shown in this reference. It retains every documented status code.
The right pane shows successful response examples. Each endpoint's collapsed
**Errors** section explains its documented failures.
