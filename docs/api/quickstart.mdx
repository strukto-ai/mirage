title: Quickstart
description: Create a workspace and run your first shell command over HTTP.

---

Set these variables before starting a [local server](/home/access/http#launch-a-server).
Use the same token and base URL in the terminal that sends requests:

```bash
export MIRAGE_AUTH_MODE=token
export MIRAGE_AUTH_TOKEN='replace-with-your-token'
export MIRAGE_BASE_URL='http://127.0.0.1:8765'
```

For a hosted workspace, set `MIRAGE_BASE_URL` to the API URL from your deployment
and use its token. The request paths and JSON bodies are the same.

Create a workspace with an in-memory filesystem:

```bash
curl "$MIRAGE_BASE_URL/v1/workspaces" \
  -H "Authorization: Bearer $MIRAGE_AUTH_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"id":"demo","config":{"mounts":{"/":{"vfs":"ram","mode":"write"}}}}'
```

The response has status `201` and the workspace identifier `demo`. An identical
retry returns the existing workspace with status `200`. Supply either `config`
or a saved `template`, never both.

Run a shell command in that workspace:

```bash
curl "$MIRAGE_BASE_URL/v1/workspaces/demo/shell" \
  -H "Authorization: Bearer $MIRAGE_AUTH_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"command":"echo hello"}'
```

The response contains the command's output and exit status:

```json
{"kind":"io","exit_code":0,"stdout":"hello\n","stderr":"","refusal":null}
```

Use [Create a workspace](/api/operations/workspaces/create-a-workspace) and
[Run a shell line](/api/operations/shell/run-a-shell-line) for the complete
request fields and responses. Browse the resource groups on the left, or use
the [endpoint search](/api/reference) to find an operation by path, parameter
or response field.
