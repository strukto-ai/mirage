Mirage implements a subset of the [GitHub CLI (`gh`)](https://github.com/cli/cli).

Create a token in [GitHub setup](/home/setup/github), then register it on an
existing `ws`.

Fine-grained tokens need permissions matching the commands used: Issues, Pull
requests, Actions, Contents, or Administration. `gh api` is endpoint-specific;
consult GitHub's [fine-grained token permission table](https://docs.github.com/en/rest/authentication/permissions-required-for-fine-grained-personal-access-tokens).

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    clis:
      gh:
        cli: gh
        machine: in_process
        config:
          token: ${GITHUB_TOKEN}
          repo: acme/tools
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    from mirage.commands.cli.builtin.gh import GH
    from mirage.core.github.config import GhConfig

    config = GhConfig(token="github_pat_...", repo="acme/tools")
    ws.register_cli("gh", GH, config)
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { GH } from '@struktoai/mirage-node'

    ws.registerCli('gh', GH, { token: 'github_pat_...', repo: 'acme/tools' })
    ```
