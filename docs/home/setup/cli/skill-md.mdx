title: SKILL.md
description: The Markdown file that tells an agent which CLIs it can run and how to call them.

SKILL.md lists the CLIs installed in a workspace, each with its top-level
help; a subcommand's usage is one `--help` away. It is built from the live
workspace and follows the session's [profile](/home/policy/overview): a CLI
or subcommand the profile denies is never mentioned. Each CLI's reference
shows its SKILL.md, such as [Slack](/python/cli/slack#skill-md). The mounted
paths are in [VFS.md](/home/setup/vfs-md).

## Get it


- **No session or profile**: what the workspace's default profile allows.
- **A session**: what that session's agent sees.
- **A profile**: a preview of what a session with that profile would see.
- **A path**: the file appears in the workspace, read-only and always
  current, so the agent runs `cat /SKILL.md`.

## What SKILL.md says about each CLI

- **Usage**: the CLI's top-level `--help`: its groups, options and operands,
  from the same spec its parser uses.
- **Denied subcommands**: when the profile allows only part of a CLI, the
  help pages down to what it allows, listing only the subcommands that lead
  there.
- **Own argument parsing**: a script CLI with no spec shows only its
  registered description.

Mount commands such as `ls` and `grep` are in VFS.md, not here.
