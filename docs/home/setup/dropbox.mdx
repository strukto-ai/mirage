A Dropbox account, or one folder of it, becomes a folder tree of its real
files, served as raw bytes.

## Setup

Create a Dropbox app, give it file permissions and trade one sign-in for a
long-lived refresh token. Mirage mints the short-lived access tokens (about 4
hours) from it and renews each one 5 minutes before it expires.

<AccordionGroup>
  <Accordion title="1. Create a Dropbox app">
    1. Open the [App Console](https://www.dropbox.com/developers/apps) and
       click **Create app**.
    1. Choose **Scoped access**.
    1. Choose **App folder** (one folder Dropbox creates for the app, the
       least privilege) or **Full Dropbox** (the whole account).
    1. Name it (for example "Mirage") and click **Create app**.
  </Accordion>
  <Accordion title="2. Set permissions">
    On the **Permissions** tab, check:

    | Scope | Purpose |
    | --- | --- |
    | `files.metadata.read` | List folders, read file metadata |
    | `files.content.read` | Download file bytes |
    | `files.content.write` | Upload, overwrite, create, delete, move and copy (write mounts) |
    | `account_info.read` | Account space usage for `df` (optional) |

    Click **Submit**. Dropbox leaves unchecked scopes out of tokens, even
    when the sign-in URL asks for them.
  </Accordion>
  <Accordion title="3. Get the refresh token">
    1. On the **Settings** tab, add `http://localhost:1` under **OAuth 2** >
       **Redirect URIs**, then copy the **App key** and the **App secret**.
    1. Open this URL in a browser, with `YOUR_APP_KEY` replaced.
       `token_access_type=offline` is required for a refresh token:

       ```text
       https://www.dropbox.com/oauth2/authorize?client_id=YOUR_APP_KEY&response_type=code&token_access_type=offline&redirect_uri=http://localhost:1
       ```

    1. Sign in and click **Allow**. The browser goes to
       `http://localhost:1/?code=...`, a page that does not load. Copy the
       `code` value and exchange it right away:

       ```bash
       curl https://api.dropboxapi.com/oauth2/token \
         -d "code=THE_CODE" \
         -d "grant_type=authorization_code" \
         -d "client_id=YOUR_APP_KEY" \
         -d "client_secret=YOUR_APP_SECRET" \
         -d "redirect_uri=http://localhost:1"
       ```

    The JSON reply holds `refresh_token` (and `expires_in: 14400` for the
    access token). Save the refresh token.
  </Accordion>
  <Accordion title="Browser sign-in with PKCE (no app secret)">
    A browser app can skip the app secret: the TypeScript `DropboxVFS` from
    `@struktoai/mirage-browser` takes only `clientId` and `refreshToken`.

    1. Add `http://localhost:5173/vfs/dropbox/dropbox_pkce.html` to the
       **Redirect URIs**. It must match exactly, with no trailing slash.
    1. Set only `DROPBOX_APP_KEY` in `.env.development` at the repo root.
    1. Run `pnpm dev` in `examples/browser/` and open that URL.
    1. Click **Connect Dropbox**.

    The example keeps the refresh token in `localStorage`. The same token
    works headless as `DROPBOX_REFRESH_TOKEN`.
  </Accordion>
  <Accordion title="Troubleshooting">
    | Issue | Fix |
    | --- | --- |
    | `400 invalid_grant` on the exchange | The code is single-use and short-lived: sign in again |
    | No `refresh_token` in the reply | Add `token_access_type=offline` to the URL |
    | `path/not_found` on `ls /dropbox` | The account is empty, or an App folder app's folder does not exist yet |
    | `missing_scope` on a read | Check `files.content.read` and click **Submit** on **Permissions** |
    | Refresh stops working | The refresh token was revoked: sign in again |

    A refresh token lasts until it is revoked: the user disconnects the app
    at [connected apps](https://www.dropbox.com/account/connected_apps), or
    the app is deleted.
  </Accordion>
</AccordionGroup>

```bash
export DROPBOX_APP_KEY=abc123appkey
export DROPBOX_APP_SECRET=def456appsecret
export DROPBOX_REFRESH_TOKEN=ghi789refresh
```

## Connect

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    mounts:
      /dropbox:
        vfs: dropbox
        mode: read
        config:
          client_id: ${DROPBOX_APP_KEY}
          client_secret: ${DROPBOX_APP_SECRET}
          refresh_token: ${DROPBOX_REFRESH_TOKEN}
    ```

    ```bash
    mirage workspace create workspace.yaml --id dbx
    mirage shell -w dbx -c 'ls /dropbox'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from mirage import MountMode, Workspace
    from mirage.vfs.dropbox import DropboxConfig, DropboxVFS

    config = DropboxConfig(
        client_id=os.environ["DROPBOX_APP_KEY"],
        client_secret=os.environ["DROPBOX_APP_SECRET"],
        refresh_token=os.environ["DROPBOX_REFRESH_TOKEN"],
    )
    ws = Workspace({"/dropbox": DropboxVFS(config)}, mode=MountMode.READ)
    result = await ws.shell("ls /dropbox")
    print(await result.stdout_str())
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { DropboxVFS, MountMode, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      {
        '/dropbox': new DropboxVFS({
          clientId: process.env.DROPBOX_APP_KEY!,
          clientSecret: process.env.DROPBOX_APP_SECRET!,
          refreshToken: process.env.DROPBOX_REFRESH_TOKEN!,
        }),
      },
      { mode: MountMode.READ },
    )
    const result = await ws.shell('ls /dropbox')
    console.log(result.stdoutText)
    ```
  </Tab>
</Tabs>

## Layout

```text
/dropbox/
  Photos/
  Projects/
    data.csv
    report.pdf
  notes.txt
```

- `root_path` (such as `/Team/data`) mounts one folder; an App folder app sees
  only its own folder.
- Files keep their names and bytes.
- `grep -rw` asks Dropbox search first; below the Professional plan it matches
  file names only.

## Sample runs

```bash
$ ls /dropbox
Photos
Projects
notes.txt
```

```bash
$ head -n 3 /dropbox/Projects/data.csv
date,region,revenue
2026-11-01,us-east,1250
2026-11-01,eu-west,980
```

```bash
$ find /dropbox/Projects -name '*.pdf'
/dropbox/Projects/report.pdf
```

On a `write` mount, `tee`, `cp`, `mv`, `rm` and `mkdir` change Dropbox and
need `files.content.write`. `rmdir` fails with `ENOTEMPTY` on a non-empty
folder; `rm -r` removes it.
