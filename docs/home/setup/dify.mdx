A Dify Knowledge dataset becomes a tree of text files. Each document is one
file, assembled from its segments.

## Setup

The mount reads the Dify Knowledge Base API with a Knowledge API key:

1. In Dify, open **Knowledge**, click **Service API** in the top right, then
   **API Key**, and create a key. Only workspace owners and admins can.
1. Give the key access to all knowledge bases or to the one to mount. The scope
   cannot change later.
1. Copy the Service API endpoint from the same panel: `https://api.dify.ai/v1`
   on Dify Cloud, the instance's own `/v1` URL when self-hosted.
1. Copy the dataset ID, the value after `/datasets/` in the knowledge base URL.
1. Keep **API Access** on for that knowledge base (it is on by default).

```bash
export DIFY_API_KEY=dataset-...
export DIFY_BASE_URL=https://api.dify.ai/v1
export DIFY_DATASET_ID=...
```

<AccordionGroup>
  <Accordion title="Give documents a slug">
    A document's path is the value of its `slug` metadata field. Without one,
    the file takes the document name. `slug_metadata_name` picks another field,
    such as `path`.

    | Dify document | `slug` value | Mirage path |
    | --- | --- | --- |
    | Quickstart | `guides/quickstart.md` | `/knowledge/guides/quickstart.md` |
    | Support Policy | `policies/support.md` | `/knowledge/policies/support.md` |

    In the Knowledge UI, open each document and add a metadata item named
    `slug`. Documents uploaded through the API carry the same item in their
    metadata.

    - Forward slashes make folders; leading and trailing slashes are trimmed.
    - No empty segment, `.` or `..`.
    - Values stay unique: two documents with one slug fail as a duplicate path.
    - A slug is never a parent of another: `guides` and `guides/quickstart.md`
      collide.
  </Accordion>
  <Accordion title="Scoped search on name-based files">
    `search` limited to a path filters Dify retrieval by the slug field, or by
    `document_name` for a document without one. That filter needs **Built-in
    Fields** turned on in the dataset's metadata settings, with
    `document_name` available. Without it, scoped `search` on name-based files
    may return nothing, while `ls`, `find`, `cat` and `grep` still work. A slug
    on every document gives the most predictable paths.
  </Accordion>
</AccordionGroup>

## Connect

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    mounts:
      /knowledge:
        vfs: dify
        mode: read
        config:
          api_key: ${DIFY_API_KEY}
          base_url: ${DIFY_BASE_URL}
          dataset_id: ${DIFY_DATASET_ID}
    ```

    ```bash
    mirage workspace create workspace.yaml --id dify
    mirage shell -w dify -c 'ls /knowledge'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from mirage import MountMode, Workspace
    from mirage.vfs.dify import DifyConfig, DifyVFS

    config = DifyConfig(
        api_key=os.environ["DIFY_API_KEY"],
        base_url=os.environ["DIFY_BASE_URL"],
        dataset_id=os.environ["DIFY_DATASET_ID"],
    )
    ws = Workspace({"/knowledge": DifyVFS(config)}, mode=MountMode.READ)
    result = await ws.shell("ls /knowledge")
    print(await result.stdout_str())
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { DifyVFS, MountMode, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      {
        '/knowledge': new DifyVFS({
          apiKey: process.env.DIFY_API_KEY!,
          baseUrl: process.env.DIFY_BASE_URL!,
          datasetId: process.env.DIFY_DATASET_ID!,
        }),
      },
      { mode: MountMode.READ },
    )
    const result = await ws.shell('ls /knowledge')
    console.log(result.stdoutText)
    ```
  </Tab>
</Tabs>

## Layout

```text
/knowledge/
  README.md
  guides/
    api.md
    quickstart.md
  policies/
    support.md
```

- Only enabled, fully indexed, unarchived documents appear.
- A file is plain text, its segments joined by line breaks, whatever the
  original format.
- The [`search` CLI](/python/cli/search) asks Dify's retrieval with
  `--method semantic`, `fulltext`, `hybrid` or `keyword`; `--top-k` is capped
  at 100.

## Sample runs

```bash
$ ls /knowledge/guides
api.md
quickstart.md
```

```bash
$ head -n 2 /knowledge/policies/support.md
# Support Policy
Email support answers within one business day.
```

```bash
$ grep -rn "business day" /knowledge
/knowledge/policies/support.md:2:Email support answers within one business day.
```

The mount is read-only.
