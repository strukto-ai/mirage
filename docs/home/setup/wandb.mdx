Each configured entity becomes a folder of projects and runs. A run folder
holds its metadata, config, summary and full metric history as JSON, plus the
files the run uploaded.

## Setup

Create a key under **API Keys** in [User Settings](https://wandb.ai/settings)
with **Create new API key**, and copy it: W&B shows the full key only once.
The key reads what its user can read. Set `entities` to the user or team
segment of a project URL (`wandb.ai/<entity>/<project>`); Mirage does not
discover entities from the key.

```bash
export WANDB_API_KEY=...
```

## Connect

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    mounts:
      /wandb:
        vfs: wandb
        mode: read
        config:
          entities: [my-team]
          api_key: ${WANDB_API_KEY}
    ```

    ```bash
    mirage workspace create workspace.yaml --id wb
    mirage shell -w wb -c 'ls /wandb/my-team'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from mirage import MountMode, Workspace
    from mirage.vfs.wandb import WandbConfig, WandbVFS

    config = WandbConfig(
        entities=["my-team"],
        api_key=os.environ["WANDB_API_KEY"],
    )
    ws = Workspace({"/wandb": WandbVFS(config)}, mode=MountMode.READ)
    result = await ws.shell("ls /wandb/my-team")
    print(await result.stdout_str())
    await ws.close()
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, Workspace, buildVfs } from '@struktoai/mirage-node'

    const ws = new Workspace(
      {
        '/wandb': await buildVfs('wandb', {
          entities: ['my-team'],
          api_key: process.env.WANDB_API_KEY,
        }),
      },
      { mode: MountMode.READ },
    )
    const result = await ws.shell('ls /wandb/my-team')
    console.log(result.stdoutText)
    await ws.close()
    ```
  </Tab>
</Tabs>

## Layout

```text
/wandb/
  my-team/
    image-cls/
      3k9x2m7q/
        run.json
        config.json
        summary.json
        history.jsonl
        files/
          output.log
          wandb-metadata.json
```

- Run IDs name the folders; runs that share a display name stay separate.
  `find /wandb/my-team -maxdepth 3 -name run.json` lists every run path.
- `run.json` holds identity, state, tags, creator (not the key's user) and
  counts. `summary.json` is the stored summary, which can differ from the best
  value in history. `history.jsonl` is the full, unsampled history in order.
- Listings follow W&B pagination: `page_size` defaults to 100 (at most 1000)
  and `max_pages` to 10000; running out fails rather than return a partial
  list. Recursive `du` stops at 1000 entries.

## Sample runs

```bash
$ ls /wandb/my-team/image-cls
3k9x2m7q
8vbd0q1t
```

```bash
$ jq -r '.display_name, .state, .history_line_count' /wandb/my-team/image-cls/3k9x2m7q/run.json
resnet50-baseline
finished
1200
```

```bash
$ head -n 2 /wandb/my-team/image-cls/3k9x2m7q/history.jsonl
{"_step":0,"_runtime":12.4,"train/loss":2.31,"lr":0.01}
{"_step":1,"_runtime":24.9,"train/loss":1.87,"lr":0.01}
```

The mount is read-only. It registers no write operations and no W&B CLI.
