Every object in a QingStor (QingCloud Object Storage) bucket becomes a file, and every `/` in a key becomes a folder.



## Setup

Create an access key in the [QingCloud console](https://console.qingcloud.com/), then export it.

<AccordionGroup>
  <Accordion title="Create a QingStor access key">

1. Open **API Keys** from the account menu and create a key.
1. Copy the **Access Key ID** and **Secret Access Key**.
1. Note the bucket's zone, for example `pek3a`. The zone goes in `region`.

  </Accordion>
</AccordionGroup>

```bash
export QINGSTOR_BUCKET=my-bucket
export QINGSTOR_ZONE=pek3a
export QINGSTOR_ACCESS_KEY_ID=...
export QINGSTOR_SECRET_ACCESS_KEY=...
```

## Connect

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    mounts:
      /qingstor:
        vfs: qingstor
        mode: read
        config:
          bucket: ${QINGSTOR_BUCKET}
          region: ${QINGSTOR_ZONE}
          access_key_id: ${QINGSTOR_ACCESS_KEY_ID}
          secret_access_key: ${QINGSTOR_SECRET_ACCESS_KEY}
    ```

    ```bash
    mirage workspace create workspace.yaml --id qingstor
    mirage shell -w qingstor -c 'ls /qingstor'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from mirage import MountMode, Workspace
    from mirage.vfs.qingstor import QingStorConfig, QingStorVFS

    config = QingStorConfig(
        bucket=os.environ["QINGSTOR_BUCKET"],
        region=os.environ["QINGSTOR_ZONE"],
        access_key_id=os.environ["QINGSTOR_ACCESS_KEY_ID"],
        secret_access_key=os.environ["QINGSTOR_SECRET_ACCESS_KEY"],
    )
    ws = Workspace({"/qingstor": QingStorVFS(config)}, mode=MountMode.READ)
    result = await ws.shell("ls /qingstor")
    print(await result.stdout_str())
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, QingStorVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      {
        '/qingstor': new QingStorVFS({
          bucket: process.env.QINGSTOR_BUCKET!,
          region: process.env.QINGSTOR_ZONE!,
          accessKeyId: process.env.QINGSTOR_ACCESS_KEY_ID!,
          secretAccessKey: process.env.QINGSTOR_SECRET_ACCESS_KEY!,
        }),
      },
      { mode: MountMode.READ },
    )
    const result = await ws.shell('ls /qingstor')
    console.log(result.stdoutText)
    ```
  </Tab>
</Tabs>

## Layout

```text
/qingstor/
  README.md
  logs/
    app-2026-11-15.log
    app-2026-11-16.log
  reports/
    2026-q3.csv
    2026-q4.csv
```

- The endpoint comes from the zone: `s3.<zone>.qingstor.com`, the
  S3-compatible host, not the native `<zone>.qingstor.com`. Set `endpoint_url`
  (`endpoint` in TypeScript) for another host, such as `s3.<zone>.qsstor.com`.
- `key_prefix` (`keyPrefix` in TypeScript) mounts one folder of the bucket as
  the root.
- `grep -r`, `find` and `du` stop after 1000 files; a glob matching more,
  `tar -c`, `cp -r` and `rm -r` are refused.

## Sample runs

```bash
$ ls /qingstor
README.md
logs
reports
```

```bash
$ find /qingstor -name '*.csv'
/qingstor/reports/2026-q3.csv
/qingstor/reports/2026-q4.csv
```

```bash
$ grep -r ERROR /qingstor/logs
/qingstor/logs/app-2026-11-15.log:2026-11-15T08:01:13Z ERROR timeout reaching db
/qingstor/logs/app-2026-11-16.log:2026-11-16T09:12:40Z ERROR timeout reaching db
```

On a `write` mount, `cp`, `mv`, `rm` and `>` change objects in the bucket. For
`write: conditional`, see [S3-compatible VFSes](/home/setup/s3#s3-compatible-vfses).
