Every object in an existing Backblaze B2 bucket becomes a file, and every `/` in a key becomes a folder.



## Setup

Create an application key in the [Backblaze web console](https://secure.backblaze.com/), then export it.

<AccordionGroup>
  <Accordion title="Create a B2 application key">

1. Under **B2 Cloud Storage**, open **Application Keys** and click
   **Add a New Application Key**.
1. In **Allow Access to Bucket(s)**, pick the bucket and tick
   **Allow List All Bucket Names**.
1. Pick **Read Only**, or **Read and Write** for a write mount, then click
   **Create New Key**.
1. Copy the **keyID** (the access key ID) and the **applicationKey** (the
   secret access key). The applicationKey is shown only once.
1. Read the region off the bucket's **Endpoint**, `s3.<region>.backblazeb2.com`,
   for example `us-west-004`.

The master application key does not work with the S3-compatible API, and
neither does a key created before May 4, 2020.

  </Accordion>
</AccordionGroup>

```bash
export B2_BUCKET=my-bucket
export B2_REGION=us-west-004
export B2_ACCESS_KEY_ID=...
export B2_SECRET_ACCESS_KEY=...
```

## Connect

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    mounts:
      /b2:
        vfs: backblaze
        mode: read
        config:
          bucket: ${B2_BUCKET}
          region: ${B2_REGION}
          access_key_id: ${B2_ACCESS_KEY_ID}
          secret_access_key: ${B2_SECRET_ACCESS_KEY}
    ```

    ```bash
    mirage workspace create workspace.yaml --id b2
    mirage shell -w b2 -c 'ls /b2'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from mirage import MountMode, Workspace
    from mirage.vfs.backblaze import BackblazeConfig, BackblazeVFS

    config = BackblazeConfig(
        bucket=os.environ["B2_BUCKET"],
        region=os.environ["B2_REGION"],
        access_key_id=os.environ["B2_ACCESS_KEY_ID"],
        secret_access_key=os.environ["B2_SECRET_ACCESS_KEY"],
    )
    ws = Workspace({"/b2": BackblazeVFS(config)}, mode=MountMode.READ)
    result = await ws.shell("ls /b2")
    print(await result.stdout_str())
    await ws.close()
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { BackblazeVFS, MountMode, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      {
        '/b2': new BackblazeVFS({
          bucket: process.env.B2_BUCKET!,
          region: process.env.B2_REGION!,
          accessKeyId: process.env.B2_ACCESS_KEY_ID!,
          secretAccessKey: process.env.B2_SECRET_ACCESS_KEY!,
        }),
      },
      { mode: MountMode.READ },
    )
    const result = await ws.shell('ls /b2')
    console.log(result.stdoutText)
    await ws.close()
    ```
  </Tab>
</Tabs>

## Layout

```text
/b2/
  README.md
  logs/
    app-2026-11-15.log
    app-2026-11-16.log
  reports/
    2026-q3.csv
    2026-q4.csv
```

- The endpoint comes from `region`: `s3.<region>.backblazeb2.com`.
  `endpoint_url` (`endpoint` in TypeScript) overrides it.
- `key_prefix` (`keyPrefix` in TypeScript) mounts one folder of the bucket as
  the root.
- `grep -r`, `find` and `du` stop after 1000 files; a glob matching more,
  `tar -c`, `cp -r` and `rm -r` are refused.

## Sample runs

```bash
$ ls /b2
README.md
logs
reports
```

```bash
$ find /b2 -name '*.csv'
/b2/reports/2026-q3.csv
/b2/reports/2026-q4.csv
```

```bash
$ grep -r ERROR /b2/logs
/b2/logs/app-2026-11-15.log:2026-11-15T08:01:13Z ERROR timeout reaching db
/b2/logs/app-2026-11-16.log:2026-11-16T09:12:40Z ERROR timeout reaching db
```

On a `write` mount, `cp`, `mv`, `rm` and `>` change objects in the bucket. For
`write: conditional`, see [S3-compatible VFSes](/home/setup/s3#s3-compatible-vfses).
