Mirage turns your data sources into one unified virtual filesystem. Each
source is a VFS mounted under its own folder, such as S3 under `/s3`, Slack
under `/slack` and PostgreSQL under `/pg`, and an agent reads them all with
`ls`, `cat`, `grep` and `find`.

Each VFS turns its service into files and folders. An S3 object is a file, a
Slack channel is a folder with one `chat.jsonl` per day, and a PostgreSQL
table is a folder with its rows in `rows.jsonl`. [RAM](/home/setup/ram) needs
no credentials, so start there to try it.

## Example: Slack

Mount Slack under `/slack` with a [bot token](/home/setup/slack), plus a user
token for search:

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from mirage import MountMode, Workspace
    from mirage.vfs.slack import SlackConfig, SlackVFS

    slack = SlackVFS(
        config=SlackConfig(
            token=os.environ["SLACK_BOT_TOKEN"],
            search_token=os.environ["SLACK_USER_TOKEN"],
            content_search=True,
        )
    )
    ws = Workspace({"/slack": slack}, mode=MountMode.READ)
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, SlackVFS, Workspace } from '@struktoai/mirage-node'

    const slack = new SlackVFS({
      token: process.env.SLACK_BOT_TOKEN!,
      searchToken: process.env.SLACK_USER_TOKEN,
      contentSearch: true,
    })
    const ws = new Workspace({ '/slack': slack }, { mode: MountMode.READ })
    ```
  </Tab>
  <Tab title="YAML" icon="file-code">
    ```yaml
    mounts:
      /slack:
        vfs: slack
        mode: read
        config:
          token: ${SLACK_BOT_TOKEN}
          search_token: ${SLACK_USER_TOKEN}
          content_search: true
    ```
  </Tab>
</Tabs>

Slack becomes:

```text
/slack/
  channels/
    general__C04KEPWF6V7/
      2026-04-05/
        chat.jsonl
        files/
          roadmap__F07AB12CD.pdf
  dms/
    alice__D0AQDJ5FP9V/
      2026-04-05/
        chat.jsonl
  users/
    alice__U12345678.json
```

Each channel and DM has one folder per day for the last 90 days, and a day's
`chat.jsonl` holds one message per line. A name ends with its Slack ID after
`__`, so two channels with the same name stay apart.

```bash
ls /slack/channels/
head -1 /slack/channels/general__C04KEPWF6V7/2026-04-05/chat.jsonl
grep -rw refund /slack/channels/
```

The `head` prints:

```json
{"type":"message","user":"U12345678","text":"PR #326 is up for review","ts":"1775383200.000100"}
```

The `grep` uses Slack's own search: it asks Slack which days mention `refund`
and reads only those, not every day of every channel. That takes the
`search_token` (a user token with `search:read`), `content_search` and `-w`,
since Slack matches whole words. Without them, or when Slack's search cannot
answer, `grep` reads the files. Slack searches message text, file names and
reactions, and finds a new message only once it has indexed it. Attachments
under `files/` are always read.

## Supported VFS

A ✓ means the VFS runs there. In a browser, some need a proxy or CORS:
[Redis](/typescript/setup/redis#browser) uses an HTTP endpoint,
[PostgreSQL](/typescript/setup/postgres) uses Neon and
[MongoDB](/typescript/setup/mongodb) an HTTP bridge.
