A VFS (virtual filesystem) makes a data source available at a path in Mirage.
Virtualize S3 at `/data`, Slack at `/slack`, or PostgreSQL at `/db`, then use
commands such as `ls`, `cat`, `grep` and `find` to explore them.

Each VFS gives the service a file layout: objects become files, database rows
become JSONL, and messages appear under channels or mailboxes. Start with
[RAM](/python/vfs/ram) to try it without credentials, or choose your data
source below.

## Supported VFS

The columns show SDK availability: **Python**, **TypeScript on Node.js**, and
**TypeScript in a browser**. Linked names open setup or usage instructions.
Read and write operations depend on the VFS and your account permissions.

Browser connections may need a proxy, presigned URLs or CORS configuration.
In particular, [Redis](/typescript/setup/redis#browser) uses an HTTP endpoint,
[PostgreSQL](/typescript/setup/postgres) uses Neon, and
[MongoDB](/typescript/setup/mongodb) uses an HTTP bridge.

## Add your own VFS

Implement `readdir`, `stat` and `read` to expose another service as files.
Start with the [Python](/python/vfs/new) or [TypeScript](/typescript/vfs/new)
guide. Optional [search methods](/home/integration/search) let commands use
your service's index to avoid reading every file.
