A LanceDB table becomes nested folders, one level per group-by column. Each
row is a Markdown card plus an optional blob file, such as its image.

## Setup

A local directory needs no setup: LanceDB stores the table there, with no
server. Object storage and LanceDB Cloud need credentials.

<AccordionGroup>
  <Accordion title="Object storage">
    `uri` also takes `s3://`, `gs://` and `az://` URIs. Pass the store's
    credentials or endpoint in `storage_options`.
  </Accordion>
  <Accordion title="LanceDB Cloud and Enterprise">
    1. In the LanceDB Cloud UI, open the project and copy its database URI
       (it starts with `db://`) and an API key.
    1. Note the project's region; `region` defaults to `us-east-1`.
    1. LanceDB Enterprise: the LanceDB team provides the URI, the API key and
       the endpoint that goes in `host_override`.
    1. In the config, set `uri: ${LANCEDB_URI}`, `api_key: ${LANCEDB_API_KEY}`
       and `region: ${LANCEDB_REGION}`.
  </Accordion>
</AccordionGroup>

```bash
export LANCEDB_URI=db://my-database
export LANCEDB_API_KEY=...
export LANCEDB_REGION=us-east-1
```

## Connect

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    mounts:
      /fashion:
        vfs: lancedb
        mode: read
        config:
          uri: /data/fashion.lancedb
          table: fashion
          group_by: [gender, articleType, baseColour]
          title_column: productDisplayName
          blob_column: image_bytes
          blob_ext: jpg
    ```

    ```bash
    mirage workspace create workspace.yaml --id lance
    mirage shell -w lance -c 'ls /fashion'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    from mirage import MountMode, Workspace
    from mirage.vfs.lancedb import LanceDBConfig, LanceDBVFS

    config = LanceDBConfig(
        uri="/data/fashion.lancedb",
        table="fashion",
        group_by=["gender", "articleType", "baseColour"],
        title_column="productDisplayName",
        blob_column="image_bytes",
        blob_ext="jpg",
    )
    ws = Workspace({"/fashion": LanceDBVFS(config)}, mode=MountMode.READ)
    result = await ws.shell("ls /fashion")
    print(await result.stdout_str())
    await ws.close()
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { LanceDBVFS, MountMode, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      {
        '/fashion': new LanceDBVFS({
          uri: '/data/fashion.lancedb',
          table: 'fashion',
          groupBy: ['gender', 'articleType', 'baseColour'],
          titleColumn: 'productDisplayName',
          blobColumn: 'image_bytes',
          blobExt: 'jpg',
        }),
      },
      { mode: MountMode.READ },
    )
    const result = await ws.shell('ls /fashion')
    console.log(result.stdoutText)
    await ws.close()
    ```
  </Tab>
</Tabs>

## Layout

```text
/fashion/
  Men/
    Shoes/
      Black/
        7.jpg
        7.md
      White/
        3.jpg
        3.md
    Watches/
      Silver/
        15.jpg
        15.md
  Women/
    Tops/
      Blue/
        12.jpg
        12.md
```

- Without `table`, every table is a top-level folder.
- A card lists the row's columns, without the vector and blob columns.
- The [`search` CLI](/python/cli/search) ranks rows by meaning and returns
  their `<id>.md` paths, `search_limit` (10) by default. The table needs an
  embedding function on a source column.

## Sample runs

```bash
$ ls /fashion/Men/Shoes/White
3.jpg
3.md
```

```bash
$ cat /fashion/Men/Shoes/White/3.md
# Nike Men White Running Sneakers

id: 3
gender: Men
articleType: Shoes
baseColour: White
productDisplayName: Nike Men White Running Sneakers
blob: 3.jpg
```

```bash
$ grep -rl Sneakers /fashion
/fashion/Men/Shoes/White/3.md
```

The mount is read-only. One folder listing reads at most `max_rows` (1,000)
rows, so keep `group_by` to low-cardinality columns.
