Every object in a Wasabi bucket becomes a file, and every `/` in a key becomes a folder.



## Setup

Create an access key in the [Wasabi console](https://console.wasabisys.com/), then export it.

<AccordionGroup>
  <Accordion title="Create a Wasabi access key">

1. Open **Access Keys** and click **Create Access Key**.
1. Pick **Root User** or **Sub-User**. A sub-user whose policy covers only the
   bucket is the safer choice.
1. Click **Create**, then copy or download the **Access Key** and
   **Secret Key**. The secret key cannot be shown again.
1. Note the bucket's region, for example `us-east-2`.

Each user holds at most two access keys.

  </Accordion>
</AccordionGroup>

```bash
export WASABI_BUCKET=my-bucket
export WASABI_REGION=us-east-2
export WASABI_ACCESS_KEY_ID=...
export WASABI_SECRET_ACCESS_KEY=...
```

## Connect

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    mounts:
      /wasabi:
        vfs: wasabi
        mode: read
        config:
          bucket: ${WASABI_BUCKET}
          region: ${WASABI_REGION}
          access_key_id: ${WASABI_ACCESS_KEY_ID}
          secret_access_key: ${WASABI_SECRET_ACCESS_KEY}
    ```

    ```bash
    mirage workspace create workspace.yaml --id wasabi
    mirage shell -w wasabi -c 'ls /wasabi'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from mirage import MountMode, Workspace
    from mirage.vfs.wasabi import WasabiConfig, WasabiVFS

    config = WasabiConfig(
        bucket=os.environ["WASABI_BUCKET"],
        region=os.environ["WASABI_REGION"],
        access_key_id=os.environ["WASABI_ACCESS_KEY_ID"],
        secret_access_key=os.environ["WASABI_SECRET_ACCESS_KEY"],
    )
    ws = Workspace({"/wasabi": WasabiVFS(config)}, mode=MountMode.READ)
    result = await ws.shell("ls /wasabi")
    print(await result.stdout_str())
    await ws.close()
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, WasabiVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      {
        '/wasabi': new WasabiVFS({
          bucket: process.env.WASABI_BUCKET!,
          region: process.env.WASABI_REGION!,
          accessKeyId: process.env.WASABI_ACCESS_KEY_ID!,
          secretAccessKey: process.env.WASABI_SECRET_ACCESS_KEY!,
        }),
      },
      { mode: MountMode.READ },
    )
    const result = await ws.shell('ls /wasabi')
    console.log(result.stdoutText)
    await ws.close()
    ```
  </Tab>
</Tabs>

## Layout

```text
/wasabi/
  README.md
  logs/
    app-2026-11-15.log
    app-2026-11-16.log
  reports/
    2026-q3.csv
    2026-q4.csv
```

- The endpoint comes from `region`: `s3.<region>.wasabisys.com`, or
  `s3.wasabisys.com` for `us-east-1`, the default. `endpoint_url` (`endpoint`
  in TypeScript) overrides it.
- `key_prefix` (`keyPrefix` in TypeScript) mounts one folder of the bucket as
  the root.
- `grep -r`, `find` and `du` stop after 1000 files; a glob matching more,
  `tar -c`, `cp -r` and `rm -r` are refused.

## Sample runs

```bash
$ ls /wasabi
README.md
logs
reports
```

```bash
$ find /wasabi -name '*.csv'
/wasabi/reports/2026-q3.csv
/wasabi/reports/2026-q4.csv
```

```bash
$ grep -r ERROR /wasabi/logs
/wasabi/logs/app-2026-11-15.log:2026-11-15T08:01:13Z ERROR timeout reaching db
/wasabi/logs/app-2026-11-16.log:2026-11-16T09:12:40Z ERROR timeout reaching db
```

On a `write` mount, `cp`, `mv`, `rm` and `>` change objects in the bucket. For
`write: conditional`, see [S3-compatible VFSes](/home/setup/s3#s3-compatible-vfses).
