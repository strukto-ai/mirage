An OCI Object Storage bucket becomes a folder tree, with one file per
object, reached through OCI's Amazon S3 Compatibility API.



## Setup

The OCI VFS needs a bucket, the tenancy's Object Storage namespace, the region
and a Customer Secret Key pair.

<AccordionGroup>
  <Accordion title="Create the bucket, namespace and keys">
    1. In the OCI Console, open **Storage** > **Buckets**, choose the compartment
       and pick **Create bucket**, such as `mirage`. Keep the **Standard** tier
       unless archive is wanted.
    1. Open the **Profile** menu > **Tenancy** and copy the
       **Object Storage namespace**, such as `idsiqbdbcr4i`, or run
       `oci os ns get`.
    1. Open the **Profile** menu > **User settings** > **Customer secret keys**
       and pick **Generate secret key**. Copy the **Secret Key** right away:
       Oracle shows it only once. Then copy the key's **Access Key** from the list.
    1. Give the user's group policies such as
       `Allow group <group> to read buckets in compartment <compartment>` and
       `Allow group <group> to manage objects in compartment <compartment>`
       (`read objects` for a read-only mount).
    1. Read the region identifier from the region selector, such as
       `us-ashburn-1`, `us-phoenix-1` or `eu-frankfurt-1`.
  </Accordion>
</AccordionGroup>

```bash
export OCI_BUCKET=mirage
export OCI_NAMESPACE=idsiqbdbcr4i
export OCI_REGION=us-ashburn-1
export OCI_ACCESS_KEY_ID=...
export OCI_SECRET_ACCESS_KEY=...
```

- The namespace and region build the endpoint
  `https://<namespace>.compat.objectstorage.<region>.oci.customer-oci.com`,
  addressed path-style.
- A user holds at most two Customer Secret Keys.
- A prefix such as `data/` is not part of the bucket name; set `key_prefix` to
  mount it.

## Connect

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    mounts:
      /oci:
        vfs: oci
        mode: read
        config:
          bucket: ${OCI_BUCKET}
          namespace: ${OCI_NAMESPACE}
          region: ${OCI_REGION}
          access_key_id: ${OCI_ACCESS_KEY_ID}
          secret_access_key: ${OCI_SECRET_ACCESS_KEY}
    ```

    ```bash
    mirage workspace create workspace.yaml --id oci
    mirage shell -w oci -c 'ls /oci'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from mirage import MountMode, Workspace
    from mirage.vfs.oci import OCIConfig, OCIVFS

    config = OCIConfig(
        bucket=os.environ["OCI_BUCKET"],
        namespace=os.environ["OCI_NAMESPACE"],
        region=os.environ["OCI_REGION"],
        access_key_id=os.environ["OCI_ACCESS_KEY_ID"],
        secret_access_key=os.environ["OCI_SECRET_ACCESS_KEY"],
    )
    ws = Workspace({"/oci": OCIVFS(config)}, mode=MountMode.READ)
    result = await ws.shell("ls /oci")
    print(await result.stdout_str())
    await ws.close()
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, OCIVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      {
        '/oci': new OCIVFS({
          bucket: process.env.OCI_BUCKET!,
          namespace: process.env.OCI_NAMESPACE!,
          region: process.env.OCI_REGION!,
          accessKeyId: process.env.OCI_ACCESS_KEY_ID!,
          secretAccessKey: process.env.OCI_SECRET_ACCESS_KEY!,
        }),
      },
      { mode: MountMode.READ },
    )
    const result = await ws.shell('ls /oci')
    console.log(result.stdoutText)
    await ws.close()
    ```
  </Tab>
</Tabs>

## Layout

```text
/oci/
  data/
    events.jsonl
    users.parquet
  reports/
    2026-11/
      metrics.csv
      summary.md
```

- Each object key is a file path; folders are key prefixes, and the bucket holds no directory objects.
- `key_prefix` (`keyPrefix` in TypeScript) mounts one subpath of the bucket as the root.
- `grep -r`, `find` and `du` stop after 1000 files; a glob matching more, `tar -c`, `cp -r` and `rm -r` are refused.

## Sample runs

```bash
$ find /oci -type f
/oci/data/events.jsonl
/oci/data/users.parquet
/oci/reports/2026-11/metrics.csv
/oci/reports/2026-11/summary.md
```

```bash
$ head -n 3 /oci/reports/2026-11/metrics.csv
date,signups,active_users
2026-11-01,412,9810
2026-11-02,398,9875
```

```bash
$ grep -c signup /oci/data/events.jsonl
2
```

On a `write` mount, redirects, `cp`, `mv` and `rm` change objects in the bucket.
For `write: conditional`, see [S3-compatible VFSes](/home/setup/s3#s3-compatible-vfses).
