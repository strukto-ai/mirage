A [Qdrant](https://qdrant.tech/) collection becomes nested folders, one level
per group-by payload field. Each point is a `.json` payload file, plus a `.txt`
text file and an optional blob.

## Setup

A self-hosted Qdrant needs no key: set `host` and `port` (default
`localhost:6333`) instead of `url`. Qdrant Cloud needs the cluster URL and an
API key:

1. In the Qdrant Cloud console, open the cluster and go to its **API Keys** tab.
1. Click **Create**, name the key and pick an expiration (90 days by default).
1. Pick read-only access, for the whole cluster or for the collections to mount.
1. Copy the key, which shows only once, and the cluster URL.

```bash
export QDRANT_URL=https://xyz-example.eu-central.aws.cloud.qdrant.io:6333
export QDRANT_API_KEY=...
```

A folder listing creates a keyword payload index for a `group_by` field only
when Qdrant reports one is required. A read-only key cannot, so index those
fields first or use a key that manages the collection.

## Connect

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    mounts:
      /fashion:
        vfs: qdrant
        mode: read
        config:
          url: ${QDRANT_URL}
          api_key: ${QDRANT_API_KEY}
          collection: fashion
          group_by: [gender, articleType, baseColour]
          text_field: productDisplayName
    ```

    ```bash
    mirage workspace create workspace.yaml --id qdrant
    mirage shell -w qdrant -c 'ls /fashion'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from mirage import MountMode, Workspace
    from mirage.vfs.qdrant import QdrantConfig, QdrantVFS

    config = QdrantConfig(
        url=os.environ["QDRANT_URL"],
        api_key=os.environ["QDRANT_API_KEY"],
        collection="fashion",
        group_by=["gender", "articleType", "baseColour"],
        text_field="productDisplayName",
    )
    ws = Workspace({"/fashion": QdrantVFS(config)}, mode=MountMode.READ)
    result = await ws.shell("ls /fashion")
    print(await result.stdout_str())
    await ws.close()
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, QdrantVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      {
        '/fashion': new QdrantVFS({
          url: process.env.QDRANT_URL!,
          apiKey: process.env.QDRANT_API_KEY!,
          collection: 'fashion',
          groupBy: ['gender', 'articleType', 'baseColour'],
          textField: 'productDisplayName',
        }),
      },
      { mode: MountMode.READ },
    )
    const result = await ws.shell('ls /fashion')
    console.log(result.stdoutText)
    await ws.close()
    ```
  </Tab>

## Layout

```text
/fashion/
  Men/
    Shoes/
      Black/
        7.json
        7.txt
      White/
        3.json
        3.txt
    Watches/
      Silver/
        15.json
        15.txt
  Women/
    Tops/
      Blue/
        12.json
        12.txt
```

- Without `collection`, every collection is a top-level folder. Files are named
  by point id, or `<name>__<id>` with `name_field`.
- Fields take dotted payload paths, such as `group_by: [metadata.source]`, and
  `basename_fields` keeps only the last path segment of a value.
- The [`search` CLI](/python/cli/search) ranks points by meaning. It needs an
  `embed` hook (Python and TypeScript) or `cloud_inference: true`, where the
  cluster embeds the query with `embedding_model`; with neither it refuses the
  query. The stored vectors must come from the same model.

## Sample runs

```bash
$ ls /fashion/Men/Shoes/White
3.json
3.txt
```

```bash
$ cat /fashion/Men/Shoes/White/3.json
{"gender":"Men","articleType":"Shoes","baseColour":"White","productDisplayName":"Nike Men White Running Sneakers","id":3}
```

```bash
$ grep -rl Trail /fashion
/fashion/Men/Shoes/Black/7.json
/fashion/Men/Shoes/Black/7.txt
```

The mount is read-only. One folder listing scrolls at most `max_rows` (1,000)
points, and `search` returns `search_limit` (10) results by default.
