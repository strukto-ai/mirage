RAM keeps files in process memory, for scratch work, tests and trying Mirage.
The mount starts empty and its files are gone when the process exits.

## Connect

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    mounts:
      /data:
        vfs: ram
        mode: write
    ```

    ```bash
    mirage workspace create workspace.yaml --id scratch
    mirage shell -w scratch -c 'echo hello > /data/note.txt && cat /data/note.txt'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    from mirage import MountMode, Workspace
    from mirage.vfs.ram import RAMVFS

    ws = Workspace({"/data": RAMVFS()}, mode=MountMode.WRITE)
    result = await ws.shell("echo hello > /data/note.txt && cat /data/note.txt")
    print(await result.stdout_str())
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, RAMVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace({ '/data': new RAMVFS() }, { mode: MountMode.WRITE })
    const result = await ws.shell('echo hello > /data/note.txt && cat /data/note.txt')
    console.log(result.stdoutText)
    ```
  </Tab>
</Tabs>

## Layout

```text
/data/
  note.txt
  reports/
    q1.csv
```

- Files and folders exist only once a command writes them.
- Runs in Python, Node and browsers; see the
  [browser quickstart](/typescript/browser-quickstart).
- `capacity: 100MB` under `config` caps the bytes it holds; a write past it
  fails with "Disk quota exceeded". See [capacity](/home/setup/vfs#mount-capacity).

## Sample runs

```bash
$ tree /data
/data
|-- note.txt
`-- reports
    `-- q1.csv

2 directories, 2 files
```

```bash
$ sort -t, -k2 -n /data/reports/q1.csv
region,revenue
east,95
west,120
```

```bash
$ head -c 2000 /dev/zero > /data/big.bin
bash: line 1: /data/big.bin: Disk quota exceeded
```

The last run is on a mount with `capacity: 1KB`. Every command that writes
works here: `cp`, `mv`, `rm`, `mkdir`, `tee` and redirects.
