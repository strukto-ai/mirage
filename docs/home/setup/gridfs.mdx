GridFS keeps files inside MongoDB: names and sizes in `<bucket>.files`,
content in chunks in `<bucket>.chunks`. Slash-separated file names become
folders.

## Setup

Get a MongoDB connection URI as for the [MongoDB VFS](/home/setup/mongodb),
for a user with `readWrite` on the database that holds the bucket (`read` for
a `read` mount). In Atlas, the built-in **Read and write to any database**
role also works. Then export it:

```bash
export MONGODB_URI="mongodb+srv://<username>:<password>@cluster0.xxxxx.mongodb.net/"
```

Python needs `pip install "mirage-ai[gridfs]"`; Node needs the `mongodb` peer
dependency (`pnpm add @struktoai/mirage-node mongodb`).

## Connect

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    mounts:
      /gridfs:
        vfs: gridfs
        mode: write
        config:
          uri: ${MONGODB_URI}
          database: app
    ```

    ```bash
    mirage workspace create workspace.yaml --id files
    mirage shell -w files -c 'ls /gridfs'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from mirage import MountMode, Workspace
    from mirage.vfs.gridfs import GridFSConfig, GridFSVFS

    config = GridFSConfig(uri=os.environ["MONGODB_URI"], database="app")
    ws = Workspace({"/gridfs": GridFSVFS(config)}, mode=MountMode.WRITE)
    result = await ws.shell("ls /gridfs")
    print(await result.stdout_str())
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { GridFSVFS, MountMode, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      {
        '/gridfs': new GridFSVFS({
          uri: process.env.MONGODB_URI!,
          database: 'app',
        }),
      },
      { mode: MountMode.WRITE },
    )
    const result = await ws.shell('ls /gridfs')
    console.log(result.stdoutText)
    ```
  </Tab>
</Tabs>

## Layout

```text
/gridfs/
  data/
    config.json
    file.txt
  reports/
    q1.csv
```

- The bucket is `fs` unless `bucket` names another; `key_prefix` scopes the
  mount to the files under that prefix.
- A write adds a revision and the newest one is read. `rm` moves every
  revision to a trash no mount path reaches; `keep_revisions` bounds how many
  are kept.
- `mkdir` stores a zero-byte `data/` marker so an empty folder stays visible.

## Sample runs

```bash
$ tree /gridfs
/gridfs
|-- data
|   |-- config.json
|   `-- file.txt
`-- reports
    `-- q1.csv

3 directories, 3 files
```

```bash
$ grep -r west /gridfs
/gridfs/reports/q1.csv:west,120
```

```bash
$ find /gridfs -name '*.csv'
/gridfs/reports/q1.csv
```

Every command that writes works on a `write` mount; `mv` renames every
revision on the server.
