Every object in a Tencent Cloud Object Storage (COS) bucket becomes a file, and every `/` in a key becomes a folder.



## Setup

Create an API key in the [CAM console](https://console.cloud.tencent.com/cam), then export it.

<AccordionGroup>
  <Accordion title="Create a COS API key">

1. Open **Users** > **User List** and create or pick a sub-user. Attach a COS
   policy to it: read-only for a read mount, read and write for a write mount.
1. Click the sub-user's name, open the **API Key** tab and click
   **Create Key**.
1. Copy the **SecretId** (the access key ID) and **SecretKey** (the secret
   access key).
1. Note the bucket's region, for example `ap-guangzhou`, and its full name.

A COS bucket name always ends in the account's APPID, as in
`my-bucket-1250000000`. Use the full name, suffix included, for `COS_BUCKET`.

  </Accordion>
</AccordionGroup>

```bash
export COS_BUCKET=my-bucket-1250000000
export COS_REGION=ap-guangzhou
export COS_SECRET_ID=...
export COS_SECRET_KEY=...
```

## Connect

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    mounts:
      /cos:
        vfs: tencent
        mode: read
        config:
          bucket: ${COS_BUCKET}
          region: ${COS_REGION}
          access_key_id: ${COS_SECRET_ID}
          secret_access_key: ${COS_SECRET_KEY}
    ```

    ```bash
    mirage workspace create workspace.yaml --id cos
    mirage shell -w cos -c 'ls /cos'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from mirage import MountMode, Workspace
    from mirage.vfs.tencent import TencentConfig, TencentVFS

    config = TencentConfig(
        bucket=os.environ["COS_BUCKET"],
        region=os.environ["COS_REGION"],
        access_key_id=os.environ["COS_SECRET_ID"],
        secret_access_key=os.environ["COS_SECRET_KEY"],
    )
    ws = Workspace({"/cos": TencentVFS(config)}, mode=MountMode.READ)
    result = await ws.shell("ls /cos")
    print(await result.stdout_str())
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, TencentVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      {
        '/cos': new TencentVFS({
          bucket: process.env.COS_BUCKET!,
          region: process.env.COS_REGION!,
          accessKeyId: process.env.COS_SECRET_ID!,
          secretAccessKey: process.env.COS_SECRET_KEY!,
        }),
      },
      { mode: MountMode.READ },
    )
    const result = await ws.shell('ls /cos')
    console.log(result.stdoutText)
    ```
  </Tab>
</Tabs>

## Layout

```text
/cos/
  README.md
  logs/
    app-2026-11-15.log
    app-2026-11-16.log
  reports/
    2026-q3.csv
    2026-q4.csv
```

- The endpoint comes from `region`: `cos.<region>.myqcloud.com`.
  `endpoint_url` (`endpoint` in TypeScript) overrides it.
- `key_prefix` (`keyPrefix` in TypeScript) mounts one folder of the bucket as
  the root.
- `grep -r`, `find` and `du` stop after 1000 files; a glob matching more,
  `tar -c`, `cp -r` and `rm -r` are refused.

## Sample runs

```bash
$ ls /cos
README.md
logs
reports
```

```bash
$ find /cos -name '*.csv'
/cos/reports/2026-q3.csv
/cos/reports/2026-q4.csv
```

```bash
$ grep -r ERROR /cos/logs
/cos/logs/app-2026-11-15.log:2026-11-15T08:01:13Z ERROR timeout reaching db
/cos/logs/app-2026-11-16.log:2026-11-16T09:12:40Z ERROR timeout reaching db
```

On a `write` mount, `cp`, `mv`, `rm` and `>` change objects in the bucket. For
`write: conditional`, see [S3-compatible VFSes](/home/setup/s3#s3-compatible-vfses).
