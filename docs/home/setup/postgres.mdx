Every schema becomes a folder of tables and views. Each one holds its column
types, a summary of what it means and its rows as JSON lines.

## Setup

Get a connection string and a role that can read the tables. Then export the
string:

<AccordionGroup>
  <Accordion title="Get a connection string">
    - Local server: `postgres://postgres:postgres@localhost:5432/postgres`.
    - Neon: select **Connect** in the console, pick the branch, database and
      role, and copy the string. Neon requires `sslmode=require`.
    - Supabase: select **Connect** at the top of the project and copy a
      string. Use the direct connection, or the session pooler on an
      IPv4-only network. Put the database password in it.
    - Other managed servers (RDS and the like) print the string in their
      dashboard. Add `?sslmode=require` when the server needs TLS.
  </Accordion>
  <Accordion title="Grant a read-only role">
    The mount only reads. The role it connects as needs at least:

    ```sql
    GRANT USAGE ON SCHEMA public TO mirage_reader;
    GRANT SELECT ON ALL TABLES IN SCHEMA public TO mirage_reader;
    ALTER DEFAULT PRIVILEGES IN SCHEMA public GRANT SELECT ON TABLES TO mirage_reader;
    ```

    Repeat the grants for each schema the mount should see.
  </Accordion>
</AccordionGroup>

```bash
export DATABASE_URL="postgres://mirage_reader:<password>@<host>:5432/<database>?sslmode=require"
```

Python needs `pip install "mirage-ai[postgres]"`; Node needs the `pg` peer
dependency (`pnpm add @struktoai/mirage-node pg`).

## Connect

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    mounts:
      /pg:
        vfs: postgres
        mode: read
        config:
          dsn: ${DATABASE_URL}
          schemas: [public]
    ```

    ```bash
    mirage workspace create workspace.yaml --id pg
    mirage shell -w pg -c 'ls /pg/public/tables'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from mirage import MountMode, Workspace
    from mirage.vfs.postgres import PostgresConfig, PostgresVFS

    config = PostgresConfig(dsn=os.environ["DATABASE_URL"], schemas=["public"])
    ws = Workspace({"/pg": PostgresVFS(config)}, mode=MountMode.READ)
    result = await ws.shell("ls /pg/public/tables")
    print(await result.stdout_str())
    await ws.close()
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, PostgresVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      {
        '/pg': new PostgresVFS({
          dsn: process.env.DATABASE_URL!,
          schemas: ['public'],
        }),
      },
      { mode: MountMode.READ },
    )
    const result = await ws.shell('ls /pg/public/tables')
    console.log(result.stdoutText)
    await ws.close()
    ```
  </Tab>
</Tabs>

## Layout

```text
/pg/
  database.json
  public/
    tables/
      customers/
        schema.json
        semantic.json
        rows.jsonl
    views/
      paid_orders/
        schema.json
        semantic.json
        rows.jsonl
```

- `database.json` lists every table with its estimated rows and size;
  `schema.json` holds columns, keys and indexes.
- `schemas` limits the tree to those schemas. Unset, it shows all but
  `pg_catalog`, `information_schema` and `pg_*`.
- A whole read of `rows.jsonl` past `max_read_rows` (10,000, counted on the
  rows the table really has) or `max_read_bytes` (10 MiB) fails with
  `File too large`, and so does a `head -n` or `tail -n` count past it;
  `wc -l` counts past it. Raise them in `config` for bigger reads.
- `default_row_limit` (1,000) is what a windowed read with an offset but no
  limit returns.

## Sample runs

```bash
$ head -n 2 /pg/public/tables/customers/rows.jsonl
{"id":1,"name":"Ada Lovelace","email":"ada@example.com","country":"UK"}
{"id":2,"name":"Linus Torvalds","email":"linus@example.com","country":"FI"}
```

```bash
$ grep -i refunded /pg/public/tables/orders/rows.jsonl
{"id":2,"customer_id":2,"total":"35.00","status":"refunded","created_at":"2026-11-14 10:00:00+00"}
```

```bash
$ wc -l /pg/public/tables/orders/rows.jsonl
4 /pg/public/tables/orders/rows.jsonl
```

`head`, `tail`, `wc -l` and `grep` ask Postgres for only the rows they need.
The mount is read-only: no command changes the database.
