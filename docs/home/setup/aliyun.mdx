Every object in an existing Alibaba Cloud OSS bucket becomes a file, and every `/` in a key becomes a folder.



## Setup

Create an AccessKey pair for a RAM user in the [RAM console](https://ram.console.aliyun.com/), then export it.

<AccordionGroup>
  <Accordion title="Create an OSS AccessKey pair">

1. Open **Identities** > **Users** and create or pick a RAM user. Grant it
   `AliyunOSSReadOnlyAccess`, or `AliyunOSSFullAccess` for a write mount.
1. Click the user's name and, in the **AccessKey** section of its credential
   tab, click **Create AccessKey**.
1. Copy the **AccessKey ID** and **AccessKey Secret**. The secret is shown
   only once.
1. Note the bucket's region, for example `cn-hangzhou`.

Use a RAM user's key, not the root account's. Each RAM user holds at most two
AccessKey pairs.

  </Accordion>
</AccordionGroup>

```bash
export OSS_BUCKET=my-bucket
export OSS_REGION=cn-hangzhou
export OSS_ACCESS_KEY_ID=...
export OSS_ACCESS_KEY_SECRET=...
```

## Connect

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    mounts:
      /oss:
        vfs: aliyun
        mode: read
        config:
          bucket: ${OSS_BUCKET}
          region: ${OSS_REGION}
          access_key_id: ${OSS_ACCESS_KEY_ID}
          secret_access_key: ${OSS_ACCESS_KEY_SECRET}
    ```

    ```bash
    mirage workspace create workspace.yaml --id oss
    mirage shell -w oss -c 'ls /oss'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from mirage import MountMode, Workspace
    from mirage.vfs.aliyun import AliyunConfig, AliyunVFS

    config = AliyunConfig(
        bucket=os.environ["OSS_BUCKET"],
        region=os.environ["OSS_REGION"],
        access_key_id=os.environ["OSS_ACCESS_KEY_ID"],
        secret_access_key=os.environ["OSS_ACCESS_KEY_SECRET"],
    )
    ws = Workspace({"/oss": AliyunVFS(config)}, mode=MountMode.READ)
    result = await ws.shell("ls /oss")
    print(await result.stdout_str())
    await ws.close()
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { AliyunVFS, MountMode, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      {
        '/oss': new AliyunVFS({
          bucket: process.env.OSS_BUCKET!,
          region: process.env.OSS_REGION!,
          accessKeyId: process.env.OSS_ACCESS_KEY_ID!,
          secretAccessKey: process.env.OSS_ACCESS_KEY_SECRET!,
        }),
      },
      { mode: MountMode.READ },
    )
    const result = await ws.shell('ls /oss')
    console.log(result.stdoutText)
    await ws.close()
    ```
  </Tab>
</Tabs>

## Layout

```text
/oss/
  README.md
  logs/
    app-2026-11-15.log
    app-2026-11-16.log
  reports/
    2026-q3.csv
    2026-q4.csv
```

- The endpoint comes from `region`: `s3.oss-<region>.aliyuncs.com`, the
  S3-compatible host, not the native `oss-<region>.aliyuncs.com`.
  `endpoint_url` (`endpoint` in TypeScript) overrides it.
- `key_prefix` (`keyPrefix` in TypeScript) mounts one folder of the bucket as
  the root.
- `grep -r`, `find` and `du` stop after 1000 files; a glob matching more,
  `tar -c`, `cp -r` and `rm -r` are refused.

## Sample runs

```bash
$ ls /oss
README.md
logs
reports
```

```bash
$ find /oss -name '*.csv'
/oss/reports/2026-q3.csv
/oss/reports/2026-q4.csv
```

```bash
$ grep -r ERROR /oss/logs
/oss/logs/app-2026-11-15.log:2026-11-15T08:01:13Z ERROR timeout reaching db
/oss/logs/app-2026-11-16.log:2026-11-16T09:12:40Z ERROR timeout reaching db
```

On a `write` mount, `cp`, `mv`, `rm` and `>` change objects in the bucket. For
`write: conditional`, see [S3-compatible VFSes](/home/setup/s3#s3-compatible-vfses).
