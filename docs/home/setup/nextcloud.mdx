The files of one WebDAV account appear under the mount as they are on the
server. It works with Nextcloud, ownCloud, Hetzner Storage Share or any
[WebDAV](http://www.webdav.org/specs/rfc4918.html) endpoint.

## Setup

Any WebDAV server works: a hosted Nextcloud, a self-hosted one
(`docker run -p 8080:80 nextcloud`), ownCloud or Hetzner Storage Share.

1. In Nextcloud, open **Personal settings**, then **Security**.
2. Under **Devices & sessions**, enter an app name such as `mirage` and click
   **Create new app password**. Copy it: Nextcloud shows it only once.
3. Find the WebDAV URL under **Files settings**, **WebDAV**. On Nextcloud it is
   `https://<server>/remote.php/dav/files/<username>/`, with any install
   subdirectory before `/remote.php`. Other WebDAV servers give their own URL.

```bash
export NEXTCLOUD_URL=https://cloud.example.com/remote.php/dav/files/alice/
export NEXTCLOUD_USERNAME=alice
export NEXTCLOUD_PASSWORD=...
```

The account password also works, but an app password can be revoked on its
own without changing the account password.

## Connect

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    mounts:
      /nc:
        vfs: nextcloud
        mode: read
        config:
          url: ${NEXTCLOUD_URL}
          username: ${NEXTCLOUD_USERNAME}
          password: ${NEXTCLOUD_PASSWORD}
    ```

    ```bash
    mirage workspace create workspace.yaml --id nc
    mirage shell -w nc -c 'ls /nc'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from mirage import MountMode, Workspace
    from mirage.vfs.nextcloud import NextcloudConfig, NextcloudVFS

    config = NextcloudConfig(
        url=os.environ["NEXTCLOUD_URL"],
        username=os.environ["NEXTCLOUD_USERNAME"],
        password=os.environ["NEXTCLOUD_PASSWORD"],
    )
    ws = Workspace({"/nc": NextcloudVFS(config)}, mode=MountMode.READ)
    result = await ws.shell("ls /nc")
    print(await result.stdout_str())
    await ws.close()
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, NextcloudVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      {
        '/nc': new NextcloudVFS({
          url: process.env.NEXTCLOUD_URL!,
          username: process.env.NEXTCLOUD_USERNAME!,
          password: process.env.NEXTCLOUD_PASSWORD!,
        }),
      },
      { mode: MountMode.READ },
    )
    const result = await ws.shell('ls /nc')
    console.log(result.stdoutText)
    await ws.close()
    ```
  </Tab>
</Tabs>

## Layout

```text
/nc/
  Documents/
    notes.md
    contract.pdf
  Photos/
    2024/
      cat.jpg
```

- `/nc/Documents/notes.md` is `<NEXTCLOUD_URL>/Documents/notes.md` on the
  server.
- Files keep their own names and bytes; nothing is converted.
- Partial reads such as `head -c` send HTTP `Range` requests.

## Sample runs

```bash
$ ls /nc
Documents
Photos
```

```bash
$ ls /nc/Documents
contract.pdf
notes.md
```

```bash
$ head -n 2 /nc/Documents/notes.md
# Q4 planning
- Ship the sync client
```

On a `write` mount, `cp`, `mv`, `rm` and `mkdir` run as WebDAV `COPY`, `MOVE`,
`DELETE` and `MKCOL`. A write buffers the whole file before it uploads.
