OPFS mounts a folder of the browser's Origin Private File System. Its files
stay scoped to the page's origin and survive page reloads.

## Connect

<Tabs>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, OPFSVFS, Workspace } from '@struktoai/mirage-browser'

    const ws = new Workspace(
      { '/data': new OPFSVFS({ root: 'mirage' }) },
      { mode: MountMode.WRITE },
    )
    const result = await ws.shell('echo hello > /data/note.txt && cat /data/note.txt')
    console.log(result.stdoutText)
    await ws.close()
    ```
  </Tab>
</Tabs>

## Layout

```text
/data/
  note.txt
  drafts/
    plan.md
```

- `root` is a folder under the origin's OPFS root, so several workspaces can
  keep apart. It defaults to the OPFS root itself.
- Browser only. In Python or Node, use [Disk](/home/setup/disk).
- `capacity: '100MB'` caps the bytes the folder holds; see
  [capacity](/home/setup/vfs#mount-capacity).

## Sample runs

```bash
$ tree /data
/data
|-- drafts
|   `-- plan.md
`-- note.txt

2 directories, 2 files
```

```bash
$ cat /data/note.txt
hello
```

Every command that writes works on a `write` mount. The browser sets the
origin's quota and may evict the data under storage pressure; the
[OPFS guide](/typescript/setup/opfs#storage-and-quotas) shows how to check
usage and ask for persistent storage.
