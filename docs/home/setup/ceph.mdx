A bucket on a Ceph Rados Gateway (RGW) becomes a folder tree, with one file
per object.



## Setup

RGW signs S3 requests with an RGW user's key pair. On a host with
`radosgw-admin` access, create the user:

```bash
radosgw-admin user create --uid=mirage --display-name="Mirage"
```

Copy `access_key` and `secret_key` from the `keys` block of the output;
`radosgw-admin user info --uid=mirage` prints them again. If a key holds a
`\` JSON escape, remove the backslash or generate a new key.

```bash
export CEPH_BUCKET=my-bucket
export CEPH_ENDPOINT_URL=https://ceph.example.com
export CEPH_ACCESS_KEY_ID=...
export CEPH_SECRET_ACCESS_KEY=...
```

- RGW is self-hosted, so the endpoint is required and requests are path-style.

## Connect

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    mounts:
      /ceph:
        vfs: ceph
        mode: read
        config:
          bucket: ${CEPH_BUCKET}
          endpoint_url: ${CEPH_ENDPOINT_URL}
          access_key_id: ${CEPH_ACCESS_KEY_ID}
          secret_access_key: ${CEPH_SECRET_ACCESS_KEY}
    ```

    ```bash
    mirage workspace create workspace.yaml --id ceph
    mirage shell -w ceph -c 'ls /ceph'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from mirage import MountMode, Workspace
    from mirage.vfs.ceph import CephConfig, CephVFS

    config = CephConfig(
        bucket=os.environ["CEPH_BUCKET"],
        endpoint_url=os.environ["CEPH_ENDPOINT_URL"],
        access_key_id=os.environ["CEPH_ACCESS_KEY_ID"],
        secret_access_key=os.environ["CEPH_SECRET_ACCESS_KEY"],
    )
    ws = Workspace({"/ceph": CephVFS(config)}, mode=MountMode.READ)
    result = await ws.shell("ls /ceph")
    print(await result.stdout_str())
    await ws.close()
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { CephVFS, MountMode, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      {
        '/ceph': new CephVFS({
          bucket: process.env.CEPH_BUCKET!,
          endpoint: process.env.CEPH_ENDPOINT_URL!,
          accessKeyId: process.env.CEPH_ACCESS_KEY_ID!,
          secretAccessKey: process.env.CEPH_SECRET_ACCESS_KEY!,
        }),
      },
      { mode: MountMode.READ },
    )
    const result = await ws.shell('ls /ceph')
    console.log(result.stdoutText)
    await ws.close()
    ```
  </Tab>
</Tabs>

## Layout

```text
/ceph/
  data/
    events.jsonl
    users.parquet
  reports/
    2026-11/
      metrics.csv
      summary.md
```

- Each object key is a file path; folders are key prefixes, and the bucket holds no directory objects.
- `key_prefix` (`keyPrefix` in TypeScript) mounts one subpath of the bucket as the root.
- `grep -r`, `find` and `du` stop after 1000 files; a glob matching more, `tar -c`, `cp -r` and `rm -r` are refused.

## Sample runs

```bash
$ find /ceph -type f
/ceph/data/events.jsonl
/ceph/data/users.parquet
/ceph/reports/2026-11/metrics.csv
/ceph/reports/2026-11/summary.md
```

```bash
$ head -n 3 /ceph/reports/2026-11/metrics.csv
date,signups,active_users
2026-11-01,412,9810
2026-11-02,398,9875
```

```bash
$ grep -c signup /ceph/data/events.jsonl
2
```

On a `write` mount, redirects, `cp`, `mv` and `rm` change objects in the bucket.
For `write: conditional`, see [S3-compatible VFSes](/home/setup/s3#s3-compatible-vfses).
