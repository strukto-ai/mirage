QuickJS is the default runtime for `node` and `js` in both SDKs. It supports
ES2023 for small scripts and pipe transforms, with access to workspace files
under the same permissions as shell commands. Despite the command name,
it does not provide Node.js APIs, npm packages or network access.

## Installation

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```bash
    pip install 'mirage-ai[quickjs]'
    ```

    Download `qjs-wasi.wasm` from a
    [quickjs-ng release](https://github.com/quickjs-ng/quickjs/releases).
    Point `home`, or `MIRAGE_QUICKJS_HOME`, at its directory.
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```bash
    pnpm add quickjs-emscripten
    ```

    The package bundles its WebAssembly.
  </Tab>
</Tabs>

## Usage

QuickJS is in the default runtimes, so `node` works once it is installed. To
list it yourself:

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    from mirage import RAMVFS, MountMode, Workspace
    from mirage.runtime.js import QuickJsRuntime

    ws = Workspace(
        {"/data": RAMVFS()},
        mode=MountMode.EXEC,
        runtimes=[QuickJsRuntime(config={"home": "/path/to/quickjs"})],
    )
    await ws.shell("node -e 'console.log(1 + 1)'")
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, RAMVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace({ '/data': new RAMVFS() }, { mode: MountMode.EXEC, runtimes: ['quickjs'] })
    await ws.shell("node -e 'console.log(1 + 1)'")
    ```
  </Tab>
  <Tab title="YAML" icon="file-code">
    ```yaml
    mode: exec
    runtimes:
      - name: quickjs
        config:
          home: /path/to/quickjs
    mounts:
      /data:
        vfs: ram
    ```

    `home` is for the Python SDK; TypeScript ignores it.
  </Tab>
</Tabs>

## JavaScript compatibility

`std` and `os` are globals. The SDK columns identify where their APIs differ.

In TypeScript, any `std` or `os` function not listed as supported throws
`TypeError`.

Examples assume a writable `/data` mount. Mount modes and permissions still apply.

### `std.open()`

`std.open(path, mode, errorObj)` returns `null` on failure and sets
`errorObj.errno`. A read-only mount refuses modes that write. Modes and
modifiers are listed separately; for example, `rb` combines `r` and `b`.

| Mode or modifier | Python SDK | TypeScript SDK |
| --- | --- | --- |
| `r` | ✓ | ✓ |
| `w` | ✓ | ✓ |
| `a` | ✓ | ✓ |
| `x` | ✓ | ✓ |
| `b` | ✓ | ✓ |
| `+` | ✓ | ✓ |

<AccordionGroup>
  <Accordion title="Example: append to a workspace file" id="std-open-example">
    ```javascript
    const error = {};
    const file = std.open("/data/log.txt", "a", error);
    if (file === null) {
      throw new Error("Open failed: " + error.errno);
    }
    try {
      file.puts("Job completed.\n");
    } finally {
      file.close();
    }
    ```
  </Accordion>
  <Accordion title="Limitations" id="std-open-limitations">
    | API or behavior | Limitation |
    | --- | --- |
    | `x` | Exclusive-creation modifier: use `wx` or `ax`; `x` alone is not a valid mode. |
    | Write modes | A read-only mount refuses modes that write. |
  </Accordion>
</AccordionGroup>

## Notes

- `-e <code>` runs the argument, a file runs a mounted script, and with
  neither, piped input is the program. A `.mjs` file runs as an ES module;
  `.js` and `-e` run as classic scripts, and `-m` forces module mode.
- `console.log` and `print` add a newline; `std.out.puts` and `std.err.puts`
  write raw.
- An error in async code fails the run. In TypeScript this holds for a
  module and for the promise a script ends with, as in `main()`; a promise
  the script drops before then is not reported.
- QuickJS cannot reach host files or the network. `command_limits` bound its
  time and output, and in TypeScript a run also stops at 64 MiB of memory.
  Run untrusted or heavy code in a [sandbox](/home/setup/runtime/sandbox).
