[Pydantic Monty](https://github.com/pydantic/monty) runs `python3` in both
SDKs, including Node and browsers. It supports a subset of Python and works
with workspace files under the same permissions as shell commands. Programs
cannot access host files, host environment variables or the network.

## Installation

  <Tab title="Python" icon="/images/python-logo.svg">

## Usage

Monty is in the default runtimes, so `python3` works with no setup. To list
it yourself:

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    from mirage import RAMVFS, MountMode, Workspace

    ws = Workspace({"/data": RAMVFS()}, mode=MountMode.EXEC, runtimes=["monty"])
    await ws.shell("python3 -c 'print(1 + 1)'")
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, RAMVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace({ '/data': new RAMVFS() }, { mode: MountMode.EXEC, runtimes: ['monty'] })
    await ws.shell("python3 -c 'print(1 + 1)'")
    ```
  </Tab>
  <Tab title="YAML" icon="file-code">
    ```yaml
    mode: exec
    runtimes:
      - monty
    mounts:
      /data:
        vfs: ram
    ```
  </Tab>
</Tabs>

## Memory

Set `max_memory` to limit the Python program's memory per run, using a size
such as `64M`:

```yaml
runtimes:
  - name: monty
    config:
      max_memory: 64M
```

A run that needs more raises `MemoryError`. A run also holds no more than its
workspace's [`max_memory`](/home/core/output-limits#limit-a-workspaces-memory)
has left, 32 MB by default.

## Python compatibility

Support applies to both SDKs unless a row says otherwise.
For Python syntax and standard-library coverage, see
[Monty's limitations](https://pydantic.dev/docs/monty/limitations/).

Examples assume a writable `/data` mount. Mount modes and permissions still apply.

### `open()`

Modes and modifiers are listed separately; for example, `rb` combines `r` and `b`.

| Mode or modifier | Support |
| --- | --- |
| `r` | ✓ |
| `w` | ✓ |
| `a` | ✓ |
| `b` | ✓ |

<AccordionGroup>
  <Accordion title="Example: append to a workspace file" id="open-example">
    ```python
    with open("/data/log.txt", "a") as f:
        f.write("Job completed.\n")
    ```
  </Accordion>
  <Accordion title="Limitations" id="open-limitations">
    | API or behavior | Limitation |
    | --- | --- |
    | `x` | Exclusive creation is not supported. |
    | `+` | Read/write update modes (`r+`, `w+`, `a+`) are not supported. |
  </Accordion>
</AccordionGroup>

### File objects

| API | Support |
| --- | --- |
| `f.read()` | ✓ |
| `f.readline()` | ✓ |
| `f.readlines()` | ✓ |
| `f.seek()` | ✓ |
| `f.tell()` | ✓ |
| `f.write()` | ✓ |

<AccordionGroup>
  <Accordion title="Example: write and read lines" id="file-objects-example">
    ```python
    with open("/data/example.txt", "w") as f:
        f.write("first\nsecond\n")

    with open("/data/example.txt", "r") as f:
        print(f.readline())  # first
        f.seek(0)
        print(f.tell())  # 0
        print(f.readlines())  # ["first\n", "second\n"]
    ```
  </Accordion>
  <Accordion title="Limitations" id="file-objects-limitations">
    | API or behavior | Limitation |
    | --- | --- |
    | Reads and seeks | The whole file is loaded into memory; reads and seeks use that copy. |
    | `for line in f` | ✗ |
    | `f.truncate()` | ✗ |
    | `f.fileno()` | ✗ |
    | `f.write()` | Each call is written at once. |
  </Accordion>
</AccordionGroup>

  </Accordion>

### `json`

JSON parsing and serialization come from Monty; see its
[`json` reference](https://pydantic.dev/docs/monty/limitations/json/).

<AccordionGroup>
  <Accordion title="Example: write and read workspace JSON" id="json-example">
    ```python
    import json

    with open("/data/result.json", "w") as f:
        f.write(json.dumps({"status": "done"}))

    with open("/data/result.json", "r") as f:
        result = json.loads(f.read())
    print(result["status"])  # done
    ```
  </Accordion>
  <Accordion title="Limitations" id="json-limitations">
    Monty 1.0.0 does not provide `json.load()` or `json.dump()`. For workspace
    files, use `json.loads(f.read())` and `f.write(json.dumps(value))`, as above.
    See [Monty's JSON limitations](https://pydantic.dev/docs/monty/limitations/json/)
    for supported options and other differences from CPython.
  </Accordion>
</AccordionGroup>

## Notes

- A run starts in the shell's working directory. The script and every
  relative path pass the same mount and permission checks as `cat`: a rule
  protecting `/data/job.py` refuses `python3 job.py` from `/data`.
- Script arguments follow shell expansion, including globs.
- A console session takes the working directory on its first input and keeps
  its own after that.
- `raise SystemExit` exits successfully. `raise SystemExit("message")` exits
  with status 1 and prints the message.

## Python subset

Monty 1.0.0 implements a subset of Python, and Mirage never falls back to
another interpreter.

Monty maintains the details of its
[standard-library modules](https://pydantic.dev/docs/monty/limitations/modules/)
and [language limitations](https://pydantic.dev/docs/monty/limitations/language/).
Those pages track upstream Monty; the integration tables above describe the
version used by Mirage. Third-party imports are unavailable.

## Unsupported modules

Common modules unavailable in Monty 1.0.0:

- **Files:** `glob`, `io`, `os.path`, `shutil`, `tempfile`.
- **Networking:** `http`, `socket`, `ssl`, `urllib`.
- **Processes and concurrency:** `concurrent.futures`, `multiprocessing`, `queue`, `subprocess`, `threading`.
- **Data formats and archives:** `array`, `csv`, `pickle`, `struct`, `tomllib`, `zipfile`, `zlib`.
- **Numbers and hashing:** `decimal`, `fractions`, `hashlib`, `hmac`, `uuid`.
- **Language and introspection:** `abc`, `contextlib`, `ctypes`, `importlib`, `inspect`, `types`, `weakref`.
- **CLI and diagnostics:** `argparse`, `logging`, `traceback`, `unittest`, `warnings`.
- **Other utilities:** `enum`, `heapq`, `operator`, `string`.
