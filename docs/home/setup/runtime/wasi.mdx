`wasi` runs CPython in WebAssembly, with the standard library available
subject to the restrictions below. Programs can access workspace files
under the same permissions as shell commands, but cannot access host files
or the network. Python SDK only.

## Installation

```bash
pip install 'mirage-ai[wasi]'
```

Download and unzip a release from
[cpython-wasi-build](https://github.com/brettcannon/cpython-wasi-build/releases).
Point `home`, or `MIRAGE_WASI_HOME`, at the unzipped directory.

## Usage

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    from mirage import RAMVFS, MountMode, Workspace
    from mirage.runtime.python import WasiRuntime

    ws = Workspace(
        {"/data": RAMVFS()},
        mode=MountMode.EXEC,
        runtimes=[WasiRuntime(config={"home": "/path/to/build"})],
    )
    await ws.shell("python3 -c 'print(1 + 1)'")
    ```
  </Tab>
  <Tab title="YAML" icon="file-code">
    ```yaml
    mode: exec
    runtimes:
      - name: wasi
        config:
          home: /path/to/build
    mounts:
      /data:
        vfs: ram
    ```
  </Tab>
</Tabs>

## Memory

`max_memory` caps the memory one run may grow to:

```yaml
runtimes:
  - name: wasi
    config:
      home: /path/to/build
      max_memory: 256M
```

A run that needs more raises `MemoryError`. CPython starts at about 40M, so
a cap below that fails every run. There is no cap by default.

## Python compatibility

Examples assume a writable `/data` mount. Mount modes and permissions still apply.

### `open()`

Modes and modifiers are listed separately; for example, `rb` combines `r` and `b`.

| Mode or modifier | Support |
| --- | --- |
| `r` | ✓ |
| `w` | ✓ |
| `a` | ✓ |
| `x` | ✓ |
| `b` | ✓ |
| `t` | ✓ |
| `+` | ✓ |

<AccordionGroup>
  <Accordion title="Example: append to a workspace file" id="open-example">
    ```python
    with open("/data/log.txt", "a") as f:
        f.write("Job completed.\n")
    ```
  </Accordion>
  <Accordion title="Limitations" id="open-limitations">
    | API or behavior | Limitation |
    | --- | --- |
    | File access | Writes to workspace files follow mount permissions. Paths outside the mounts expose the CPython build read-only. |
  </Accordion>
</AccordionGroup>

### File objects

Reads fetch ranges from the mount as the program asks for them.

| API | Support |
| --- | --- |
| `f.read()` | ✓ |
| `f.write()` | ✓ |
| `f.truncate()` | ✓ |

<AccordionGroup>
  <Accordion title="Example: write, read and truncate a file" id="file-objects-example">
    ```python
    with open("/data/example.txt", "w+") as f:
        f.write("first\nsecond\n")
        f.seek(0)
        print(f.read(5))  # first
        f.truncate(5)
    ```
  </Accordion>
  <Accordion title="Limitations" id="file-objects-limitations">
    | API or behavior | Limitation |
    | --- | --- |

  </Accordion>

## Notes

- Each command starts with fresh Python state. Files saved to workspace
  mounts persist between commands.
- Exit codes are limited to 0–255.
- Empty-path behavior depends on the Python build. Use `.` for the current
  directory.
- A workspace mount at `/lib` or under `/lib/python` hides the interpreter's
  standard library, so `python3` exits 126. Mounts elsewhere under `/lib`
  (`/lib/app`) are fine.
