`wasi` runs full CPython, with the whole standard library, compiled to
WebAssembly and run on [wasmtime](https://wasmtime.dev) inside the Mirage
process. It has no host files or network: the files it opens are the
workspace's, under the same mount modes and permissions as shell commands.
The first run compiles the interpreter and caches it; later runs start in
milliseconds. Python SDK only.

## Installation

```bash
pip install 'mirage-ai[wasi]'
```

Download and unzip a release from
[cpython-wasi-build](https://github.com/brettcannon/cpython-wasi-build/releases).
Point `home`, or `MIRAGE_WASI_HOME`, at the unzipped directory.

## Usage

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    from mirage import RAMVFS, MountMode, Workspace
    from mirage.runtime.python import WasiRuntime

    ws = Workspace(
        {"/data": RAMVFS()},
        mode=MountMode.EXEC,
        runtimes=[WasiRuntime(config={"home": "/path/to/build"})],
    )
    await ws.shell("python3 -c 'print(1 + 1)'")
    ```
  </Tab>
  <Tab title="YAML" icon="file-code">
    ```yaml
    mode: exec
    runtimes:
      - name: wasi
        config:
          home: /path/to/build
    mounts:
      /data:
        vfs: ram
    ```
  </Tab>
</Tabs>

## Memory

`max_memory` caps the memory one run may grow to:

```yaml
runtimes:
  - name: wasi
    config:
      home: /path/to/build
      max_memory: 256M
```

A run that needs more raises `MemoryError`. CPython starts at about 40M, so
a cap below that fails every run. There is no cap by default.

## What is wired

Anything built on these calls, such as `os.path`, `pathlib`, `glob`,
`shutil` and `json.load`, works too.

| Python | Supported | Notes |
| --- | --- | --- |
| `open()` in every mode, `os.open` | Yes | |
| `f.read()`, `os.read`, `os.pread` | Yes | Read in ranges, as the program asks. |
| `f.write()`, `os.write`, `os.pwrite` | Yes | Written at close or `os.fsync`. |
| `f.truncate()`, `os.truncate` | Yes | |
| `os.stat`, `os.lstat`, `os.fstat`, `Path.stat` | Yes | `st_mode` has only the file type bits. |
| `os.listdir`, `os.scandir`, `os.walk`, `glob.glob`, `Path.glob` | Yes | |
| `os.mkdir`, `os.makedirs`, `os.rmdir`, `shutil.rmtree` | Yes | |
| `os.remove`, `os.unlink`, `Path.unlink` | Yes | |
| `os.rename`, `os.replace`, `shutil.move` | Yes | `EXDEV` across mounts, where `shutil.move` copies instead. |
| `os.symlink`, `os.readlink` | Yes | |
| `os.utime`, `Path.touch` | Yes | |
| `os.getcwd`, `os.chdir` | Yes | The shell's working directory; a change lasts for the run. |
| `os.environ`, `sys.argv`, `sys.stdin` | Yes | The session's environment, the words after the script, and the piped input. |
| `os.chmod` | No | Does nothing. |
| `os.link` | No | Raises `PermissionError`. |
| `os.getxattr` and the other xattr calls | No | They do not exist. |
| `subprocess`, `socket` | No | Raise `OSError` (errno 58). |

Paths outside the mounts show the CPython build, read-only.


Compiled modules and idle engines are reused across runs; each invocation still
gets a fresh store, filesystem descriptors, memory and interruption epoch. A
sleeping guest observes cancellation through the preview1 poll bridge. Exit
statuses use the low eight bits, including 130, 200 and 255, and open files are
flushed on exit. Traceback source lines come from the user program's line cache.

The CPython WASI libc can normalize an empty path before issuing a syscall;
Mirage cannot recover spelling already removed by the interpreter. Its preview1
boundary rejects empty paths and preserves trailing directory requirements.
