A runtime runs the programs in a line. Mirage's own commands (`grep`, `cat`, pipes, redirects) run in the workspace itself; `python3`, `node` and any other program go to the runtime that captures them. Each runtime reaches the workspace's files its own way.

| Runtime | Runs | Where | SDK |
| --- | --- | --- | --- |
| `workspace` | Mirage's own commands | Mirage workspace | both |
| [`monty`](/home/setup/runtime/monty) | `python3`, a Python subset | Mirage workspace | both (default) |
| [`wasi`](/home/setup/runtime/wasi) | `python3`, CPython in WebAssembly | Mirage workspace | Python |
| [`pyodide`](/home/setup/runtime/pyodide) | `python3`, CPython in WebAssembly | Mirage workspace | TypeScript |
| [`quickjs`](/home/setup/runtime/quickjs) | `node` and `js`, without Node.js APIs | Mirage workspace | both (default) |
| [`local`](/home/setup/runtime/local) | host programs such as `python3`, `node` or `tsx` | host | Python, Node |
| [Sandboxes](/home/setup/runtime/sandbox) | native programs | a container, VM, cloud sandbox or SSH machine, or this Linux host with Sandlock | Python, Node; E2B also in the browser |

## Routing

`runtimes` is an ordered list: the first runtime whose `captures` name a program runs it, and `workspace` takes the rest. Without the key, the list is `[monty, quickjs, workspace]` in both SDKs.

```yaml
runtimes:
  - monty
  - name: docker
    config:
      container: my-sandbox
      mount_type: ssh
  - workspace
```

An entry is a name, or a mapping with `name`, `captures` and `config`. The
name is a runtime Mirage ships, one you registered in code, or
a `./file.py:Class` (Python) or `./file.mjs:Class` (TypeScript) reference to
your own runtime. Config keys are snake_case in YAML for both SDKs, and a
runtime rejects a key it does not know.

To choose a runtime for each command line, see [Route Runtime](/home/policy/route-runtime).

## Captures

`captures` lists the programs a runtime takes:

| Entry | Takes |
| --- | --- |
| A name, such as `python3` or `ffmpeg` | That program |
| `@external` | Every program Mirage does not have itself, such as `gcc`, `ffmpeg`, `perl` or a vendor CLI |
| `*` | The whole line, Mirage's own commands included (sandboxes only) |

| Runtime | Default `captures` |
| --- | --- |
| `monty`, `wasi`, `pyodide`, `local` | `python3`, `python` |
| `quickjs` | `node`, `js` |
| Sandboxes | `@external` |

- Mirage's own commands (`cat`, `grep`, `sha1sum`), pipes and redirects stay
  in Mirage. `cd`, `export` and `echo` stay even when named.
- `@external` does not take `python`, `python3`, `node` or `js`: Mirage has
  those itself and gives them to the Python or JavaScript runtime in the list.
  Name them to send them somewhere else.
- A program no runtime takes exits 127, `command not found`.
- A name only `@external` takes has no file, so `which`, `command -v` and
  `type` report it missing; running it still works.
- Globs expand against the workspace first (`python3 job.py *.csv` runs
  `python3 job.py a.csv b.csv`), and permission rules judge that argv.

```yaml
runtimes:
  - name: docker
    captures: ["python3", "@external"]
    config:
      container: my-sandbox
```

Here `python3 job.py | grep error` runs `python3` in the container and
`grep` in Mirage, and `ffmpeg -i a.mp4 b.webm` runs in the container.

## Files

| Where | Reaches the workspace through | Outside the workspace |
| --- | --- | --- |
| Monty, WASI, QuickJS | directly | no host files or network |
| Pyodide | directly | Browser programs retain JavaScript and network access; `init_module` enables host access. See [containment](/typescript/runtime/python#containment). |
| `local`, Sandlock | a [FUSE folder](/home/setup/fuse) you mount | the host's disk and network; under Sandlock, only the paths you grant |
| Other sandboxes | SFTP and `sshfs` with `mount_type: ssh` (`docker`, `e2b`, `ssh`, `smolvm`, `apple_container`, `microsandbox`), or a Mirage inside the sandbox | that sandbox's disk and network |

Mount modes, profiles and policies apply to every file call that reaches the
workspace. A host or sandbox runtime also has its own files and network, which
they do not cover. Pyodide has its own containment limits; use a sandbox with
a process and kernel boundary for hostile code.

### Verify workspace file access

Run these lines inside Mirage's shell after configuring a writable `/data`
mount visible to the runtime capturing `python3`. They check that Python can
read a workspace file and write one back:

```bash
(
  scratch=$(mktemp /data/mirage-check.XXXXXX) || exit
  trap 'rm -f -- "$scratch"' EXIT
  printf 'hello\n' > "$scratch" &&
  MIRAGE_CHECK_FILE="$scratch" python3 -c 'import os; from pathlib import Path; path = Path(os.environ["MIRAGE_CHECK_FILE"]); text = path.read_text(); path.write_text(text.upper()); print(text, end="")' &&
  cat "$scratch"
)
# hello
# HELLO
```

Monty, WASI, Pyodide and QuickJS access workspace files automatically.
For `local` and Sandlock, first mount a [FUSE folder](/home/setup/fuse).
For other sandboxes, finish the provider page's **Connecting the workspace**
steps first.

## Resource limits

`command_limits` apply to a runtime's programs as to any command: past
`timeout_seconds` a program exits 124 (`python3: timed out after Ns`), and
`max_bytes` and `max_lines` cap its output.

```yaml
mounts:
  /data:
    vfs: ram
    command_limits:
      python3:
        timeout_seconds: 30
```

The deadline also stops the run in Monty, WASI, Pyodide, QuickJS, `local` and
Sandlock. The other sandboxes only stop waiting, so give untrusted code a
finite workload; see [sandbox timeouts](/home/setup/runtime/sandbox#timeouts).

If a host or remote runtime cannot enforce the session's file restrictions,
Mirage refuses to launch the program as a policy refuses a command:
`<runtime>: Permission denied`, exit 126. See
[sandbox file permissions](/home/setup/runtime/sandbox#serving-the-sessions-files)
for restrictions that affect runtime selection.
