A runtime runs the programs in a line. Mirage's own commands (`grep`, `cat`, pipes, redirects) run in the workspace itself; `python3`, `node` and any other program go to the runtime that captures them. Each runtime reaches the workspace's files its own way.

| Runtime | Runs | Where | SDK |
| --- | --- | --- | --- |
| `workspace` | Mirage's own commands | Mirage workspace | both |
| [`monty`](/home/setup/runtime/monty) | `python3`, a Python subset | Mirage workspace | both (default) |
| [`wasi`](/home/setup/runtime/wasi) | `python3`, CPython in WebAssembly | Mirage workspace | Python |
| [`pyodide`](/home/setup/runtime/pyodide) | `python3`, CPython in WebAssembly | Mirage workspace | TypeScript |
| [`quickjs`](/home/setup/runtime/quickjs) | `node` and `js`, with Node.js's common APIs | Mirage workspace | both (default) |
| [`local`](/home/setup/runtime/local) | host programs such as `python3`, `node` or `tsx` | host | Python, Node |
| [`machine`](/home/setup/machine/overview) | native programs | a [machine](/home/setup/machine/overview): a container, VM, cloud sandbox or SSH host | Python, Node; E2B also in the browser |
| [`sandlock`](/home/setup/runtime/sandlock) | native programs | this Linux host, confined | Python, Node |

## Routing

`runtimes` is an ordered list: the first runtime whose `captures` name a program runs it, and `workspace` takes the rest. Without the key, the list is `[monty, quickjs, workspace]` in both SDKs, and `[monty, workspace]` on [Cloudflare Workers](/typescript/cloudflare-quickstart), which runs no QuickJS.

```yaml
machines:
  box:
    provider: docker
    container: my-sandbox
    mount_type: ssh
runtimes:
  - monty
  - name: machine
    machine: box
  - workspace
```

An entry is a name, or a mapping with `name`, `captures` and `config`; a
`machine` entry names its `machine` instead of taking `config`. The
name is a runtime Mirage ships, one you registered in code, or
a `./file.py:Class` (Python) or `./file.mjs:Class` (TypeScript) reference to
[your own runtime](/home/setup/runtime/custom). Config keys are snake_case in YAML for both SDKs, and a
runtime rejects a key it does not know.

To choose a runtime for each command line, see [Route Runtime](/home/policy/route-runtime).

## Captures

`captures` lists the programs a runtime takes:

| Entry | Takes |
| --- | --- |
| A name, such as `python3` or `ffmpeg` | That program |
| `@python`, `@js` | `python3` and `python`, or `node` and `js` |
| `@external` | Every program Mirage does not have itself, such as `gcc`, `ffmpeg`, `perl` or a vendor CLI |
| `@line` | The whole line, Mirage's own commands included (any runtime that runs a shell line) |

| Runtime | Default `captures` |
| --- | --- |
| `monty`, `wasi`, `pyodide`, `local` | `@python` |
| `quickjs` | `@js` |
| `sandlock`, `machine` | `@external` |

- Mirage's own commands (`cat`, `grep`, `sha1sum`), pipes and redirects stay
  in Mirage. Name `cat`, `grep`, `ps` or `kill` to run it on a runtime
  instead; `cd`, `export`, `echo`, `ln`, functions and installed CLIs stay
  in Mirage even when named.
- `@external` does not take `python`, `python3`, `node` or `js`: Mirage has
  those itself and gives them to the Python or JavaScript runtime in the list.
  Name them, or `@python` or `@js`, to send them somewhere else. A tool such
  as `pip` is an ordinary program: capture it on the same runtime when
  packages must land there, as in `captures: ["@python", "pip", "pip3"]`.
- `monty`, `wasi`, `pyodide` and `quickjs` take only their own interpreter's
  names; naming another program on one is refused when the workspace is
  built. `local`, `sandlock` and `machine` take any name.
- `nice`, `nohup`, `stdbuf`, `ionice` and `setsid` run their program where
  it runs alone: `nice gcc x.c` where `gcc` is taken, `nice grep` in Mirage.
- Under `local`, `sandlock` and `machine`, a program a captured program
  starts runs there: `make` running `gcc`, or a script calling `subprocess`. Capture the
  launcher on the same runtime as the tool. A Pyodide script's `subprocess`
  calls go back through Mirage's routing like any other command.
- An alias is captured as the word it expands to, once `shopt -s
  expand_aliases` is on and the alias was defined on an earlier line.
- If two runtimes take the same name or group, the first wins and Mirage
  logs a warning.
- A program no runtime takes exits 127, `command not found`.
- A `workspace` entry with `captures` runs only those mount commands itself:
  another mount command, such as `ls`, exits 126, `no runtime accepted this
  line`, and an unknown program exits 127. The shell's own words (`cd`,
  `export`, `echo`) still run.
- A name only `@external` takes has no file, so `which`, `command -v` and
  `type` report it missing; running it still works.
- Globs expand against the workspace first (`python3 job.py *.csv` runs
  `python3 job.py a.csv b.csv`), and permission rules judge that argv.

```yaml
machines:
  box:
    provider: docker
    container: my-sandbox
runtimes:
  - name: machine
    captures: ["@python", "@external"]
    machine: box
```

Here `python3 job.py | grep error` runs `python3` in the container and
`grep` in Mirage, and `ffmpeg -i a.mp4 b.webm` runs in the container.

## Files

| Where | Reaches the workspace through | Outside the workspace |
| --- | --- | --- |
| Monty, WASI, QuickJS | directly | no host files or network |
| Pyodide | directly | Browser programs retain JavaScript and network access; `init_module` enables host access. See [containment](/typescript/runtime/python#containment). |
| `local`, Sandlock | a [FUSE folder](/home/setup/fuse) you mount | the host's disk and network; under Sandlock, only the paths you grant |
| `machine` | SFTP and `sshfs` with `mount_type: ssh` (`docker`, `e2b`, `ssh`, `smolvm`, `apple_container`, `microsandbox`), or a Mirage inside the machine | that machine's disk and network |

Mount modes, profiles and policies apply to every file call that reaches the
workspace. A host runtime or a machine also has its own files and network,
which they do not cover. Pyodide has its own containment limits; use a machine
with a process and kernel boundary for hostile code.

### Verify workspace file access

Run these lines inside Mirage's shell after configuring a writable `/data`
mount visible to the runtime capturing `python3`. They check that Python can
read a workspace file and write one back:

```bash
(
  scratch=$(mktemp /data/mirage-check.XXXXXX) || exit
  trap 'rm -f -- "$scratch"' EXIT
  printf 'hello\n' > "$scratch" &&
  MIRAGE_CHECK_FILE="$scratch" python3 -c 'import os; from pathlib import Path; path = Path(os.environ["MIRAGE_CHECK_FILE"]); text = path.read_text(); path.write_text(text.upper()); print(text, end="")' &&
  cat "$scratch"
)
# hello
# HELLO
```

Monty, WASI, Pyodide and QuickJS access workspace files automatically.
For `local` and Sandlock, first mount a [FUSE folder](/home/setup/fuse).
For a machine, finish its provider page's **Connecting the workspace** steps
first.

## Resource limits

`command_limits` apply to a runtime's programs as to any command: a line past
its `@line` entry's `timeout_seconds` exits 124 (`line: timed out after Ns`), and
`max_bytes` and `max_lines` cap a program's output.

```yaml
command_limits:
  "@line":
    timeout_seconds: 30
```

The deadline also stops the run in Monty, WASI, Pyodide, QuickJS, `local`,
Sandlock and on a machine; see [machine timeouts](/home/setup/machine/overview#timeouts)
for what a machine needs.

If a host or remote runtime cannot enforce the session's file restrictions,
Mirage refuses to launch the program as a policy refuses a command:
`<runtime>: Permission denied`, exit 126. See
[machine file permissions](/home/setup/machine/overview#serving-session-files)
for restrictions that affect runtime selection.
