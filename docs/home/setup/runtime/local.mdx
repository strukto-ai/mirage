`local` runs programs installed on your host, such as `python3`, `node`,
`tsx`, `ffmpeg` or a vendor CLI. Add their names to `captures` to select them.
A program sees the host's files and network, not the workspace
mounts; to reach the mounts, give it a [FUSE folder](/home/setup/fuse).
Nothing confines it; on Linux, [Sandlock](/home/setup/runtime/sandbox/sandlock)
does. Python SDK and Node only, and never in the default runtimes.

## Installation

Install the programs you want to run on the host. `home` selects only the
Python interpreter. Without it, Mirage
uses `MIRAGE_LOCAL_HOME`, then the interpreter running Mirage (Python) or
`python3` on `PATH` (Node).

## Usage

`captures` defaults to `python3` and `python`. Add names such as `node` or `tsx`, or
[`@external`](/home/setup/runtime/overview#captures) for every program
Mirage does not have itself. Mirage's own commands, pipes and redirects stay
in Mirage: `ffmpeg -i in.mp4 out.webm | wc -c` sends only `ffmpeg`.

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    from mirage import RAMVFS, MountMode, Workspace
    from mirage.runtime.python import LocalRuntime

    ws = Workspace(
        {"/data": RAMVFS()},
        mode=MountMode.EXEC,
        runtimes=[LocalRuntime(captures=["python3", "@external"])],
    )
    await ws.shell("python3 -c 'print(1 + 1)'; echo hi | cksum")
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { LocalRuntime, MountMode, RAMVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      { '/data': new RAMVFS() },
      { mode: MountMode.EXEC, runtimes: [new LocalRuntime({ captures: ['python3', '@external'] })] },
    )
    await ws.shell("python3 -c 'print(1 + 1)'; echo hi | cksum")
    ```
  </Tab>
  <Tab title="YAML" icon="file-code">
    ```yaml
    mode: exec
    runtimes:
      - name: local
        captures: ["python3", "@external"]
        config:
          home: /path/to/venv/bin/python
    mounts:
      /data:
        vfs: ram
    ```
  </Tab>
</Tabs>

## Connecting the workspace

A local program opens host paths, not the workspace's. To give it workspace
files, expose a mount as a [FUSE folder](/home/setup/fuse):

```yaml
mounts:
  /data:
    vfs: s3
    config:
      bucket: my-bucket
    backend: fuse
    mountpoint: /data
runtimes:
  - name: local
    captures: ["python3", "@external"]
```

After the folder is mounted, run the shared
[workspace file check](/home/setup/runtime/overview#verify-workspace-file-access).

- Put the folder at the mount's own path when you can, so a path typed in
  the shell names the same file in the program.
- Calls into the folder follow mount modes and policies. A folder added in
  code with a session, `add_fuse_mount(prefix, mountpoint, session_id)` or
  `addFuseMount(prefix, mountpoint, sessionId)`, also follows that
  session's permissions.

## Python compatibility

`python3` is the same Mirage command on every Python runtime: Mirage reads
the script from the workspace and checks it like any file, and `local` runs
it on the host's interpreter. Every other program is a plain host program.

Python module availability and file modes come from the host interpreter.
Mirage does not replace them with a subset. Workspace paths become host paths
only when exposed through a FUSE folder. Examples below assume that folder
is mounted at `/data`.

### `open()`

Files are host files, including any FUSE folders. Modes and modifiers follow
the host interpreter's Python version.

| Mode or modifier | Support |
| --- | --- |
| `r` | Host interpreter |
| `w` | Host interpreter |
| `a` | Host interpreter |
| `x` | Host interpreter |
| `b` | Host interpreter |
| `t` | Host interpreter |
| `+` | Host interpreter |

<AccordionGroup>
  <Accordion title="Example: append to a workspace file" id="open-example">
    ```python
    with open("/data/log.txt", "a") as f:
        f.write("Job completed.\n")
    ```
  </Accordion>
  <Accordion title="Limitations" id="open-limitations">
    | API or behavior | Limitation |
    | --- | --- |
    | File access | Opens host files. Workspace files are accessible only through a mounted FUSE folder. |
  </Accordion>
</AccordionGroup>

### File objects

| API | Support |
| --- | --- |
| File-object methods | Host interpreter |

<Accordion title="Example: write, read and truncate a file" id="file-objects-example">
  ```python
  with open("/data/example.txt", "w+") as f:
      f.write("first\nsecond\n")
      f.seek(0)
      print(f.read(5))  # first
      f.truncate(5)
  ```
</Accordion>

### `os`

| API | Support |
| --- | --- |
| Filesystem APIs | Host interpreter |
| `os.environ` | ✓ |
| `os.getcwd()` | ✓ |

<AccordionGroup>
  <Accordion title="Example: list a workspace directory" id="os-example">
    ```python
    import os

    print(os.listdir("/data"))
    ```
  </Accordion>
  <Accordion title="Limitations" id="os-limitations">
    | API or behavior | Limitation |
    | --- | --- |
    | Filesystem APIs | Operate on host paths, including FUSE folders. |
    | `os.environ` | The session's environment plus config `env`; none of the host's environment. |
    | `os.getcwd()` | Starts in Mirage's own working directory. |
  </Accordion>
</AccordionGroup>

| API | Support |
| --- | --- |

### Runtime globals

| API | Support |
| --- | --- |
| `__file__` | ✓ |

- `__file__`: The script's workspace path; tracebacks use that path too.


## Runtime behavior

| Capability | `python3` | Other programs |
| --- | --- | --- |
| Program | The host's `python3`, given the script from the workspace | The name, found on the host's `PATH`; exit 127 if it is not there |
| Arguments | `sys.argv` | Its argv, with no shell |
| Piped input | stdin | stdin |
| Environment | The session's, plus the config `env`; none of the host's | The same |
| Working directory | Mirage's own | The shell's; exit 126 if it does not exist on the host |
| Files | The host's, and FUSE folders | The host's, and FUSE folders |
| Network | The host's | The host's |

## Notes

- A timeout kills the subprocess. `kill` sends it the signal it names, then
  `KILL` a second later if it is still running. A program that handles the
  signal and exits gives `wait` its own exit status, as in Bash.
