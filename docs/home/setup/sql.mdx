SQL keeps workspace files in a database's tables, laid out as
[AgentFS](https://github.com/tursodatabase/agentfs)'s. The files last as long
as the database does.

## Connect

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    mounts:
      /sql:
        vfs: sql
        mode: write
        config:
          path: ./workspace.db
    ```

    ```bash
    mirage workspace create workspace.yaml --id db
    mirage shell -w db -c 'ls /sql'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    from mirage import MountMode, Workspace
    from mirage.vfs.sql import SqlVFS

    ws = Workspace({"/sql": SqlVFS("./workspace.db")}, mode=MountMode.WRITE)
    result = await ws.shell("ls /sql")
    print(await result.stdout_str())
    await ws.close()
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, SqlVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      { '/sql': new SqlVFS({ path: './workspace.db' }) },
      { mode: MountMode.WRITE },
    )
    const result = await ws.shell('ls /sql')
    console.log(result.stdoutText)
    await ws.close()
    ```
  </Tab>
</Tabs>

## Layout

```text
/sql/
  notes/
    hello.txt
  users.csv
```

- `path` is a SQLite file; leave it out to keep the database in memory. The
  file holds the tables `fs_inode`, `fs_dentry`, `fs_data` and `fs_config`.
- `root: /workspace` under `config` serves only that folder, made when
  missing. Several mounts can share one database this way, and a mount of the
  whole database lists the folder too.
- A Postgres server, a Durable Object's storage or a D1 database mounts from
  code, through its driver; see the SDK guides.

## Sample runs

```bash
$ tree /sql
/sql
|-- notes
|   `-- hello.txt
`-- users.csv

2 directories, 2 files
```

```bash
$ cut -d, -f2 /sql/users.csv
name
ada
linus
```

```bash
$ cat /sql/notes/hello.txt
hello world
```

Every command that writes works on a `write` mount. Add `capacity: 100MB`
under `config` to cap the bytes the database's files hold, whichever folder
they are in; see [capacity](/home/setup/vfs#mount-capacity).
