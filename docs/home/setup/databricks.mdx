## Credentials

The resource reads a Unity Catalog volume over the Databricks Files REST API.
It needs two things: your workspace **host** and a **bearer token**, both given
to the resource as config.

The token is held as a secret, so a snapshot writes `<REDACTED>` in its place
and restoring that snapshot asks for a fresh resource.

### 1. Get Your Workspace Host

Your workspace URL, e.g. `https://dbc-xxxxxxxx-xxxx.cloud.databricks.com`
(AWS) or `https://adb-xxxxxxxxxxxx.xx.azuredatabricks.net` (Azure).

### 2. Create a Personal Access Token

1. In the workspace, open **Settings** -> **Developer** -> **Access tokens**.
1. Click **Generate new token**, set a comment and lifetime, and copy it.

### 3. Set Environment Variables

```bash
# .env.development
DATABRICKS_HOST=https://dbc-xxxxxxxx-xxxx.cloud.databricks.com
DATABRICKS_TOKEN=dapi...
```

Your program reads these and passes them in; MIRAGE reads no environment
variable of its own and no `~/.databrickscfg` profile.

### Beyond a personal access token

Any credential your program can turn into a bearer token works: OAuth
machine-to-machine, on-behalf-of a signed-in user, or a token read from a
secret manager. Mint it your own way and pass the string as `token`.

MIRAGE sends that token on every Files API call and never refreshes or retries
it. When it expires the call fails with `DatabricksVolumeAuthError`, and your
program obtains a new token and builds a new resource. See the
[Python](/python/setup/databricks) and
[TypeScript](/typescript/setup/databricks_volume) setup guides.
