One Unity Catalog volume, or a folder inside it, becomes a directory tree of
its files, read and written through the Databricks Files API.

## Setup

Create a workspace access token, pick a volume and grant the token's principal
access to it, then export the workspace host and token.

<AccordionGroup>
  <Accordion title="Create a token and grant volume access">
    1. In the workspace, click the username in the top bar, then **Settings**,
       **Developer**, and **Manage** next to **Access tokens**.
    2. Click **Generate new token** and give it a name and a lifetime. A scoped
       token needs the [`files` API scope](https://docs.databricks.com/api/workspace/scopes).
       Copy the token: it is shown once.
    3. Pick a volume in Catalog Explorer. Its
       `/Volumes/<catalog>/<schema>/<volume>/` path gives the `catalog`,
       `schema` and `volume` fields.
    4. Grant the principal `USE CATALOG`, `USE SCHEMA` and `READ VOLUME`, plus
       `WRITE VOLUME` for a write mount. See
       [volume privileges](https://docs.databricks.com/aws/en/volumes/utility-commands).

    Databricks recommends OAuth over personal access tokens; an OAuth access
    token works the same way.
  </Accordion>
</AccordionGroup>

```bash
export DATABRICKS_HOST=https://dbc-xxxxxxxx-xxxx.cloud.databricks.com
export DATABRICKS_TOKEN=dapi...
```

- `DATABRICKS_HOST` is the workspace origin, such as
  `https://adb-xxxxxxxxxxxx.xx.azuredatabricks.net` on Azure: `http://` or
  `https://`, no path, query, fragment or user info. A trailing slash is fine.
- `token` also takes a function, sync or async, that returns the current
  token. The function owns refresh, caching and concurrent refreshes.
- Mirage reads no environment variables, SDK profiles or default credentials,
  and never retries a refused request with another credential.
- Bind each VFS and workspace to one principal and keep caches apart across
  identities. Rebuild the workspace or drop its caches when the principal or
  its permissions change; a token refresh for the same principal keeps the VFS.

## Connect

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml workspace.yaml
    mounts:
      /dbx:
        vfs: databricks_volume
        mode: read
        config:
          catalog: main
          schema: default
          volume: agent_files
          host: ${DATABRICKS_HOST}
          token: ${DATABRICKS_TOKEN}
    ```

    ```bash
    mirage workspace create workspace.yaml --id dbx
    mirage shell -w dbx -c 'ls /dbx'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from mirage import MountMode, Workspace
    from mirage.vfs.databricks_volume import DatabricksVolumeConfig, DatabricksVolumeVFS

    config = DatabricksVolumeConfig(
        catalog="main",
        schema="default",
        volume="agent_files",
        host=os.environ["DATABRICKS_HOST"],
        token=os.environ["DATABRICKS_TOKEN"],
    )
    ws = Workspace({"/dbx": DatabricksVolumeVFS(config)}, mode=MountMode.READ)
    result = await ws.shell("ls /dbx")
    print(await result.stdout_str())
    await ws.close()
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { buildVfs, MountMode, Workspace } from '@struktoai/mirage-node'

    const dbx = await buildVfs('databricks_volume', {
      catalog: 'main',
      schema: 'default',
      volume: 'agent_files',
      host: process.env.DATABRICKS_HOST!,
      token: process.env.DATABRICKS_TOKEN!,
    })
    const ws = new Workspace({ '/dbx': dbx }, { mode: MountMode.READ })
    const result = await ws.shell('ls /dbx')
    console.log(result.stdoutText)
    await ws.close()
    ```
  </Tab>
</Tabs>

## Layout

```text
/dbx/
  reports/
    2026/
      q1/
        summary.md
  datasets/
    orders.csv
```

- `/dbx/reports/2026/q1/summary.md` is
  `/Volumes/main/default/agent_files/reports/2026/q1/summary.md`.
- `root_path: /reports` mounts only that folder of the volume; `..` is refused.
- Files keep their own names and bytes; nothing is converted.

## Sample runs

```bash
$ ls /dbx
datasets
reports
```

```bash
$ head -n 3 /dbx/datasets/orders.csv
order_id,customer,total
1001,acme,129.50
1002,globex,48.00
```

```bash
$ cat /dbx/reports/2026/q1/summary.md
# Q1 summary
Revenue grew 12% over Q4.
```

On a `write` mount, `>`, `cp`, `mv`, `rm` and `mkdir` change the volume, as far
as the principal's `WRITE VOLUME` grant allows.
