A FUSE mount shows a VFS as a folder on the machine running Mirage, so editors,
language servers and scripts use it like any other folder, even when the data
lives in S3 or another service. Mount from your [Python](/python/setup/fuse) or
[TypeScript](/typescript/setup/fuse) app, or through the CLI. To mount a
workspace from another machine, use [SSHFS](/home/access/ssh#connect).

## Support

| OS | Python | TypeScript (Node) | Setup |
| --- | --- | --- | --- |
| Linux | Supported | Supported | [Linux](/home/setup/linux) |
| macOS | Supported, one mount per process | Supported, one mount per process | [macOS](/home/setup/macos) |
| Windows | Experimental | Not supported | [Windows](/home/setup/windows) |

A browser cannot mount a folder; use Mirage's shell and file APIs there.

| | Linux | macOS | Windows |
| --- | --- | --- | --- |
| Unmount | `fusermount3 -u` or closing the workspace | `diskutil unmount` or closing the workspace | When the process exits |
| A file whose size is unknown | Reads in full | Reads in full | Size fetched when opened |
| Mountpoint folder | Must exist | Must exist | Must not exist; created for you |

## Try it with the CLI

Set `backend: fuse` and a local folder on a mount:

```yaml workspace.yaml
mounts:
  /data:
    vfs: ram
    mode: write
    backend: fuse
    mountpoint: /tmp/mirage-data
```

Write a file through Mirage, then read it from the folder:

```bash
mkdir -p /tmp/mirage-data
mirage workspace create workspace.yaml --id demo
mirage shell -w demo -c 'echo "hello mirage" > /data/hello.txt'
cat /tmp/mirage-data/hello.txt
```

This prints `hello mirage`. `mirage workspace delete demo` unmounts the folder.

- Replace RAM with any [supported VFS](/home/setup/vfs) to expose your own data.
- The folder follows the mount's mode: a `read` mount cannot be written.
- A mount set up this way is not tied to an agent session or profile.
