The `e2b` machine provider reaches a running [E2B](https://e2b.dev)
sandbox, by ID, and the `machine` runtime runs captured programs in it. You create the sandbox from a template; Mirage only runs programs in
it. Python SDK, Node and browsers.

## Installation

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```bash
    pip install 'mirage-ai[e2b,ssh]'
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```bash
    pnpm add e2b ssh2
    ```
  </Tab>
</Tabs>

The `ssh` extra and `ssh2` serve the workspace into the sandbox with
`mount_type: ssh`. Create the sandbox from a template that has what
[connecting the workspace](#connecting-the-workspace) needs. Set `api_key`
in the config, as a value or a [credential pointer](/home/authentication#pointer-fields),
or `E2B_API_KEY`.

## Usage

`captures` defaults to [`@external`](/home/setup/runtime/overview#captures):
every program Mirage does not have itself. Name `@python` to run
Python in the sandbox too.

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    from mirage import RAMVFS, MountMode, Workspace
    from mirage.runtime.machine import MachineRuntime

    ws = Workspace(
        {"/data": RAMVFS()},
        mode=MountMode.EXEC,
        machines={
            "box": {
                "provider": "e2b",
                "sandbox_id": "sandbox-id",
                "mount_type": "ssh",
            }
        },
        runtimes=[MachineRuntime(["@python", "@external"], machine="box")],
    )
    await ws.shell("python3 -c 'print(1 + 1)'")
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, MachineRuntime, RAMVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      { '/data': new RAMVFS() },
      {
        mode: MountMode.EXEC,
        machines: { box: { provider: 'e2b', sandboxId: 'sandbox-id', mountType: 'ssh' } },
        runtimes: [new MachineRuntime({ captures: ['@python', '@external'], machine: 'box' })],
      },
    )
    await ws.shell("python3 -c 'print(1 + 1)'")
    ```

    In a browser, import `@struktoai/mirage-core/machine/e2b/handle` once
    to register the provider (`pnpm add @struktoai/mirage-core`), pass
    `apiKey`, and use `mountType: 'fuse'` or leave it unset.
  </Tab>
  <Tab title="YAML" icon="file-code">
    ```yaml
    mode: exec
    machines:
      box:
        provider: e2b
        sandbox_id: ${E2B_SANDBOX_ID}
        mount_type: ssh
    runtimes:
      - name: machine
        captures: ["@python", "@external"]
        machine: box
    mounts:
      /data:
        vfs: ram
    ```
  </Tab>
</Tabs>

## Connecting the workspace

Pick a [`mount_type`](/home/setup/machine/overview#connecting-the-workspace). `ssh` and `both` do not work in browsers, and
each file call is about 150 ms for a small file from a laptop. With `fuse`,
base the template on [the machine image](/home/setup/machine/overview#the-machine-image)
and run `mirage workspace create /tmp/sandbox.yaml` in the sandbox.

### A template for ssh

Build a template with `sshfs` and pass its sandbox ID as `sandbox_id`:

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    from e2b import AsyncSandbox, Template

    Template.build(Template().from_base_image().apt_install("sshfs"), "mirage-sshfs")
    sandbox = await AsyncSandbox.create("mirage-sshfs")
    print(sandbox.sandbox_id)
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { Sandbox, Template } from 'e2b'

    await Template.build(Template().fromBaseImage().aptInstall('sshfs'), 'mirage-sshfs')
    const sandbox = await Sandbox.create('mirage-sshfs')
    console.log(sandbox.sandboxId)
    ```
  </Tab>
</Tabs>

Keep the base image's user, which has `sudo` for mountpoints such as
`/data`. On the default template, run `sudo apt-get install -y sshfs`
instead.

## Notes

- Closing the workspace leaves the sandbox running.
- Output comes back as the program wrote it, binary included: the
  sandbox base64-encodes it on the way out, so the image needs `dd` and
  `base64` (Debian, Ubuntu and Alpine images have both), and output
  takes about a third more to transfer. Without them a line runs
  nothing, prints why and exits 127.
- Commands run concurrently, each with its own input and output. Without
  piped input, stdin starts closed.
- Templates, sizing, networking and lifecycle stay E2B settings.
- A Mirage [timeout](/home/setup/machine/overview#timeouts) tries to kill the command; its child
  processes may survive.
