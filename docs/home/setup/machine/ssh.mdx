The `ssh` machine provider reaches a machine running `sshd`, and the `machine`
runtime runs captured programs on it. Anything you can
already `ssh` into works, with nothing to install on it. You run the
machine; Mirage only runs programs on it. Python SDK and Node.

## Installation

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```bash
    pip install 'mirage-ai[ssh]'
    ```

## Usage

`captures` defaults to [`@external`](/home/setup/runtime/overview#captures):
every program Mirage does not have itself. Name `@python` to run
Python on the machine too.

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    from mirage import RAMVFS, MountMode, Workspace
    from mirage.runtime.machine import RemoteRuntime

    ws = Workspace(
        {"/data": RAMVFS()},
        mode=MountMode.EXEC,
        machines={
            "box": {
                "provider": "ssh",
                "host": "mybox",
                "username": "deploy",
                "identity_file": "~/.ssh/id_ed25519",
            }
        },
        runtimes=[RemoteRuntime(["@python", "@external"], machine="box")],
    )
    await ws.shell("python3 -c 'print(1 + 1)'")
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, RemoteRuntime, RAMVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      { '/data': new RAMVFS() },
      {
        mode: MountMode.EXEC,
        machines: {
          box: {
            provider: 'ssh',
            host: 'mybox',
            username: 'deploy',
            identityFile: '~/.ssh/id_ed25519',
          },
        },
        runtimes: [new RemoteRuntime({ captures: ['@python', '@external'], machine: 'box' })],
      },
    )
    await ws.shell("python3 -c 'print(1 + 1)'")
    ```
  </Tab>
  <Tab title="YAML" icon="file-code">
    ```yaml
    mode: exec
    machines:
      box:
        provider: ssh
        host: mybox
        username: deploy
        identity_file: ~/.ssh/id_ed25519
    runtimes:
      - name: remote
        captures: ["@python", "@external"]
        machine: box
    mounts:
      /data:
        vfs: ram
    ```
  </Tab>
</Tabs>

## Connecting the workspace

Pick a [`mount_type`](/home/setup/machine/overview#connecting-the-workspace). With `ssh`, the machine needs `sshfs`, and
passwordless `sudo` for a mountpoint its user cannot create (`/data`).

Without `mount_type`, two ways:

**Files already on the machine.** Mount the machine's directory with the
[ssh VFS](/python/vfs/ssh) at a prefix equal to its path there. The same
path then names the same file on both sides, with nothing to install:

```yaml
mounts:
  /home/user/proj:
    vfs: ssh
    config:
      host: mybox
      root: /home/user/proj
machines:
  box:
    provider: ssh
    host: mybox
runtimes:
  - name: remote
    captures: ["@python", "@external"]
    machine: box
```

**Any other mount** (S3, Slack and so on). Install Mirage and `fuse3` on the
machine, and start Mirage with a `sandbox.yaml` that lists the same paths:

```bash
ssh mybox mirage workspace create sandbox.yaml
```

Mirage never rewrites paths and nothing checks that they match. A program on
the machine opens its files directly, outside this workspace's mount modes
and permissions.

## Notes

- `host` is also the address unless `hostname` overrides it; `port`,
  `username`, `identity_file`, `private_key` and `timeout` are optional.
  Authentication is a key or an agent, never a password.
- `private_key` takes the key's own text rather than a path, so a
  [credential pointer](/home/service-credentials#pointer-fields) can read it
  from a secret store.
- The machine's login shell must be POSIX-compatible. Commands use the
  session's working directory and environment.

<Warning>
  Host keys are not verified, so treat the network path to the machine as
  trusted.
</Warning>
