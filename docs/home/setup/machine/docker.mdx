The `docker` machine provider reaches a running container, by name, and
runs the programs it captures in it. You start
and stop the container; Mirage only runs programs in it. Python SDK and
Node.

## Installation

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```bash
    pip install 'mirage-ai[ssh]'
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```bash
    pnpm add ssh2
    ```
  </Tab>
</Tabs>

These serve the workspace into the container with `mount_type: ssh`. Start
the container with FUSE allowed and `sshfs` in it, or from an image that has
what [connecting the workspace](#connecting-the-workspace) needs:

```bash
docker run -d --cap-add SYS_ADMIN --device /dev/fuse \
  --name my-sandbox python:3.12-slim sleep infinity
docker exec my-sandbox sh -c 'apt-get update && apt-get install -y sshfs'
```

## Usage

`captures` defaults to [`@external`](/home/setup/machine/overview#captures):
every program Mirage does not have itself. Name `@python` to run
Python in the container too.

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    from mirage import RAMVFS, MountMode, Workspace

    ws = Workspace(
        {"/data": RAMVFS()},
        mode=MountMode.EXEC,
        machines={
            "box": {
                "provider": "docker",
                "container": "my-sandbox",
                "mount_type": "ssh",
                "captures": ["@python", "@external"],
            }
        },
    )
    await ws.shell("python3 -c 'print(1 + 1)'")
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, RAMVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      { '/data': new RAMVFS() },
      {
        mode: MountMode.EXEC,
        machines: { box: { provider: 'docker', container: 'my-sandbox', mountType: 'ssh', captures: ['@python', '@external'] } },
      },
    )
    await ws.shell("python3 -c 'print(1 + 1)'")
    ```
  </Tab>
  <Tab title="YAML" icon="file-code">
    ```yaml
    mode: exec
    machines:
      box:
        provider: docker
        container: my-sandbox
        mount_type: ssh
        captures: ["@python", "@external"]
    mounts:
      /data:
        vfs: ram
    ```
  </Tab>
</Tabs>

Save the YAML as `workspace.yaml` and run a line from the CLI:

```bash
mirage workspace create workspace.yaml -w box-demo
mirage shell -w box-demo -c 'echo hello > /data/hi.txt; python3 -c "print(open(\"/data/hi.txt\").read().upper())"'
```

`python3` runs in the container and reads the file Mirage wrote, so this
prints `HELLO`. Remove both with `mirage workspace delete box-demo` and
`docker rm -f my-sandbox`.

## Connecting the workspace

Pick a [`mount_type`](/home/setup/machine/overview#connecting-the-workspace). With `ssh`, the image needs only `sshfs`. With
`fuse`, copy `sandbox.yaml` in and start Mirage in the container:

```bash
docker cp sandbox.yaml my-sandbox:/tmp/sandbox.yaml
docker exec my-sandbox mirage workspace create /tmp/sandbox.yaml
```

## Notes

- `container` takes a name or an ID. The Docker CLI is the transport, so
  Docker Desktop, Colima and a compatible Podman alias all work.
- Sizing, GPUs, networks, volumes and bind mounts go on your own
  `docker run`. You can bake `sandbox.yaml` into the image instead of
  copying it, and point it at `host.docker.internal` for a host service.

<Warning>
  Environment values go on the `docker exec` command line, so other users of
  the host can see them in `ps`. Avoid secrets on a host shared with
  untrusted users.
</Warning>
