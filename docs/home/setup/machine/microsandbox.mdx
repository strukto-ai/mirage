The `microsandbox` machine provider reaches a running
[microsandbox](https://microsandbox.dev) microVM, by name, and the `machine`
runtime runs captured programs in it. You create and start the sandbox; Mirage runs programs in
it through the `msb` CLI. Python SDK and Node.

## Installation

Install `msb` 0.7.14 or newer on the host and put it on `PATH`. Create a
sandbox from an image with `sh`, your programs, and the tools needed for
[connecting the workspace](#connecting-the-workspace):

```bash
msb create my-registry/mirage-fuse:latest --name mirage-box
```

## Usage

`captures` defaults to [`@external`](/home/setup/runtime/overview#captures).
Add `@python` to run Python programs in the guest too.

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    from mirage import RAMVFS, MountMode, Workspace
    from mirage.runtime.machine import MachineRuntime

    ws = Workspace(
        {"/data": RAMVFS()},
        mode=MountMode.EXEC,
        machines={"box": {"provider": "microsandbox", "sandbox": "mirage-box"}},
        runtimes=[MachineRuntime(["@python", "@external"], machine="box")],
    )
    await ws.shell("python3 -c 'print(1 + 1)'")
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, MachineRuntime, RAMVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace(
      { '/data': new RAMVFS() },
      {
        mode: MountMode.EXEC,
        machines: { box: { provider: 'microsandbox', sandbox: 'mirage-box' } },
        runtimes: [new MachineRuntime({ captures: ['@python', '@external'], machine: 'box' })],
      },
    )
    await ws.shell("python3 -c 'print(1 + 1)'")
    ```
  </Tab>
  <Tab title="YAML" icon="file-code">
    ```yaml
    mode: exec
    machines:
      box:
        provider: microsandbox
        sandbox: mirage-box
    runtimes:
      - name: machine
        captures: ["@python", "@external"]
        machine: box
    mounts:
      /data:
        vfs: ram
    ```
  </Tab>
</Tabs>

## Connecting the workspace

Pick a [`mount_type`](/home/setup/machine/overview#connecting-the-workspace). With `ssh`, install `mirage-ai[ssh]` on a Python
host or `ssh2` on a Node host; the guest needs `sshfs` and access to
`/dev/fuse`. With `fuse`, copy `sandbox.yaml` in and start Mirage in the
guest:

```bash
msb copy sandbox.yaml mirage-box:/tmp/sandbox.yaml
msb exec mirage-box -- mkdir -p /data
msb exec mirage-box -- mirage workspace create /tmp/sandbox.yaml
```

Matching paths alone does not share data; configure both workspaces to use
the same backend.

## Notes

- Keep the sandbox running while Mirage is connected. Reconnect after a restart.
- Closing the runtime leaves the sandbox running.
- A [timeout](/home/setup/machine/overview#timeouts) cancels the CLI call and
  stops that run's processes in the sandbox.
- A program's output reaches Mirage as it prints, except when Mirage pipes
  input into the program: then the output arrives when the program ends.
- Commands share the sandbox's files and processes. Use one sandbox per tenant.
- Environment values are passed as CLI arguments. Avoid secrets on hosts shared
  with untrusted users.
