A profile sets what a session can run and see, so agents can share one
workspace with different files and commands.

```yaml workspace.yaml
mounts:
  /data:
    vfs: ram

profiles:
  researcher:
    cwd: /data
    mounts:
      /data: { mode: read }
    paths:
      hide: [/data/private]
    commands:
      "*": deny
      ls: allow
      cat: allow
      grep: allow
      find: allow
      stat: allow
      pwd: allow

profile: researcher
```

A session under `researcher` reads `/data`, never sees `/data/private`, and
gets `Permission denied` for any command `commands` does not name, builtins
such as `cd` included.

## What a profile controls

| Key | Sets |
| --- | --- |
| `commands` | What the session can run: each command, subcommand or option allowed, refused or sent for approval. See [Command rules](#command-rules). |
| `paths.hide` | Files and folders the session cannot see. |
| `paths.show` | A path to reopen inside a hidden folder, or to give a mode of its own. |
| `mounts` | A mount's access, `read`, `write` or `exec`, and command rules for one mount, folder or file. See [In one folder](#in-one-folder). |
| `cwd`, `env` | The starting folder and environment. `env` takes [credential pointers](/home/service-credentials#set-environment-variables). |
| `vars.hide` | Variable names that read as unset. |
| `processes` | Whose processes `ps` lists and `kill` stops, and the most it runs. |
| `command_limits` | [Output and execution limits](/home/limits#command-output). |
| `network` | A narrower [`network`](/home/configuration/workspace#network) than the workspace's. |
| `policy` | [Policy scripts](/home/policy/scripts) to run. |

```yaml
profiles:
  worker:
    vars:
      hide: [AWS_*, GITHUB_TOKEN]
    processes: {list: workspace, kill: session, max: 8}
    command_limits:
      grep: {max_lines: 200}
    network:
      allowed_domains: ["*.github.com"]
    policy:
      pre_command:
        - {script: ./guard.py, runtime: monty}
```

- `processes` scopes are `session` (the default) or `workspace`. `max` is 128
  by default; past it a new process fails with `Resource temporarily unavailable`.
- A profile's `processes` overrides the workspace's field by field. Its
  `network` can only narrow the workspace's.

## Use a profile

| | Create a session under `researcher` |
| --- | --- |
| Python | `ws.create_session("s1", profile="researcher")` |
| TypeScript | `ws.createSession('s1', { profile: 'researcher' })` |
| CLI | `mirage workspace session create -w ID -p researcher` |
| HTTP | `POST /v1/workspaces/{id}/sessions` with `profile` |

A session with no profile gets the one `profile:` names, else `default`, else
no limits.

No command inside a session can change its own profile.

## Command rules

`commands` is a tree that follows each command's own subcommands and
options. Each entry decides `allow`, `ask` or `deny`.

```yaml
commands:
  "*": allow
  rm: {decision: ask, reason: Deletes need sign-off}
  gh:
    "*": deny
    pr:
      view: allow
      merge: {"*": allow, --admin: deny}
  curl:
    --request: {values: {DELETE: deny}}
  git:
    --force: deny
    checkout: {operands: {main: deny}}
```

| Line | Result |
| --- | --- |
| `ls /data` | Runs. `"*"` allows every command the tree does not name. |
| `rm notes.txt` | Waits for approval, with the reason. |
| `gh pr view 5` | Runs. |
| `gh pr list` | Refused. `gh` denies whatever it does not name. |
| `gh pr merge 5` | Runs. |
| `gh pr merge 5 --admin` | Refused. |
| `curl -X DELETE https://example.com` | Refused. `curl -X PUT https://example.com` runs. |
| `git add -f notes.txt` | Refused, as any `git` subcommand with `--force` is. |
| `git checkout main` | Refused. `git checkout dev` runs. |

A refused line prints `rm: Permission denied` and exits 126. A line that
waits for approval reads the same until a host
[approves it](/home/policy/policies#asks). A path that a mount's `mode` or
[`paths.show`](#hide-and-show) makes read-only fails as the command's own
error instead, such as
`rm: cannot remove '/data/keep/2024.csv': Read-only file system`, exit 1.

### Keys

| Key | Means |
| --- | --- |
| `"*"` | The decision at this level: at the root, every command the tree does not name; under a command, that command and every subcommand below that states none. |
| A name, such as `rm` or `pr` | A command at the root, a subcommand under a command. |
| A key starting with `-`, such as `--admin` | An option. `"-*"` is any option the tree does not name. |
| `operands` | The next operand on the line. Each key under it is a word. |
| `values`, under an option | The option's value. Each key under it is a word. |

An entry's value is `allow`, `ask` or `deny`. Write `{decision, reason}` to
add a reason. To make a tree apply in one folder only, see
[In one folder](#in-one-folder).

### How a line is judged

1. Mirage reads the line with the command's own grammar, so `rm -rf`,
   `rm -fr` and `rm --recursive --force` are the same line.
2. The line's words pick the entry: its subcommands, then its operands, as
   far as the tree names them. The deepest entry that states a decision
   gives the result. With no decision anywhere, the line runs.
3. The options on the line, and their values, can only tighten that result:
   `deny` beats `ask`, and `ask` beats `allow`.

So a deeper name can reopen what its parent refuses, as `gh pr view` does
above. An option never can.

### Run only the commands you name

```yaml
commands:
  "*": deny
  ls: allow
  cat: allow
  grep: allow
```

| Line | Result |
| --- | --- |
| `cat notes.txt` | Runs. |
| `rm notes.txt` | Refused. |
| `cd /data` | Refused. Builtins are commands too. |

- `[` and `[[` are commands too. Name them if the session runs tests.
- A call to a shell function the agent defined is not judged by the root
  `"*"`. Each command in its body is judged when it runs.
- `commands` does not cover executed paths, direct VFS calls or MCP file
  tools. Limit file access with `mounts` and `paths`.

### A subcommand

```yaml
commands:
  gh:
    "*": deny
    pr: {view: allow, diff: allow}
  git:
    status: deny
```

| Line | Result |
| --- | --- |
| `gh pr view 5` | Runs. |
| `gh pr merge 5`, `gh issue list`, `gh` | Refused. |
| `git status` | Refused. |
| `git -C /data status` | Refused. An option before the subcommand does not hide it. |
| `git log` | Runs. |

Without `"*": deny`, only the subcommands you deny are refused:
`gh: {repo: {delete: deny}}` refuses `gh repo delete` and nothing else.

### An option

```yaml
commands:
  gh:
    pr:
      merge: {--admin: deny}
  git:
    --force: deny
    add: {--force: allow}
```

| Line | Result |
| --- | --- |
| `gh pr merge 5 --admin` | Refused. |
| `gh pr merge 5` | Runs. |
| `git rm -f notes.txt` | Refused. An option entry applies to its command and every subcommand below. |
| `git add -f notes.txt` | Runs. A deeper entry for the same option replaces the one above it. |

### Options together

An option under an option applies when both are on the line.

```yaml
commands:
  rm:
    --recursive: {--force: deny}
```

| Line | Result |
| --- | --- |
| `rm -rf build` | Refused. |
| `rm -r build` | Runs. |
| `rm -f notes.txt` | Runs. |

### Only these options

`"-*"` decides for every option the tree does not name.

```yaml
commands:
  rm: {"-*": deny, --force: allow, --verbose: allow}
```

| Line | Result |
| --- | --- |
| `rm -fv notes.txt` | Runs. |
| `rm -rf build` | Refused. `--recursive` is not named. |
| `rm notes.txt` | Runs. |

### An option's value

```yaml
commands:
  curl:
    --request:
      values: {DELETE: deny, "*": ask}
```

| Line | Result |
| --- | --- |
| `curl -X DELETE https://example.com` | Refused. |
| `curl -X PUT https://example.com` | Waits for approval. |
| `curl https://example.com` | Runs. The option is not on the line. |

A value can also name options that must be on the line with it. With
`--request: {values: {POST: {--insecure: deny}}}`, `curl -X POST -k` is
refused and `curl -X POST` runs.

### An operand

```yaml
commands:
  git:
    checkout:
      operands: {main: deny, "release/*": ask}
```

| Line | Result |
| --- | --- |
| `git checkout main` | Refused. |
| `git checkout release/2.1` | Waits for approval. |
| `git checkout dev` | Runs. |

- An operand can reopen a denied command. With
  `checkout: {"*": deny, operands: {main: allow}}`, `git checkout main` runs
  and `git checkout dev` is refused.
- An operand entry can hold options and a further `operands` for the next
  word. With `merge: {operands: {"5": {--admin: deny}}}`,
  `gh pr merge 5 --admin` is refused and `gh pr merge 6 --admin` runs.
- `operands` goes on a command that has no subcommands.

Keys under `operands` and `values` are shell globs. When several keys match
one word, an exact key wins. Otherwise the strictest matching glob wins, and
`"*"` answers only for a word no other key matches.

| `operands` of `git checkout` | Line | Result |
| --- | --- | --- |
| `{"release/*": allow, "*": deny}` | `git checkout release/2.1` | Runs. |
| | `git checkout dev` | Refused. |
| `{main: allow, "release/*": ask, "rel*": deny}` | `git checkout main` | Runs. |
| | `git checkout release/2.1` | Refused. Two globs match. |

Write `"[*]"` for a literal star. A word that starts with `-` is an operand
only after `--` on the line: `rm: {operands: {"-rf": deny}}` refuses
`rm -- -rf` and leaves `rm -rf build` alone.

### A command without a grammar

Mirage reads a program it has no grammar for, such as one a
[machine](/home/setup/machine/overview) runs, as a name and its operands.

```yaml
commands:
  kubectl:
    operands:
      delete: {operands: {namespace: deny}}
```

| Line | Result |
| --- | --- |
| `kubectl delete namespace prod` | Refused. |
| `kubectl delete pod web-1` | Runs. |

An option key under such a command is refused when the profile loads. To
write rules on its options, [register it as a CLI](/home/setup/cli/new).

### A CLI that reaches a service

A hide stops file paths, and a CLI such as `gh` reaches its service
without a path. So under a profile that hides any path, such a CLI stays
off until the tree names it with an allow. `"*": allow` alone does not
turn it on.

| Profile | `gh pr view 5` |
| --- | --- |
| `commands: {"*": allow}` | Runs. |
| `paths: {hide: [/data/.env]}`, `commands: {"*": allow}` | `gh: Permission denied`, exit 126. |
| The same, with `gh: allow` | Runs. |
| The same, with `gh: {pr: {view: allow}}` | Runs. An allow anywhere under `gh` turns it on, so `gh pr list` runs too. |
| The same, with `gh: {pr: {merge: {--admin: deny}}}` | `gh: Permission denied`, exit 126. The tree names `gh` but allows nothing. |

### Ask with a reason

```yaml
commands:
  rm:
    "*": {decision: ask, reason: Deletes need sign-off}
    --recursive: {decision: ask, reason: Recursive deletes need sign-off}
```

| Step | Line | Result |
| --- | --- | --- |
| 1 | `rm a.log` | Waits for approval: `Deletes need sign-off`. |
| 2 | | A host approves it for the session. |
| 3 | `rm b.log` | Runs. The approval covers that entry. |
| 4 | `rm -r build` | Waits for approval again. `--recursive` is another entry. |

Changing an entry's decision or reason makes its lines ask again.

### In one folder

An entry under `mounts` gives one mount, folder or file a tree of its own.
It applies to a line that names a path at or under its key, and to a line
whose working directory is inside the key.

```yaml
profiles:
  agent:
    commands:
      "*": allow
    mounts:
      /data/keep:
        commands: {rm: deny}
      /repo/prod:
        commands: {git: {commit: deny}}
```

| Working directory | Line | Result |
| --- | --- | --- |
| `/` | `rm /data/keep/2024.csv` | Refused. |
| `/` | `rm /data/tmp/a.log` | Runs. |
| `/data/keep` | `rm /data/tmp/a.log` | Refused. The working directory is inside `/data/keep`. |
| `/` | `cd /data/keep && rm /data/tmp/a.log` | Refused. |
| `/` | `echo before; rm /data/keep/2024.csv` | Refused, and prints nothing. A refused command holds the whole line. |
| `/` | `ls /data/keep` | Runs. The entry names only `rm`. |
| `/repo/prod` | `git commit -m fix` | Refused. |
| `/repo/dev` | `git commit -m fix` | Runs. |
| `/repo/prod` | `git status` | Runs. |

A key is one of:

- A mount, such as `/data`. The entry can hold the mount's mode as well:
  `/data: {mode: write, commands: {rm: ask}}`.
- A folder, such as `/data/keep`: the folder itself and everything under it.
- A file, such as `/data/keep/2024.csv`: that file only. With
  `/data/keep/2024.csv: {commands: {rm: deny}}`, `rm /data/keep/sub/notes.txt`
  runs.

`"*"` in an entry covers every command in the folder, the folder itself
included, and a redirect with no command.

```yaml
profiles:
  agent:
    mounts:
      /data/keep:
        commands: {"*": deny, ls: allow}
```

| Line | Result |
| --- | --- |
| `cat /data/keep/2024.csv` | Refused. |
| `cd /data/keep` | Refused. The entry covers the folder itself. |
| `ls /data/keep` | Runs. Inside the entry, an allow reopens what its `"*"` refuses. |
| `> /data/keep/new.txt` | `bash: line 1: /data/keep/new.txt: Permission denied`, exit 1. |
| `{ cat; } < /data/keep/2024.csv` | `bash: line 1: /data/keep/2024.csv: Permission denied`, exit 1. |
| `find /data` | Lists `/data` without going inside `/data/keep`, prints `find: '/data/keep': Permission denied` and exits 1. |
| `grep -r audit /data` | Searches `/data` without going inside `/data/keep`, prints `grep: /data/keep: Permission denied` and exits 2. |
| `du /data` | Counts `/data` without going inside `/data/keep`, prints `du: cannot read directory '/data/keep': Permission denied` and exits 1. |

- A command that reads a parent folder recursively, such as `find`,
  `grep -r`, `du`, `ls -R` or `tree`, runs and skips a folder its entry
  refuses, with the command's own error and exit status.
- A command that would remove or move the folder with its parent is refused
  whole. With the entry on `/data/keep/sub`, `rm -r /data/keep` and
  `mv /data/keep /data/old` are refused.
- An `ask` entry waits for approval once per command, however many paths it
  names in the folder. A recursive read over a parent folder does not ask:
  with `grep: ask` on `/data/keep`, `grep -r audit /data` skips
  `/data/keep`.
- An entry cannot reopen what the top-level `commands` refuses. With
  `commands: {rm: deny}`, an entry `/data/tmp: {commands: {rm: allow}}`
  still leaves `rm /data/tmp/a.log` refused.

To let a session change files in one folder only, give the mount a read-only
mode and reopen that folder with `paths.show`:

```yaml
profiles:
  agent:
    mounts:
      /data: {mode: read}
    paths:
      show: {/data/tmp: write}
```

| Line | Result |
| --- | --- |
| `rm /data/tmp/a.log` | Runs. |
| `echo x > /data/tmp/b.log` | Runs. |
| `rm /data/keep/2024.csv` | `rm: cannot remove '/data/keep/2024.csv': Read-only file system`, exit 1. |

Mirage refuses an entry it cannot apply when it loads the profile:

| Written, with a mount at `/data` | Refused because |
| --- | --- |
| `mounts: {/data/keep: read}` | A mode applies to a whole mount. Put it on `/data`, or give the folder a mode with `paths.show`. |
| `mounts: {/data/*/sub: {commands: {rm: deny}}}` | A key is a literal path, not a glob. Write one key per folder. |

<Note>
A command rule with `paths`, such as
`rm: {decision: deny, paths: [/data/keep/*]}`, does not load:
`commands.rm: a rule takes no paths; scope it to a folder with mounts[/data/keep].commands.rm`.
Move the rule into that entry. For a name pattern such as `*.pem`, the error
points to `paths.hide`.
</Note>

### Lines, not file calls

A tree judges the lines a session runs. It does not stop another way to the
same file: a command the tree does not name, a program, or a file call
outside a line, such as `session.vfs` or the agent's file tools. To keep a
file from every way in, make it read-only with the mount's `mode` or
`paths.show`, or hide it with `paths.hide`.

```yaml
profiles:
  rule:
    mounts:
      /data/keep:
        commands: {rm: deny}
  read-only:
    paths:
      show: {/data/keep: read}
```

| Way in | Under `rule` | Under `read-only` |
| --- | --- | --- |
| `rm /data/keep/2024.csv` | `rm: Permission denied`, exit 126 | `rm: cannot remove '/data/keep/2024.csv': Read-only file system`, exit 1 |
| `find /data/keep -name '*.csv' -delete` | Deletes the file. | `find: cannot delete '/data/keep/2024.csv': Read-only file system`, exit 1 |
| `python3 -c "import os; os.remove('/data/keep/2024.csv')"` | Deletes the file. | `OSError: [Errno 30] Read-only file system: '/data/keep/2024.csv'`, exit 1 |
| `session.vfs.unlink("/data/keep/2024.csv")` in Python | Deletes the file. | Raises `PermissionError`: `[Errno 30] Read-only file system`. |

### Names

- Write an option in any spelling the command declares: `-r`, `-R` or
  `--recursive` for `rm`. A subcommand takes its aliases too, such as `ls`
  for `gh pr list`.
- Write each option as its own key. `-rf` is refused; write `-r` and `-f`.
- Quote a key that YAML would not read as a string: `"*"`, `"5"`, `"true"`.

Mirage checks every name when it loads the profile, and refuses a tree it
cannot read one way:

| Written | Refused because |
| --- | --- |
| `gh: {pr: {mrge: deny}}` | `gh pr` has no subcommand `mrge`. |
| `gh: {pr: {merge: {--amdin: deny}}}` | `gh pr merge` has no option `--amdin`. |
| `gh: {pr: {merge: {admin: deny}}}` | `admin` is no subcommand. An operand goes under `operands`. |
| `curl: {--request: {DELETE: deny}}` | A value goes under `values`. |
| `gh: {operands: {x: deny}}` | `gh` takes a subcommand, so operands go under one. |
| `rm: {-r: ask, --recursive: deny}` | `-r` and `--recursive` are the same option. |
| `git: {-f: deny}` | `-f` is a different option in different `git` subcommands. Write `--force`, or put the entry under its subcommand. |
| `allow: [ls, cat]` | `allow`, `ask` and `deny` lists of patterns are the old format. Write a tree. |

A misspelt operand is not caught. `operands: {mian: deny}` loads and never
matches.

### What a tree cannot say

- **Allow a command only with an option.** Options only tighten, so
  `git: {rm: {"*": deny, --cached: allow}}` still refuses
  `git rm --cached notes.txt`. Deny the options you do not want instead, as
  in [Only these options](#only-these-options).
- **Allow a command in one folder only.** An entry cannot reopen what the
  top-level `commands` refuses. Make the folder the only writable place
  instead, as in [In one folder](#in-one-folder).
- **Keep a file from other ways in.** A tree judges lines, not
  `find -delete`, a program or a file call. Use a mode, `paths.show` or
  `paths.hide`, as in [Lines, not file calls](#lines-not-file-calls).

## Hide and show

- `paths.hide` makes a path look absent. `paths.show` reopens a deeper path.
- `paths.show` can also give a path its own mode: `{/data/keep: read}` makes
  one folder read-only, and `{/data/tmp: write}` makes one folder writable
  in a read-only mount.
- `paths.hide` takes absolute paths or name patterns such as `*.pem`;
  `paths.show` takes absolute paths only. `*` can cross `/`.
- A hidden path is gone everywhere: from command output and counts, from
  links into it, from git history, and from what a checkout touches.
- Moving a folder that holds a hidden path is refused.

Use [Explain](/home/policy/explain) to check a rule before running a line.
