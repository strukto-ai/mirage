A profile sets what a session can run and see, so agents can share one
workspace with different files and commands.

```yaml workspace.yaml
mounts:
  /data:
    vfs: ram

profiles:
  researcher:
    cwd: /data
    mounts:
      /data: { mode: read }
    paths:
      hide: [/data/private]
    commands:
      allow: [ls, cat, grep, find, stat, pwd]

profile: researcher
```

A session under `researcher` reads `/data`, never sees `/data/private`, and
gets `Permission denied` for any command off the list, builtins such as `cd`
included.

## What a profile controls

| Key | Sets |
| --- | --- |
| `commands.allow` | The only commands the session can run. |
| `commands.ask` | Commands that need approval. |
| `commands.deny` | Commands that are refused. |
| `paths.hide` | Files and folders the session cannot see. |
| `paths.show` | A path to reopen inside a hidden folder. |
| `mounts` | A mount's access: `read`, `write` or `exec`. |
| `cwd`, `env` | The starting folder and environment. `env` takes [credential pointers](/home/service-credentials#set-environment-variables). |
| `vars.hide` | Variable names that read as unset. |
| `processes` | Whose processes `ps` lists and `kill` stops, and the most it runs. |
| `command_limits` | [Output and execution limits](/home/limits#command-output). |
| `network` | A narrower [`network`](/home/configuration/workspace#network) than the workspace's. |
| `policy` | [Policy scripts](/home/policy/scripts) to run. |

```yaml
profiles:
  worker:
    vars:
      hide: [AWS_*, GITHUB_TOKEN]
    processes: {list: workspace, kill: session, max: 8}
    command_limits:
      grep: {max_lines: 200}
    network:
      allowed_domains: ["*.github.com"]
    policy:
      pre_command:
        - {script: ./guard.py, runtime: monty}
```

- `processes` scopes are `session` (the default) or `workspace`. `max` is 128
  by default; past it a new process fails with `Resource temporarily unavailable`.
- A profile's `processes` overrides the workspace's field by field. Its
  `network` can only narrow the workspace's.

## Use a profile

| | Create a session under `researcher` |
| --- | --- |
| Python | `ws.create_session("s1", profile="researcher")` |
| TypeScript | `ws.createSession('s1', { profile: 'researcher' })` |
| CLI | `mirage workspace session create -w ID -p researcher` |
| HTTP | `POST /v1/workspaces/{id}/sessions` with `profile` |

A session with no profile gets the one `profile:` names, else `default`, else
no limits.

To change rules while the workspace runs, add or replace a profile with
[Set profile](/api/operations/workspaces/set-profile), then move sessions onto
it. A moved session keeps its folder, variables and history, and
`workspace.yaml` is never rewritten. No command inside a session can change its
own profile.

## Rule matching

### Commands

| Pattern | Matches |
| --- | --- |
| `git push` | `git push origin main`: a pattern matches the leading words. |
| `rm -rf` | Not `rm -r -f`: spelling and order count. |
| `git * main` | Any one word in place of `*`. |

- `allow: []` allows no command. No `allow` key means no allow list.
- `[` and `[[` are commands too, and an allow list must name them.
- Shell functions are exempt; each line inside one is checked.
- `commands.allow` does not cover executed paths, direct VFS calls or MCP file
  tools. Limit file access with `mounts` and `paths`.

### Ask and deny

```yaml
commands:
  allow: [rm]
  ask:
    - {commands: {rm: ["/data/review/*"]}, reason: deletes need review}
  deny:
    - {commands: {rm: ["/data/*"]}, reason: data is retained}
```

- The rule with the deeper path wins; at equal depth, deny wins. So
  `rm /data/review/note.txt` asks, and `rm /data/other.txt` is denied.
- A command with several paths must pass for each one.
- Ask and deny leave the paths visible.

### Hide and show

- `paths.hide` makes a path look absent. `paths.show` reopens a deeper path.
- `paths.hide` takes absolute paths or name patterns such as `*.pem`;
  `paths.show` takes absolute paths only. `*` can cross `/`.
- A hidden path is gone everywhere: from command output and counts, from
  links into it, from git history, and from what a checkout touches.
- Moving a folder that holds a hidden path is refused.

Use [Explain](/home/policy/explain) to check a rule before running a line.
