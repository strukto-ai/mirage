---
title: Limit command output
description: Cap command output, execution time and walks at the workspace, mount, or profile level.
icon: gauge
---

Mirage keeps large results from flooding an agent. `cat`, `grep`, `rg`, `head`,
and `tail` return at most 2,000 lines by default, every command stops after
600 seconds, and a walk stops at its mount's `walk_limit`.

## Set Limits

Set a workspace default for every session, a mount override for commands that
run on that mount, or a profile override for sessions created with that profile.

<CodeGroup>
```python Python
from mirage import MountMode, Workspace
from mirage.types import Limit, OnExceed
from mirage.vfs.ram import RAMVFS

ws = Workspace(
    {
        "/data": (RAMVFS(), MountMode.WRITE, {
            "grep": Limit(max_lines=50, on_exceed=OnExceed.ERROR),
        }),
    },
    mode=MountMode.WRITE,
    command_limits={"head": Limit(max_lines=500, timeout_seconds=30)},
    profiles={
        "researcher": {"command_limits": {"head": Limit(max_lines=5000)}},
    },
)
ws.create_session("research", profile="researcher")
```

```ts TypeScript
import { Limit, MountMode, OnExceed, RAMVFS, Workspace } from '@struktoai/mirage-node'

const ws = new Workspace(
  {
    '/data': [
      new RAMVFS(),
      MountMode.WRITE,
      { grep: new Limit({ maxLines: 50, onExceed: OnExceed.ERROR }) },
    ],
  },
  {
    mode: MountMode.WRITE,
    commandLimits: { head: new Limit({ maxLines: 500, timeoutSeconds: 30 }) },
    profiles: { researcher: { commandLimits: { head: new Limit({ maxLines: 5000 }) } } },
  },
)
ws.createSession('research', { profile: 'researcher' })
```
</CodeGroup>

The workspace YAML uses the same fields in snake case under `command_limits`.

## Choose Which Limit Applies

Each field comes from the most specific entry that sets it: the session profile,
the mount, then the workspace (each looked up by the command's name, then under
`"*"`, the entry for every command), the command's own default, and Mirage's
built-in default; a walk's `walk_limit` ends at the mount backend's default. An
entry that sets one field inherits the rest, so `"cat": Limit(max_lines=10)`
keeps cat's timeout.

The `line` entry bounds a whole top-level line, loops and pipelines included:
its `timeout_seconds` is the line's deadline, the profile's over the
workspace's, and there is none by default. A line past it exits 124 with
`line: timed out after Ns`.

For commands spanning multiple mounts, Mirage applies the tightest resolved
limit from those mounts.

## Handle a Reached Limit

- `max_lines` and `max_bytes` cap output. Use `None` in Python or `null` in
  TypeScript for no cap.
- `timeout_seconds` sets a deadline. A command that passes it exits 124.
- `walk_limit` caps the entries one walk lists on a mount, `-1` for no cap; see
  [walks](/home/integration/walks).
- `on_exceed=TRUNCATE`, the default, returns the capped output, writes a notice
  to stderr, and preserves the command's exit code.
- `on_exceed=ERROR` drops the output and exits 1, so `&&` and `||` see a failure.

In TypeScript, use the camel-case forms `maxLines`, `maxBytes`, `timeoutSeconds`,
`walkLimit`, and `onExceed`.

Caps apply to each command's printed output. `cat big.txt; echo end` still prints
`end`. Input to a pipe, redirect, or command substitution is not cut, so
`cat big.txt | wc -l` counts every line.
