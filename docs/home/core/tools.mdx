Unix commands over every mount. A mount's capabilities and the session's
permissions decide which ones run there.

Expand a command to see every flag it takes, read from the same grammar the
shell parses with; `man COMMAND` prints its manual. A familiar name does not
promise every option of the original program.

## Limits

- `rm -i` and `-I` are accepted but ignored; deletion does not prompt for confirmation.
- File operations depend on the backend; a read-only mount cannot accept writes. Permission and owner metadata may live in Mirage's overlay rather than the remote service.
- Mount roots are protected from removal, renaming, and use as copy sources. `mount` lists configured mounts; it does not attach new backends.
- `ln -s` creates a virtual symlink. Without `-s`, a regular file is copied; there is no shared hard-link inode.
- `find` supports `-a`, `-o`, `!`, parentheses, and both `-exec ... \;` and `-exec ... {} +`. Tests must precede actions in each AND chain, and OR branches must use the same action. `-newer` and `-newermt` must be in a top-level AND chain. `-ok` and `-okdir` are unsupported.
- `rg` cannot sort by creation time. `ls --color` and `grep --color` are accepted without colored output.
- Under a UTF-8 locale (`LANG=C.UTF-8`), `find` names a file or a value between `‘` and `’`, as Linux's does. Other commands keep straight quotes in their messages.
- Under a UTF-8 locale, `sed`, `grep`, `expr`, `nl`, `[[ =~ ]]` and `git`'s filters match whole characters. A pattern byte that is only part of one, such as `\xa9` against `é` (bytes `C3 A9`), matches nothing there, where Linux's `sed` can match it inside the character.
- In rare patterns, `sed`, `expr` and `[[ =~ ]]` capture different text in a group than Linux does, or find a match where Linux finds none. Such a pattern repeats a group that holds an anchor (`^`, `$`, `\b`, `\<`, `\>`) or can match nothing, or refers back to one. For example, `[[ ab =~ (a|b|$){1,3} ]]` leaves `BASH_REMATCH[1]` empty where Linux sets it to `b`, and `echo babc | sed 's/\(\<[a-][ab]\|[a-c]\)\{2\}/<&>/'` prints `<ba>bc` where Linux prints `babc`.
- `getconf -a` lists the same variables and values as Linux, in the order of POSIX's tables rather than the C library's.
- `xargs -p` and `-o` fail because there is no terminal. `timeout` signals its command as `kill` does, so a program can handle the signal; a Mirage command cannot trap one.
