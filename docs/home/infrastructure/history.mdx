---
title: History
description: Where a workspace records the commands it runs, in memory, on disk or on Redis.
icon: clock-rotate-left
---

The history store records every command a session runs at the top level. The
`history` builtin and `/.bash_history` are two views of that one record, and a
[policy](/home/policy/policies) reads it as `/.bash_history`.
From outside, `ws.history()`, [`GET /v1/workspaces/{id}/history`](/home/access/http#read-a-workspaces-history)
and `mirage workspace history` read every session's record: each line as a
`command` entry when it starts and a `result` entry (exit code, stdout,
stderr) when it ends, and with `vfs`, each call it made to a mount between
them.

History is kept per session. A workspace built again shows a session's
history once it has that session again: keep the
[sessions](/home/infrastructure/sessions) where they survive too, or give the
session a fixed id with `default_session_id`.

History grows with every command, so it can go to a backend of its own while
the rest of the state stays where it is.

| `type` | Keeps it | Keys |
| --- | --- | --- |
| `ram` | In the process's memory, until it exits | |
| `disk` | In files under `root` | `root`, default `~/.mirage/state` |

The group key is `store.observer`. History is never kept on Redis: a Redis
store keeps it on the machine's disk, under the store's `root`, unless
`observer` says otherwise. To see it across machines, send it to
[OpenTelemetry](#send-it-to-opentelemetry).

## On disk

<Tabs>
  <Tab title="YAML" icon="file-code">
    ```yaml
    workspace_id: agent
    store:
      type: redis
      url: redis://redis.internal:6379/0
      observer:
        type: disk
        root: /var/lib/mirage
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    from mirage import Workspace
    from mirage.workspace.store import DiskWorkspaceStateStore, RedisWorkspaceStateStore

    store = RedisWorkspaceStateStore(
        url="redis://redis.internal:6379/0",
        observer=DiskWorkspaceStateStore(root="/var/lib/mirage"),
    )
    ws = Workspace(mounts, workspace_id="agent", store=store, owns_store=True)
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { DiskWorkspaceStateStore, RedisWorkspaceStateStore, Workspace } from '@struktoai/mirage-node'

    const store = new RedisWorkspaceStateStore({
      url: 'redis://redis.internal:6379/0',
      observer: new DiskWorkspaceStateStore({ root: '/var/lib/mirage' }),
    })
    const ws = new Workspace(mounts, { workspaceId: 'agent', store, ownsStore: true })
    ```
  </Tab>
</Tabs>

Here the rest of the state is on Redis and only the history stays on the
machine's disk.

## Send it to OpenTelemetry

Every line that ends is also a trace span: `command`, from its start to its
end, and under it a `vfs.<call>` span for each call it made to a mount. Nothing
is sent until the process sets up an OpenTelemetry SDK, whose exporter picks
the backend: OTLP to Datadog, Honeycomb, Grafana, Langfuse and others.

| Span | Attributes |
| --- | --- |
| `command` | `mirage.workspace.id`, `mirage.session.id`, `mirage.command`, `mirage.exit_code` |
| `vfs.<call>` | `mirage.vfs.path`, `mirage.vfs.source`, `mirage.vfs.bytes` |

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```bash
    OTEL_TRACES_EXPORTER=otlp OTEL_EXPORTER_OTLP_ENDPOINT=https://otlp.example.com \
      opentelemetry-instrument python agent.py
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { trace } from '@opentelemetry/api'
    import { BasicTracerProvider, BatchSpanProcessor } from '@opentelemetry/sdk-trace-base'
    import { OTLPTraceExporter } from '@opentelemetry/exporter-trace-otlp-http'

    trace.setGlobalTracerProvider(
      new BasicTracerProvider({
        spanProcessors: [new BatchSpanProcessor(new OTLPTraceExporter({ url: 'https://otlp.example.com/v1/traces' }))],
      }),
    )
    ```
  </Tab>
</Tabs>
