description: A lightweight terminal inside a FastAPI or Express server, with Python on Monty and no container.

Most of the time an agent does not need a sandbox, only a terminal-like
interface. An embedded terminal runs inside an application server. Each terminal is a
Mirage session with its own working directory, environment and history, and
[Monty](/home/setup/runtime/monty) runs Python in-process, so a terminal
starts with no container or VM. Mirage is async native, so one server process
runs many terminals at once on its event loop.

This page builds that server, then uses its terminal the way an agent would:
it runs [MCP servers as commands](#mcp-as-cli) and
[reviews a code change](#code-review) with `git`, pipes and Python.

## Server

One endpoint creates a session, another runs a command line in it. At start,
the server registers [`git`](/python/cli/git) and installs two public MCP
servers as CLIs, used in [MCP as CLI](#mcp-as-cli) and
[Code Review](#code-review).

<Tabs>
  <Tab title="FastAPI" icon="/images/python-logo.svg">
    ```python app.py
    from contextlib import asynccontextmanager

    from fastapi import FastAPI
    from pydantic import BaseModel

    from mirage import RAMVFS, MountMode, Workspace, mcp_cli
    from mirage.commands.cli.builtin.git import GIT
    from mirage.runtime.python.monty import MontyRuntime

    ws = Workspace(
        {"/work": (RAMVFS(), MountMode.EXEC)},
        runtimes=[MontyRuntime(captures=["python", "python3"])],
    )
    ws.register_cli("git", GIT)

    MCP_SERVERS = {
        "deepwiki": "https://mcp.deepwiki.com/mcp",
        "context7": "https://mcp.context7.com/mcp",
    }


    @asynccontextmanager
    async def lifespan(app: FastAPI):
        for name, url in MCP_SERVERS.items():
            config = {"url": url}
            ws.register_cli(name, await mcp_cli(config), config)
        yield
        await ws.close()


    app = FastAPI(lifespan=lifespan)


    class Run(BaseModel):
        command: str


    @app.post("/sessions/{session_id}")
    async def create(session_id: str) -> None:
        ws.create_session(session_id)


    @app.post("/sessions/{session_id}/run")
    async def run(session_id: str, body: Run) -> dict:
        r = await ws.shell(body.command, session_id=session_id)
        return {"stdout": await r.stdout_str(), "stderr": await r.stderr_str(), "exit_code": r.exit_code}
    ```

    ```bash
    uvicorn app:app --port 3000
    ```
  </Tab>
  <Tab title="Express" icon="/images/typescript-logo.svg">
    ```typescript app.mjs
    import express from 'express'
    import { GIT, MontyRuntime, MountMode, RAMVFS, Workspace, mcpCli } from '@struktoai/mirage-node'

    const ws = new Workspace(
      { '/work': new RAMVFS() },
      { mode: MountMode.EXEC, runtimes: [new MontyRuntime({ captures: ['python', 'python3'] })] },
    )
    ws.registerCli('git', GIT)

    const mcpServers = {
      deepwiki: 'https://mcp.deepwiki.com/mcp',
      context7: 'https://mcp.context7.com/mcp',
    }
    for (const [name, url] of Object.entries(mcpServers)) {
      const config = { url }
      ws.registerCli(name, await mcpCli(config), config)
    }

    const app = express()
    app.use(express.json())

    app.post('/sessions/:id', (req, res) => {
      ws.createSession(req.params.id)
      res.sendStatus(201)
    })

    app.post('/sessions/:id/run', async (req, res) => {
      const r = await ws.shell(req.body.command, { sessionId: req.params.id })
      res.json({ stdout: r.stdoutText, stderr: r.stderrText, exitCode: r.exitCode })
    })

    app.listen(3000, '127.0.0.1')
    ```

    ```bash
    node app.mjs
    ```
  </Tab>
</Tabs>

## Usage

```bash
curl -X POST localhost:3000/sessions/a
curl -X POST localhost:3000/sessions/a/run -H 'content-type: application/json' \
  -d '{"command": "cd /work && echo \"print(sum(range(10)))\" > s.py && python3 s.py"}'
```

The run prints `45`. A later call to session `a` starts in `/work`, where the
`cd` left it.

The examples below send several lines in one request. This shell function
reads the lines from standard input, sends them to session `a` as the
`command`, and prints the terminal's standard output. It needs
[`jq`](https://jqlang.org):

```bash
run() {
  jq -Rs '{command: .}' |
    curl -s localhost:3000/sessions/a/run -H 'content-type: application/json' -d @- |
    jq -j .stdout
}

run <<'SH'
pwd
python3 s.py
SH
```

```text
/work
45
```

The lines between `SH` and `SH` run in the terminal on the server, not in
the shell that calls `run`.

- Sessions share the workspace's mounts, so a file one writes under `/work`
  is visible to the others. Give each session its own directory, or its own
  workspace, to keep files apart.
- Monty supports a subset of Python and has no network or host access. For
  more, see [Hybrid Terminal](#hybrid-terminal).
- The server runs any line for any caller that names a session. Put
  authentication and a check that the caller owns the session in front of it
  before it listens beyond localhost.

## MCP as CLI

The server installed DeepWiki and Context7 at start, so every terminal has a
`deepwiki` and a `context7` command. Each tool of an
[MCP server](/python/cli/mcp) is a subcommand that takes its arguments as one
JSON object, and `--help` prints the tool's schema. `run` is the function
from [Usage](#usage):

```bash
run <<'SH'
deepwiki --help
deepwiki read-wiki-structure '{"repoName": "facebook/react"}' | head -15
context7 resolve-library-id '{"libraryName": "fastapi", "query": "dependency injection"}' | grep -i "library id" | head -5
context7 query-docs '{"libraryId": "/websites/fastapi_tiangolo", "query": "dependency injection with Depends"}' | grep -n Depends | head -5
SH
```

A large answer goes to a file, and the caller reads only what it asks for:

```bash
run <<'SH'
deepwiki read-wiki-contents '{"repoName": "facebook/react"}' > /work/react-wiki.md
wc -c /work/react-wiki.md
grep -n -i "usestate" /work/react-wiki.md | head -5
SH
```

The whole React wiki is about 670 KB, roughly 170,000 tokens; the caller
sees a byte count and a few lines.

- The tool list is read once, at registration, and no schema reaches the
  model until it runs `--help`.
- The server needs both MCP servers to start; `mcp_cli` raises when one
  cannot be reached. Remove an entry from `MCP_SERVERS` to run without it.
- A profile can deny a tool, and a `network:` rule can limit the hosts a
  terminal reaches. See [From MCP](/python/cli/mcp).
- DeepWiki and Context7 are third-party services with rate limits. Context7
  takes an API key for higher limits, sent with
  `auth: {"type": "header", ...}`.

## Code Review

An agent with this terminal can review a change the way a developer does:
clone the repository, read the diff and search the tree. `git` is a Mirage
CLI, so the clone lands in `/work` and no `git` program runs on the host.
The lines below are what an agent would send. They review release 9.2.0 of
[tenacity](https://github.com/jd/tenacity), a Python retry library, and then
one fix in it, through `run` from [Usage](#usage).

The first block clones the release tag and measures the change since 9.1.4:

```bash
run <<'SH'
git clone -q -b 9.2.0 https://github.com/jd/tenacity.git /work/tenacity
cd /work/tenacity
git log --oneline 9.1.4..9.2.0 | wc -l
git diff 9.1.4 9.2.0 > /work/release.patch
grep -c '^diff --git' /work/release.patch
git log --oneline --grep '^fix' 9.1.4..9.2.0 | head -3
SH
```

- DeepWiki's answer agrees with the commit message: a predicate that never

the 200 KB patch stayed in the terminal.

## Async

`ws.shell` is a coroutine in Python and a promise in TypeScript, and it never
blocks the event loop. The handlers above are `async`, so while one terminal
waits on a file read, a runtime or a slow command, the server keeps serving
every other terminal, with no thread or process per terminal.

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import asyncio

    for sid in ["a", "b", "c"]:
        ws.create_session(sid)
    await asyncio.gather(*(ws.shell("sleep 1", session_id=sid) for sid in ["a", "b", "c"]))
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    for (const sid of ['a', 'b', 'c']) ws.createSession(sid)
    await Promise.all(['a', 'b', 'c'].map((sid) => ws.shell('sleep 1', { sessionId: sid })))
    ```
  </Tab>
</Tabs>

The three lines finish together in about a second; 20 sessions take the
same. Within one session, lines run one after another in order, as in a real
terminal, so three `sleep 1` lines on session `a` take three seconds.

## Hybrid Terminal

A hybrid terminal keeps light Python on Monty and sends the rest to a Docker
container: lines that use `numpy` or `pandas` by route policy, and every
program Mirage does not have itself, such as `ffmpeg`, by `@external`. Redis
holds the files, sessions, jobs and processes, so a terminal outlives the
server process that runs it.

| Line | Runs on |
| --- | --- |
| `cat`, `grep`, pipes, redirects | Mirage |
| `python3 s.py` | Monty |
| `python3 -c 'import numpy; ...'` | Docker, by the route policy |
| `ffmpeg -i in.mp4 out.gif` | Docker, by `@external` |

Build the container's image with `sshfs`, which serves the workspace into it,
and the programs the lines need, and start Redis:

```dockerfile Dockerfile
FROM python:3.12-slim
RUN apt-get update \
    && apt-get install -y --no-install-recommends sshfs ffmpeg \
    && rm -rf /var/lib/apt/lists/* \
    && pip install --no-cache-dir numpy pandas
```

```bash
docker build -t mirage-box .
docker run -d --name redis -p 6379:6379 redis
```

A container serves one session, so each terminal gets a workspace and a
container of its own. The server starts the container when it creates the
terminal:

<Tabs>
  <Tab title="FastAPI" icon="/images/python-logo.svg">
    ```bash
    pip install 'mirage-ai[monty,redis,ssh]' fastapi uvicorn
    ```

    ```python app.py
    import asyncio
    import re
    from contextlib import asynccontextmanager

    from fastapi import FastAPI, HTTPException
    from pydantic import BaseModel

    from mirage import MountMode, Workspace
    from mirage.runtime.machine import RemoteRuntime
    from mirage.runtime.python.monty import MontyRuntime
    from mirage.vfs.redis import RedisVFS
    from mirage.workspace.store import RedisWorkspaceStateStore

    REDIS_URL = "redis://localhost:6379/0"
    terminals: dict[str, Workspace] = {}


    def terminal(terminal_id: str) -> Workspace:
        if terminal_id not in terminals:
            terminals[terminal_id] = Workspace(
                {"/work": RedisVFS(url=REDIS_URL)},
                mode=MountMode.EXEC,
                workspace_id=terminal_id,
                store=RedisWorkspaceStateStore(url=REDIS_URL),
                owns_store=True,
                machines={
                    "box": {
                        "provider": "docker",
                        "container": f"box-{terminal_id}",
                        "mount_type": "ssh",
                    }
                },
                runtimes=[
                    MontyRuntime(captures=["python", "python3"]),
                    RemoteRuntime(["@python", "@external"], machine="box"),
                ],
                route_policy=lambda ctx: "remote" if re.search(r"\b(numpy|pandas)\b", ctx.line) else None,
            )
        return terminals[terminal_id]


    @asynccontextmanager
    async def lifespan(app: FastAPI):
        yield
        for ws in terminals.values():
            await ws.close()


    app = FastAPI(lifespan=lifespan)


    class Run(BaseModel):
        command: str


    @app.post("/sessions/{session_id}")
    async def create(session_id: str) -> None:
        docker = await asyncio.create_subprocess_exec(
            "docker", "run", "-d", "--cap-add", "SYS_ADMIN", "--device", "/dev/fuse",
            "--name", f"box-{session_id}", "mirage-box", "sleep", "infinity",
        )
        if await docker.wait() != 0:
            raise HTTPException(500, "could not start the terminal's container")
        terminal(session_id).create_session(session_id)


    @app.post("/sessions/{session_id}/run")
    async def run(session_id: str, body: Run) -> dict:
        r = await terminal(session_id).shell(body.command, session_id=session_id)
        return {"stdout": await r.stdout_str(), "stderr": await r.stderr_str(), "exit_code": r.exit_code}
    ```

    ```typescript app.mjs
    import { execFile } from 'node:child_process'
    import { promisify } from 'node:util'
    import express from 'express'
    import {
      MontyRuntime,
      MountMode,
      RemoteRuntime,
      RedisVFS,
      RedisWorkspaceStateStore,
      Workspace,
    } from '@struktoai/mirage-node'

    const redisUrl = 'redis://localhost:6379/0'
    const terminals = new Map()

    function terminal(id) {
      if (!terminals.has(id)) {
        terminals.set(
          id,
          new Workspace(
            { '/work': new RedisVFS({ url: redisUrl }) },
            {
              mode: MountMode.EXEC,
              workspaceId: id,
              store: new RedisWorkspaceStateStore({ url: redisUrl }),
              ownsStore: true,
              machines: {
                box: { provider: 'docker', container: `box-${id}`, mountType: 'ssh' },
              },
              runtimes: [
                new MontyRuntime({ captures: ['python', 'python3'] }),
                new RemoteRuntime({ captures: ['@python', '@external'], machine: 'box' }),
              ],
              routePolicy: (ctx) => (/\b(numpy|pandas)\b/.test(ctx.line) ? 'remote' : null),
            },
          ),
        )
      }
      return terminals.get(id)
    }

    const app = express()
    app.use(express.json())

    app.post('/sessions/:id', async (req, res) => {
      const id = req.params.id
      await promisify(execFile)('docker', [
        'run', '-d', '--cap-add', 'SYS_ADMIN', '--device', '/dev/fuse',
        '--name', `box-${id}`, 'mirage-box', 'sleep', 'infinity',
      ])
      terminal(id).createSession(id)
      res.sendStatus(201)
    })

    app.post('/sessions/:id/run', async (req, res) => {
      const r = await terminal(req.params.id).shell(req.body.command, { sessionId: req.params.id })
      res.json({ stdout: r.stdoutText, stderr: r.stderrText, exitCode: r.exitCode })
    })

    app.listen(3000, '127.0.0.1')
    ```

- Send each terminal's requests to one replica, for example by hashing the
  terminal id at the load balancer. A replica keeps a session in memory once
  it has loaded it, so two replicas serving one terminal would each keep
  their own working directory. After a restart, the replica reads the
  terminal back from Redis, in the directory it left.
- Every terminal's `/work` is the same Redis keys, so terminals share files.
  Give each `RedisVFS` its own `key_prefix` to keep them apart.
- Remove a terminal's container with `docker rm -f box-<id>` when the
  terminal ends.
- `ws.explain(line)` shows which runtime serves each command.
