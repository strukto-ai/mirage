[OpenClaw](https://github.com/openclaw/openclaw) runs MCP servers and installs agent plugin bundles. Mirage reaches it two ways:

| Way | OpenClaw gets | Workspace |
| --- | --- | --- |
| [MCP](#mcp) | Mirage's seven tools | the one you name, local or on a Mirage server |
| [Plugin](#plugin) | the seven tools, plus the `mirage-filesystem` and `mirage-vfs-authoring` skills | `~/.mirage/workspace.yaml` |

OpenClaw keeps its own exec and file tools. Mirage sees only the calls to its tools.

## Install

<CodeGroup>
```bash uv
uv tool install mirage-ai
```
```bash npm
npm install -g @struktoai/mirage-cli
```
</CodeGroup>

Install [OpenClaw](https://docs.openclaw.ai) separately.

## Workspace

```yaml workspace.yaml
mounts:
  /data: { vfs: ram, mode: write }
```

```bash
mirage workspace create workspace.yaml --id demo
```

## MCP

<CodeGroup>
```bash mirage mcp
openclaw mcp set mirage '{"command":"mirage","args":["mcp","-w","demo"]}'
```
```bash Mirage server
openclaw mcp set mirage '{"url":"https://mirage.example.com/v1/workspaces/demo/mcp","transport":"streamable-http","headers":{"Authorization":"Bearer ${MIRAGE_TOKEN}"}}'
```
</CodeGroup>

```bash
openclaw mcp probe mirage
```

This prints `mirage: 7 tools`. A session already open picks them up after `openclaw mcp reload`.

`mirage mcp` sends your saved [login](/home/access/cli#log-in) or the local token file. OpenClaw starts it with only `HOME`, `PATH`, `USER` and `LOGNAME`, so a `MIRAGE_TOKEN` in the Gateway's environment does not reach it. If the Gateway runs as a service, set `command` to the path `command -v mirage` prints.

For a Mirage server, OpenClaw fills `${MIRAGE_TOKEN}` in the header from the Gateway's environment.

## Plugin

```bash
openclaw plugins install mirage --marketplace strukto-ai/mirage
openclaw plugins inspect mirage
```

Answer `y` to both prompts: one confirms a source from outside ClawHub, the other the plugin's skills. `inspect` shows `Bundle capabilities: skills, mcpServers`. The skills and tools load in the next session.

The plugin starts `npx -y @struktoai/mirage-cli mcp` from its folder under `~/.openclaw/extensions/`, so it serves the workspace in your home folder, not `demo`:

```yaml ~/.mirage/workspace.yaml
mounts:
  /data: { vfs: ram, mode: write }
```
