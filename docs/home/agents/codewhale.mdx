Connect Codewhale to a Mirage workspace to give it a shell and file tools over
the workspace's mounts. Codewhale's built-in tools operate on its host
workspace. Mirage applies the workspace's [session profile](/home/configuration/session)
to calls through its [MCP tools](/home/access/mcp#tools).

## Create a Workspace

Install [Codewhale](https://github.com/codewhale-hq/Codewhale/blob/v0.10.3/docs/INSTALL.md)
and the [Mirage CLI](/home/access/cli#install). Save this RAM-backed workspace as
`codewhale-demo.yaml`.

```yaml codewhale-demo.yaml
mounts:
  /data:
    vfs: ram
    mode: write
```

```bash
mirage workspace create codewhale-demo.yaml --id codewhale-demo
mirage shell -w codewhale-demo -c 'echo "hello from Mirage" > /data/hello.txt'
```

## Connect Over MCP

```bash
codewhale mcp add mirage_demo --command "$(command -v mirage)" --arg=mcp --arg=-w --arg=codewhale-demo
codewhale mcp validate
codewhale mcp tools mirage_demo
```

Start Codewhale. If it is already open, run `/mcp reload` to pick up the new server.
Ask Codewhale to read `/data/hello.txt` with `mcp_mirage_demo_read`. The tool result
contains `hello from Mirage`.

## Use an Editor

Configure the editor to launch `codewhale serve --acp`. Codewhale loads the MCP
server from its own configuration. Codewhale v0.10.3 rejects MCP servers supplied
in the ACP session request. That includes the server added by `mirage acp`.
[Codewhale ACP setup](https://github.com/codewhale-hq/Codewhale/blob/v0.10.3/docs/ACP.md)

## Clean Up

Remove the demo connection and workspace when you finish.

```bash
codewhale mcp remove mirage_demo
mirage workspace delete codewhale-demo
```
