Cursor, VS Code and Antigravity open a remote project by installing their own
server on the host over SSH and reaching it through port forwards. Mirage does
not run that server itself: it runs on a [machine](/home/setup/machine/overview)
the workspace sends its lines to, which sees the workspace's mounts at the
same paths.

## Set up

<Steps>
  <Step title="Turn on SSH">
    Set up the [SSH server](/home/access/ssh#set-up): a port, and a public key in
    `~/.mirage/ssh/authorized_keys`.
  </Step>
  <Step title="Start a machine">
    ```bash
    docker run -d --cap-add SYS_ADMIN --device /dev/fuse \
      --name dev-box python:3.12-slim sleep infinity
    docker exec dev-box sh -c 'apt-get update && apt-get install -y sshfs curl'
    ```
    The editor needs 64-bit Linux with glibc, and `curl` or `wget` to fetch its
    server. `python3`, `socat` or `bash` carries its port forwards.
  </Step>
  <Step title="Create the workspace">
    ```yaml workspace.yaml
    mounts:
      /project:
        vfs: ram
        mode: write
    machines:
      box:
        provider: docker
        container: dev-box
        mount_type: ssh
        captures: ["@line"]
    command_limits:
      "@line": {timeout_seconds: 0}
    ```
    ```bash
    mirage workspace create workspace.yaml --id demo
    ```
    `@line` runs every SSH line whole on the machine, and `mount_type: ssh`
    shows the mounts there. `timeout_seconds: 0` lifts the 10 minute line
    limit, since the editor's setup line stays open as long as its window does.
  </Step>
</Steps>

## Connect

Add the workspace as an SSH host:

```text ~/.ssh/config
Host mirage-demo
  HostName 127.0.0.1
  Port 2222
  User demo
```

On a hosted server, use the [Over HTTPS](/home/access/ssh#over-https) entry
instead and connect to `demo@mirage`.

The files under `/project` are the workspace's. The editor's terminal, tasks
and extensions run on the machine, the terminal with a real terminal device,
so a coding agent installed on the machine runs in it as in any terminal.

## Without a machine

Plain `ssh`, `sftp`, `scp` and `sshfs` need no machine, and neither does
Codex's [SSH](/home/agents/codex#ssh): its tools run in the workspace itself.
To edit without a machine, show the workspace as a local folder with
[SSHFS](/home/access/ssh#connect) or [FUSE](/home/setup/fuse) and open that
folder. The editor's extensions and terminal then run on the local computer,
and each file call into the folder still goes through the workspace.

## How it behaves

- A dropped connection leaves the editor's server running, as sshd does, so
  the editor reconnects to the same server.
- Each SSH connection and port forward is a session of its own, judged by the
  login's [profile](/home/configuration/session) and policies as any line.
  The machine serves every session with the first one's view: the same
  profile and standing decisions. A login under another profile needs a
  machine of its own.
- A line that comes over SSH runs on the machine without a terminal device.
  Run an interactive program, such as a coding agent's full-screen interface,
  in the editor's terminal; one that needs no terminal runs from `ssh` too.
- The editor's server runs its own commands on the machine. Mirage's command
  rules see the lines that come over SSH, and every file call into a mount
  still goes through the workspace.
- A reconnect leaves the old setup line running until the editor's server
  exits, and each counts against the server's `max_sessions`.
