The [Agent Client Protocol](https://agentclientprotocol.com) is how an app
such as Zed, a JetBrains IDE or t3code drives a coding agent: the app starts the
agent and the two talk JSON-RPC over the agent's stdin and stdout.
`mirage acp` goes in place of the agent's command and starts the agent itself:

```text
ACP client ◀── ACP ──▶ mirage acp ◀── ACP ──▶ agent
                           │                    │
                     file requests          MCP tools
                           └───▶ workspace ◀────┘
```

ACP carries the conversation: prompts, replies, tool calls and permission
requests, which pass through unchanged. The agent reaches the workspace two
ways underneath:

| When the agent | It goes through |
| --- | --- |
| Asks the client for a file (`fs/read_text_file`, `fs/write_text_file`) | `mirage acp`, which answers from the workspace and does not pass the request on |
| Calls `shell`, `read`, `write`, `edit`, `ls`, `grep` or `glob` | MCP, to the `mirage mcp` server added to its session |

Claude never asks the client for files, and its built-in tools are turned
off, so it works over MCP alone. Gemini CLI writes and edits files through
the client, but reads them and runs commands with its own tools.

The agent runs where the client starts it and nothing is uploaded, so no
[machine](/home/setup/machine/overview) is needed. A workspace on a hosted
server works the same way, reached with the CLI's
[login](/home/access/cli#log-in).

Only Claude's own tools are turned off. Another agent's own tools work on
the computer it runs on, beside the workspace's tools; turn them off in the
agent's settings to keep it to the workspace, such as `tools.exclude` for
Gemini CLI or `permission` for OpenCode.

### Codewhale

MCP tools over ACP require Codewhale v0.10.3 or later. Add Mirage to
[Codewhale's MCP configuration](/home/access/mcp#connect), then configure your
editor to launch `codewhale serve --acp` directly. Codewhale rejects the server
that `mirage acp` adds to the session request. See [Codewhale's editor setup](https://github.com/codewhale-hq/Codewhale/blob/v0.10.3/docs/ACP.md).

Codewhale's built-in file tools use the host filesystem. Use the Mirage MCP tools
to read and write files in the Mirage workspace.

## Set up

<Steps>
  <Step title="Install the CLI">
    <CodeGroup>
    ```bash uv
    uv tool install mirage-ai
    ```
    ```bash npm
    npm install -g @struktoai/mirage-cli
    ```
    </CodeGroup>
  </Step>
  <Step title="Create the workspace">
    ```yaml workspace.yaml
    mounts:
      /:
        vfs: ram
        mode: write
    ```
    ```bash
    mirage workspace create workspace.yaml --id demo
    ```
  </Step>
  <Step title="Install the agent">
    Install the agent's ACP command from the [agents](#agents) table, such as
    Claude's:
    ```bash
    npm install -g @agentclientprotocol/claude-agent-acp
    ```
  </Step>
  <Step title="Add the agent to the client">
    <CodeGroup>
    ```json Zed
    {
      "agent_servers": {
        "Claude on Mirage": {
          "type": "custom",
          "command": "mirage",
          "args": ["acp", "-w", "demo", "--", "claude-agent-acp"],
          "env": {}
        }
      }
    }
    ```
    ```json JetBrains
    {
      "agent_servers": {
        "Claude on Mirage": {
          "command": "mirage",
          "args": ["acp", "-w", "demo", "--", "claude-agent-acp"]
        }
      }
    }
    ```
    </CodeGroup>
    Give the full path of `mirage` when the client does not start it from a
    shell that has it on its `PATH`.
  </Step>
</Steps>

## Example

Fix a bug in a workspace file from Zed, with Claude.

<Steps>
  <Step title="Put a file in the workspace">
    ```bash
    mirage shell -w demo -c 'mkdir -p /project && printf "def add(a, b):\n    return a - b\n" > /project/calc.py'
    ```
  </Step>
  <Step title="Ask in Zed">
    Open any folder, start a **Claude on Mirage** thread from the set up
    above, and ask:

    ```text
    Fix the bug in /project/calc.py so add returns the sum.
    ```

    Claude reads the file with the workspace's `read` tool and changes it
    with `edit`. The folder open in Zed stays as it was.
  </Step>
  <Step title="Check the workspace">
    ```bash
    mirage shell -w demo -c 'cat /project/calc.py'
    ```
    ```text
    def add(a, b):
        return a + b
    ```
  </Step>
</Steps>

## Options

```bash
mirage acp [-w ID | -c CONFIG] [-s SESSION] [--root PATH] -- AGENT...
```

| Option | Default | Means |
| --- | --- | --- |
| `-w`, `--workspace` | | The workspace to use. |
| `-c`, `--config` | `.mirage/workspace.yaml` | A config to create the workspace from, as `mirage mcp` takes one. |
| `-s`, `--session` | the workspace's default | The session the agent's files and tools act as, under its [profile](/home/configuration/session). |
| `--root` | `/` | The workspace path the client's project folder stands for. |

An agent asks for a file by its absolute path on the client. A path inside
the session's folder lands under `--root`; any other absolute path is read
as a workspace path. Put `--` before the agent's command so its options stay
its own. The exit status is the agent's, and 127 when there is no such
command.

## How it behaves

- A request the agent makes of the client, other than a file read or write,
  reaches the client unchanged, as does everything the client sends.
- An MCP server of the client's named `mirage` is replaced by the
  workspace's; the others stay.
- A config with no `workspace_id` makes a workspace that lives as long as
  `mirage acp` does, as with `mirage mcp`.
