Walks lets a VFS hand over a whole folder tree in one call, instead of one
listing per folder. Override `read_tree` to make `find`, `du`, `ls -R` and
`tree` cheaper.

## Supported commands

These commands ask the VFS for the whole tree. The others list each folder as
usual.

| Command | What happens |
| --- | --- |
| `find`, `du`, `ls -R`, `tree`, `grep -r`, `rg` on a folder | Asks for the whole tree in one call. |
| `cp -r` inside the mount, when the VFS overrides `copy` | Asks for the whole tree in one call. |
| `find -maxdepth N`, `tree -L N`, `rg --max-depth N` | Lists each folder. |
| `ls` without `-R` | Lists the folder. |
| `cp -r` to another mount | Lists each folder. |

Every walk stops at its command's
[`walk_limit`](/home/integration/search#walk_limit) on the mount, whether the
VFS handed over the tree or Mirage listed each folder.

## For VFS authors

A custom VFS overrides `read_tree` when its service can list a whole tree in
one call. It returns `None` (TypeScript: `null`) when it cannot, and Mirage
lists each folder with `readdir`. TypeScript names methods in camelCase
(`readTree`).

### `read_tree`

Every file and folder below one folder. This example extends `NotesVFS` from
[Adding a New VFS](/home/setup/vfs/new#write-one). Its pages
sit in one folder, so one `readdir` is the whole tree. A service with nested
folders would return them all from one recursive call.

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    from mirage import FileStat, PathSpec

    from notes import NotesVFS


    class TreeNotesVFS(NotesVFS):
        async def read_tree(self, path: PathSpec) -> dict[str, FileStat] | None:
            return {entry.name: entry for entry in await self.readdir(path)}
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import type { FileStat, PathSpec } from '@struktoai/mirage-node'
    import { NotesVFS } from './notes.ts'

    export class TreeNotesVFS extends NotesVFS {
      override async readTree(path: PathSpec): Promise<Map<string, FileStat> | null> {
        return new Map((await this.readdir(path)).map((entry) => [entry.name, entry]))
      }
    }
    ```
  </Tab>
</Tabs>

`path` is the folder. For a path that is not a folder, raise what `readdir`
raises.

Return every file and folder below `path`, keyed by its path below it
(`guides`, `guides/start.md`), each with the `FileStat` that `stat` gives.
Mirage walks it without listing any folder. With this example, `find /notes`,
`du -a /notes`, `ls -R /notes` and `tree /notes` call `read_tree` once.
`find /notes -maxdepth 1` lists the folder instead.

### `walk_limit`

To stop paging early, `read_tree` and `readdir` take `limit` (TypeScript:
`handed.limit`):

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    async def read_tree(self, path: PathSpec, limit: int | None = None) -> dict[str, FileStat] | None: ...
    async def readdir(self, path: PathSpec, limit: int | None = None) -> list[FileStat] | DirListing: ...
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    readTree(path: PathSpec, handed?: Handed): Promise<Map<string, FileStat> | null>
    readdir(path: PathSpec, handed?: Handed): Promise<readonly FileStat[] | DirListing>
    ```
  </Tab>
</Tabs>

`limit` is how many entries the walk can still use, or `None` (TypeScript:
`undefined`) when nothing caps the walk.

- Past `limit` entries, or for a folder too large to send in one call,
  `read_tree` returns `None`. Mirage then lists each folder and stops calling
  `readdir` once the limit is spent.
- Past `limit` entries, `readdir` returns what it holds as a `DirListing` with
  `partial=True`. Mirage does not keep it as the whole folder.
- A `read_tree` that ignores `limit` returns the whole tree, and the command
  keeps what fits.
