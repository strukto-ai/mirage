A VFS can answer some commands from its service's search, queries or metadata
instead of reading files. `head` can show the first lines without downloading
the whole file.

Each capability is a set of methods a VFS overrides, and the commands they make
cheaper:

| Capability | Methods | Commands |
| --- | --- | --- |
| [Search](/home/integration/search) | `files_containing`, `lines_containing` | `grep`, `rg` |
| [Lines](/home/integration/lines) | `first_lines`, `last_lines`, `line_count`, `follow` | `head`, `tail`, `wc -l`, `tail -f` |
| [Checksums](/home/integration/checksums) | `checksum` | `md5sum`, `sha256sum` and other hash commands |
| [Walks](/home/integration/walks) | `read_tree` | `find`, `du`, `ls -R`, `tree` |

Built-in VFSs already implement these where their service allows. A
[custom VFS](/home/setup/vfs/new) overrides the methods it can answer.
Mirage still handles options and output, and reads or lists files whenever a
method returns `None`.

## Built-in VFSs

These tables list which built-in VFSs answer each command from their service.
A command or VFS not listed reads the files as usual.

- A search a VFS does not speed up reads the files itself, up to the mount's
  [`walk_limit`](/home/integration/search#walk_limit), and says so on stderr
  when it stops there. It never leaves a file out silently. Some patterns and
  flags always read every file; see
  [Search](/home/integration/search#files_containing).
- A file the service's search leaves out is not read, so `grep` does not
  print a match in it. To read every file instead, set the mount's
  [`walk_limit`](/home/integration/search#walk_limit) to `-1` on `"@all"`.
