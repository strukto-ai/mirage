Search lets a VFS answer `grep` and `rg` from its service's search instead of
reading every file. Override `files_containing` and `lines_containing` to make
`grep` and `rg` cheaper.

## Supported commands

These commands ask the service where the text may be. Mirage still matches
each line itself, so the output is the same as reading every file.

| Command | What happens |
| --- | --- |
| `grep -r`, `grep -R`, `grep -d recurse`, `rg` on a folder | Asks the service which files may hold the text, and reads only those. A file named on the line is always read. |
| `grep -rw`, `grep -rx`, `rg -w`, `rg -x` | Asks the same way, for the whole word. |
| `grep -ri`, `rg -i`, `rg -S` with a lowercase pattern | Asks with case ignored, except in the cases below. |
| `grep` or `rg` on one file, alone or with `-c`, `-l`, `-q`, `-o`, `-m N`, `-i`, `-w`, `-x`, `-F`, `-r` or `grep -L` | Asks the service for the lines that may hold the text and matches only those. The file is never read. |
| `grep` or `rg` on one file with `-n`, `-b`, `-A N`, `-B N`, `-C N`, more than one pattern (`-e a -e b`, `'a\|b'`), `grep -z`, `rg --null-data`, `rg --column`, `rg --vimgrep` or `rg -U` | Asks for the lines, and reads the file only when they hold a match. |
| `rg -i`, or `rg -S` with a lowercase pattern, when the text has a `k`, an `s` or a non-ASCII letter | Asks once per way to write its case, since `rg` also matches `k` to the Kelvin sign `K` and `s` to `ſ`. `rg -i café` asks for `café`, `CAFÉ` and 14 other spellings. Reads every file when there are more than 16. |
| `grep -i` when the text has a non-ASCII letter, or in a UTF-8 locale an `i`, `k` or `s` | Reads every file. |
| `-v` or `-f FILE` | Reads every file. |
| A pattern with no plain text of 3 or more characters, other than a `-w` or `-x` word | Reads every file. `grep 'refund.*2026'` asks, since every match contains `refund`. |
| `rg` with `--passthru`, `--files-without-match`, `--json`, `--stats`, `-z`, `-L`, `--pre COMMAND`, `-E ENCODING`, or `-c` or `--count-matches` with `--include-zero` | Reads every file. |

- A pattern outside **Searches**, or a VFS not listed, reads every file.
- A search that can miss a match leaves out a file that holds the text, so
  `grep` does not print it.
- On the VFSs from Google Drive to GitHub, a mount `walk_limit` of `-1` turns
  the service's search off, so every file is read and no match is missed. See
  [`walk_limit`](#walk_limit).

## `walk_limit`

`walk_limit` caps how many files one command walks under a folder
(TypeScript: `walkLimit`). It is a field of
[`command_limits`](/home/limits#command-output). A mount's `"@all"` entry, else
the workspace's, sets the mount's own `walk_limit`. An entry named for one
command, such as `find`, changes only how far that command walks.

| Value | Searches and listings | Globs, copies and removals |
| --- | --- | --- |
| `-1` | Walk every file | Never refused |
| `0` | Read or list nothing under a folder | Always refused |
| A positive number | Stop after that many files | Refused above that many files |

It is 1000 unless the VFS starts at another value or a `command_limits` entry
sets it. Built-in VFSs start at 1000, or 5000 on GitHub, where each file is one
request, and 10000 on disk, RAM and OPFS.

Each command does this past the limit:

| Command | Past the limit |
| --- | --- |
| `grep -r`, `rg` | Stops. It keeps what it printed, prints `grep: <folder>: stopped after <N> files (walk_limit); narrow the path` and exits 2. |
| `git grep` | Stops. It keeps what it printed, prints `fatal: stopped after <N> files (walk_limit); narrow the pathspec` and exits 128. |
| `find`, `ls -R`, `du`, `tree`, `getfattr -R` | Stops listing. It keeps what it printed, prints the same `stopped after` line and exits 1 (`tree`: 2). |
| `git status`, `git add`, `git commit -a`, `git diff`, `git checkout`, `git reset`, `git rm` | Refused before it changes anything. It prints `fatal: more than <N> files in the work tree (walk_limit)` and exits 128. `git add`, `git diff` and `git rm` given paths walk only those, and a file named outright costs nothing. |
| A glob, such as `cat /notes/*` | Refused, so the command does not run. It prints `cat: Argument list too long` and `cat: /notes/*: matches more than <N> files (walk_limit); narrow the path`, and exits 126. |
| `tar -c`, `zip -r`, `cp -r`, `rm -r`, `chmod -R`, `chown -R`, `chgrp -R`, `mv` to another mount, `diff -r`, `gzip -r` | Refused before it touches anything. It prints `tar: more than <N> files in scope (walk_limit); narrow the path` and exits 1. Within the limit, the VFS can still refuse through [`before_full_walk`](#before_full_walk). |

- A search counts only the files it reads, so a file the service rules out
  costs nothing. A listing counts every entry it lists, folders included.
- A walk cut short exits as it does when some files could not be read, so a
  script treats it as one with an error.
- A glob, a copy and a removal are refused instead of cut short, since running
  on part of what they name would look complete later. A glob in a `for` list
  stops the line with
  `bash: /notes/*: matches more than <N> files (walk_limit); narrow the path`.
- A walk that crosses into another mount counts that mount's files against its
  own limit, and names that mount's folder where it stops.
- Codex's `fs/walk` ([exec-server](/home/agents/codex#exec-server-forward))
  lists the same way and returns `truncated: true` where it stops.

### Example: Raise the Limit on Slack

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from mirage import Limit, MountMode, Workspace
    from mirage.vfs.slack import SlackConfig, SlackVFS

    slack = SlackVFS(
        config=SlackConfig(
            token=os.environ["SLACK_BOT_TOKEN"],
            search_token=os.environ["SLACK_USER_TOKEN"],
        )
    )
    ws = Workspace(
        {"/slack": (slack, MountMode.READ, {"@all": Limit(walk_limit=5000)})},
        mode=MountMode.READ,
    )
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript

      searchToken: process.env.SLACK_USER_TOKEN,
    })
    const ws = new Workspace(
      { '/slack': [slack, MountMode.READ, { '@all': new Limit({ walkLimit: 5000 }) }] },
      { mode: MountMode.READ },
    )
    ```
  </Tab>
  <Tab title="YAML" icon="file-code">
    ```yaml
    mounts:
      /slack:
        vfs: slack
        mode: read
        config:
          token: ${SLACK_BOT_TOKEN}
          search_token: ${SLACK_USER_TOKEN}

          "@all":
            walk_limit: 5000
    ```

  </Tab>
</Tabs>

`grep -rw refund /slack/channels/` then asks Slack's search which days mention
`refund` and reads only those. `grep -r refund /slack/channels/`, which Slack
cannot narrow, reads the first 5000 days and stops there.

## For VFS authors

A custom VFS overrides the methods its service can answer. A method returns
`None` (TypeScript: `null`) when it cannot answer, and Mirage reads the files.
TypeScript names methods and arguments in camelCase (`files_containing` is
`filesContaining`) and passes keyword arguments in an `opts` object. The
examples extend `NotesVFS` from
[Adding a New VFS](/home/setup/vfs/new#write-one).

### `files_containing`

Which files under a folder may contain a text. The folder searches in
[Supported commands](#supported-commands) call it.

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    from mirage import PathSpec
    from mirage.utils.key_prefix import mounted_path

    from notes import NotesVFS


    class SearchableNotesVFS(NotesVFS):
        async def files_containing(
            self, path: PathSpec, text: str, *, whole_word: bool, ignore_case: bool
        ) -> list[PathSpec] | None:
            if ignore_case:
                return None
            return [
                mounted_path(path, "/" + name)
                for name, page in self.pages.items()
                if text in page
            ]
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import type { PathSpec } from '@struktoai/mirage-node'
    import { mountedPath } from '@struktoai/mirage-core/utils/key_prefix'
    import { NotesVFS } from './notes.ts'

    export class SearchableNotesVFS extends NotesVFS {
      override async filesContaining(
        path: PathSpec,
        text: string,
        opts: { wholeWord: boolean; ignoreCase: boolean },
      ): Promise<PathSpec[] | null> {
        if (opts.ignoreCase) return null
        return Object.entries(this.pages)
          .filter(([, page]) => page.includes(text))
          .map(([name]) => mountedPath(path, `/${name}`))
      }
    }
    ```
  </Tab>
</Tabs>

`path` is the folder the command walks. `text` is a text every match contains.
It is asked once per text, so `grep -r -e refund -e order` asks twice.
`whole_word` is `True` for `-w` or `-x`, when `text` must match as a whole
word. `ignore_case` is `True` for `-i`, and for `rg -S` with a lowercase
pattern. Under `rg -i`, a text with a `k`, an `s` or a non-ASCII letter is
asked once per spelling with `ignore_case` `False`.

Return the files that may contain `text`. Mirage reads only these, so include
every file that could match. An empty list reads no file under `path`.
`mounted_path` turns a name below the mount into a path. With this example,
`grep -rn mirage /notes` reads only the pages that contain `mirage`.

### `lines_containing`

Which lines of one file may contain a text. The one-file searches in
[Supported commands](#supported-commands) call it.

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import io

    from mirage import PathSpec

    from notes import NotesVFS


    class LineSearchNotesVFS(NotesVFS):
        async def lines_containing(
            self, path: PathSpec, text: str, *, ignore_case: bool
        ) -> bytes | None:
            page = self.page(path)
            if ignore_case or "\0" in page:
                return None
            lines = io.StringIO(page, newline="\n").readlines()
            return "".join(line for line in lines if text in line).encode()
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import type { PathSpec } from '@struktoai/mirage-node'
    import { NotesVFS } from './notes.ts'

    export class LineSearchNotesVFS extends NotesVFS {
      override async linesContaining(
        path: PathSpec,
        text: string,
        opts: { ignoreCase: boolean },
      ): Promise<Uint8Array | null> {
        const page = this.page(path)
        if (opts.ignoreCase || page.includes('\0')) return null
        const lines = page.split(/(?<=\n)/).filter((line) => line.includes(text))
        return new TextEncoder().encode(lines.join(''))
      }
    }
    ```
  </Tab>
</Tabs>

`path` is the file the command would read. `text` is a text every match
contains, asked once per text. `ignore_case` is `True` for `-i`, and for
`rg -S` with a lowercase pattern.

Return the lines that may contain `text`, in their order, as bytes or a stream
of byte chunks. Empty bytes means no match, and the file is not read. Return
`None` for a file that may hold a NUL byte. With this example,
`grep mirage /notes/todo.txt` and `grep -c mirage /notes/todo.txt` read
nothing. `grep -n mirage /notes/todo.txt` reads the page, since it holds a
match.

### `before_full_walk`

Whether a command may copy, compare, change or remove every file under a
folder. `tar -c`, `zip -r`, `cp -r`, `rm -r`, `chmod -R`, `chown -R`,
`chgrp -R`, `gzip -r`, `diff -r` and `mv` to another mount ask it before they
touch anything.

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    from mirage import PathSpec

    from notes import NotesVFS


    class GuardedNotesVFS(NotesVFS):
        async def before_full_walk(self, path: PathSpec, *, files: int | None = None) -> None:
            if files is not None and files > 100:
                raise ValueError("more than 100 pages; narrow the path")
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import type { PathSpec } from '@struktoai/mirage-node'
    import { NotesVFS } from './notes.ts'

    export class GuardedNotesVFS extends NotesVFS {
      override async beforeFullWalk(_path: PathSpec, files: number | null): Promise<void> {
        if (files !== null && files > 100) throw new Error('more than 100 pages; narrow the path')
      }
    }
    ```
  </Tab>
</Tabs>

`path` is the folder the command is about to read, change or remove in full.
`files` is how many files the session sees under `path`, or `None` when Mirage
could not count them. TypeScript passes it as the second argument.

Return to let the command run. Raise `ValueError` (TypeScript: reject) to
refuse it: the command prints `<command>: <message>` and exits 1. Mirage
refuses more than the command's [`walk_limit`](#walk_limit) files before it
asks, so the default lets the walk run. With this example,
`diff -r /notes /backup` on a folder of 150 pages prints
`diff: more than 100 pages; narrow the path` and exits 1.
