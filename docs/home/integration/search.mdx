Mirage connects your service's search API to `grep` and `rg`. Agents use
familiar commands while the backend finds relevant files or rows, avoiding
unnecessary downloads.

## Example: search a RAG knowledge base

With a Chroma knowledge base mounted at `/knowledge/`:

```bash
grep -r 'refund' /knowledge/
```

Mirage asks Chroma which document chunks contain `refund`, then reads the
matching documents and applies grep. Adding `-n` prints the original line
numbers:

```bash
grep -rn 'refund' /knowledge/
```

This searches for exact text. For semantic search, use
[`chroma-query`](/python/vfs/chroma#vector-search).

## Connect your own search

Override these methods on your VFS. Mirage handles the command options and
output formatting; you do not need a separate implementation for `grep -n`,
`grep -c` or each other option.

Mirage checks the candidates with the command's matcher. Include every
possible match; return `None` in Python or `null` in TypeScript when your
search cannot answer, and Mirage reads the files normally.

### `files_containing`

Return paths of files that may contain the text. Used by `grep -r`, `grep -R`,
`grep -d recurse` and `rg` when searching directories. The TypeScript name is
`filesContaining`.

| Command or option | How Mirage uses your retrieval |
| --- | --- |
| Plain recursive search | Read candidate files and match their contents. |
| Line numbers (`-n`) or byte offsets (`-b`) | Read candidate files and calculate the original positions. |
| Context (`-A`, `-B`, `-C`; grep's `-NUM`) | Read candidate files and include surrounding lines. |
| Counts, filenames, match-only output or limits (`-c`, `-l`, `-q`, `-o`, `-m`) | Apply the options while reading candidate files. |
| Case or word matching (`-i`, `-w`, `-x`; rg's `-S`) | Retrieve candidates for the requested matching mode. |
| Multiple patterns (`-e`) | Combine candidate files from the search terms. |
| Nonmatching lines (`-v`) or patterns from a file (`-f`) | Use normal file reads instead of retrieval. |

For example, `grep -rn 'refund' /knowledge/` uses your retrieval to choose
documents, then Mirage reads them and adds line numbers.

### `lines_containing`

Return candidate lines from one file, in their original order. Used by
`grep` and `rg`, including during directory searches. The TypeScript name is
`linesContaining`.

| Command or option | How Mirage uses your retrieval |
| --- | --- |
| Plain search with one term | Match the returned lines directly. |
| Line numbers (`-n`) or byte offsets (`-b`) | Check for candidates, then read the original file to calculate positions. |
| Context (`-A`, `-B`, `-C`; grep's `-NUM`) | Check for candidates, then read the original file for surrounding lines. |
| Counts, filenames, match-only output or limits (`-c`, `-l`, `-q`, `-o`, `-m`) | Apply the options to returned lines for one term, without positions or context. |
| Case or word matching (`-i`, `-w`, `-x`; rg's `-S`) | Retrieve candidate lines, then apply the exact matching rules. |
| Multiple patterns (`-e`) | Check the terms; read the original file when candidates need combining. |
| rg's `--column`, `--vimgrep` or multiline searches | Check for candidates, then read the original file. |
| Nonmatching lines (`-v`) or patterns from a file (`-f`) | Use normal file reads instead of retrieval. |

For example, `grep 'refund' tickets.jsonl` can search the returned rows
directly. Adding `-n` requires reading the original file because snippets
alone do not provide original line numbers.

Both tables assume your search can answer the requested text. Some modes,
such as rg's `--json`, `--stats`, preprocessing and compressed-file search,
use normal file reads instead.

## Enable cloud content search

Some backends, such as Dropbox and Google Drive, have a `content_search`
mount option. Set it to `true` to let Mirage use the provider's content index.
It defaults to `false`, which uses ordinary file reads. In TypeScript config
objects, the option is named `contentSearch`.

For example, with content search enabled on Dropbox:

```bash
grep -rw 'refund' /dropbox/policies/
```

The `-w` requests whole-word matches, which Dropbox's index supports. See the
[backend's docs](/python/vfs/dropbox) for its search coverage and setup.
