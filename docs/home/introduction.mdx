- **[Virtual filesystem](/home/setup/vfs).** Virtualize S3, Drive, Slack, databases and more under one root, accessible with `ls`, `cat`, `grep` and `find`.
- **[Virtual CLIs](/home/setup/clis).** Give agents commands such as `git`, `slack` and `ntn`, with credentials configured per tool.
- **[Dynamic runtimes](/home/setup/runtime/overview).** Route commands to in-process, sandboxed or remote runtimes, independently of where the data lives.
- **[Virtual shell](/home/core/shell).** Compose files, CLIs and runtimes with pipes, redirects, variables and jobs.
- **[Agent profiles](/home/policy/overview).** Choose what each agent can run and which files and folders it can see.
- **[Policy engine](/home/policy/policies).** Apply rules to commands, file operations and session changes before they run.
- **Authentication.** Connect credentials from environment variables, dotenv, AWS Secrets Manager or a custom source.
- **[Notifications](/home/events).** Turn changes in connected services into events agents can react to.

<h2 className="text-2xl font-bold mt-16 mb-6">Try Mirage</h2>

Create a workspace with an in-memory filesystem, write a file, and search it.
This example needs no credentials or external services.

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    Run inside an async function or a Jupyter notebook:

    ```python
    from mirage import MountMode, RAMVFS, Workspace

    ws = Workspace({"/data": RAMVFS()}, mode=MountMode.WRITE)
    await ws.shell('echo "hello mirage" > /data/hello.txt')
    result = await ws.shell("grep -n hello /data/hello.txt")
    print(await result.stdout_str(), end="")
    await ws.close()
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, RAMVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace({ '/data': new RAMVFS() }, { mode: MountMode.WRITE })
    await ws.shell('echo "hello mirage" > /data/hello.txt')
    const result = await ws.shell('grep -n hello /data/hello.txt')
    process.stdout.write(result.stdoutText)
    await ws.close()
    ```
  </Tab>
  <Tab title="CLI" icon="terminal">
    [Install the CLI](/home/install#cli), then run:

    ```bash
    cat > workspace.yaml <<'EOF'
    mounts:
      /data:
        vfs: ram
        mode: write
    EOF

    mirage workspace create workspace.yaml --id hello
    mirage shell -w hello -c 'echo "hello mirage" > /data/hello.txt'
    mirage shell -w hello -c 'grep -n hello /data/hello.txt'
    ```
  </Tab>
</Tabs>

The search prints:

```text
1:hello mirage
```

`/data` is a path inside Mirage. Replace RAM with a [supported VFS](/home/setup/vfs)
to use the same commands on your own data. Continue with the
[Python](/python/quickstart) or [TypeScript](/typescript/quickstart) quickstart.

<h2 className="text-2xl font-bold mt-16 mb-6">Real use case: run a Slack report and save it to Redis</h2>

<div className="max-w-none text-[15px] leading-7 mb-4">
  <p className="my-0">
    An agent can read a script shared in Slack, run it, save the result to Redis, and post a reply. Here RAM, <Icon icon="database" /> Redis and <Icon icon="slack" /> Slack share one root, <code>python3</code> runs on Monty inside the workspace, and <code>slack</code> is a virtual CLI.
  </p>
  <p className="mt-3 mb-0">
    Set up <a href="/home/setup/slack">Slack credentials</a> and a Redis connection first. Set <code>SLACK_BOT_TOKEN</code> and <code>REDIS_URL</code>, then replace the example channel and file path with your own. Install the Redis and Monty extras: <code>uv add "mirage-ai[redis,monty]"</code> in Python, or <code>npm install @struktoai/mirage-node redis @pydantic/monty</code> in TypeScript.
  </p>
</div>

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    Run inside an async function or a Jupyter notebook:

    ```python
    import os

    from mirage import RAMVFS, MountMode, Workspace
    from mirage.commands.cli.builtin.slack import SLACK
    from mirage.vfs.redis import RedisVFS
    from mirage.vfs.slack import SlackConfig, SlackVFS

    token = os.environ["SLACK_BOT_TOKEN"]

    ws = Workspace(
        {
            "/tmp": (RAMVFS(), MountMode.EXEC),
            "/redis": (RedisVFS(url=os.environ["REDIS_URL"]), MountMode.WRITE),
            "/slack": (SlackVFS(SlackConfig(token=token)), MountMode.EXEC),
        },
        runtimes=["monty", "workspace"],
    )
    ws.register_cli("slack", SLACK, {"token": token})

    await ws.shell("grep -rln session /redis /tmp")
    await ws.shell("python3 /slack/channels/general__C04KEPWF6V7/2026-04-04/files/report__F07Q2.py > /redis/report.txt")
    await ws.shell('slack send-message --channel C04KEPWF6V7 --text "report is up"')
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, RAMVFS, RedisVFS, SLACK, SlackVFS, Workspace } from '@struktoai/mirage-node'

    const token = process.env.SLACK_BOT_TOKEN!

    const ws = new Workspace(
      {
        '/tmp': [new RAMVFS(), MountMode.EXEC],
        '/redis': [new RedisVFS({ url: process.env.REDIS_URL! }), MountMode.WRITE],
        '/slack': [new SlackVFS({ token }), MountMode.EXEC],
      },
      { runtimes: ['monty', 'workspace'] },
    )
    ws.registerCli('slack', SLACK, { token })

    await ws.shell('grep -rln session /redis /tmp')
    await ws.shell('python3 /slack/channels/general__C04KEPWF6V7/2026-04-04/files/report__F07Q2.py > /redis/report.txt')
    await ws.shell('slack send-message --channel C04KEPWF6V7 --text "report is up"')
    ```
  </Tab>
  <Tab title="CLI" icon="terminal">
    ```bash
    cat > workspace.yaml <<'EOF'
    runtimes:
      - monty
      - workspace
    mounts:
      /tmp:
        vfs: ram
        mode: exec
      /redis:
        vfs: redis
        mode: write
        config:
          url: ${REDIS_URL}
      /slack:
        vfs: slack
        mode: exec
        config:
          token: ${SLACK_BOT_TOKEN}
    clis:
      slack:
        cli: slack
        config:
          token: ${SLACK_BOT_TOKEN}
    EOF

    mirage workspace create workspace.yaml --id demo
    mirage shell -w demo -c 'grep -rln session /redis /tmp'
    mirage shell -w demo -c 'python3 /slack/channels/general__C04KEPWF6V7/2026-04-04/files/report__F07Q2.py > /redis/report.txt'
    mirage shell -w demo -c 'slack send-message --channel C04KEPWF6V7 --text "report is up"'
    ```
  </Tab>
</Tabs>

<div className="max-w-none text-[15px] leading-7 mt-4 mb-2">
  <ol className="my-0">
    <li><code>grep -rln session /redis /tmp</code> searches Redis and RAM in one pass and lists the files that mention <code>session</code>.</li>
    <li><code>python3</code> runs a script someone shared in Slack's <code>#general</code>. Monty runs it inside Mirage, with no host files or network, and <code>&gt;</code> writes its output into Redis. The path is an example: list the day's <code>files/</code> folder for your file's real name.</li>
    <li><code>slack send-message</code> is a virtual CLI: Mirage answers it with the token you registered, with nothing installed. It is found by name, so <code>man</code>, <code>type</code> and <code>which</code> see it like any other program.</li>
  </ol>

<h2 className="text-2xl font-bold mt-16 mb-6">FAQ</h2>

<AccordionGroup>
  <Accordion title="Do I need FUSE?">
    No. Mirage runs the workspace in-process: <code>ws.shell(...)</code> parses and dispatches commands without mounting anything on the host. FUSE is an optional surface if you also want host tools (editors, language servers, <code>rg</code>) to see the workspace.
  </Accordion>
  <Accordion title="Where does the shell run? Is it really bash?">
    The shell runs in your Mirage process: a tree-sitter bash parser plus an executor that routes each command to the mount that owns its paths. There is no <code>/bin/bash</code> underneath. Common Unix commands work (<code>ls</code>, <code>cat</code>, <code>grep</code>, <code>find</code>, <code>head</code>, <code>wc</code>, <code>jq</code>, ...) with pipes, redirects, globs, and <code>&&</code>/<code>||</code>. <code>python3</code>, <code>node</code> and other programs go to the <a href="/home/setup/runtime/overview">runtime</a> that captures them.
  </Accordion>
  <Accordion title="Is it sandboxed?">
    The shell only sees your mounts. The default runtimes run inside Mirage with no host files or network: Monty takes <code>python3</code> in a pool of local worker processes, and QuickJS takes <code>node</code> in-process. Host and sandbox runtimes (<code>local</code>, Docker, E2B, Daytona, SSH) have their own files and network; see <a href="/home/setup/runtime/overview#files">what each runtime reaches</a>.
  </Accordion>
  <Accordion title="What about latency and cost?">
    Backend-bound. <code>cat /s3/...</code> is one GetObject; <code>find /postgres/...</code> is a SQL query. Reads go through the workspace cache: under the default <code>read: bounded</code> a repeat read within the mount's <code>ttl</code> makes no backend call, and under <code>read: fresh</code> it costs one metadata check (and a download if the file changed).
  </Accordion>
  <Accordion title="Hosted or self-hosted?">
    Self-hosted. Mirage is a library plus a thin local daemon. The daemon lives in your process or sandbox; data only leaves your network if a mount you configured already does (e.g. an S3 read).
  </Accordion>
  <Accordion title="Which agent frameworks are supported?">
    Anything that exposes a shell tool: Claude Code, Codex / OpenAI Agents SDK, Cursor, OpenHands, Pydantic deepagents. Direct SDK integrations live under <a href="/python/agents">Python agents</a> and <a href="/typescript/agents">TypeScript agents</a>.
  </Accordion>
  <Accordion title="Python or TypeScript?">
    Both. The two SDKs share the same <code>Workspace</code> API, commands and CLIs, and most mounts. Runtimes differ: <code>wasi</code> is Python-only and <code>pyodide</code> TypeScript-only; see the <a href="/home/setup/runtime/overview">runtime table</a>. TypeScript ships <code>@struktoai/mirage-node</code> for Node and <code>@struktoai/mirage-browser</code> for browsers.
  </Accordion>
  <Accordion title="What if a VFS I want isn't supported yet?">
    VFS types are pluggable. The <a href="/python/vfs/new">"Add a VFS"</a> guide walks through the read/write/stat surface a new backend implements. PRs welcome.
  </Accordion>
</AccordionGroup>
