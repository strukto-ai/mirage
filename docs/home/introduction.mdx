Mirage is a virtual terminal for AI agents, with a unified virtual filesystem,
virtual CLIs and a router that picks where each command runs.

- **Composable.** The filesystem, CLIs, shell and compute are separate parts you
  put together. Run the terminal in your app or a FastAPI or Fastify server, and
  send programs to a microVM or sandbox.
- **Scriptable.** A scriptable policy engine, written in code or as scripts, hides files per
  agent profile, refuses commands, asks for approval, caps output and routes
  commands to runtimes.
- **Durable.** Each part can live in your own storage: sessions in RAM, and the
  observer's history of every command and each shell job's output in Redis.

## Architecture

<img noZoom src="/images/mirage-overview-dark.svg" alt="Mirage connects agents to files, tools and runtimes, with access controls and notifications" className="hidden dark:block w-full" />

- **[Virtual filesystem](/home/setup/vfs).** Virtualize S3, Drive, Slack, databases and more under one root, accessible with `ls`, `cat`, `grep` and `find`.
- **[Virtual CLIs](/home/setup/clis).** Give agents commands such as `git`, `slack` and `ntn`, with credentials configured per tool.
- **[Mirage shell](/home/core/shell).** Compose files, CLIs and runtimes with pipes, redirects, variables and jobs.
- **[Agent profiles](/home/profiles).** Choose what each agent can run and which files and folders it can see.
- **[Policy engine](/home/policy/policies).** Apply rules to commands, file operations and session changes before they run.
- **[Runtimes](/home/setup/runtime/overview).** Run code in the workspace, on your host, in a sandbox or on a remote machine.
- **[Service credentials](/home/authentication).** Connect credentials from environment variables, dotenv, AWS Secrets Manager or 1Password.
- **[Notifications](/home/notifications).** Notify agents about external file or directory changes in the virtual filesystem.

## Benefits

- **Fewer tokens.** One shell interface replaces a tool per service. Across 200
  tasks, it used 52% fewer tokens per task than MCP tools
  ([AgentVFS](https://agentvfs.org/blogs/agentvfs-1)).
- **Cloud search through shell commands.** With Chroma at `/knowledge/`,
  `grep -r refund /knowledge/` asks Chroma which documents match, then reads
  only those. A backend without search reads its files. See
  [Search](/home/integration/search).
- **Full control.** Choose which files each agent can see and which commands it
  can run with [agent profiles](/home/profiles) and
  [policies](/home/policy/overview).

## Try Mirage

[Install Mirage](/home/install), then create a workspace with an in-memory
filesystem, write a file with a POSIX-style call, and search it with the shell.
No credentials or services are needed.

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import asyncio

    from mirage import MountMode, RAMVFS, Workspace


    async def main() -> None:
        ws = Workspace({"/data": RAMVFS()}, mode=MountMode.WRITE)
        await ws.vfs.write("/data/hello.txt", b"hello mirage\n")
        result = await ws.shell("grep -n hello /data/hello.txt")
        print(await result.stdout_str(), end="")
        await ws.close()


    asyncio.run(main())
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { MountMode, RAMVFS, Workspace } from '@struktoai/mirage-node'

    const ws = new Workspace({ '/data': new RAMVFS() }, { mode: MountMode.WRITE })
    await ws.vfs.write('/data/hello.txt', new TextEncoder().encode('hello mirage\n'))
    const result = await ws.shell('grep -n hello /data/hello.txt')
    process.stdout.write(result.stdoutText)
    await ws.close()
    ```
  </Tab>
  <Tab title="CLI" icon="terminal">
    [Install the CLI](/home/install#cli), then run:

    ```bash
    cat > workspace.yaml <<'EOF'
    mounts:
      /data:
        vfs: ram
        mode: write
    EOF

    mirage workspace create workspace.yaml --id hello
    echo "hello mirage" | mirage vfs write /data/hello.txt -w hello
    mirage shell -w hello -c 'grep -n hello /data/hello.txt'
    ```
  </Tab>
</Tabs>

The search prints:

```text
1:hello mirage
```

`/data` is a path inside Mirage. Replace RAM with a [supported VFS](/home/setup/vfs)
to use the same commands on your own data. Continue with the
[Python](/python/quickstart) or [TypeScript](/typescript/quickstart) quickstart.

## Example Use Cases

- **Respond to changes.** React to Slack replies or GitHub pushes through file notifications.
- **Search connected data.** Use `grep` for text search and `search` for semantic matches in vector stores.
- **Investigate traces.** Query Langfuse and Jaeger traces with `grep` and `jq`.

## FAQ

<AccordionGroup>
  <Accordion title="Do I need FUSE?">
    No. Agents can use workspace files through Mirage directly. Use <a href="/home/setup/fuse">FUSE</a> when host tools, such as editors or language servers, need to open those files.
  </Accordion>
  <Accordion title="Where does the shell run? Is it really bash?">
    Mirage provides a Bash-compatible shell in your application. It supports common commands, pipes, redirects, variables and jobs. See the <a href="/home/core/shell">shell guide</a> for supported behavior and differences from Bash.
  </Accordion>
  <Accordion title="Is it sandboxed?">
    The shell sees the files you mount. The default Monty and QuickJS runtimes cannot access host files or the network. Other runtimes have different access; see <a href="/home/setup/runtime/overview#files">runtime file and network access</a> before choosing one.
  </Accordion>
  <Accordion title="What about latency and cost?">
    Operations use the APIs of the services you connect, so their latency and usage charges apply.
  </Accordion>
  <Accordion title="Hosted or self-hosted?">
    Self-hosted. Run Mirage in your own application, server or sandbox, and connect the services you need.
  </Accordion>
  <Accordion title="Which agent frameworks are supported?">
    Any agent that can call a shell tool can use Mirage. See the <a href="/home/agents">agent integrations</a> for setup guides.
  </Accordion>
  <Accordion title="Python or TypeScript?">
    Both SDKs provide workspaces, shell commands and service integrations. Runtime availability differs; see the <a href="/home/setup/runtime/overview">runtime comparison</a>. Start with the <a href="/python/quickstart">Python</a> or <a href="/typescript/quickstart">TypeScript</a> quickstart.
  </Accordion>
  <Accordion title="What if a VFS I want isn't supported yet?">
    You can add a custom filesystem. See <a href="/python/vfs/new">Add a VFS</a> for the required API and examples.
  </Accordion>
</AccordionGroup>
