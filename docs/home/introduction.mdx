<h2 className="text-2xl font-bold mt-16 mb-6">Mirage in 30 Seconds</h2>

<div className="max-w-none text-[15px] leading-7 mb-4">
  <p className="my-0">
    Mount your sources, pick the runtimes, and register the CLIs. Here RAM, <Icon icon="database" /> Redis and <Icon icon="slack" /> Slack share one root, <code>python3</code> runs on Monty inside the workspace, and <code>slack</code> is a virtual CLI.
  </p>
</div>

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from mirage import RAMVFS, MountMode, Workspace
    from mirage.commands.cli.builtin.slack import SLACK
    from mirage.vfs.redis import RedisVFS
    from mirage.vfs.slack import SlackConfig, SlackVFS

    token = os.environ["SLACK_BOT_TOKEN"]

    ws = Workspace(
        {
            "/tmp": (RAMVFS(), MountMode.EXEC),
            "/redis": (RedisVFS(url=os.environ["REDIS_URL"]), MountMode.WRITE),
            "/slack": (SlackVFS(SlackConfig(token=token)), MountMode.EXEC),
        },
        runtimes=["monty", "workspace"],
    )
    ws.register_cli("slack", SLACK, {"token": token})

    await ws.shell("grep -rln session /redis /tmp")
    await ws.shell("python3 /slack/channels/general__C04KEPWF6V7/2026-04-04/files/report__F07Q2.py > /redis/report.txt")
    await ws.shell('slack send-message --channel C04KEPWF6V7 --text "report is up"')
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">

    ```typescript
    await ws.shell('slack send-message --channel C04KEPWF6V7 --text "report is up"')
    ```
  </Tab>
  <Tab title="CLI" icon="terminal">
    ```bash
    cat > workspace.yaml <<'EOF'
    runtimes:
      - monty
      - workspace
    mounts:
      /tmp:
        vfs: ram
        mode: exec
      /redis:
        vfs: redis
        mode: write
        config:
          url: ${REDIS_URL}
      /slack:
        vfs: slack
        mode: exec
        config:
          token: ${SLACK_BOT_TOKEN}
    clis:
      slack:
        cli: slack
        config:
          token: ${SLACK_BOT_TOKEN}
    EOF

    mirage workspace create workspace.yaml --id demo
    mirage shell -w demo -c 'grep -rln session /redis /tmp'
    mirage shell -w demo -c 'python3 /slack/channels/general__C04KEPWF6V7/2026-04-04/files/report__F07Q2.py > /redis/report.txt'
    mirage shell -w demo -c 'slack send-message --channel C04KEPWF6V7 --text "report is up"'
    ```

<h2 className="text-2xl font-bold mt-16 mb-6">What is Mirage?</h2>

<CardGroup cols={2}>
  <Card title="Virtual Filesystem" icon="folder" href="/home/vfs-matrix">
    S3, Google Drive, Slack, Gmail, Redis and the rest mount side by side under one root. An agent reaches all of them with the tools it already knows: <code>ls</code>, <code>grep</code>, <code>find</code>, <code>jq</code>.
  </Card>
  <Card title="Virtual CLIs" icon="wrench" href="/home/setup/clis">
    <code>git</code>, <code>gh</code>, <code>slack</code>, <code>ntn</code> and more are answered by Mirage itself, with nothing installed. One tool can be installed twice under two names, each with its own account.
  </Card>
  <Card title="Virtual Runtimes" icon="microchip" href="/home/setup/runtime/overview">
    Python, JavaScript and any other program go to a configured runtime: in-process, sandboxed or remote. Computation and storage change independently.
  </Card>
  <Card title="Mirage Shell" icon="terminal" href="/home/core/shell">
    One command line binds the filesystem, the CLIs and the runtimes, so pipes, redirects, variables, jobs and history work across all three.
  </Card>
  <Card title="Profiles" icon="robot" href="/home/policy/overview">
    <code>allow</code>, <code>ask</code> and <code>deny</code> govern commands and CLIs; <code>hide</code> and <code>show</code> govern paths. A hidden file is not just unreadable: it is absent.
  </Card>
  <Card title="Policy Engine" icon="scale-balanced" href="/home/policy/policies">
    A policy script refuses a dangerous action before it runs. The same stack gates every VFS call and session write, so neither a file nor a variable leaks.
  </Card>
  <Card title="Notifications" icon="bell" href="/python/watch">
    External changes arrive as events on the mount. A new Slack reply is a change to the chat file, so the agent reacts instead of rescanning the tree.
  </Card>
  <Card title="Authentication" icon="key">
    An environment variable can resolve to a credential in the environment, dotenv, AWS Secrets Manager, 1Password or Auth0.
  </Card>
</CardGroup>

<h4 className="text-lg font-bold mt-8 mb-2">Code</h4>

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    from agents import Runner
    from agents.run import RunConfig
    from agents.sandbox import SandboxAgent, SandboxRunConfig

    from mirage import Workspace
    from mirage.agents.openai_agents import MirageSandboxClient
    from mirage.commands.cli.builtin.linear import LINEAR
    from mirage.vfs.github import GitHubConfig, GitHubVFS
    from mirage.vfs.slack import SlackConfig, SlackVFS

    slack = SlackVFS(SlackConfig(token=os.environ["SLACK_BOT_TOKEN"]))
    github = GitHubVFS(
        GitHubConfig(token=os.environ["GITHUB_TOKEN"]),
        owner="strukto-ai",
        repo="mirage",
    )

    ws = Workspace({"/slack": slack, "/github": github})
    ws.register_cli("linear", LINEAR, {"api_key": os.environ["LINEAR_API_KEY"]})

    agent = SandboxAgent(
        name="Design feedback triage",
        model="gpt-5.5",
        instructions=(await ws.vfs_md()),
    )
    config = RunConfig(sandbox=SandboxRunConfig(client=MirageSandboxClient(ws)))

    task = (
        "Scan recent messages in the Slack #incident channel. If anyone posts "
        "feedback about Mirage with a screenshot, read the image, locate the "
        "relevant CLI code in the Mirage GitHub repo, and file a design issue "
        "with `linear issue create`, including the user's feedback and links "
        "to the offending source files."
    )
    result = await Runner.run(agent, task, run_config=config)
    print(result.final_output)
    ```

    ```typescript
    import { Agent, run, shellTool } from '@openai/agents'
    import { MirageShell, buildSystemPrompt } from '@struktoai/mirage-agents/openai'
    import { GitHubVFS, LINEAR, SlackVFS, Workspace } from '@struktoai/mirage-node'

    const slack = new SlackVFS({ token: process.env.SLACK_BOT_TOKEN! })
    const github = await GitHubVFS.create({
      token: process.env.GITHUB_TOKEN!,
      owner: 'strukto-ai',
      repo: 'mirage',
    })

    const ws = new Workspace({ '/slack': slack, '/github': github })
    ws.registerCli('linear', LINEAR, { apiKey: process.env.LINEAR_API_KEY! })

    const agent = new Agent({
      name: 'Design feedback triage',
      model: 'gpt-5.5',
      instructions: await buildSystemPrompt({ workspace: ws }),
      tools: [shellTool({ shell: new MirageShell(ws) })],
    })

    const task =
      'Scan recent messages in the Slack #incident channel. If anyone posts ' +
      'feedback about Mirage with a screenshot, read the image, locate the ' +
      'relevant CLI code in the Mirage GitHub repo, and file a design issue ' +
      "with `linear issue create`, including the user's feedback and links " +
      'to the offending source files.'

    const result = await run(agent, task)
    console.log(result.finalOutput)
    ```

<h2 className="text-2xl font-bold mt-16 mb-6">FAQ</h2>

<AccordionGroup>
  <Accordion title="Do I need FUSE?">
    No. Mirage runs the workspace in-process: <code>ws.shell(...)</code> parses and dispatches commands without mounting anything on the host. FUSE is an optional surface if you also want host tools (editors, language servers, <code>rg</code>) to see the workspace.
  </Accordion>
  <Accordion title="Where does the shell run? Is it really bash?">
    The shell runs in your Mirage process: a tree-sitter bash parser plus an executor that routes each command to the mount that owns its paths. There is no <code>/bin/bash</code> underneath. Common Unix commands work (<code>ls</code>, <code>cat</code>, <code>grep</code>, <code>find</code>, <code>head</code>, <code>wc</code>, <code>jq</code>, ...) with pipes, redirects, globs, and <code>&&</code>/<code>||</code>. <code>python3</code>, <code>node</code> and other programs go to the <a href="/home/setup/runtime/overview">runtime</a> that captures them.
  </Accordion>
  <Accordion title="Is it sandboxed?">
    The shell only sees your mounts. The default runtimes, Monty for <code>python3</code> and QuickJS for <code>node</code>, run in-process with no host files or network. Host and sandbox runtimes (<code>local</code>, Docker, E2B, Daytona, SSH) have their own files and network; see <a href="/home/setup/runtime/overview#files">what each runtime reaches</a>.
  </Accordion>
  <Accordion title="What about latency and cost?">
    Backend-bound. <code>cat /s3/...</code> is one GetObject; <code>find /postgres/...</code> is a SQL query. Reads go through the workspace <a href="/home/cache">cache</a>: under the default <code>read: bounded</code> a repeat read within the mount's <code>ttl</code> makes no backend call, and under <code>read: fresh</code> it costs one metadata check (and a download if the file changed).
  </Accordion>
  <Accordion title="Hosted or self-hosted?">
    Self-hosted. Mirage is a library plus a thin local daemon. The daemon lives in your process or sandbox; data only leaves your network if a mount you configured already does (e.g. an S3 read).
  </Accordion>
  <Accordion title="Which agent frameworks are supported?">
    Anything that exposes a shell tool: Claude Code, Codex / OpenAI Agents SDK, Cursor, OpenHands, Pydantic deepagents. Direct SDK integrations live under <a href="/python/agents">Python agents</a> and <a href="/typescript/agents">TypeScript agents</a>.
  </Accordion>
  <Accordion title="Python or TypeScript?">
    Both. The two SDKs share one layout and the same semantics: the same <code>Workspace</code>, mounts, commands, CLIs and runtimes. TypeScript ships <code>@struktoai/mirage-node</code> for Node and <code>@struktoai/mirage-browser</code> for browsers.
  </Accordion>
  <Accordion title="What if a VFS I want isn't supported yet?">
    VFS types are pluggable. The <a href="/python/vfs/new">"Add a VFS"</a> guide walks through the read/write/stat surface a new backend implements. PRs welcome.
  </Accordion>
</AccordionGroup>
