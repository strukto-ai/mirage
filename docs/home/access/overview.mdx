| Way in | For | Reach it with |
| --- | --- | --- |
| In-app | an agent in your own process | `Workspace` and `Session`, in [Python](/python/access/in-app) or [TypeScript](/typescript/access/in-app) |
| [HTTP](/home/access/http) | programs and services | `/v1/...` routes |
| [MCP](/home/access/mcp) | agent harnesses such as Claude Code, Cursor and Codex | `/v1/workspaces/{id}/mcp`, or `mirage mcp` on stdio |
| [RPC](/home/access/rpc) | programs that run lines and move bytes | `/v1/workspaces/{id}/rpc`, or `mirage rpc` on stdio |
| [CLI](/home/access/cli) | people and scripts | `mirage <verb>` |
| [SSH](/home/access/ssh) | people and tools that speak SSH | `ssh`, `sftp`, `scp`, on the SSH port or through `mirage ssh-proxy` |
| [FUSE](/home/setup/fuse) | editors, language servers and other host programs | a folder on the machine running Mirage |

HTTP, MCP, RPC, CLI and SSH connections go through the Mirage server, a FastAPI app in [Python](/python/access/server) and a Fastify app in [TypeScript](/typescript/access/server) that speak the same protocol. It serves HTTP, and SSH on its own port when `ssh_port` is set or over HTTP through `mirage ssh-proxy`. The CLI starts the server on your machine when it needs one. In-app access reaches the workspace directly.

## What each one exposes

Each way in exposes what its own protocol defines. A dash means the protocol has no such operation.

| | In-app | HTTP | MCP | RPC | CLI | SSH |
| --- | --- | --- | --- | --- | --- | --- |
| Create, list, delete workspaces | ✓ | ✓ | – | – | ✓ | – |
| Create, list, delete sessions | ✓ | ✓ | – | – | ✓ | – |
| Run a line | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| Send stdin to a line | ✓ | ✓ | – | ✓ | ✓ | ✓ |
| Cancel a running line | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| Cancel or kill all of a session's or workspace's work | ✓ | ✓ | – | – | ✓ | – |
| VFS.md, SKILL.md and session profiles | ✓ | ✓ | – | – | ✓ | – |
| The seven agent tools | ✓ | ✓ | ✓ | ✓ | ✓ | – |
| File operations on bytes | ✓ | ✓ | ✓ | ✓ | ✓ | `sftp`, `scp`, `sshfs` |
| Explain a line or a VFS call | ✓ | ✓ | ✓ | ✓ | ✓ | – |
| Snapshots | ✓ | ✓ | – | – | ✓ | – |
| Asks | ✓ | ✓ | – | – | ✓ | – |
| Jobs | – | ✓ | – | – | ✓ | – |

## Sessions

A session is one shell inside a workspace. It keeps its own working directory,
environment variables and history, and runs under one [agent profile](/home/profiles).
Agents in different sessions share the workspace's files but not their shell
state.

| Way in | Specify the session with |
| --- | --- |
| HTTP, MCP, RPC | `?session_id=` |
| MCP or RPC over stdio | `-s` |
| CLI | `-s` |
| SSH, `sshfs` included | Each login opens a new session under its key's profile. |

A call that specifies no session runs in the workspace's default session. Its
profile is the one the config's `profile:` names, else the one called
`default`, else none.

## Cancel

Through the server, every line runs as a job. `GET /v1/jobs` lists them, and a cancelled one ends as `canceled`.

| Way in | Cancel a running line with |
| --- | --- |
| CLI, SSH | Ctrl-C |
| MCP | `notifications/cancelled` |
| RPC | `$/cancelRequest` |
| HTTP | A dropped request, or `DELETE /v1/jobs/{id}` |

To stop a whole session or workspace, whichever way its lines came in:

| Stop | HTTP | CLI |
| --- | --- | --- |
| A session's running lines | `POST /v1/workspaces/{id}/sessions/{session_id}/cancel` | `mirage session cancel ID S` |
| A session's background jobs | `POST /v1/workspaces/{id}/sessions/{session_id}/kill` | `mirage session kill ID S` |
| Every session's running lines | `POST /v1/workspaces/{id}/cancel` | `mirage workspace cancel ID` |
| Every session's background jobs | `POST /v1/workspaces/{id}/kill` | `mirage workspace kill ID` |

## Auth

When authentication is configured, every way in proves who is calling. `GET /v1/health` and OAuth discovery stay public.

| Way in | Authenticates with |
| --- | --- |
| HTTP, MCP, RPC | A bearer token: `Authorization: Bearer <token>` |
| CLI, and MCP or RPC over stdio | The CLI's local token, sent for you |
| SSH on the SSH port | A public key |
| SSH through `mirage ssh-proxy` | The CLI's token |

A server you start directly in `local` mode, with no token configured, accepts requests without one. In `jwt` mode a token's `sub` is an [account](/home/access/http#accounts) that reaches only its own workspaces, and an SSH key names its account with `mirage-account`. See [Auth](/home/access/http#auth).
