Every workspace on the Mirage server is an [MCP](https://modelcontextprotocol.io) server at:

```
http://127.0.0.1:8765/v1/workspaces/{id}/mcp
```

An agent connected to it gets a shell and six file tools over the workspace's
files.

## Connect

On your own machine, let the client launch `mirage mcp`. It starts the server if needed and sends your token.
These examples use the `demo` workspace from the [CLI quickstart](/home/access/cli#quickstart).

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add mirage -- mirage mcp -w demo
    ```
  </Tab>
  <Tab title="Cursor">
    ```json .cursor/mcp.json
    {
      "mcpServers": {
        "mirage": { "command": "mirage", "args": ["mcp", "-w", "demo"] }
      }
    }
    ```
  </Tab>
  <Tab title="VS Code">
    ```json .vscode/mcp.json
    {
      "servers": {
        "mirage": { "type": "stdio", "command": "mirage", "args": ["mcp", "-w", "demo"] }
      }
    }
    ```
  </Tab>
  <Tab title="Codex">
    ```toml ~/.codex/config.toml
    [mcp_servers.mirage]
    command = "mirage"
    args = ["mcp", "-w", "demo"]
    ```
  </Tab>
</Tabs>

For a server elsewhere, give the client the URL and a token:

<Tabs>
  <Tab title="Claude Code">
    ```bash
    claude mcp add --transport http mirage https://mirage.example.com/v1/workspaces/demo/mcp \
      --header "Authorization: Bearer $MIRAGE_TOKEN"
    ```
  </Tab>
  <Tab title="Cursor">

    ```json .cursor/mcp.json
    {
      "mcpServers": {
        "mirage": {
          "url": "https://mirage.example.com/v1/workspaces/demo/mcp",
          "headers": { "Authorization": "Bearer ${env:MIRAGE_TOKEN}" }
        }
      }
    }
    ```
  </Tab>
  <Tab title="VS Code">
    ```json .vscode/mcp.json
    {
      "servers": {
        "mirage": {
          "type": "http",
          "url": "https://mirage.example.com/v1/workspaces/demo/mcp",
          "headers": { "Authorization": "Bearer ${env:MIRAGE_TOKEN}" }
    ```

  </Tab>


## Auth

MCP uses the same bearer token as [HTTP](/home/access/http#auth). `mirage mcp`
sends the CLI's token for you: a saved [login](/home/access/cli#log-in),
`MIRAGE_TOKEN`, or the local token file. A client that connects by URL sends the
header itself; the endpoint does not start an OAuth sign-in.

## Tools

Every tool answers text, with `isError` set when it fails.

| Tool | Does | Read-only |
| --- | --- | --- |
| [`shell`](#shell) | Run a shell line. | |
| [`read`](#read) | Read a file as numbered lines. | yes |
| [`write`](#write) | Write a file. | |
| [`edit`](#edit) | Replace a string in a file. | |
| [`ls`](#ls) | List a directory. | yes |
| [`grep`](#grep) | Search file contents. | yes |
| [`glob`](#glob) | Find paths by pattern. | yes |

A session sees only the tools its [agent profile](/home/policy/explain#which-tools-the-agent-gets)
allows: `shell` needs a command the allow list allows, `ls` and `grep` need
those commands, and `write` and `edit` need a mount the session may write. A
tool it does not see answers `not found`.

### shell

Runs a shell line in the session's working directory. A `cd` or `export` holds
for the next call.

<ParamField body="command" type="string" required>The line to run.</ParamField>

Answers stdout, then stderr. `isError` is set when the line exits non-zero.

```text
x = 2
print(x)

ls: cannot access '/nope': No such file or directory
```

### read

Reads a file as numbered lines.

<ParamField body="path" type="string" required>Absolute path of the file.</ParamField>
<ParamField body="offset" type="integer" default="0">First line to return, zero-based.</ParamField>
<ParamField body="limit" type="integer" default="2000">Most lines to return.</ParamField>

```text
     1	x = 1
     2	print(x)
```

### write

Writes a file, creating missing parent directories. To replace a file that
exists, `read` all of it first; the write fails if it changed since. Use
[`edit`](#edit) to change part of a file.

<ParamField body="path" type="string" required>Absolute path of the file.</ParamField>
<ParamField body="content" type="string" required>The text to write.</ParamField>

```text
Written: /data/a.py
```

### edit

Replaces a string in a file. Fails if the file changed since it was read, or if
`old_string` is missing or appears more than once without `replace_all`.

<ParamField body="path" type="string" required>Absolute path of the file.</ParamField>
<ParamField body="old_string" type="string" required>The exact text to replace.</ParamField>
<ParamField body="new_string" type="string" required>The text to put in its place.</ParamField>
<ParamField body="replace_all" type="boolean" default="false">Replace every occurrence.</ParamField>

```text
Edited: /data/a.py (1 occurrence(s))
```

### ls

Lists a directory, one name per line.

<ParamField body="path" type="string" required>Absolute path of the directory.</ParamField>

```text
a.py
sub
```

### grep

Searches files under a path for a regular expression, as `grep -rn` does.
Finding nothing is not an error.

<ParamField body="pattern" type="string" required>The regular expression.</ParamField>
<ParamField body="path" type="string" required>Absolute path of the file or directory to search.</ParamField>
<ParamField body="ignore_case" type="boolean" default="false">Match case-insensitively (`-i`).</ParamField>
<ParamField body="fixed_strings" type="boolean" default="false">Read the pattern as plain text (`-F`).</ParamField>
<ParamField body="include" type="string">Search only files whose name matches this glob, such as `*.py` (`--include`).</ParamField>
<ParamField body="context" type="integer">Lines of context around each match (`-C`).</ParamField>
<ParamField body="files_with_matches" type="boolean" default="false">Print only the names of matching files (`-l`).</ParamField>
<ParamField body="count" type="boolean" default="false">Print only a count of matching lines per file (`-c`).</ParamField>
<ParamField body="max_count" type="integer">Stop each file after this many matches (`-m`).</ParamField>

```text
/data/a.py:2:print(x)
```

### glob

Finds files whose path matches a pattern, sorted. `**` matches any number of
directories. A pattern that matches more files than a mount's
[`walk_limit`](/home/integration/search#walk_limit) is an error that
names the limit.

<ParamField body="pattern" type="string" required>The pattern, such as `**/*.py`. A relative one is matched under `path`.</ParamField>
<ParamField body="path" type="string" default="/">The directory a relative pattern is matched under.</ParamField>

```text
/data/a.py
```

## Output progress

A `shell` call can send output previews while it runs. Pass a progress token in
the request's `_meta`:

```json
{
  "jsonrpc": "2.0",
  "id": 7,
  "method": "tools/call",
  "params": {
    "name": "shell",
    "arguments": { "command": "echo ready; sleep 1; echo done" },
    "_meta": { "progressToken": "run-7" }
  }
}
```

Mirage then sends `notifications/progress` messages that start with `[stdout]`
or `[stderr]`, over HTTP and `mirage mcp` alike. Previews are trimmed and
batched, so take the full output from the final result.

## VFS calls

Add `?calls=all` to the URL, or `--all-calls` to `mirage mcp`, for 23 more
tools: `vfs_read`, `vfs_is_dir` and the rest, one per
[VFS call](/home/access/http#call-the-vfs). They take the same arguments and
answer the same JSON as HTTP. With them on, `shell` and every `vfs_<call>` also
take `explain: true`, which says what the call would do and runs nothing; see
[Explain](/home/policy/explain).

## Sessions

Calls run in the workspace's default session. To use another, add
`?session_id=<id>` to the URL, or `-s <id>` to `mirage mcp`. The session's
[agent profile](/home/profiles) applies as it does to a shell line: a path
hidden from `cat` is hidden from `read`. Command rules apply only to `shell`,
`ls` and `grep`.
