SSHFS exposes a Mirage server's workspace as a folder on your machine.
Editors and other programs can read and write its files through SSH/SFTP.
FUSE is needed on your machine; the server does not need it.

To expose a VFS directly from your own app instead, use a
[local FUSE mount](/home/setup/local-fuse).

## Connect over SSH

Install [SSHFS](https://github.com/libfuse/sshfs) on your machine and
[enable SSH](/home/access/ssh#turn-it-on) on the Mirage server with your key authorized.
On Linux, install `sshfs`; on macOS, install macFUSE and SSHFS from
[macfuse.github.io](https://macfuse.github.io).

Replace `demo` with your workspace ID and `your-server` with the server's hostname:

```bash
mkdir -p ~/mnt/demo
sshfs -p 2222 -o direct_io demo@your-server:/ ~/mnt/demo
ls ~/mnt/demo
```

The folder shows the workspace's virtual filesystem. For example, a VFS at
`/data` appears as `~/mnt/demo/data`.

Keep `-o direct_io` so files whose size is unknown can be read correctly.
The connection uses the SSH key's [agent profile](/home/access/ssh#bind-a-key-to-a-profile).

## Connect over HTTPS

If your server exposes SSH through HTTPS, use the CLI's configured server
and token ([setup](/home/access/ssh#over-https)):

```bash
sshfs -o ProxyCommand="mirage ssh-proxy %r" -o direct_io demo@mirage:/ ~/mnt/demo
```

## Disconnect

<CodeGroup>
```bash Linux
fusermount3 -u ~/mnt/demo
```

```bash macOS
umount ~/mnt/demo
```
</CodeGroup>
