The Mirage server holds workspaces and serves them over HTTP. The Python and
TypeScript servers speak the same protocol. Routes are under `/v1` and return
JSON.

## Launch a server

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import uvicorn

    from mirage.server.app import build_app

    uvicorn.run(build_app(), host="127.0.0.1", port=8765)
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { buildApp } from '@struktoai/mirage-server'

    await buildApp().listen({ host: '127.0.0.1', port: 8765 })
    ```
  </Tab>
</Tabs>

The server accepts only the host names in `MIRAGE_ALLOWED_HOSTS`: `127.0.0.1`,
`localhost` and `::1` by default. Add the name your clients use. It also
refuses a browser page served from any other origin, a page on another port of
`localhost` included, even when the list is `*`. Other options
are on the [Python](/python/access/server) and [TypeScript](/typescript/access/server)
server pages.

## Auth

Set a token in the server's environment before you launch it:

```bash
export MIRAGE_AUTH_MODE=token
export MIRAGE_AUTH_TOKEN=my-secret
```

Clients send it on every request as `Authorization: Bearer my-secret`.
`GET /v1/health` needs no token.

Without a token, the default `local` mode accepts every request, so set one
before anyone else can reach the server. For JWTs and per-account workspaces,
see [Configure authentication](#configure-authentication).

## Make a request

Create a workspace with an in-memory mount, then run a line in it:

<Tabs>
  <Tab title="Terminal" icon="terminal">
    ```bash
    curl http://127.0.0.1:8765/v1/workspaces \
      -H "Authorization: Bearer $MIRAGE_AUTH_TOKEN" \
      -H 'Content-Type: application/json' \
      -d '{"id":"demo","config":{"mounts":{"/":{"vfs":"ram","mode":"write"}}}}'

    curl http://127.0.0.1:8765/v1/workspaces/demo/shell \
      -H "Authorization: Bearer $MIRAGE_AUTH_TOKEN" \
      -H 'Content-Type: application/json' \
      -d '{"command":"echo hello"}'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import os

    import httpx

    headers = {"Authorization": f"Bearer {os.environ['MIRAGE_AUTH_TOKEN']}"}
    with httpx.Client(base_url="http://127.0.0.1:8765/v1", headers=headers) as client:
        client.post("/workspaces", json={
            "id": "demo",
            "config": {"mounts": {"/": {"vfs": "ram", "mode": "write"}}},
        }).raise_for_status()
        result = client.post("/workspaces/demo/shell", json={"command": "echo hello"}).json()
        print(result["stdout"], end="")
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    const base = 'http://127.0.0.1:8765/v1'
    const headers = {
      Authorization: `Bearer ${process.env.MIRAGE_AUTH_TOKEN}`,
      'Content-Type': 'application/json',
    }

    await fetch(`${base}/workspaces`, {
      method: 'POST',
      headers,
      body: JSON.stringify({ id: 'demo', config: { mounts: { '/': { vfs: 'ram', mode: 'write' } } } }),
    })
    const res = await fetch(`${base}/workspaces/demo/shell`, {
      method: 'POST',
      headers,
      body: JSON.stringify({ command: 'echo hello' }),
    })
    const result = await res.json()
    process.stdout.write(result.stdout)
    ```
  </Tab>
</Tabs>

The shell call returns:

```json
{"kind": "io", "exit_code": 0, "stdout": "hello\n", "stderr": "", "refusal": null}
```

## Errors

A `200` means the server ran the line, not that the line succeeded: check
`exit_code`. Most errors return JSON with a `detail` message, but an auth or
`Host` refusal can be plain text, so check `Content-Type` before parsing.

| Status | Means |
| --- | --- |
| `400` | The request is malformed, its host is not allowed, or a browser page from another origin sent it. |
| `401` | The token is missing or wrong. |
| `403` | A policy or mount mode refused the call. |
| `404` | The workspace, session, job or file does not exist. |
| `409` | The id is taken, the workspace is busy, or a file changed since it was read. |
| `413` | The request is too large. |
| `422` | The request body is invalid. |
| `429` | Past a [rate limit](#rate-limits), with `Retry-After` in seconds, or a new session past `max_sessions`. |
| `499` | The job was canceled. |
| `500` | The job failed inside the server. |
| `503` | The server is at `max_workspaces`, or shutting down. |
| `507` | A file call's write would pass its store's capacity. |

## Server

### Check health

<Badge color="blue">GET</Badge> `/v1/health`

Returns `{"status": "ok", "workspaces": 2, "uptime_s": 12.5}` without requiring a token.

### Check readiness

<Badge color="blue">GET</Badge> `/v1/ready`

Whether the server takes new workspaces, without requiring a token. Returns
`{"status": "ready"}` with `200`, or `503` with `{"status": "full"}` at
`max_workspaces` and `{"status": "shutting_down"}` while it shuts down. Point a load
balancer's readiness check here and its liveness check at `/v1/health`.

### Metrics

The server records its metrics through [OpenTelemetry](https://opentelemetry.io/docs/concepts/signals/metrics/),
under the meter `mirage.server`. Nothing is sent until the process sets up an
OpenTelemetry SDK, and the exporter it picks decides where they go: OTLP to
Datadog, New Relic, Honeycomb, Grafana Cloud, CloudWatch or Google Cloud, a
Prometheus page, or the console. They are server-wide and name no workspace or
account.

| Instrument | Kind | Value |
| --- | --- | --- |
| `mirage.workspace.count` | up-down counter | Workspaces it holds. |
| `mirage.workspace.limit` | up-down counter | Its `max_workspaces`, when set. |
| `mirage.session.count` | up-down counter | Sessions across its workspaces. |
| `mirage.job.running` | up-down counter | [Jobs](#jobs) running. |
| `mirage.server.shutting_down` | gauge | `1` while it shuts down. |
| `mirage.request.refused` | counter | Requests refused for a server limit, by `reason`: `rate_limit`, `max_sessions`, `max_workspaces` or `shutting_down`. |

In Python, run the app under `opentelemetry-instrument`, which also records
each HTTP request:

```bash
pip install opentelemetry-distro opentelemetry-exporter-otlp
OTEL_METRICS_EXPORTER=otlp OTEL_EXPORTER_OTLP_ENDPOINT=https://otlp.example.com \
  opentelemetry-instrument uvicorn main:app
```

In TypeScript, register a meter provider before `buildApp`:

```ts
import { metrics } from '@opentelemetry/api'
import { OTLPMetricExporter } from '@opentelemetry/exporter-metrics-otlp-http'
import { MeterProvider, PeriodicExportingMetricReader } from '@opentelemetry/sdk-metrics'
import { buildApp } from '@struktoai/mirage-server'

metrics.setGlobalMeterProvider(
  new MeterProvider({
    readers: [new PeriodicExportingMetricReader({ exporter: new OTLPMetricExporter() })],
  }),
)
const app = buildApp()
```

### Rate limits

By default, the server allows 1000 requests per minute per client IP, counted
before authentication so rejected tokens consume the same budget. Configured
limits replace this default; include an `ip` limit to keep unauthenticated
requests bounded. An explicit empty list in code or `rate_limits = ""` in
`config.toml` disables rate limiting.

Each limit allows a number of requests per second, minute, hour or day for each
value of its key, and answers `429` with `Retry-After` past it until the window
that value's first request opened ends. Set them in `config.toml`:

```toml
[daemon]
rate_limits = "ip=1000/minute, account=600/minute, header:x-tenant=50/second"
forwarded_allow_ips = "10.0.0.0/8"
```

| Key | Counts requests by |
| --- | --- |
| `ip` | The client address. Behind a proxy, list it in `forwarded_allow_ips`, or every client counts as the proxy. |
| `account` | The signed-in [account](#accounts). |
| `workspace` | The workspace the path names. |
| `header:<name>` | That header's value. |

A request with no value for a key (no account, no workspace in its path, no such
header) is not counted by that limit. `/v1/health`, `/v1/ready` and the OAuth
protected-resource metadata are never counted. WebSocket handshakes consume the
same budget as HTTP requests; messages on an established connection do not.
In code, a key may also be a function of the request that returns the value to
count by, or nothing to skip the limit:

<CodeGroup>
```python Python
from mirage.server import RateLimit, build_app

app = build_app(
    rate_limits=[
        RateLimit("account", "600/minute"),
        RateLimit(lambda request: request.headers.get("x-tenant"), "50/second"),
    ]
)
```

```ts TypeScript
import { buildApp } from '@struktoai/mirage-server'

const app = buildApp({
  rateLimits: [
    { key: 'account', rate: '600/minute' },
    { key: (request) => request.headers['x-tenant']?.toString() ?? null, rate: '50/second' },
  ],
})
```
</CodeGroup>

### Shut down

<Badge color="green">POST</Badge> `/v1/shutdown`

Requests the server to shut down, returning `{"status": "shutting_down", "pid": 4242}`.
A server you launch stops only if you gave it `on_idle_exit` (`onIdleExit` in
TypeScript).

## Workspaces

Routes that return a workspace yield this object:

<ResponseField name="id" type="string">The workspace id.</ResponseField>
<ResponseField name="mode" type="string">The default mount mode: `read`, `write` or `exec`.</ResponseField>
<ResponseField name="created_at" type="number">Unix time, in seconds.</ResponseField>
<ResponseField name="sessions" type="Session[]">Its [sessions](#sessions).</ResponseField>
<ResponseField name="mounts" type="object[]">
  <Expandable title="mount">
    <ResponseField name="prefix" type="string">Where it is mounted, such as `/data/`.</ResponseField>
    <ResponseField name="vfs" type="string">The VFS, such as `s3`.</ResponseField>
    <ResponseField name="mode" type="string">`read`, `write` or `exec`.</ResponseField>
    <ResponseField name="description" type="string">What the agent is told about the mount.</ResponseField>
  </Expandable>
</ResponseField>
<ResponseField name="fuse_mountpoints" type="object">Mount prefix to local folder, for [FUSE](/home/setup/fuse) mounts.</ResponseField>
<ResponseField name="internals" type="object | null">With `?verbose=true`: `cache_bytes`, `cache_entries`, `history_length`, `in_flight_jobs`.</ResponseField>

### Create a workspace

<Badge color="green">POST</Badge> `/v1/workspaces`

<ParamField body="config" type="object" required>The workspace YAML as JSON: its `mounts`, [`network`](/home/configuration#network), `profiles` and the rest of [Workspace configuration](/home/configuration).</ParamField>
<ParamField body="id" type="string">The workspace id. A fresh one when absent.</ParamField>
<ParamField query="explain" type="boolean">Return what the [server policies](#server-policies) say of the config instead, and create nothing.</ParamField>

Returns HTTP 201 Created with the workspace object. Re-submitting the same ID and
config returns HTTP 200 OK with the existing workspace; submitting a different
config under an already taken ID returns HTTP 409 Conflict. A config a server
policy refuses returns HTTP 403 Forbidden with its reason. With
`?explain=true` the answer is `{"outcome", "reason", "source", "refusal",
"answers"}`, as on [Explain](/home/policy/explain).

### List workspaces

<Badge color="blue">GET</Badge> `/v1/workspaces`

Returns an array of workspace summaries:

```json
[{"id": "demo", "mode": "write", "mount_count": 2, "session_count": 1, "created_at": 1792630121.06}]
```

### Get a workspace

<Badge color="blue">GET</Badge> `/v1/workspaces/{id}`

<ParamField query="verbose" type="boolean" default="false">Add cache and job internals.</ParamField>

Returns the workspace object.

### Read a workspace's history

<Badge color="blue">GET</Badge> `/v1/workspaces/{id}/history`

<ParamField query="session_id" type="string">Only this session's entries.</ParamField>
<ParamField query="since" type="integer">Only entries at or after this time, in epoch milliseconds.</ParamField>
<ParamField query="last" type="integer">Only the newest this many entries.</ParamField>
<ParamField query="vfs" type="boolean" default="false">Add a `vfs` entry for each call a line made to a mount.</ParamField>

Returns what the workspace ran, oldest first. A line is a `command` entry
when it starts and a `result` entry when it ends, which names the line as its
`parent`; a line still running has no `result` yet. With `vfs`, each call the
line made to a mount is a `vfs` entry between them.

```json
[
  {"type": "command", "id": "exec_01a1", "command": "cat /data/a.txt", "cwd": "/", "session": "s1", "timestamp": 1792630121040},
  {"type": "vfs", "parent": "exec_01a1", "vfs": "read", "path": "/data/a.txt", "source": "s3", "bytes": 6, "duration_ms": 12, "session": "s1", "timestamp": 1792630121048},
  {"type": "result", "parent": "exec_01a1", "exit_code": 0, "stdout": "hello\n", "stderr": "", "duration_ms": 21, "cwd": "/", "session": "s1", "timestamp": 1792630121061}
]
```

`stdout` and `stderr` keep their first 4096 characters.

### Delete a workspace

<Badge color="red">DELETE</Badge> `/v1/workspaces/{id}`

Closes the workspace, deletes its persistent state, and returns `{"id": "demo", "closed_at": 1792630121.33}`.

### Close a workspace

<Badge color="green">POST</Badge> `/v1/workspaces/{id}/close`

Stops the workspace, preserves its state on disk, and returns `{"id": "demo", "closed_at": 1792630121.32}`.
Creating the same id again picks up its sessions, history and disk files. RAM
mounts are lost unless you snapshot first.

### Cancel a workspace's lines

<Badge color="green">POST</Badge> `/v1/workspaces/{id}/cancel`

Cancels all running and queued lines across every session, returning `{"canceled": 2}` once they have ended. The sessions stay open.

### Kill a workspace's jobs

<Badge color="green">POST</Badge> `/v1/workspaces/{id}/kill`

Kills every session's background jobs (`cmd &`) and the processes runtimes started, returning `{"killed": 1}`.

### Set a profile

<Badge color="orange">PUT</Badge> `/v1/workspaces/{id}/profiles/{name}`

The body is the [profile](/home/policy/overview) as JSON, the same document as an entry under `profiles` in the workspace YAML.

Adds the profile or replaces what the name means, returning `{"name": "reader"}`.
An invalid profile document returns HTTP 422 Unprocessable Entity and changes
nothing. A session on the name keeps its rules until you [change its
profile](#change-a-sessions-profile) to the name again. The workspace's config
is not rewritten, so creating the workspace again after a restart brings back
the profiles its YAML defines. Restored sessions keep the rules they last ran
under, except that the default session takes the YAML's default profile again
when the YAML names one.

```bash
curl -X PUT http://127.0.0.1:8765/v1/workspaces/demo/profiles/reader \
  -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"paths":{"hide":["/vault"]},"commands":{"allow":["cat","ls","whoami"]}}'
```

### Clone a workspace

<Badge color="green">POST</Badge> `/v1/workspaces/{id}/clone`

<ParamField body="id" type="string">The new workspace's id.</ParamField>
<ParamField body="override" type="object">Configuration overrides for the clone. Mount definitions replace corresponding source mounts. Overriding `/` replaces its backing VFS, but it remains the scratch root.</ParamField>

Returns HTTP 201 Created with the cloned workspace.

### Snapshot a workspace

<Badge color="blue">GET</Badge> `/v1/workspaces/{id}/snapshot`

Returns the tar archive (`application/x-tar`). Secrets are stored redacted. The server never writes a snapshot to its own disk. While it captures, new lines and file writes wait, and running ones get 30 seconds to end; if any are still running then, it returns HTTP 409 Conflict, so cancel them and retry. A clone waits the same way.

<Badge color="green">POST</Badge> `/v1/workspaces/{id}/snapshot`

<ParamField body="key" type="string" required>Stores the tar archive in the server's snapshot store under this key, returning `{id, key, size}`. Returns HTTP 400 Bad Request when the server has no snapshot store configured.</ParamField>

### Load a snapshot

<Badge color="green">POST</Badge> `/v1/workspaces/load`

Upload the tar as `multipart/form-data`: a `request` part holding the JSON fields below, then a `snapshot` part of up to 1 GiB. Or send JSON with a `key` to load from the snapshot store.

<ParamField body="key" type="string">The tar's key in the snapshot store; leave it out when uploading.</ParamField>
<ParamField body="id" type="string">The new workspace's id.</ParamField>
<ParamField body="override" type="object">Configuration overrides for the restored workspace, including credentials redacted from the snapshot. Overriding `/` replaces its backing VFS, but it remains the scratch root.</ParamField>

Returns HTTP 201 Created with the restored workspace.

## Sessions

A session keeps its own working directory, environment, and history. Requests use the workspace's default session unless they specify `session_id`.
Routes that return a session yield an object with session details: `{"session_id": "agent", "cwd": "/"}`.

### Create a session

<Badge color="green">POST</Badge> `/v1/workspaces/{id}/sessions`

<ParamField body="session_id" type="string">The session id. A fresh one when absent.</ParamField>
<ParamField body="profile" type="string">A [profile](/home/policy/overview) from the workspace's `profiles`.</ParamField>
<ParamField body="mounts" type="object">Prefix to mode (`read`, `write`, `exec`) to narrow those mounts, such as `{"/data": "read"}`.</ParamField>

Returns HTTP 201 Created with the session object.

### List sessions

<Badge color="blue">GET</Badge> `/v1/workspaces/{id}/sessions`

Returns an array of session objects.

### Delete a session

<Badge color="red">DELETE</Badge> `/v1/workspaces/{id}/sessions/{session_id}`

Cancels active lines, terminates jobs, closes the session, and returns `{"session_id": "agent"}`.

### Cancel a session's lines

<Badge color="green">POST</Badge> `/v1/workspaces/{id}/sessions/{session_id}/cancel`

Cancels running and queued lines in the session, returning `{"canceled": 1}` once they have ended. The session stays open.

### Kill a session's jobs

<Badge color="green">POST</Badge> `/v1/workspaces/{id}/sessions/{session_id}/kill`

Kills background jobs and processes associated with the session, returning `{"killed": 1}`. The session stays open.

### Change a session's profile

<Badge color="orange">PATCH</Badge> `/v1/workspaces/{id}/sessions/{session_id}`

<ParamField body="profile" type="string | object | null" required>A [profile](/home/policy/overview) from the workspace's `profiles`, `null` for the workspace default, or a profile document. A document runs without a name, so `whoami` and the profile's policy programs see none.</ParamField>

Replaces the session's modes, hides and rules with the profile's current
definition, returning the updated session object. Its cwd, env and history stay.

### VFS.md and SKILL.md

<Badge color="blue">GET</Badge> `/v1/workspaces/{id}/vfs-md` · `/v1/workspaces/{id}/sessions/{session_id}/vfs-md`

<Badge color="orange">PUT</Badge> the same routes

<ParamField query="profile" type="string">GET only, on the workspace route: preview this profile.</ParamField>
<ParamField body="path" type="string" required>PUT only: expose the document as a live, read-only file at this path.</ParamField>

Returns raw Markdown (`text/markdown`). Use `skill-md` in place of `vfs-md` for SKILL.md; [VFS.md and SKILL.md](/home/setup/vfs-md) covers both. Errors: `404` for a missing session or parent folder, `409` for a path already taken, `422` for a bad path or profile.

## Shell, VFS calls and tools

Each call acts as the session `?session_id=` names, the default one when absent. `?explain=true` on the shell or a VFS call returns what the call would do without executing it; see [Explain](/home/policy/explain).

### Run a shell line

<Badge color="green">POST</Badge> `/v1/workspaces/{id}/shell`

<ParamField body="command" type="string" required>The line.</ParamField>
<ParamField body="cwd" type="string">A working directory for this line only.</ParamField>
<ParamField body="runtime" type="string">Run the line on this [runtime](/home/setup/runtime/overview), by name, instead of the one routing picks.</ParamField>
<ParamField body="record" type="boolean" default="true">Add the line to the session's history. `false` leaves it out.</ParamField>
<ParamField query="session_id" type="string">The session. The default when absent.</ParamField>
<ParamField query="background" type="boolean" default="false">Return HTTP 202 Accepted with `{job_id, workspace_id, submitted_at}` immediately.</ParamField>
<ParamField query="explain" type="boolean" default="false">Return the line's explanation without executing it.</ParamField>
<ParamField query="stream" type="boolean" default="false">Stream stdout, stderr and final status as NDJSON. Cannot be combined with background or explain.</ParamField>

Returns `{kind, exit_code, stdout, stderr, refusal}` when the line ends, with
the job id in the `X-Mirage-Job-Id` header. Closing the request cancels the
line. With `explain`, send only `command`.

**Stdin.** Post `multipart/form-data`: a `request` part with the JSON body, then
a `stdin` part of up to 64 MiB. The line reads it as it arrives.

<Tabs>
  <Tab title="Terminal" icon="terminal">
    ```bash
    printf 'b\na\n' | curl http://127.0.0.1:8765/v1/workspaces/demo/shell \
      -H "Authorization: Bearer $MIRAGE_AUTH_TOKEN" \
      -F 'request={"command":"sort"};type=application/json' \
      -F 'stdin=@-'
    ```
  </Tab>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import json
    import os

    import httpx

    headers = {"Authorization": f"Bearer {os.environ['MIRAGE_AUTH_TOKEN']}"}
    with httpx.Client(base_url="http://127.0.0.1:8765/v1", headers=headers) as client:
        result = client.post("/workspaces/demo/shell", files={
            "request": (None, json.dumps({"command": "sort"}), "application/json"),
            "stdin": ("stdin", b"b\na\n"),
        }).json()
        print(result["stdout"], end="")
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    const form = new FormData()
    form.append('request', new Blob([JSON.stringify({ command: 'sort' })], { type: 'application/json' }))
    form.append('stdin', new Blob(['b\na\n']))

    const res = await fetch('http://127.0.0.1:8765/v1/workspaces/demo/shell', {
      method: 'POST',
      headers: { Authorization: `Bearer ${process.env.MIRAGE_AUTH_TOKEN}` },
      body: form,
    })
    const result = await res.json()
    process.stdout.write(result.stdout)
    ```
  </Tab>
</Tabs>

**Streaming.** With `?stream=true`, the response is streamed as NDJSON: one record per output
chunk, with base64 `data`, then a final record whose `status` is `done`,
`failed` or `canceled`. A stream without that record was cut off.

```json
{"stream":"stdout","data":"aGVsbG8K"}
{"stream":"stderr","data":"b29wcwo="}
{"status":"done","result":{"kind":"io","exit_code":0,"stdout":"","stderr":"","refusal":null},"error":null}
```

### Call the VFS

<Badge color="green">POST</Badge> `/v1/workspaces/{id}/vfs/{call}`

<ParamField query="session_id" type="string">The session. The default when absent.</ParamField>
<ParamField query="explain" type="boolean" default="false">Return the call's explanation without executing it.</ParamField>

The body is the call's arguments, up to 4 MiB. A call returns what
[`session.vfs`](/python/access/in-app#session-vfs) produces, as JSON, and `null`
when it returns nothing. Bytes are base64 strings, both ways.

**Read**

| Call | Arguments | Returns |
| --- | --- | --- |
| `read` | `path`, `offset?`, `size?`, `raw?`, `stream?` | `string`, the bytes |
| `stat` | `path`, `nofollow?` | `FileStat` |
| `readdir` | `path` | `string[]`, full paths |
| `list_files` | `path` | `string[]`, file names only |
| `exists` | `path` | `boolean` |
| `is_dir` | `path` | `boolean` |
| `is_file` | `path` | `boolean` |

`raw` reads the stored bytes where the mount renders the file through a
`filetype` read, as a read-modify-write needs. `stream` returns the bytes
themselves as `application/octet-stream`, read as the response is sent. The
server reads the whole file first when the backend answers bytes, the file is
rendered, `offset` or `size` asks for a window, or a `post_vfs` policy applies.
A failure before the first byte returns an error response like any failed call.

**Write**

| Call | Arguments | Returns |
| --- | --- | --- |
| `write` | `path`, `data` | `null` |
| `append` | `path`, `data` | `null` |
| `pwrite` | `path`, `data`, `offset` | `null` |
| `truncate` | `path`, `length` | `null` |
| `create` | `path` | `null` |
| `mkdir` | `path` | `null` |
| `rmdir` | `path` | `null` |
| `unlink` | `path` | `null` |
| `rename` | `src`, `dst` | `null` |

**Links**

| Call | Arguments | Returns |
| --- | --- | --- |
| `symlink` | `path`, `target` | `null` |
| `readlink` | `path` | `string`, the target |

**Attributes**

| Call | Arguments | Returns |
| --- | --- | --- |
| `setattr` | `path`, `mode?`, `uid?`, `gid?`, `atime?`, `mtime?`, `nofollow?` | `object`, the fields the backend could not keep, which Mirage stores instead |
| `getxattr` | `path`, `name`, `nofollow?` | `string`, the bytes |
| `listxattr` | `path`, `nofollow?` | `string[]` |
| `setxattr` | `path`, `name`, `value`, `create?`, `replace?`, `nofollow?` | `null` |
| `removexattr` | `path`, `name`, `nofollow?` | `null` |

`FileStat` has the fields listed under [`session.vfs`](/python/access/in-app#session-vfs).

**Errors**

A failed call returns `{detail, errno}`, plus a `refusal` record when a policy
refused it. The errno picks the status, as [Errors](/home/access/errors#file-calls)
lists.

### Call a custom function

<Badge color="green">POST</Badge> `/v1/workspaces/{id}/vfs/{name}`

<ParamField body="path" type="string" required>The path the function acts on.</ParamField>
<ParamField body="kwargs" type="object">The function's keyword arguments, Python only: a TypeScript custom function takes none, so send `path` alone. Names that start with `_`, and dispatch arguments such as `session_id`, are refused with `400`.</ParamField>
<ParamField query="session_id" type="string">The session. The default when absent.</ParamField>

Calls a function a mount's VFS declares beyond the built-in calls, such as one
added in a [custom VFS](/python/vfs/new). It goes through the same policy
checks and returns its result as JSON.

### Match paths

<Badge color="green">POST</Badge> `/v1/workspaces/{id}/glob`

<ParamField body="pattern" type="string" required>A pathname pattern, such as `/src/**/*.py`.</ParamField>
<ParamField query="session_id" type="string">The session. The default when absent.</ParamField>

Returns a list of every matching path visible to the session. A pattern matching
more files than a mount's [`walk_limit`](/home/integration/search#walk_limit)
returns HTTP 400 Bad Request, and `detail` names the limit.

### Call a tool

<Badge color="green">POST</Badge> `/v1/workspaces/{id}/tools/{tool}`

<ParamField query="session_id" type="string">The session. The default when absent.</ParamField>

Runs one of the [agent tools](/home/access/mcp#tools); the body is the tool's
input.

Returns `{text, is_error}`. Failed tool executions still return HTTP 200 with `is_error` set.

## Jobs

Every shell line is a job: `pending`, `running`, then `done`, `failed` or `canceled`.
Routes that return a job yield this object:

## Asks

An ask refuses the current action and records a pending decision. List pending asks, allow or deny one, then retry the refused line or VFS call in the same session; resolving alone does not resume the original request. See [Asks](/home/policy/policies#asks).
Routes that return an ask yield this object:

<ResponseField name="id" type="string">The ask id, also in the refused line's `refusal.ask_id`.</ResponseField>
<ResponseField name="session_id" type="string">The session that asked.</ResponseField>
<ResponseField name="command" type="string">The command, such as `rm`.</ResponseField>
<ResponseField name="argv" type="string[]">Its arguments.</ResponseField>
<ResponseField name="cwd" type="string">Its working directory.</ResponseField>
<ResponseField name="paths" type="string[]">The paths it touches.</ResponseField>
<ResponseField name="reason" type="string">The rule's reason.</ResponseField>
<ResponseField name="outcome" type="string | null">`allow` or `deny`; `null` until answered.</ResponseField>
<ResponseField name="scope" type="string">`once` or `session`.</ResponseField>
<ResponseField name="note" type="string">A note left with the answer.</ResponseField>

### List asks

<Badge color="blue">GET</Badge> `/v1/workspaces/{id}/asks`

<ParamField query="session_id" type="string">Only this session's asks.</ParamField>

## Configure authentication

`MIRAGE_AUTH_MODE` picks what the server accepts on its HTTP, MCP and RPC routes.

| Mode | Accepts | Set on the server |
| --- | --- | --- |
| `local` (default) | The configured token or `~/.mirage/auth_token` if either exists, otherwise any request | `MIRAGE_AUTH_TOKEN` (optional) |
| `token` | One shared token | `MIRAGE_AUTH_TOKEN` |
| `jwt` | A signed JWT, whose `sub` is the caller's [account](#accounts) | the [JWT settings](#jwt) |

### JWT

Point the server at your issuer's keys:

```bash
export MIRAGE_AUTH_MODE=jwt
export MIRAGE_JWT_ALG=RS256
export MIRAGE_JWT_JWKS_URL=https://issuer.example.com/.well-known/jwks.json
export MIRAGE_JWT_ISSUER=https://issuer.example.com
export MIRAGE_JWT_AUDIENCE=https://mirage.example.com
```

Every token needs `exp` and `sub`. A token with `aud` must name an entry in
`MIRAGE_JWT_AUDIENCE`; with none set, every such token is refused.

| Setting | Does |
| --- | --- |
| `MIRAGE_JWT_ALG` | The one algorithm accepted, such as `RS256`. Required. |
| `MIRAGE_JWT_JWKS_URL` | Fetch the signing keys from this URL. Rotating them needs no restart. |
| `MIRAGE_JWT_PUBKEY`, `MIRAGE_JWT_PUBKEY_FILE` | A fixed key instead of a JWKS URL. Changing it needs a restart. |
| `MIRAGE_JWT_ISSUER` | Require this `iss`. |
| `MIRAGE_JWT_AUDIENCE` | The `aud` values a token may name, comma-separated. |
| `MIRAGE_JWT_AUTHORIZED_PARTIES` | The `azp` values a token without `aud` may name, comma-separated. |
| `MIRAGE_JWT_CLOCK_SKEW_SECONDS` | Clock difference allowed when checking times. Default `5`. |

Set one of the JWKS URL or a fixed key, not both.

<Accordion title="Accept both app session tokens and OAuth access tokens">
  A token with `aud` must name an entry in `MIRAGE_JWT_AUDIENCE`. A token
  without `aud` needs an `azp` in `MIRAGE_JWT_AUTHORIZED_PARTIES` when that is
  set, and is refused when only an audience is set. So one server can accept an
  app's session tokens (`azp`) and an OAuth client's access tokens (`aud`), as
  Clerk issues them:

  ```bash
  export MIRAGE_AUTH_MODE=jwt
  export MIRAGE_JWT_ALG=RS256
  export MIRAGE_JWT_JWKS_URL=https://clerk.example.com/.well-known/jwks.json
  export MIRAGE_JWT_ISSUER=https://clerk.example.com
  export MIRAGE_JWT_AUTHORIZED_PARTIES=https://app.example.com
  export MIRAGE_JWT_AUDIENCE=client_cli
  ```

  To let `mirage login` sign in to this server, see
  [Log in](/home/access/cli#log-in).
</Accordion>

### Accounts

In `jwt` mode, a token's `sub` is its account, and an account reaches only the
workspaces it created. Another account's workspace, session, job or ask returns
HTTP 404 Not Found, matching a missing resource. An [SSH key](/home/access/ssh#auth-optional)
joins an account with its `mirage-account` option.

<Accordion title="What else an account changes">
  - `GET /v1/workspaces` and `GET /v1/jobs` list only the caller's.
  - A stored workspace reopens after a restart only for its owner. One stored
    before the server used `jwt` mode has no owner, and no account can create
    its id.
  - Snapshot keys live under `accounts/<account>/` in the snapshot store.
  - `POST /v1/shutdown` returns HTTP 403 Forbidden.
</Accordion>

<Warning>
  Accounts keep workspaces apart, not the host: a workspace config can still
  mount a host directory or run the `local` runtime, unless a
  [server policy](#server-policies) refuses it. In `local` and `token` mode,
  any accepted token can use every route and every workspace, including
  `POST /v1/shutdown`.
</Warning>

## Server policies

A server can hold every workspace it builds to its own rules. Its
policies answer [`pre_workspace`](/home/policy/policies#pre_workspace)
before a create, clone or load builds anything, and are registered on
every workspace it builds, so a workspace's own config cannot lift them.
In `jwt` mode every method's `caller.account` is the account that owns the
workspace, so a rule can single one out.

<Tabs>
  <Tab title="Python" icon="/images/python-logo.svg">
    ```python
    import uvicorn

    from mirage.server.app import build_app

    app = build_app(policies=[NoHostFiles()])
    uvicorn.run(app, host="127.0.0.1", port=8765)
    ```
  </Tab>
  <Tab title="TypeScript" icon="/images/typescript-logo.svg">
    ```typescript
    import { buildApp } from '@struktoai/mirage-server'

    const app = buildApp({ policies: [noHostFiles] })
    await app.listen({ host: '127.0.0.1', port: 8765 })
    ```
  </Tab>
</Tabs>

The same rules can be [policy programs](/home/policy/scripts) in a file,
named in `~/.mirage/config.toml` or by `MIRAGE_POLICY_FILE`. The file holds
a profile's `policy` block, plus `pre_workspace`:

```yaml policy.yaml
pre_workspace:
  - script: no_host_files.py
pre_command:
  - script: audit.py
```

```toml ~/.mirage/config.toml
[daemon]
policy_file = "policy.yaml"
```

Where a workspace's connections may go is its own
[`network`](/home/configuration#network). A server that wants a say in it
refuses a config at `pre_workspace`, as it refuses anything else there. In
`jwt` mode the server also refuses the addresses clouds serve machine
credentials at (`169.254.169.254` and the rest of `169.254.0.0/16`,
`fe80::/10`, `fd00:ec2::254`).
