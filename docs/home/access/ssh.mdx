The Mirage server can listen for SSH next to HTTP. The SSH username names the
workspace, every line runs in Mirage's shell, and every file operation goes
through the workspace's mounts.

## Set up

<Steps>
  <Step title="Install the SSH library">
    <Tabs>
      <Tab title="Python" icon="/images/python-logo.svg">
        ```bash
        pip install 'mirage-ai[ssh]'
        ```
      </Tab>
      <Tab title="TypeScript" icon="/images/typescript-logo.svg">
        ```bash
        npm install -g ssh2
        ```
      </Tab>
    </Tabs>
  </Step>
  <Step title="Pick a port">
    ```bash
    mirage config set ssh_port 2222
    ```
    SSH stays off until a port is set.
  </Step>
  <Step title="Authorize your key">
    ```bash
    mkdir -p ~/.mirage/ssh
    cat ~/.ssh/id_ed25519.pub >> ~/.mirage/ssh/authorized_keys
    ```
    Only public keys log in, and the file is read on every login.
  </Step>
  <Step title="Restart the server">
    ```bash
    mirage daemon restart
    mirage workspace create workspace.yaml --id demo
    ```
  </Step>
</Steps>

<Accordion title="Settings">
  An environment variable wins over `~/.mirage/config.toml`, which wins over the
  default.

  | Key | Env var | Default |
  | --- | --- | --- |
  | `ssh_port` | `MIRAGE_SSH_PORT` | unset (off) |
  | `ssh_host` | `MIRAGE_SSH_HOST` | `127.0.0.1` |
  | `ssh_host_key_file` | `MIRAGE_SSH_HOST_KEY_FILE` | `~/.mirage/ssh/host_ed25519_key` |
  | `ssh_authorized_keys` | `MIRAGE_SSH_AUTHORIZED_KEYS` | `~/.mirage/ssh/authorized_keys` |

  The server makes its host key on first start and keeps it, so your
  `known_hosts` entry stays valid.
</Accordion>

## Connect

| Command | Does |
| --- | --- |
| `ssh -p 2222 demo@127.0.0.1` | Open a shell in workspace `demo`. |
| `ssh -p 2222 demo@127.0.0.1 'ls /data \| wc -l'` | Run one line. |
| `ssh -T -p 2222 demo@127.0.0.1 < setup.sh` | Run a script. |
| `sftp -P 2222 demo@127.0.0.1` | Transfer files. |
| `scp -P 2222 notes.txt demo@127.0.0.1:/data/` | Copy a file in. |
| `sshfs -p 2222 -o direct_io demo@127.0.0.1:/ ~/mnt/demo` | Show the workspace as a local folder. |

Each run gets a fresh session, so a `cd` or `export` never leaks between them.
Ctrl-C cancels the running line, and `ssh host cmd` exits with the line's status.
To mount a folder on the machine running Mirage instead, use [FUSE](/home/setup/fuse).

### Over HTTPS

A hosted server carries SSH over its HTTPS port, so it needs no SSH port or key.
`mirage ssh-proxy` relays it with the CLI's token:

```text ~/.ssh/config
Host mirage
  ProxyCommand mirage ssh-proxy %r
```

Then `ssh demo@mirage`, `sftp demo@mirage`, `scp notes.txt demo@mirage:/data/`
and `sshfs -o direct_io demo@mirage:/ ~/mnt/demo` all work. The CLI sends its
token, your [`mirage login`](/home/access/cli#log-in) on a hosted server, and the
login runs under the workspace's default profile.

## Auth (optional)

In `local` and `token` mode, an authorized key opens every workspace under the
workspace's default profile. Options in front of a key in `authorized_keys`
narrow it:

```text ~/.mirage/ssh/authorized_keys
mirage-profile="guarded" ssh-ed25519 AAAA... agent-a
mirage-account="alice",mirage-profile="guarded" ssh-ed25519 AAAA... alice-agent
ssh-ed25519 AAAA... me
```

| Option | Does |
| --- | --- |
| `mirage-profile` | Runs every login of the key under this [agent profile](/home/profiles). The server reads it, so a key cannot pick looser rules. |
| `mirage-account` | Opens only the workspaces this [account](/home/access/http#accounts) created. Another account's workspace answers like a missing one. |

On a [`jwt`](/home/access/http#jwt) server, each login reaches only its
account's workspaces:

| Way in | How |
| --- | --- |
| [Over HTTPS](#over-https) | `mirage login`, then connect through `mirage ssh-proxy`. Your JWT is the account; no key needed. |
| SSH port | The operator adds `mirage-account="you"` to your key. A key without it opens nothing. |

<Accordion title="Account rules in detail">
  - The account holds for shell, exec, `sftp` and `scp` alike.
  - In `local` and `token` mode, a key without `mirage-account` opens every
    workspace.
  - An option that is empty or given twice opens nothing.
</Accordion>

<Accordion title="How sessions behave">
  - Each `ssh`, `sftp` or `scp` run gets a fresh session, closed when it ends.
  - The session's profile and the mount modes apply as in any shell: a
    read-only mount refuses `sftp put`.
  - Output streams as the line prints it.
  - Ctrl-C cancels the running line and sets `$?` to 130. A dropped connection
    cancels it too.
  - The server sends a keepalive every 15 seconds and closes a connection that
    misses three, so a half-open one cancels its line as well.
  - Nothing is forwarded: no ports, no agent, no X11.
</Accordion>
