RPC is a session's in-app API over [JSON-RPC 2.0](https://www.jsonrpc.org/specification).
Each method is named after the call it makes: `shell` is `session.shell`,
`vfs/read` is `session.vfs.read`. Use it when a program drives the workspace and
needs exact bytes, with stdout, stderr and the exit code apart.

Every workspace on the Mirage server answers RPC at:

```
http://127.0.0.1:8765/v1/workspaces/{id}/rpc
```

## Connect

These examples use the `demo` workspace from the [CLI quickstart](/home/access/cli#quickstart).

<Tabs>
  <Tab title="stdio" icon="terminal">
    `mirage rpc` reads one message per line on stdin and writes one answer per
    line on stdout. It starts the server if needed and sends your token.

    ```bash
    echo '{"jsonrpc": "2.0", "id": 1, "method": "shell", "params": {"command": "ls / | wc -l"}}' | mirage rpc -w demo
    ```
  </Tab>
  <Tab title="HTTP" icon="globe">
    One message, or a batch, per `POST`. The answer is the body.

    ```bash
    curl -s http://127.0.0.1:8765/v1/workspaces/demo/rpc \
      -H "Authorization: Bearer $MIRAGE_TOKEN" \
      -H 'Content-Type: application/json' \
      -d '{"jsonrpc": "2.0", "id": 1, "method": "shell", "params": {"command": "ls / | wc -l"}}'
    ```
  </Tab>
</Tabs>

Both answer:

```json
{"jsonrpc": "2.0", "id": 1, "result": {"kind": "io", "exit_code": 0, "stdout": "3\n", "stderr": "", "refusal": null}}
```

Answers come back as calls finish, so match them by `id`.

## Auth

RPC uses the same bearer token as [HTTP](/home/access/http#auth). `mirage rpc`
sends the CLI's token for you: a saved [login](/home/access/cli#log-in),
`MIRAGE_TOKEN`, or the local token file. A client that posts to the URL sends
the header itself.

## Methods

| Method | Params | Result |
| --- | --- | --- |
| `initialize` | | `{server_info, protocol_version, workspace_id, session_id, methods}` |
| `shell` | `command`, `cwd?`, `env?`, `stdin?`, `explain?` | `{kind, exit_code, stdout, stderr, refusal}` |
| `glob` | `pattern` | `string[]`, the matching paths |
| `vfs/<call>` | the call's arguments, `explain?` | what the call returns |
| `tools/<tool>` | the tool's input | `{text, is_error}` |
| `tools/list` | | `{tools}`, as MCP lists them |
| `tools/call` | `name`, `arguments` | `{text, is_error}` |

- `?` marks an optional param.
- `initialize` is optional and creates nothing: it reports the server, and the
  workspace and session the connection uses.
- `vfs/<call>` is each of the 23 [VFS calls](/home/access/http#call-the-vfs),
  with the same arguments and results as HTTP. The [tools](/home/access/mcp#tools)
  take the inputs listed on the MCP page.
- `explain: true` on `shell` or `vfs/<call>` says what it would do and runs
  nothing; see [Explain](/home/policy/explain).
- Bytes, `stdin` included, are base64 strings. A message is at most 4 MiB, so
  send larger stdin over [HTTP](/home/access/http#run-a-shell-line) or SSH.
- A line that exits non-zero is a result, not an error.
- A `glob` that matches more files than a mount's
  [`walk_limit`](/home/integration/search#walk_limit) is the error
  `-32602`, and its message names the limit.

## Sessions

Calls run in the workspace's default session. To use another, add
`?session_id=<id>` to the URL, or `-s <id>` to `mirage rpc`. The session's
[agent profile](/home/profiles) applies to every method.

## Cancel

Send the notification `$/cancelRequest` with the id of a running request. That
request answers `-32800`, and its job ends `canceled`. A dropped HTTP request
cancels its calls too.

```json
{"jsonrpc": "2.0", "method": "$/cancelRequest", "params": {"id": 7}}
```

## Errors

| Code | Means |
| --- | --- |
| `-32700` | The message is not JSON. |
| `-32600` | Not a JSON-RPC 2.0 request: no `"jsonrpc": "2.0"`, or no method. |
| `-32601` | No such method. |
| `-32602` | Bad params. |
| `-32004` | No such path (`ENOENT`). |
| `-32603` | Anything else, such as a refused path. |
| `-32800` | Canceled. |

A file error carries its errno in `data`, plus a `refusal` record when a policy
refused it:

```json
{"jsonrpc": "2.0", "id": 2, "error": {"code": -32004, "message": "No such file or directory", "data": {"detail": "No such file or directory", "errno": "ENOENT"}}}
```
