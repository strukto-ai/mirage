Your agent types into one shell. A machine is what runs a program: an
`in_process` machine runs Python on Monty inside Mirage, and a `docker` machine
runs programs in a container. A route policy looks at each line and picks the
machine for it, or names `workspace` to keep the line in Mirage itself.

## Example

Run small Python snippets on Monty, the training jobs under `/jobs/` on a
CPU container, and the GPU jobs on a GPU container:

```yaml
mode: exec
machines:
  py:
    provider: in_process
    runtime: monty
  box:
    provider: docker
    container: my-box
    captures: ["@python"]
  gpu:
    provider: docker
    container: my-gpu
    captures: ["@python"]
route_policy: {script: ./route.py, runtime: monty}
```

```python route.py
def pre_execute(ctx):
    paths = [p for c in ctx["commands"] for p in c["paths"]]
    if any(p.startswith("/jobs/gpu/") for p in paths):
        return {"kind": "route", "machine": "gpu"}
    if any(p.startswith("/jobs/") for p in paths):
        return {"kind": "route", "machine": "box"}
```

Now `python3 /jobs/gpu/train.py` runs in `my-gpu`, `python3 /jobs/train.py`
runs in `my-box`, and `cat data.csv | python3 -c "..."` stays on Monty.

Without a route, each command goes to the first machine in `machines` that
captures it. Here that is `py` for `python3`.

## What the script returns

| Return | What happens |
| --- | --- |
| `{"kind": "route", "machine": "box"}` | `box` runs every command it captures; the rest stay where they are |
| `{"kind": "route", "machine": "box", "reason": "..."}` | the same, and `ws.explain(line)` shows the reason |
| `{"kind": "route", "machine": "workspace"}` | machines that take whole lines (`@line`) are skipped; a command only they capture is refused |
| `None` | no opinion: the first machine that captures each command runs it |
| `{"kind": "deny", "reason": "..."}` | the line is refused |

A route to a machine that is not under `machines:` fails the line with a
routing error.

The script gets the line, each command with its words and paths, and the
session. It runs on Monty unless the block names another runtime, and
has 10 seconds. If it fails, times out or returns anything else, the line
fails with a routing error. See [Scripts](/home/policy/scripts) for
everything it can read.

## One machine per session

`ctx["session_id"]` tells the script whose line it is, so each agent can
get its own machine:

```yaml
mode: exec
machines:
  alice:
    provider: docker
    container: alice-box
  bob:
    provider: docker
    container: bob-box
route_policy: {script: ./route.py, runtime: monty}
```

```python route.py
def pre_execute(ctx):
    return {"kind": "route", "machine": ctx["session_id"]}
```

## In code

`route_policy` also takes a function. It returns a machine name, a `Route`,
or nothing:

<CodeGroup>

```python Python
from mirage.policy import RouteContext

def route(ctx: RouteContext) -> str | None:
    paths = [p.virtual for c in ctx.commands for p in c.paths]
    return "gpu" if any(p.startswith("/jobs/gpu/") for p in paths) else None

ws = Workspace(mounts, machines=machines, route_policy=route)
```

```typescript TypeScript
const ws = new Workspace(mounts, {
  machines,
  routePolicy: (ctx) =>
    ctx.commands.some((c) => c.paths.some((p) => p.virtual.startsWith('/jobs/gpu/')))
      ? 'gpu'
      : null,
})
```

</CodeGroup>

To pick the machine for one line yourself, pass it to the call:
`ws.shell(line, machine="gpu")`, or `{ machine: 'gpu' }` in TypeScript.

A [policy](/home/policy/policies) in code can return `Route(machine=...)`
too. At `pre_command` it moves one command: in `ls; python3 train.py`, only
`python3` goes to the machine. Behind `nohup`, `nice`, `setsid`, `stdbuf` or
`ionice`, the wrapper goes where its program goes.

## Rules

- A refused line never runs anywhere. A deny beats any route.
- If two policies pick different machines, the line is refused.
- Lines inside a line (`$( )`, `eval`, `source`, `xargs`) run where the
  outer line runs.
- `ws.explain(line)` shows which machine each command would run on.

## Ask a model

A route script can ask an LLM where a line should run. Scripts on Monty have
no network, so the model call is a
[host function](/home/policy/scripts#host-functions). Its answer counts
against the script's 10 seconds. See the example in
[Python](https://github.com/strukto-ai/mirage/tree/main/examples/python/policy/llm_routing)
and
[TypeScript](https://github.com/strukto-ai/mirage/tree/main/examples/typescript/policy/llm_routing).
