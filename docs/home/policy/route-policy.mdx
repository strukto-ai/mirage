When several runtimes can run the same command, the **route policy**
picks one per line. Here `monty` runs `python3` in-process (fast,
stdlib-only) and `docker` runs it in your container (your packages, an
exec round-trip):

```yaml
mode: exec
runtimes:
  - monty # captures python3 by default: sandboxed, stdlib-only
  - name: docker
    captures: ["python3"] # your container, has pandas installed
    config:
      container: my-box
  - workspace
route_policy: ./policy.py
```

```python policy.py
# Jobs under /jobs need the container's packages; anything else
# stays on the fast in-process sandbox. The LAST EXPRESSION is
# the answer.
paths = [p for c in ctx["commands"] for p in c["paths"]]
"docker" if any(p.startswith("/jobs/") for p in paths) else "monty"
```

`python3 /jobs/train.py` runs in the container; `cat data.csv | python3
-c ...` stays on monty.

## Input and answers

The script reads one global, `ctx`: the line, each of its commands with
its words and resolved paths, and the session, the same context a
[policy program](/home/policy/scripts#ctx) gets at `pre_execute`. Its last
expression is the answer:

| Answer | Effect |
| --- | --- |
| `"docker"` | that runtime serves every command it captures |
| `None` | the first capturer in `runtimes` order serves each command |
| anything else | the line fails with a routing error |

Refusing a line is not the route policy's: a policy's `pre_execute`
denies it ([Admit, then route](#admit-then-route)).

In code, `route_policy=` takes a plain function, sync or async, returning
the same:

```python
from mirage.policy import RouteContext

def policy(ctx: RouteContext) -> str | None:
    paths = [p.virtual for c in ctx.commands for p in c.paths]
    return "docker" if any(p.startswith("/jobs/") for p in paths) else None

ws = Workspace(mounts, runtimes=runtimes, route_policy=policy)
```

A runtime entry's own `script:` answers a yes or no: will it serve this
line? It gets the same `ctx` plus `runtime`, its `name` and `captures`,
so it can find the commands it would run. With no placement, the first
willing capturer wins. A runtime a policy places the line on must also say
yes, or the line is refused with `runtimes.<name>` as the refusal's
policy. The caller's `runtime=` argument skips the scripts.

## Admit, then route

The route policy is the built-in answer to the
[policy's](/home/policy/policies#lifecycle) `pre_execute` method, asked before
any coded policy. A coded policy places or refuses a line there:

```python
from mirage.policy import Deny, Policy, Route, RouteContext

class JobsOnDocker(Policy):
    async def pre_execute(self, ctx: RouteContext) -> Route | Deny | None:
        if "/prod/" in ctx.line:
            return Deny("the prod tree is read only")
        return Route("docker") if "/jobs/" in ctx.line else None
```

A line the rules refuse is never placed. A Deny beats any Route, and two
policies naming different runtimes refuse the line. Nested lines (`$( )`,
`eval`, `source`, `xargs`) keep the outer line's placement.
`ws.explain(line)` shows each placement answer and each command's
runtime.

## What runs the scripts

A script runs on an **evaluator runtime** from the `runtimes` list: a
`.py` script on the first Python evaluator (monty by default, or
pyodide), a `.js` one on the first JavaScript evaluator (quickjs).
With no evaluator the first decision fails. A script that runs past 10
seconds fails the line.

## Bring your own

Inherit `EvaluatorMixin` (Python) or implement `Evaluator` with the
`EVALUATOR` brand (TypeScript) on your runtime, and it can evaluate
scripts: `eval(code, inputs=...)` returns the last expression's value.
The docker examples do it by piping a harness to `python3 -`:
[python](https://github.com/strukto-ai/mirage/blob/main/examples/python/runtimes/docker/docker_eval.py),
[typescript](https://github.com/strukto-ai/mirage/blob/main/examples/typescript/runtimes/docker/docker_eval.ts).
