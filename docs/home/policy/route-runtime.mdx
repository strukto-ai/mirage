Mirage’s virtual terminal is not tied to a local terminal or a single kernel.
Your agent uses one shell while Mirage routes commands to in-process,
containerized or remote runtimes.

Use `route_policy` to choose a runtime for each command line with a script
or a function. Here, `monty` runs `python3` in-process, while `machine` runs
it on the `box` machine, a container with your packages. Start the
[Docker container](/home/setup/machine/docker) `my-box` with
`/jobs/train.py` and its dependencies before using this excerpt:

```yaml
mode: exec
machines:
  box:
    provider: docker
    container: my-box
runtimes:
  - monty
  - name: remote
    captures: ["@python"]
    machine: box
  - workspace
route_policy: {script: ./route.py, runtime: monty}
```

```python route.py
def pre_execute(ctx):
    paths = [p for c in ctx["commands"] for p in c["paths"]]
    if any(p.startswith("/jobs/") for p in paths):
        return {"kind": "route", "runtime": "remote"}
```

`python3 /jobs/train.py` runs in the container; `cat data.csv | python3
-c ...` stays on monty.

## Input and Answers

A runtime routing script is a [policy program](/home/policy/scripts) shared
by every session. Its `pre_execute` function takes the same `ctx` a program
gets at `pre_execute`: the line, each of its commands with its words and
resolved paths, and the session. It returns its answer:

| Returns | Effect |
| --- | --- |
| `{"kind": "route", "runtime": "remote"}` | that runtime serves every command it captures |
| `{"kind": "route", "machine": "box"}` | the `remote` runtime runs the line's programs on that machine |
| `{"kind": "route", "runtime": "remote", "reason": "..."}` | the same, with why for `ws.explain(line)` to show |
| `{"kind": "route", "runtime": "workspace"}` | entries that capture `@line` are excluded entirely; other entries still serve their captures, and a command only an excluded entry captures is refused |
| `None` | the first capturer in `runtimes` order serves each command |
| `{"kind": "deny", "reason": "..."}` | the line is refused, as by any `pre_execute` program |

A program that exits non-zero, runs past 10 seconds, or answers anything
else fails the line with a routing error. It runs on its own runtime,
monty unless the block names one, as
[a profile's programs do](/home/policy/scripts#runtimes).

In code, `route_policy=` takes the same block with a `ScriptSource`, or
a plain function, sync or async, returning a runtime name or `None`:

```python
from mirage.policy import RouteContext

def policy(ctx: RouteContext) -> str | None:
    paths = [p.virtual for c in ctx.commands for p in c.paths]
    return "remote" if any(p.startswith("/jobs/") for p in paths) else None

ws = Workspace(mounts, runtimes=runtimes, route_policy=policy)
```

## Admit, Then Route

Runtime selection happens at
[`pre_execute`](/home/policy/policies#lifecycle), before commands run.
Mirage checks `route_policy` first, then any policies defined in code.
These policies can also choose a runtime or refuse a command line:

```python
from mirage.policy import Deny, Policy, Route, RouteContext

class JobsOnTheBox(Policy):
    async def pre_execute(self, ctx: RouteContext) -> Route | Deny | None:
        if "/prod/" in ctx.line:
            return Deny("the prod tree is read only")
        return Route(machine="box") if "/jobs/" in ctx.line else None
```

A `pre_command` policy may answer a Route too, which places that one
command alone: `Route(machine="gpu")` for `python3 train.py` in
`ls; python3 train.py` runs only `python3` there. Behind `nohup`, `nice`,
`setsid`, `stdbuf` or `ionice`, the policy is asked about the program, and
the wrapper runs where the program is placed.

A line the rules refuse is never placed. A Deny beats any Route, and two
policies naming different runtimes or machines refuse the line. Nested
lines (`$( )`, `eval`, `source`, `xargs`) keep the outer line's placement.
`ws.explain(line)` shows each placement answer and each command's runtime
and machine. The caller's `runtime=` and `machine=` arguments place the
line itself.

## Ask a Model

A routing program can ask an LLM where a line runs. A program on monty has
no network, so the model call is a
[host function](/home/policy/scripts#host-functions) that returns the
runtime and a reason, which `explain` shows. The answer counts against the
program's 10 seconds. The example sends each `python3` line to monty or to
the host's Python, on an OpenAI model or on Jev:
[Python](https://github.com/strukto-ai/mirage/tree/main/examples/python/policy/llm_routing)
and
[TypeScript](https://github.com/strukto-ai/mirage/tree/main/examples/typescript/policy/llm_routing).
