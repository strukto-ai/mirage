Your agent types into one shell. A runtime is what runs a command:
`monty` runs Python inside Mirage, `remote` runs programs on a
[machine](/home/setup/machine/overview), and `workspace` is Mirage itself.
A route policy looks at each line and picks the runtime for it.

## Example

Run small Python snippets on monty, and the training jobs under `/jobs/`
on a container:

```yaml
machines:
  box:
    provider: docker
    container: my-box
runtimes:
  - monty
  - name: remote
    captures: ["@python"]
    machine: box
  - workspace
route_policy: {script: ./route.py, runtime: monty}
```

```python route.py
def pre_execute(ctx):
    paths = [p for c in ctx["commands"] for p in c["paths"]]
    if any(p.startswith("/jobs/") for p in paths):
        return {"kind": "route", "runtime": "remote"}
```

Now `python3 /jobs/train.py` runs on `remote`, in `my-box`, and
`cat data.csv | python3 -c "..."` stays on monty.

Without a route, each command goes to the first runtime in `runtimes` that
captures it. Here that is monty for `python3`.

## What the script returns

| Return | What happens |
| --- | --- |
| `{"kind": "route", "runtime": "remote"}` | `remote` runs every command it captures |
| `{"kind": "route", "runtime": "remote", "reason": "..."}` | the same, and `ws.explain(line)` shows the reason |
| `{"kind": "route", "runtime": "workspace"}` | runtimes that take whole lines (`@line`) are skipped; a command only they capture is refused |
| `None` | no opinion: the first runtime that captures each command runs it |
| `{"kind": "deny", "reason": "..."}` | the line is refused |

To also pick the machine, see [Route Machine](/home/policy/route-machine).

The script gets the line, each command with its words and paths, and the
session. It runs on monty unless the block names another runtime, and
has 10 seconds. If it fails, times out or returns anything else, the line
fails with a routing error. See [Scripts](/home/policy/scripts) for
everything it can read.

## In code

`route_policy` also takes a function. It returns a runtime name, a `Route`,
or nothing:

<CodeGroup>

```python Python
from mirage.policy import RouteContext

def route(ctx: RouteContext) -> str | None:
    paths = [p.virtual for c in ctx.commands for p in c.paths]
    return "remote" if any(p.startswith("/jobs/") for p in paths) else None

ws = Workspace(mounts, runtimes=runtimes, route_policy=route)
```

```typescript TypeScript
const ws = new Workspace(mounts, {
  runtimes,
  routePolicy: (ctx) =>
    ctx.commands.some((c) => c.paths.some((p) => p.virtual.startsWith('/jobs/')))
      ? 'remote'
      : null,
})
```

</CodeGroup>

To pick the runtime for one line yourself, pass it to the call:
`ws.shell(line, runtime="remote")`, or `{ runtime: 'remote' }` in
TypeScript.

## Rules

- A refused line never runs anywhere. A deny beats any route.
- If two policies pick different runtimes, the line is refused.
- Lines inside a line (`$( )`, `eval`, `source`, `xargs`) run where the
  outer line runs.
- `ws.explain(line)` shows which runtime each command would run on.

A [policy](/home/policy/policies) in code can return a `Route` too. At
`pre_command` it moves one command: in `ls; python3 train.py`, only
`python3` moves.

## Ask a model

A route script can ask an LLM where a line should run. Scripts on monty have
no network, so the model call is a
[host function](/home/policy/scripts#host-functions). Its answer counts
against the script's 10 seconds. See the example in
[Python](https://github.com/strukto-ai/mirage/tree/main/examples/python/policy/llm_routing)
and
[TypeScript](https://github.com/strukto-ai/mirage/tree/main/examples/typescript/policy/llm_routing).
