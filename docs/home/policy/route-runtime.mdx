Mirage’s virtual terminal is not tied to a local terminal or a single kernel.
Your agent uses one shell while Mirage routes commands to in-process,
containerized or remote runtimes.

Use `route_policy` to choose a runtime for each command line with a script
or a function. Here, `monty` runs `python3` in-process, while `docker` runs
it in a container with your packages. Start the [Docker container](/home/setup/runtime/sandbox/docker)
`my-box` with `/jobs/train.py` and its dependencies before using this excerpt:

```yaml
mode: exec
runtimes:
  - monty
  - name: docker
    captures: ["python3"]
    config:
      container: my-box
  - workspace
route_policy: {script: ./route.py, runtime: monty}
```

```python route.py
import json
import os

ctx = json.loads(os.environ["MIRAGE_POLICY_CTX"])
paths = [p for c in ctx["commands"] for p in c["paths"]]
if any(p.startswith("/jobs/") for p in paths):
    print(json.dumps({"kind": "route", "runtime": "docker"}))
```

`python3 /jobs/train.py` runs in the container; `cat data.csv | python3
-c ...` stays on monty.

## Input and answers

A runtime routing script is a [policy program](/home/policy/scripts) shared
by every session. It reads the same `ctx` a program gets at `pre_execute`:
the line, each of its commands with its words and resolved paths, and
the session. It prints its answer:

| Prints | Effect |
| --- | --- |
| `{"kind": "route", "runtime": "docker"}` | that runtime serves every command it captures |
| `{"kind": "route", "runtime": "docker", "reason": "..."}` | the same, with why for `ws.explain(line)` to show |
| `{"kind": "route", "runtime": "workspace"}` | the line runs in Mirage: no whole-line runtime (an `@line` capture) takes it |
| nothing | the first capturer in `runtimes` order serves each command |
| `{"kind": "deny", "reason": "..."}` | the line is refused, as by any `pre_execute` program |

A program that exits non-zero, runs past 10 seconds, or prints anything
else fails the line with a routing error. It runs on its own runtime,
monty unless the block names one, as
[a profile's programs do](/home/policy/scripts#runtimes).

In code, `route_policy=` takes the same block with a `ScriptSource`, or
a plain function, sync or async, returning a runtime name or `None`:

```python
from mirage.policy import RouteContext

def policy(ctx: RouteContext) -> str | None:
    paths = [p.virtual for c in ctx.commands for p in c.paths]
    return "docker" if any(p.startswith("/jobs/") for p in paths) else None

ws = Workspace(mounts, runtimes=runtimes, route_policy=policy)
```

## Admit, then route

Runtime selection happens at
[`pre_execute`](/home/policy/policies#lifecycle), before commands run.
Mirage checks `route_policy` first, then any policies defined in code.
These policies can also choose a runtime or refuse a command line:

```python
from mirage.policy import Deny, Policy, Route, RouteContext

class JobsOnDocker(Policy):
    async def pre_execute(self, ctx: RouteContext) -> Route | Deny | None:
        if "/prod/" in ctx.line:
            return Deny("the prod tree is read only")
        return Route("docker") if "/jobs/" in ctx.line else None
```

A line the rules refuse is never placed. A Deny beats any Route, and two
policies naming different runtimes refuse the line. Nested lines (`$( )`,
`eval`, `source`, `xargs`) keep the outer line's placement.
`ws.explain(line)` shows each placement answer and each command's
runtime. The caller's `runtime=` argument places the line itself.

## Ask a model

A routing program can ask an LLM where a line runs. A program on monty has
no network of its own, so the call to the model is a
[host function](/home/policy/scripts#host-functions) you write, with
structured output limiting the answer to your runtimes. The program keeps
the prompt:

```yaml workspace.yaml
runtimes: [monty, local, workspace]
route_policy:
  script: ./route.py
  runtime: monty
  env:
    MODEL: gpt-6-luna
```

```python route.py
import json
import os

PROMPT = (
    "Pick the runtime that can run the Python code in this line, monty "
    "when it can, and say why in one sentence.\n"
    "monty: Mirage's sandboxed Python: a subset of the language and part of "
    "the standard library, with no packages, network or subprocesses\n"
    "local: the host's full Python: the whole language and standard library "
    "and any installed package, with the host's files and network"
)

ctx = json.loads(os.environ["MIRAGE_POLICY_CTX"])
if any(c["command"] == "python3" for c in ctx["commands"]):
    choice = await parse_runtime(os.environ["MODEL"], PROMPT, ctx["line"])
    print(json.dumps({"kind": "route", **choice}))
```

```python config.py
class RuntimeChoice(BaseModel):
    runtime: Literal["monty", "local"]
    reason: str
```

```python utils.py
async def parse_runtime(model: str, prompt: str, line: str) -> dict[str, str]:
    done = await AsyncOpenAI().responses.parse(
        model=model, instructions=prompt, input=line, text_format=RuntimeChoice
    )
    return done.output_parsed.model_dump()
```

```python main.py
ws = Workspace(**config.to_workspace_kwargs(), policy_functions={"parse_runtime": parse_runtime})
```

`ws.shell(line)` runs each line where the model sends it. `ws.explain(line)`
previews the choice and its reason without running anything. `main.py`
prints the plan, then runs the line:

```
$ python3 -c "print(sum(range(1, 101)))"
  plan: allow
    route monty: Monty supports Python's built-in `range`, `sum`, and `print`, so it can run this line.
      by RoutePolicy
  output: 5050
$ python3 -c "import sqlite3; print(sqlite3.sqlite_version)"
  plan: allow
    route local: This command requires the sqlite3 module, which is not available in Monty's limited standard-library subset.
      by RoutePolicy
  output: 3.50.4
```

The model's answer counts against the program's 10 seconds. The full
example:
[Python](https://github.com/strukto-ai/mirage/tree/main/examples/python/policy/llm_routing)
and
[TypeScript](https://github.com/strukto-ai/mirage/tree/main/examples/typescript/policy/llm_routing).
