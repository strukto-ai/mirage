The [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/overview) builds agents on the same loop as Claude Code. Mirage hands it a `Workspace` as an in-process MCP server, so every file and shell call the agent makes runs in the workspace, not on the host. To run the `claude` CLI itself on a workspace, see [Claude Code](/home/agents/claude-code).

## Install

```bash
uv add 'mirage-ai[claude-agent-sdk]'
```

## Usage

`build_options` returns a `ClaudeAgentOptions` that registers the Mirage server, turns off Claude's built-in tools, allows Mirage's and sets a system prompt describing the mounts:

```python
import asyncio

from claude_agent_sdk import ResultMessage, query

from mirage import MountMode, RAMVFS, Workspace
from mirage.agents.claude_agent_sdk import build_options


async def main() -> None:
    ws = Workspace({"/": RAMVFS()}, mode=MountMode.WRITE)
    try:
        options = await build_options(ws)
        options.model = "claude-sonnet-5-5"
        async for msg in query(
            prompt="Write 'hi from mirage' to /hello.txt, then cat it.",
            options=options,
        ):
            if isinstance(msg, ResultMessage):
                print(msg.result)
    finally:
        await ws.close()


asyncio.run(main())
```

`build_options(ws, session_id="agent")` runs the tools as a session made with [`ws.session`](/python/access/in-app#workspace-methods), under its profile. `system_prompt=` replaces the default prompt.

## Tools

The server serves the session's seven tools, [`session.tools`](/python/access/in-app#session-tools): `shell`, `read`, `write`, `edit`, `ls`, `grep` and `glob`, named `mcp__mirage__<tool>` in the SDK. It carries only the ones the session's profile leaves it, so a read-only workspace gets no `write` or `edit`.

## Other MCP servers

`MirageServer` is the server alone. Put it next to other servers in a `ClaudeAgentOptions` of its own:

```python
from claude_agent_sdk import ClaudeAgentOptions

from mirage.agents.claude_agent_sdk import MirageServer, build_system_prompt

options = ClaudeAgentOptions(
    mcp_servers={"mirage": MirageServer(ws), "github": github_server},
    allowed_tools=["mcp__mirage__*", "mcp__github__*"],
    tools=[],
    system_prompt=await build_system_prompt(workspace=ws),
)
```

`tools=[]` keeps Claude's built-in tools out, and `allowed_tools` lets the listed servers run without a permission prompt.

## Keep Claude's Bash

To keep Claude's own Bash tool and run it in a workspace, point the SDK at `mirage-bash`, as for [Claude Code](/home/agents/claude-code#shell). Mirage's other tools come over [`mirage mcp`](/home/access/mcp) in place of Claude's file tools. Both reach one workspace that the Mirage daemon serves:

```bash
mirage workspace create workspace.yaml --id demo
```

```python
import shutil

from claude_agent_sdk import ClaudeAgentOptions

options = ClaudeAgentOptions(
    cwd="/Users/me/project",
    env={
        "CLAUDE_CODE_SHELL": shutil.which("mirage-bash"),
        "MIRAGE_WORKSPACE": "demo",
    },
    mcp_servers={
        "mirage": {"type": "stdio", "command": "mirage", "args": ["mcp", "-w", "demo"]},
    },
    allowed_tools=["Bash", "mcp__mirage__*"],
    disallowed_tools=["Read", "Edit", "Write", "Glob", "Grep", "mcp__mirage__shell"],
)
```

- Bash runs in the workspace. Mirage's `read`, `write`, `edit`, `ls`, `grep` and `glob` replace Claude's Read, Edit, Write, Glob and Grep, so every file the agent touches goes through Mirage.
- Mount the project and `/tmp` at their own paths, as the [Claude Code page](/home/agents/claude-code#workspace) shows, so `cd` carries over.
- To run under a [profile](/home/configuration/session), create a session with `mirage workspace session create -w demo -s agent -p reviewer`, set `MIRAGE_SESSION` to `agent` and add `-s agent` to the `mirage mcp` arguments.
