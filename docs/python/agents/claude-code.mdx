[Claude Code](https://github.com/anthropics/claude-code) can load Mirage's MCP tools and skills as a plugin. A [FUSE mount](/python/setup/fuse) also lets Claude Code's built-in filesystem tools access a workspace through a real directory.

## Install the plugin

In Claude Code, add the repository as a marketplace and install Mirage:

```text
/plugin marketplace add strukto-ai/mirage
/plugin install mirage@mirage
```

For local development, replace `strukto-ai/mirage` with the path to a Mirage checkout. Restart Claude Code after installation, then check `/plugin` and `/mcp` for the plugin and its tool server.

The plugin includes the `mirage-filesystem` and `mirage-vfs-authoring` skills, plus the shared Mirage MCP server. The server requires Node.js 20.10 or newer and launches with `npx -y @struktoai/mirage-cli mcp`.

## Configure a workspace

Create `.mirage/workspace.yaml` in the project where you start Claude Code:

```yaml
mounts:
  /scratch:
    vfs: ram
  /data:
    vfs: disk
    config:
      root: ${PWD}/data
```

Create the project's `data` directory for the disk mount. Mirage searches the current directory and its parents for the workspace config; set `MIRAGE_MCP_CONFIG` to an absolute config path when it lives elsewhere.

Ask Claude to use Mirage to list mounted files, search `/data`, or write notes to `/scratch`. The plugin's `shell`, `read`, `write`, `edit`, `ls`, `grep`, and `glob` tools operate on virtual paths. Claude Code's built-in file tools use host paths; use the FUSE setup below to expose the workspace to those tools too. See [MCP](/home/mcp) for the server lifecycle and configuration.

## Use a FUSE mount

Install Mirage's FUSE dependencies:

```bash
uv add 'mirage-ai[fuse]'
```

Then install [Claude Code](https://docs.claude.com/en/docs/claude-code/setup) separately.

### Usage

```python
from mirage import Mount, MountBackend, MountMode, Workspace
from mirage.vfs.ram import RAMVFS
from mirage.vfs.s3 import S3Config, S3VFS

s3 = S3VFS(S3Config(bucket="my-bucket"))

with Workspace(
    {"/": Mount(RAMVFS(), mode=MountMode.WRITE, backend=MountBackend.FUSE),
     "/s3": Mount(s3, mode=MountMode.READ)},
) as ws:
    print(f"cd {ws.fuse_mountpoint} && claude")
    input("Press Enter when done...")
```

The mountpoint behaves like a regular directory. `claude` reads, writes, runs `bash`, and patches files just like it would on a normal disk, every operation goes through Mirage's ops layer, so writes to `/s3/...` hit S3, writes to `/` stay in RAM.

### How FUSE integrates with Claude Code

FUSE presents a real directory to Claude Code's built-in tools. Every filesystem operation passes through Mirage's ops layer.

You lose:
- Per-tool prompt customization
- Observation hooks on tool calls
- Mirage's op-record telemetry on the agent's specific calls (host syscalls aren't recorded the same way)

You gain:
- Zero integration effort
- Compatibility with every Claude Code feature, including future ones
- The same approach works for any other directory-based agent ([OpenAI Codex](/python/agents/codex), `aider`, etc.)
