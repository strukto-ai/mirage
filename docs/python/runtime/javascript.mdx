`node` and `js` are two names for one command, run by the `quickjs` runtime
(the default): [quickjs-ng](https://github.com/quickjs-ng/quickjs) compiled
to WebAssembly and run in-process on [wasmtime](https://wasmtime.dev). It
sees the workspace mounts, and no host files or network.

It is for **small scripts and pipe transforms**: compute, JSON, regex text
processing, code generation. It is a bare ES2023 engine (ES modules, `JSON`,
`Promise`, top-level await), **not** Node: no `require`, npm, `process`,
`fs` or `fetch`.

```bash
js -e "console.log(6 * 7)"                 # inline
node /data/transform.mjs arg1 arg2         # a mounted script, args in scriptArgs
cat data.json | node -e "const d = JSON.parse(std.in.readAsString()); console.log(d.length)"
```

## Programs

- `-e <code>` runs the argument, a file runs a mounted script, and with
  neither, piped stdin is the program.
- A `.mjs` file runs as an ES module; `.js` and `-e` run as classic scripts.
  `-m` (`--module`) forces module mode:
  `js -m -e "const x = await Promise.resolve(41); console.log(x + 1)"`.
- `scriptArgs` holds the words after the code or script, and
  `std.in.readAsString()` reads stdin.
- Output follows quickjs-ng: `console.log` and `print` add a newline,
  `std.out.puts`/`std.err.puts` write raw, `std.out.printf`/`std.err.printf`
  return the characters written, and there is no `console.error`.
- A run starts in the session's cwd (a direct `run()` can pass
  `RunArgs.cwd`). `os.getcwd()` returns `[directory, 0]`, and
  `os.chdir(path)` returns `0` or a negative WASI errno; a change lasts for the
  run only.

Scripts behave the same in the TypeScript `quickjs` runtime.

## Files

- `std.open('/data/f.txt', 'r')` reads the mount live, and `os.stat`,
  `os.mkdir`, `os.rename`, `os.remove` and `os.utimes` change it (0 or a
  negative WASI errno). Writes show to every command at once.
- File calls get the same cache, write modes and session narrowing as `cat`.
  On a read-only mount, or a session narrowed to read, `std.open` returns
  `null`.
- There are no extended-attribute calls; use `getfattr` and `setfattr`.

The engine is capability-isolated: it cannot reach host files or the
network, but only `command_limits` bound its CPU and memory. Run untrusted or
heavy code in a [sandbox runtime](/python/runtime/sandbox).

## Setup

Install the extra and download `qjs-wasi.wasm` from a
[quickjs-ng release](https://github.com/quickjs-ng/quickjs/releases), then
point the config `home` (or `MIRAGE_QUICKJS_HOME`) at its directory:

```bash
pip install mirage-ai[quickjs]
```

```python
from mirage.runtime.js import QuickJsRuntime

ws = Workspace({"/data": RAMVFS()}, mode=MountMode.EXEC,
               runtimes=[QuickJsRuntime(config={"home": "/path/to/qjs-dir"}), "workspace"])
```

```yaml
runtimes:
  - name: quickjs
    config:
      home: /path/to/qjs-dir
  - workspace
```

The first run compiles `qjs-wasi.wasm` and caches `qjs-wasi.cwasm` beside
it; later runs boot in milliseconds.

## Resource limits

`command_limits` apply to `node` and `js` as to any command: past
`timeout_seconds` a run exits 124, and `max_bytes` and `max_lines` cap its
output. Each run has its own epoch-interruption engine, so the deadline traps
the run and frees its thread.

## Route policy

`quickjs` can evaluate expressions, so it can run a
[route policy](/home/policy/route-policy): `route_policy: ./policy.js` runs per line
with `ctx` as a global, and the last expression names the runtime.
