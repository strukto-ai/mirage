Query Airtable bases, tables, records and comments, and create, update or delete records. Mirage defines this command tree over the [Airtable Web API](https://airtable.com/developers/web/api/introduction).

## Setup

Create a token with the scopes in [Airtable setup](/home/setup/airtable). Reads need record and schema read scopes; writes and comments need their corresponding write scopes.

```python
from mirage import Workspace
from mirage.commands.cli.builtin.airtable import AIRTABLE
from mirage.core.airtable.config import AirtableConfig

config = AirtableConfig(token="pat_...")
ws = Workspace({})
ws.register_cli("airtable", AIRTABLE, config)
```

No service mount is required. For YAML and multiple accounts, see the
[CLI overview](/python/cli/index#register-a-cli).

## Supported commands

Run `airtable <command> --help` for the supported flags and operands.
This list is generated from Mirage's registered command tree.

| Command | Description |
| --- | --- |
| `airtable base list` | List the bases the token reaches as JSON |
| `airtable base get` | Get one base and its tables (base.json) |
| `airtable table get` | Get one table's fields and views (table.json) |
| `airtable record list` | List records as JSONL (records.jsonl) |
| `airtable record get` | Get one record as a JSONL line |
| `airtable record create` | Create records from --fields or stdin |
| `airtable record update` | Update records' cells (PATCH) from RECORD --fields or stdin |
| `airtable record delete` | Delete records by RECORD or from stdin |
| `airtable comment list` | List a record's comments, newest first |
| `airtable comment add` | Comment on a record |

## Read and filter records

```bash
airtable base list
airtable table get --base appRoadmapBase001 Features
airtable record list --base appRoadmapBase001 --table tblFeatures000001 --formula "{Status} = 'Done'"
airtable record get --base appRoadmapBase001 --table tblFeatures000001 recFeat0000000003
airtable comment list --base appRoadmapBase001 --table tblFeatures000001 recFeat0000000003
```

`--base` takes a base ID. `--table` takes a table ID or name. Find these in
API output or in the VFS's `name__id` directory names; record lines carry
`record_id` explicitly. `--formula` and `--view` filter on the server.

`base list` and `comment list` return JSON arrays. `base get` and `table get`
return the same schema objects as the mount. Record commands return JSONL.

## Write records

```bash
airtable record create --base appRoadmapBase001 --table tblFeatures000001 --fields '{"Name":"Search"}'
airtable record update --base appRoadmapBase001 --table tblFeatures000001 recFeat0000000003 --fields '{"Status":"Done"}'
airtable record delete --base appRoadmapBase001 --table tblFeatures000001 recFeat0000000003
echo 'Ready to ship' | airtable comment add --base appRoadmapBase001 --table tblFeatures000001 recFeat0000000003
```

For bulk writes, pipe record JSONL into `record create`, `record update` or
`record delete` without the single-record arguments:

```bash
jq -c 'select(.fields.Status == "Todo") | .fields.Status = "Done"' /work/records.jsonl \
  | airtable record update --base appRoadmapBase001 --table tblFeatures000001
```

| Operation | Required fields in each stdin line |
| --- | --- |
| `record create` | `fields`; existing `record_id` and `created_time` are ignored |
| `record update` | `record_id` and `fields`; omitted fields remain unchanged |
| `record delete` | `record_id` |

Each line may contain only `record_id`, `created_time` and `fields`. Mirage
validates every line before the first request, drops computed fields from
stdin writes, and sends batches of at most ten records. Inline `--fields`
is sent as given. Use `--typecast` to allow Airtable's type conversion.

## VFS and limits

The optional [Airtable VFS](/python/vfs/airtable) exposes bases and tables as
files. Record output uses the same JSONL shape, so mounted records can feed
the CLI through stdin. The CLI uses its own account config and needs no
Airtable mount.

- `base_ids` restricts accessible bases, including writes; an excluded base
  is refused before a request.
- Without `--max-records`, a list exceeding `max_read_records` fails with
  exit 1. An explicit `--max-records N` sets the requested cap.
- Bad flags, malformed JSON and invalid stdin lines exit 2. API failures
  exit 1. A partial write prints the completed records and exits 1; it
  does not roll them back.
- Requests use the config's per-base rate limit. Reads retry `429`, `502`
  and `503`; writes retry only `429`, to avoid repeating a write that may
  already have succeeded.

The service is reached by IDs and the CLI's config. Input files such as
`/work/records.jsonl` enter through shell stdin; they can live on any
readable workspace mount.

This is Mirage's Apache-2.0 command implementation for the Web API.
No compatibility with a separate Airtable CLI is claimed; the API link
documents the service rather than an upstream CLI implementation. See
[compatibility and licenses](/home/setup/clis#compatibility-and-licenses).
