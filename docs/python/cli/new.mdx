A custom CLI gives an agent your own command, with fixed subcommands and
flags: a client for your service, a tool over workspace files, or a script.
For a typed `CLI`, Mirage parses each line, refuses a bad one and generates
`--help` and `man`. A script CLI is a program that reads its own arguments.

A typed CLI declares its grammar with `CommandSpec`, the same parser Mirage's
built-in commands use, so its `--help`, error messages and exit codes work
the same way as theirs.

[Custom CLI Reference](/python/cli/new-reference) lists the fields of `CLI`,
`CommandSpec`, `Argument` and `Context`.

## Write a typed CLI

A handler gets the same four arguments a shell command's handler gets: the
install's accessor, the path operands, the text operands and a `Context`.
Mirage builds the accessor once per install from the install's validated
config, and closes it when the install goes. The default `NOOPAccessor` only
holds that config, at `accessor.config`.

```python
from typing import Literal

from pydantic import BaseModel, ConfigDict

from mirage import (Argument, CLI, CLIHandler, CommandSpec, Context,
                    FlagView, PathSpec, Workspace)
from mirage.accessor import NOOPAccessor
from mirage.io import IOResult

class PagerConfig(BaseModel):
    model_config = ConfigDict(extra="forbid")
    account: Literal["engineering", "support"]

async def acknowledge(
    accessor: NOOPAccessor,
    paths: list[PathSpec],
    texts: list[str],
    ctx: Context,
) -> tuple[bytes, IOResult]:
    incident_id = texts[0]
    by = FlagView(ctx.flags, ctx.spec).as_str("by")
    account = accessor.config.account
    return f"[{account}] acknowledged {incident_id} by {by}\n".encode(), IOResult()

PAGER = CLI(
    spec=CommandSpec(
        name="pager",
        subcommands=(CommandSpec(
            name="ack",
            arguments=(
                Argument("INCIDENT_ID"),
                Argument("--by", required=True),
            ),
        ),),
    ),
    handlers={"ack": CLIHandler(fn=acknowledge, write=True)},
    config_model=PagerConfig,
)

ws = Workspace({})
ws.register_cli("pager-eng", PAGER, {"account": "engineering"})
ws.register_cli("pager-support", PAGER, {"account": "support"})

for line in ["pager-eng ack INC-1 --by sam", "pager-support ack INC-2 --by kim"]:
    r = await ws.shell(line)
    print(await r.stdout_str(), end="")
```

```text
[engineering] acknowledged INC-1 by sam
[support] acknowledged INC-2 by kim
```

One CLI, installed twice, serves two accounts. Without `--by`, Mirage refuses
the line before `acknowledge` runs and exits 2:

```text
pager-eng ack: option '--by' is required
Try 'pager-eng ack --help' for more information.
```

The runnable [pager example](https://github.com/strukto-ai/mirage/blob/main/examples/python/cli/pager.py)
adds an incident service the handlers change.

### Command shape

| Node | Declares | Its handler gets |
| --- | --- | --- |
| Leaf | `arguments` and a `CLIHandler` | Path and text operands, and parsed flags on `ctx` |
| Group | `subcommands`, and options its leaves inherit | No handler; Mirage runs the leaf the line names |

- In `arguments`, a dashed name such as `--by` declares an option and a bare
  name such as `INCIDENT_ID` declares a positional. Declare a file operand
  with `type="path"`; a service ID stays a text operand.
- `CLI.handlers` maps each leaf's path below the root to its `CLIHandler`:
  `"ack"`, `"incident ack"`, or `""` for a program with no subcommands.
- Names and aliases are single words, and a group's children share one set
  of names. An option can't repeat in a parent and its child.
- `CLI(...)` refuses a bad tree when you build it, and Mirage refuses a bad
  line before the handler runs.
- Read flags through `FlagView(ctx.flags, ctx.spec)`. Reading an option the
  spec doesn't declare raises an error, instead of looking like an omitted
  flag.
- `config_model` validates each install's config when you register it.
  Without one, the CLI takes no config and `accessor.config` is `None`.
- Mark a handler that changes the service `write=True`. Policy reads it as
  `CommandContext.write`, so one `pre_command` method can refuse every
  writing subcommand, and Mirage drops cached mount listings after it runs.
  It grants no permission.
- Descriptions on the spec, its options and operands become `--help` and
  `man` at every level.

### Output and status

A handler returns `(stdout, IOResult)`. `stdout` is `bytes`, an async iterator
of `bytes` for output that arrives in pieces, or `None`. The `IOResult` carries
the exit status and stderr. Piped input arrives on `ctx.stdin` as bytes, an
async byte source, or `None` when nothing is piped; `materialize` reads all of
it.

```python
from collections.abc import AsyncIterator

from mirage import Context, PathSpec, UsageError
from mirage.accessor import NOOPAccessor
from mirage.io.types import IOResult, materialize

async def count(accessor: NOOPAccessor, paths: list[PathSpec],
                texts: list[str], ctx: Context) -> tuple[bytes, IOResult]:
    if ctx.stdin is None:
        raise UsageError("pipe incident IDs on stdin")
    lines = (await materialize(ctx.stdin)).splitlines()
    return f"{len(lines)}\n".encode(), IOResult()

async def watch(accessor: NOOPAccessor, paths: list[PathSpec],
                texts: list[str], ctx: Context) -> tuple[AsyncIterator[bytes], IOResult]:
    async def events() -> AsyncIterator[bytes]:
        for incident_id in texts:
            yield f"{incident_id} open\n".encode()
    return events(), IOResult()

async def close(accessor: NOOPAccessor, paths: list[PathSpec],
                texts: list[str], ctx: Context) -> tuple[None, IOResult]:
    message = f"{texts[0]} is already closed\n"
    return None, IOResult(exit_code=1, stderr=message.encode())
```

Bound as `pager count`, `pager watch INCIDENT_ID...` and
`pager close INCIDENT_ID`:

| Line | Prints | Exit |
| --- | --- | --- |
| `printf 'INC-1\nINC-2\n' \| pager-eng count` | `2` | 0 |
| `pager-eng count` | `pipe incident IDs on stdin` on stderr | 2 |
| `pager-eng watch INC-1 INC-2` | `INC-1 open` and `INC-2 open` | 0 |
| `pager-eng close INC-9` | `INC-9 is already closed` on stderr | 1 |

`UsageError(message, exit_code=2)` prints its message to stderr and sets the
exit status, and the rest of the line keeps running.

A CLI that prints paths from its own data, as `git` prints its index, returns
rows instead of bytes. Each row names the path it shows. Mirage drops the rows
the session can't see, then calls your renderer with the rest, so no line,
count or column width gives a hidden path away:

```python
from dataclasses import dataclass

from mirage import Context, PathSpec
from mirage.accessor import NOOPAccessor
from mirage.io.types import IOResult, Rows


@dataclass(frozen=True)
class Entry:
    path: PathSpec
    size: int


async def render(shown: list[Entry]) -> bytes:
    lines = [f"{entry.path.virtual} {entry.size}\n" for entry in shown]
    return "".join([*lines, f"{len(shown)} files\n"]).encode()


async def tracked(
    accessor: NOOPAccessor,
    paths: list[PathSpec],
    texts: list[str],
    ctx: Context,
) -> tuple[None, IOResult]:
    # The CLI's own record of the files it tracks.
    kept = {"/data/a.txt": 1, "/data/b.txt": 3}
    entries = [Entry(PathSpec.from_str_path(p), n) for p, n in kept.items()]
    return None, IOResult(rows=Rows(entries, render))
```

The renderer runs inside the command's timeout. A handler returns rows or
stdout, not both.

### Files and the session

Build the service client in `CLI.accessor`, from the install's config, so
every call on one install shares one client. Don't look for a matching VFS to
borrow its credentials or accessor; share core service functions and accessor
classes between a CLI and a VFS instead.

`ctx.vfs` is the session's files, with workspace policy and mount modes
applied: `read`, `write`, `stat`, `readdir`, `symlink`, `readlink` and the
rest, the same API as `session.vfs`.

- Keep the `PathSpec` a `type="path"` operand gives you, and derive paths
  with `join` and `parent`. For a path string from config, use
  `PathSpec.from_str_path(value, cwd=ctx.cwd)`.
- `ctx.vfs.stat(path, nofollow=True)` reports a link itself.
- `ctx.vfs.mount_of(path)` names the mount serving a path,
  `ctx.vfs.is_mount(path)` says whether a path is a mount root, and
  `ctx.vfs.submounts(path)` lists the mounts below a folder. A mount the
  session hides shows as the nearest folder above it that the session sees,
  so a CLI that removes a folder can refuse without learning the hidden name.
- `ctx.vfs` is `None` when your code calls a handler directly; a handler
  that needs files raises `UsageError` then.

After an install's write, Mirage drops the caches of every mount its accessor
may reach, even when the write failed, since it may still have reached the
service. Override `Accessor.reaches(peer)` to return `False` for a mount's
accessor your writes can't change; by default an accessor reaches every
mount. A script CLI marked as a write drops them too, since Mirage can't see
what it touched. A CLI with no config that works on files, such as `git`,
needs none of this: Mirage drops the cache of each path it writes.

`ctx.env` is a copy of the environment taken when the command starts.
`ctx.session` reads and writes the live session under the shell's rules, so
writing a readonly or hidden variable fails. Reads are plain calls. Writes are
coroutines: await them, or they never happen.

| Call | Does |
| --- | --- |
| `get(name)` | Returns the variable's value, or `None` |
| `snapshot()` | Returns every variable the session can see, as a `dict` |
| `await set(name, value)` | Sets the variable, as `NAME=value` does |
| `await unset(name)` | Removes the variable |
| `is_readonly(name)` | Whether `readonly` has marked the variable |
| `cwd()` | Returns the session's working directory |
| `session_id` | The session's ID |

A `login` leaf for the pager CLI. Add `CommandSpec(name="login")` to its
`subcommands` and `"login": CLIHandler(fn=login)` to its `handlers`:

```python
async def login(accessor: NOOPAccessor, paths: list[PathSpec],
                texts: list[str], ctx: Context) -> tuple[None, IOResult]:
    if ctx.session is None:
        raise UsageError("needs a workspace session")
    await ctx.session.set("PAGER_ACCOUNT", accessor.config.account)
    return None, IOResult()
```

After `pager-eng login`, `echo $PAGER_ACCOUNT` prints `engineering`. If
`PAGER_ACCOUNT` is readonly, the command exits 1 with
`pager-eng login: PAGER_ACCOUNT: readonly variable`. To run another command
from a handler, use `await ctx.shell(line)`; see [`Context`](/python/cli/new-reference#context).

### On a mount

A typed CLI registered on a mount runs its subcommands there, with the
mount's accessor, so it declares no `config_model`, `accessor` or `script`:

```python
from mirage import MountMode, RAMVFS
from mirage.accessor.ram import RAMAccessor

async def tag(accessor: RAMAccessor, paths: list[PathSpec],
              texts: list[str], ctx: Context) -> tuple[None, IOResult]:
    accessor.store.files["/" + paths[0].vfs_path] = " ".join(texts).encode()
    return None, IOResult()

NOTES = CLI(
    spec=CommandSpec(name="notes", subcommands=(CommandSpec(
        name="tag",
        arguments=(Argument("note", type="path"), Argument("tags", nargs="+")),
    ),)),
    handlers={"tag": CLIHandler(fn=tag, write=True)},
)

ws = Workspace({"/notes/": RAMVFS()}, mode=MountMode.WRITE)
ws.mount("/notes/").register_commands([NOTES])
```

`notes tag /notes/a.md draft` parses, shows help and refuses bad flags the
same way an installed CLI does.

- It runs on the working directory's mount when that mount has `notes`.
- Otherwise a writing subcommand runs on the only writable mount that has
  it. With two, Mirage refuses the line and names both; `cd` into one.
- A read-only subcommand runs on the first mount that has it.
- `--help` works from anywhere.
- A VFS gives the same tree to every mount of it with `commands=[NOTES]`.
- Its handlers reach the backend directly, without Mirage's file layer. A
  writing one must declare `write=True`; it runs only on a writable mount,
  and Mirage drops cached listings after it.

## Script CLIs

A script CLI is a program file that reads its own arguments and needs no
Mirage imports:

```yaml
machines:
  monty:
    provider: in_process
    runtime: monty
clis:
  pager:
    script: ./cli/pager.py
    machine: in_process
    config:
      width: 80
```

It runs on the [machine](/home/setup/machine/overview) its entry names, as
[Script CLIs](/home/setup/runtime/overview#script-clis) describes; without a
`machines` entry for its language it exits 127. Mirage embeds the file when
the workspace loads.

- Words after the command name arrive as argv, and `argv[0]` is the
  installed name, so two installs can tell themselves apart. A script
  declares no Mirage grammar, so every option reaches it unchanged,
  `--help` included. A script CLI built in code can add a `CommandSpec` to
  get Mirage's parsing and help.
- Piped input arrives on stdin.
- Config arrives as JSON in `MIRAGE_CLI_CONFIG`, alongside the session's
  environment. Changes the program makes to its environment stay with it.
- Its stdout, stderr and exit status become the command's.
- A script CLI takes no `config_model`, subcommands or handlers.

| Runs on | Arguments | Standard input |
| --- | --- | --- |
| Monty | `argv` global | `stdin` global |
| WASI, `host` machine | `sys.argv` | `sys.stdin` |
| QuickJS | `scriptArgs` | `std.in` |

Monty, WASI and QuickJS read and write workspace files but have no network
and no extra packages. Use `machine: host` to run the host's own interpreter
when the script needs more.

## Install it

`ws.register_cli(name, cli, config)` installs a typed or script CLI under
`name`. The agent types that name, `pager-eng`, not the spec's name, `pager`.

To install a typed CLI from workspace YAML, register its spec first, then
load the workspace:

```python
from mirage import register_cli_spec

register_cli_spec(PAGER)
```

```yaml
clis:
  pager-eng:
    cli: pager
    machine: in_process
    config:
      account: engineering
```

A script CLI needs no registration: its entry names the file with `script:`,
as in [Script CLIs](#script-clis).

`cli:` can also point at `module:ATTR` or `./file.py:ATTR`; a relative file
resolves next to the YAML file. A Python package can publish a CLI without
import side effects through an entry point:

```toml
[project.entry-points."mirage.clis"]
pager = "my_package.cli:PAGER"
```

- A registered name or a builtin wins over a `module:ATTR` reference or an
  entry point.
- Registering a name another registration or a builtin already holds fails.
  A registration may shadow an entry point.
- Only your code can install or remove a CLI. The shell has no `install`
  command, so an agent can't remove one. A shell function can still shadow
  a CLI, as in bash; refuse that with a `pre_command` policy.

See [CLI entries](/home/configuration/workspace#cli-entries) for every
`clis` key.

## Snapshots and credentials

A snapshot saves a typed CLI install by its spec name, and redacts the
config fields `config_model` declares as Pydantic secrets.

- Loading the snapshot needs fresh config for that install through `clis=`;
  Mirage refuses to restore a redacted credential as if it were real.
- The loading process must also resolve the spec name, or pass
  `(cli, config)` as that install's `clis=` entry.
- `Workspace.copy` carries a CLI installed in code, with its real config.

A script CLI's snapshot embeds the script, and saves its config as it is,
since there is no config model to mark secrets. Keep credentials in the
environment, or pass fresh config through `clis=` when loading.
