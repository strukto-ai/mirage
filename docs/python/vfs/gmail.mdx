The Gmail VFS exposes a Gmail account as a virtual filesystem
mounted at some prefix such as `/gmail/`.

For Google OAuth setup, see [Google Workspace Setup](/home/setup/google).

## Config

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.gmail import GmailConfig, GmailVFS

config = GmailConfig(
    client_id=os.environ["GOOGLE_CLIENT_ID"],
    client_secret=os.environ["GOOGLE_CLIENT_SECRET"],
    refresh_token=os.environ["GOOGLE_REFRESH_TOKEN"],
)
vfs = GmailVFS(config=config)
ws = Workspace({"/gmail": vfs}, mode=MountMode.READ)
```

          "attachments": [

              "mime_type": "application/pdf", "size": 12345 }
          ]
        }

      <subject>__<message-id>/ (same name as the .gmail.json file but without
      the extension). Cat a file inside to download bytes. grep -r over a
      date dir skips these binary files automatically.

      After a grep/rg hit, the result line points to .../<subject>__<id>.gmail.json
      — the sibling attachments dir is NOT in grep output. Once you have the
      message id (or the .gmail.json path), ls the same path with .gmail.json
      stripped to list attachments directly:
        ls /<path>/INBOX/2026-05-03/<subject>__<message-id>/
      ENOENT means the message has no attachments.

      Useful jq paths:
        .subject
        .from.email
        .body_text
        .labels[]
        .attachments[] | .filename

      To act on messages (read by id, triage, raw API calls), use the gws
      CLI if installed: gws gmail --help

    #### Supported Unix Commands for VFS

    Unix commands work on each path as on a local filesystem, as far as the path supports them:

    | Path | Supported |
    | --- | --- |
    | `/<path>` | Commands that read files (`ls`, `cat`, `grep`, `find`, `jq` and the rest). `grep -r` and `rg` ask `gmail` which files may match. |

    #### Limitations of Unix Commands for VFS

    Where a path differs from a local filesystem:

    | Path | Limitations |
    | --- | --- |
    | `/<path>` | Read only: no command changes files. `gmail` answers only for `*/*/*.gmail.json`; `grep -r` and `rg` read every other file. `grep -r`, `find` and `du` stop after 1000 files; a glob matching more, `tar -c`, `cp -r` and `rm -r` are refused. |

Label directories appear at the root. System labels use the Gmail
label ID (e.g., `INBOX`, `SENT`, `STARRED`). User-created labels
use their label name as is.

### Date Directories

Inside each label, messages are grouped into date subdirectories
formatted as `YYYY-MM-DD`. The date is derived from the message's
`internalDate` (epoch milliseconds) converted to a calendar date.

### Message Files

Each message is stored as a `.gmail.json` file. The filename shape is:

```text
<sanitized-subject>__<message-id>.gmail.json
```

Subjects are sanitized for filesystem safety and truncated when
necessary. The message ID is embedded after `__` and before
`.gmail.json`.

### Attachments

Messages that have attachments get a companion subdirectory with
the same base name (without `.gmail.json`). Decoded attachment
files are placed inside:

```text
Meeting_Notes__msg123.gmail.json    # message JSON
Meeting_Notes__msg123/              # attachment directory
  report.pdf
  screenshot.png
```

## Cache

The Gmail VFS uses `IndexCacheStore` (same as Slack, Discord,
and other mounts). Index entries store label IDs, message IDs,
and message metadata. File bytes go through the workspace
file cache.

## Example

```python
import asyncio
import os

from dotenv import load_dotenv

from mirage import MountMode, Workspace
from mirage.commands.cli.builtin.gws import GWS
from mirage.vfs.gmail import GmailConfig, GmailVFS

load_dotenv(".env.development")

config = GmailConfig(
    client_id=os.environ["GOOGLE_CLIENT_ID"],
    client_secret=os.environ["GOOGLE_CLIENT_SECRET"],
    refresh_token=os.environ["GOOGLE_REFRESH_TOKEN"],
)
vfs = GmailVFS(config=config)


async def main():
    ws = Workspace({"/gmail": vfs}, mode=MountMode.READ)
    ws.register_cli("gws", GWS, config)

    # List labels
    r = await ws.shell("ls /gmail/")
    print(await r.stdout_str())

    # List date directories in INBOX
    r = await ws.shell("ls /gmail/INBOX/")
    print(await r.stdout_str())

    # List messages for a specific date
    r = await ws.shell("ls /gmail/INBOX/2026-04-12/")
    print(await r.stdout_str())

    # Read a message
    r = await ws.shell(
        "cat /gmail/INBOX/2026-04-12/Meeting_Notes__msg123.gmail.json")
    print(await r.stdout_str())

    # Extract subject with jq
    r = await ws.shell(
        'jq ".subject"'
        " /gmail/INBOX/2026-04-12/Meeting_Notes__msg123.gmail.json")
    print(await r.stdout_str())

    # List attachments
    r = await ws.shell("ls /gmail/INBOX/2026-04-12/Meeting_Notes__msg123/")
    print(await r.stdout_str())

    # Search across all messages
    r = await ws.shell('rg "quarterly" /gmail/INBOX/')
    print(await r.stdout_str())

    # Tree view
    r = await ws.shell("tree -L 2 /gmail/INBOX/")
    print(await r.stdout_str())

    # Triage unread messages
    r = await ws.shell('gws gmail triage --query "is:unread" --max 5')
    print(await r.stdout_str())

    # Send an email
    r = await ws.shell(
        'gws gmail send --to "user@example.com"'
        ' --subject "Hello from MIRAGE"'
        ' --body "This email was sent via the MIRAGE Gmail VFS."')
    print(await r.stdout_str())


if __name__ == "__main__":
    asyncio.run(main())
```

See [`examples/python/vfs/gmail/gmail.py`](https://github.com/strukto-ai/mirage/blob/main/examples/python/vfs/gmail/gmail.py) for the full working example.

## Finding IDs

VFS-specific commands require message IDs. These can be
extracted from the filesystem:

```bash
# Message ID -- embedded in filename after "__"
ls /gmail/INBOX/2026-04-12/
# -> Meeting_Notes__msg123.gmail.json   <- message_id = msg123

# Extract message ID from filename
basename /gmail/INBOX/2026-04-12/Meeting_Notes__msg123.gmail.json .gmail.json
# -> Meeting_Notes__msg123
# The part after "__" is the message ID: msg123

# Read a message then reply
gws gmail read --id msg123
gws gmail reply --message-id msg123 --body "Thanks for the notes"
```

## Working with Large Labels

Labels with many messages are split into date directories. A bare
`ls` of a label lists the days of its 50 most recent messages; a glob
over the date names (`ls /gmail/INBOX/2026-03-*`) or a date directory
by name reaches older days. Tips for efficient access:

```bash
# List available dates
ls /gmail/INBOX/

# Check message count for a specific date
ls /gmail/INBOX/2026-04-12/ | wc -l

# Read only the most recent date
ls /gmail/INBOX/ | tail -n 1

# Search across all dates in a label
rg "keyword" /gmail/INBOX/

# Extract specific fields to reduce output
jq -r '.subject' /gmail/INBOX/2026-04-12/*.gmail.json | head -n 20

# Find messages with attachments
find /gmail/INBOX/2026-04-12/ -type d

# Tree view of a label
tree -L 2 /gmail/INBOX/
```

## Shell Commands

Standard commands available on the mounted Gmail tree:

| Command         | Notes                                      |
| --------------- | ------------------------------------------ |
| `ls`            | List labels, dates, messages, attachments  |
| `cat`           | Read message JSON or attachment content    |
| `head` / `tail` | First/last N lines                         |
| `grep` / `rg`   | Pattern search (file or directory level)   |
| `jq`            | Query message JSON fields                  |
| `wc`            | Line/word/byte counts                      |
| `stat`          | File metadata (name, size, type)           |
| `find`          | Recursive search with `-name`, `-maxdepth` |
| `tree`          | Directory tree view                        |
| `basename`      | Extract filename from path                 |
| `dirname`       | Extract directory from path                |
| `realpath`      | Resolve path to absolute form              |
| `nl`            | Number lines of output                     |

Acting on Gmail (send, reply, forward, triage, raw API calls) goes
through the [gws CLI](/python/cli/gws) when installed.

## Integration

What Gmail answers through its own API, so fewer files are read. [Integration](/home/integration/overview) explains each command.

| Command | On Gmail |
| --- | --- |
| `grep -r`, `rg` | The message text the listing keeps, for ASCII text. It misses nothing. |

The listing keeps
each message's text, and `grep -r` and `rg` read only the messages whose text
holds the pattern's text in any case, printing what reading every message
would. Listing a label already fetches its messages in full, so this asks Gmail
nothing more and saves the second fetch of each message it rules out. Gmail's
own search is not used: it reads the HTML part of a message and can miss a word
of the plain-text body a `.gmail.json` holds, such as one inside a link.
Attachments are always read, and so is every message for a text that is not
ASCII, or that may be part of the labels field (`inbox`, `STARRED`, `Label_1`,
`abel`), since a message's labels change after the listing kept its text. With
`walk_limit: -1` in the mount's `"*"` [command limit](/home/core/output-limits), the listing keeps no message text, and every message
is read.
