`GmailVFS` mounts a Gmail account read only: each label becomes a folder of
days, each message a `.gmail.json` file and its attachments a folder beside
it. Credentials are set up on the [Google Workspace page](/home/setup/google).

## Install

```bash
pip install mirage-ai
```

## Configure

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.gmail import GmailConfig, GmailVFS

config = GmailConfig(
    client_id=os.environ["GOOGLE_CLIENT_ID"],
    client_secret=os.environ["GOOGLE_CLIENT_SECRET"],
    refresh_token=os.environ["GOOGLE_REFRESH_TOKEN"],
)
ws = Workspace({"/gmail": GmailVFS(config)}, mode=MountMode.READ)

result = await ws.shell("ls /gmail && ls /gmail/INBOX | head -n 3")
print(await result.stdout_str())
```

`access_token` replaces the client and refresh token with a token or a
callable that returns one.

## Authentication

Credentials come from the first of:

1. `access_token`, a token or a callable that returns one.
2. `client_id` and `refresh_token`, with `client_secret` unless the client
   uses PKCE. Mirage trades the refresh token for access tokens on its own.

The mount needs the Gmail API with the
`https://www.googleapis.com/auth/gmail.modify` scope, which the `gws gmail`
commands also use, or `gmail.readonly` for reading alone.

## Layout

```text
/gmail/
  INBOX/
    2026-11-16/
      Invoice_November__18c2f9a4b7e3d1a0.gmail.json
      Invoice_November__18c2f9a4b7e3d1a0/
        invoice.pdf
  SENT/
  STARRED/
  Receipts/
```

- System labels are named by their label ID (`INBOX`, `SENT`, `STARRED`);
  user labels by their name.
- Inside a label, one folder per day, the date each message was received.
- A message file is named `<subject>__<message-id>.gmail.json`, the subject
  sanitized and cut short when needed. `ls` the day rather than build the
  name.
- A message with attachments has a folder of the same name without
  `.gmail.json`, holding the decoded files.
- The part after `__` is the message id that `gws gmail read --id` and
  `gws gmail reply --message-id` take.

## Behavior

- **Read only:** no command changes the mailbox. Sending, replying,
  forwarding and triage go through the [`gws`](/python/cli/gws) CLI.
- **Recent window:** `ls` of a label lists the days of its 50 most recent
  messages. A glob over the day names (`ls /gmail/INBOX/2026-03-*`) or a day
  folder named directly reaches older days.
- **Message JSON:** a `.gmail.json` is shaped by Mirage, not the raw Gmail
  API answer: sender, recipients, subject, date, the decoded plain-text body,
  labels and the attachment list.

## Integration

Gmail answers these commands from what its listing already fetched, so fewer
messages are read. See [Integration](/home/integration/overview).

- `grep -r` and `rg`: listing a label fetches its messages in full, and the
  listing keeps each message's text. Only the messages whose text holds the
  pattern's text, in any case, are read, and the output is what reading every
  message prints. Gmail's own search is not used, since it reads a message's
  HTML part and can miss a word of the plain-text body. Attachments are
  always read, and so is every message for a text that is not ASCII or that
  may be part of the labels field (`inbox`, `STARRED`, `Label_1`, `abel`),
  since labels change after the listing. With `walk_limit: -1` in the mount's
  `"@all"` [command limit](/home/core/output-limits), the listing keeps no
  text and every message is read.
