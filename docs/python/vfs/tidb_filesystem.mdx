`TiDBFilesystemVFS` mounts a [TiDB Cloud Filesystem](https://www.pingcap.com/tidb/tidb-cloud-filesystem/)
through its REST API: its directories and files appear with their own names
and bytes, with no FUSE mount needed. Set up tokens and region hosts as in [TiDB setup](/home/setup/tidb).

## Install

```bash
pip install mirage-ai
```

## Configure

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.tidb_filesystem import (
    TiDBFilesystemConfig,
    TiDBFilesystemVFS,
)

config = TiDBFilesystemConfig(
    host=os.environ["TIDB_FILESYSTEM_HOST"],
    token=os.environ["TIDB_FILESYSTEM_TOKEN"],
)
ws = Workspace({"/fs": TiDBFilesystemVFS(config)}, mode=MountMode.WRITE)

result = await ws.shell("mkdir -p /fs/notes && echo hello > /fs/notes/a.txt && ls /fs/notes")
print(await result.stdout_str())
await ws.close()
```

`root_path`, such as `/workspace`, mounts one directory. Use
`MountMode.EXEC` when `python3` or `js` should run scripts from the mount.

## Authentication

`token` is the file system's owner token or a scoped token, sent as a bearer
token. `host` is the endpoint of the file system's region, such as
`https://aws-us-east-1.drive9.ai`; a token works only against its own region.

A scoped token reaches only the path it was created for, and only with the
operations it allows (`read`, `list`, `search`, `write`, `delete`). Mount it
with `root_path` set to that path, since it cannot list the file system's
root.

TiDB Cloud Filesystem runs on the open-source
[drive9](https://github.com/mem9-ai/drive9) server, and the same VFS mounts a
self-hosted drive9 server: set `host` to its origin and `token` to an API key
it issued.

## Layout

```text
/fs/
  notes/
    a.txt
  workspace/
    data.json
```

`/fs/notes/a.txt` is `/notes/a.txt` in the file system, or
`<root_path>/notes/a.txt` with `root_path` set. `..` segments in `root_path`
are refused.
