The Box VFS mounts a Box account at some prefix such as `/box/`. All
operations involve network I/O to the
[Box v2 HTTP API](https://developer.box.com/reference/):
`/2.0/folders/{id}/items` for directories, `/2.0/files/{id}/content` for
content, and multipart upload / `/2.0/folders` / `delete` / `PUT` (rename or
move) / `copy` for writes. Files are served as raw bytes. Both `READ` and
`WRITE` modes are supported.

Box addresses everything by numeric **item id**, not by path (the account
root is folder id `0`). Mirage resolves each path to its id by listing folders
level by level and caches the path → id mapping, so nested directories cost
one API call per level on first access.

Every Box item is served as its raw bytes, keeping its real name. Box's native
`.boxnote` / `.boxcanvas` come back as their stored ProseMirror-style JSON
(text, so `cat foo.boxnote | jq .` works), and Box's Google-Workspace files
(`.gdoc` / `.gsheet` / `.gslides`) come back as the Office Open XML zips
(`docx` / `xlsx` / `pptx`) Box stores them as, opaque binary like any other
Office document.

<Note>
Box exposes no API to edit these formats from a structured payload, so Mirage
does not decode them, it hands back exactly what Box stores. For a rich,
editable view of Google-format documents, mount them through
[Google Drive](/python/vfs/gdrive) with Google credentials instead; the
`gws` commands operate on Google file ids and do not apply to Box.
</Note>

For credential setup, see the [Box Setup](/home/setup/box) guide. The
TypeScript packages ship the same backend for Node and the browser, see
[Box (TypeScript)](/typescript/box).

## Config

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.box import BoxConfig, BoxVFS

config = BoxConfig(
    # A Box developer token from the app console (~60-minute lifetime):
    access_token=os.environ["BOX_DEVELOPER_TOKEN"],
    # Optional:
    # root_folder_id="123456789",  # mount a sub-folder as the root
)

vfs = BoxVFS(config)
ws = Workspace({"/box": vfs}, mode=MountMode.WRITE)
```

Box supports three authentication modes:

- **Developer token** (`access_token`): quickest to try; expires after ~60
  minutes and cannot be refreshed programmatically.
- **OAuth2 refresh** (`client_id` + `refresh_token`, optional
  `client_secret`): Box rotates the refresh token on each refresh; supply
  `on_refresh_token_rotated` to persist the new one across restarts.
- **Client credentials** (`client_id` + `client_secret` + `enterprise_id`):
  the app authenticates as its own service account; expired tokens are simply
  re-fetched.

The access token is cached in memory and refreshed ~5 minutes before expiry
(refresh and client-credentials modes).

## Mount a subfolder

Pass `root_folder_id` to expose a single Box folder as the mount root instead
of the whole account. Every command and FUSE/VFS op is scoped to that folder;
paths outside it are unreachable. Folder ids are stable across renames and
moves, and are visible in the Box web URL (`app.box.com/folder/<id>`), so an
id-based mount survives reorganization that a path prefix would not.

```python
config = BoxConfig(
    access_token=os.environ["BOX_DEVELOPER_TOKEN"],
    root_folder_id="123456789",
)
```

## Cache

The Box VFS caches directory listings via `IndexCacheStore` to hold the
path → id mapping and reduce repeated API calls during traversal;
with no `index:` configured, listings live
for the mount's `ttl` (600 s by default), at most 24 hours; a configured
`index:` uses its own `ttl`, still capped by the mount's `ttl:`. File reads go through the standard read cache
(`caches_reads = True`). Writes invalidate the affected listings so subsequent
reads see the new state.

## Writes

A write records the `sha1` its upload reply names, so a `fresh` read
right after a `tee` or `sed -i` downloads nothing.

## Conditional writes

A Box mount accepts `write: conditional`. A
write or a file delete compares the `sha1` mirage holds with the one the
folder listing it walks anyway shows, and refuses a file changed since it
was read before sending anything; the request then carries the file's
`etag` as `If-Match`, so Box refuses (412) a change that lands in between.
A conditional write costs no request more than a plain one. `rm -r` walks
the folder file by file, and a `mv` within the mount is Box's own move,
which is not refused when its source changed (a `mv` to another mount is a
copy and a conditioned delete, so there a changed source stays and `mv`
reports the failed removal).

## Reads under `fresh`

A Box mount accepts `read: fresh`. The token is the file's `sha1`, which a
folder listing and `GET /files/{id}` both carry; a download names no version,
so a whole read stamps the listed `sha1` only when the downloaded bytes hash
to it, and a ranged read stamps nothing. On a
`write: conditional` mount a whole read stamps
the `sha1` of the bytes it downloaded, so a listing another client has since
outdated cannot leave the next write without the version the agent read. `modified_at` is never the token:
two same-size edits in one second share it.

Checking a cached file costs one request, `GET /files/{id}` by the id the
mount last listed, while the mount still holds that file's listing row. The
answer is trusted only when Box places the same active file at the same path
from the mount root; a file that was moved, renamed, trashed or recreated
falls back to listing each folder from the mount root, one listing per level
(up to two per level when the file is gone). When that fallback confirms
byte-identical content, the built-in RAM and Redis indexes retain the newly
resolved file row if the original hint is still current. A later check then
uses the recovered id without refreshing the parent listing. Custom indexes
must implement `replace_if_unchanged` to retain this row; otherwise later checks
repeat the fallback walk. A persistent 403
still requires the failed point request and a listing walk on each check.
Any stale, unknown or gone verdict on the mount
drops its cached listings, so the checks after one walk until a cold read or
an `ls` lists the folders again. A file Box reports without a `sha1` cannot
be verified: each fresh read of it downloads it again and drops the mount's
cached listings.

A folder's `etag` does not move when its children change, so under `fresh`
listings are re-fetched once per command. Repeated uses within that command
share the result; outside commands, the existing one-second listing trust
window applies. Before fetching a nested listing, mirage resolves its folder through current
parent listings up to the configured mount root. A folder moved away and
replaced under the same name is therefore resolved to the replacement on
the next fresh command. This costs one listing per ancestor level; a warm
file check still uses one metadata request.

## Integration

What Box answers through its own API, so fewer files are read, and the most files one command reads. [Integration](/home/integration/overview) explains each command.

| Command | On Box |
| --- | --- |
| `grep -r`, `rg` | Box search, for whole words |
| Can miss | Office files, PDFs, archives, the end of large files, words Box splits differently (`foo.bar`), recent writes |
| Full scan | `grep -r`, `find`, `du` and other walks stop after [`full_scan_limit`](/home/integration/search#full_scan_limit) files (default 1000); a glob matching more, `tar -c`, `cp -r` and `rm -r` are refused. `-1` reads every file without Box search |
| `sha1sum` | The SHA-1 Box keeps, asked live |

`grep -rw` and
`rg -w` read only the files Box search names. Every file is read when the
search fails, reaches its 10,000-match limit or finds nothing, or when the
searched path is not a folder. [Search](/home/integration/search) lists how
each option uses the search.

`full_scan_limit: -1` reads every file instead, since Box searches the text it extracted, not the bytes
`grep` reads, and indexes a write some time after it lands. A file that holds
the word can be left out: an office file, PDF or archive, the end of a large
file, a word Box splits differently (`foo.bar`), or a recent write.

## Example

```python
import asyncio
import os

from mirage import MountMode, Workspace
from mirage.vfs.box import BoxConfig, BoxVFS

config = BoxConfig(access_token=os.environ["BOX_DEVELOPER_TOKEN"])

vfs = BoxVFS(config)


async def main() -> None:
    ws = Workspace({"/box": vfs}, mode=MountMode.WRITE)

    r = await ws.shell("ls /box/")
    print(await r.stdout_str())

    r = await ws.shell("grep -rl report /box/docs/")
    print(await r.stdout_str())

    # Plain text from a Box Note:
    # A Box Note comes back as raw ProseMirror JSON:
    r = await ws.shell("cat /box/notes/standup.boxnote | jq .")
    print(await r.stdout_str())

    await ws.close()


asyncio.run(main())
```
