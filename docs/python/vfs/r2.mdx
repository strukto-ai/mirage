The R2 VFS mounts a Cloudflare R2 bucket at some prefix such as
`/r2/`. All operations involve network I/O to the remote object store.
Uses aioboto3 against R2's S3-compatible API.

For credential setup, see [R2 Setup](/home/setup/r2).

Install the extra:

```bash
pip install "mirage-ai[r2]"
```

## Config

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.r2 import R2Config, R2VFS

config = R2Config(
    bucket=os.environ["R2_BUCKET"],
    account_id=os.environ["R2_ACCOUNT_ID"],
    access_key_id=os.environ["R2_ACCESS_KEY_ID"],
    secret_access_key=os.environ["R2_SECRET_ACCESS_KEY"],
    # Optional:
    # endpoint_url="https://...r2.cloudflarestorage.com",
    # aws_profile="my-profile",
    # region="auto",
    # timeout=30,
    # proxy="http://proxy:8080",
)
vfs = R2VFS(config=config)
ws = Workspace({"/r2": vfs}, mode=MountMode.READ)
```

`R2VFS(config)` takes an `R2Config` object with the bucket name and
either `account_id` (endpoint is auto-built as
`https://{account_id}.r2.cloudflarestorage.com`) or an explicit
`endpoint_url`. Both `READ` and `WRITE` modes are supported.

## Filesystem Layout

The R2 VFS maps object keys to virtual paths under the mount
prefix. R2 "directories" are prefix-based — there are no real directory
objects.

For example, if bucket `my-bucket` contains:

```text
assets/logo.png
assets/style.css
data/export.parquet
data/metrics.csv
```

Then mounting at `/r2/` exposes:

```text
/r2/
  assets/
    logo.png
    style.css
  data/
    export.parquet
    metrics.csv
```

Path mapping: virtual `/r2/assets/logo.png` maps to R2 key
`assets/logo.png`.

## Cache

The R2 VFS uses `IndexCacheStore` with `index_ttl = 600`
(10 minutes). Directory listings are cached for up to 600 seconds before
being refreshed from R2. This reduces API calls for repeated directory
traversals. A configured `index:` replaces this lifetime with its own `ttl`, and the mount's `ttl:` caps it.

## Example

```python
import asyncio
import os

from dotenv import load_dotenv

from mirage import MountMode, Workspace
from mirage.vfs.r2 import R2Config, R2VFS

load_dotenv(".env.development")

config = R2Config(
    bucket=os.environ["R2_BUCKET"],
    account_id=os.environ["R2_ACCOUNT_ID"],
    access_key_id=os.environ["R2_ACCESS_KEY_ID"],
    secret_access_key=os.environ["R2_SECRET_ACCESS_KEY"],
)

vfs = R2VFS(config=config)


async def main() -> None:
    ws = Workspace({"/r2/": vfs}, mode=MountMode.READ)

    r = await ws.shell("ls /r2/")
    print(await r.stdout_str())

    r = await ws.shell("cat /r2/data/metrics.csv | head -n 10")
    print(await r.stdout_str())

    r = await ws.shell("tree /r2/")
    print(await r.stdout_str())

    r = await ws.shell("find /r2/ -name '*.csv'")
    print(await r.stdout_str())

    r = await ws.shell("stat /r2/assets/logo.png")
    print(await r.stdout_str())


if __name__ == "__main__":
    asyncio.run(main())
```

## Shell Commands

The R2 VFS supports the full set of shell commands since it operates
on real file content (text, binary, JSON, CSV, etc.). Large files benefit
from range reads to avoid downloading entire objects.

## Use Cases

- **AI agents accessing R2 data**: Mount R2 buckets for agents to read and process datasets
- **Data pipelines**: Read and write R2 objects with shell-like commands
- **FUSE mounting**: Expose R2 buckets through a virtual FUSE mount for external tools
