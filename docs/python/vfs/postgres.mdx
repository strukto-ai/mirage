`PostgresVFS` connects to a Postgres database via a DSN and exposes its schemas and tables as a tree the agent can list, read, and grep.

## Config

```python
from mirage.vfs.postgres import PostgresConfig, PostgresVFS

vfs = PostgresVFS(PostgresConfig(
    dsn="postgres://user:pass@host:5432/db?sslmode=require",
    schemas=["public", "analytics"],   # optional allowlist
    default_row_limit=1000,
    max_read_rows=10_000,
    max_read_bytes=10 * 1024 * 1024,
))
```

| Field | Default | Notes |
| --- | --- | --- |
| `dsn` | required | Postgres connection string. Redacted in snapshots. |
| `schemas` | `None` | Optional list to limit which schemas appear in the tree. |
| `default_row_limit` | `1000` | Rows a windowed read returns when it passes an offset but no limit. |
| `max_read_rows` | `10_000` | Hard ceiling per read. A whole read past it is refused; `head -n` / `tail -n` past it print that many rows, then a notice on stderr, and exit 1. |
| `max_read_bytes` | `10 MiB` | Hard ceiling per read. |

For DSN format and permissions, see [Postgres Setup](/home/setup/postgres).

## Mount mode

`read` only. Postgres mounts are read-only at the VFS level.

## Snapshot behavior

The DSN is redacted on snapshot. Hand the mount back at load (`mounts=`, or a config over the server and CLI).

## File size and `du`

`rows.jsonl` is rendered on demand. `stat -c %s` and `ls -l` show `-` when its rendered byte length is unknown; physical table storage is never used as a file size. `stat` checks existence and type without fetching columns, row counts, or relation sizes. Planner counts cannot identify content changes, so they are not used as a content fingerprint.

The metadata JSON files expose explicitly named row and storage estimates. Use `wc -c rows.jsonl` for the rendered byte count; reading the whole export is subject to the configured row and byte limits.

## grep and rg

For one plain text in a table's `rows.jsonl`, grep and rg ask Postgres for the
rows that hold it, with a `LIKE` over every column (`ILIKE` under `-i`), in the
order the table stores them, and search those rows instead of the whole table.
This needs every column to be text, an integer, a boolean or a uuid, which a
line spells as the column's cast does. The file is read as usual for a view, a
partitioned table or a table with children, when another column type is
present, when the text could match a key, `null` or the JSON between values,
or when more than `max_read_rows` rows match. Since only the matching rows are fetched, a
relation too large to read can still be searched when the output shows no line
numbers or context.
