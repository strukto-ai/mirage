`QdrantVFS` mounts a [Qdrant](https://qdrant.tech/) collection, read-only, as
nested folders, one level per group-by payload field. Each point is a `.json`
payload file, plus a `.txt` text file and an optional blob. Set up the cluster URL and API key as in [Qdrant setup](/home/setup/qdrant).

## Install

```bash
pip install "mirage-ai[qdrant]"
```

## Configure

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.qdrant import QdrantConfig, QdrantVFS

config = QdrantConfig(
    url=os.environ["QDRANT_URL"],
    api_key=os.environ["QDRANT_API_KEY"],
    collection="fashion",
    group_by=["gender", "articleType", "baseColour"],
    text_field="productDisplayName",
)
ws = Workspace({"/fashion": QdrantVFS(config)}, mode=MountMode.READ)

result = await ws.shell("ls /fashion/Men/Shoes/White && cat /fashion/Men/Shoes/White/3.json")
print(await result.stdout_str())
await ws.close()
```

A self-hosted Qdrant sets `host` and `port` (default `localhost:6333`) instead
of `url`. `blob_field` and `blob_ext` serve a payload field of raw or base64
bytes as a file, such as `3.jpg`.

## Authentication

A self-hosted Qdrant needs no key. Qdrant Cloud needs `api_key`; a read-only
key, for the cluster or for the mounted collections, is enough to browse.

A filtered listing creates a keyword payload index for a `group_by` field only
when Qdrant reports that one is required. A read-only key cannot create it, so
index those fields first or use a key that manages the collection.

## Layout

```text
/fashion/
  Men/
    Shoes/
      White/
        3.json
        3.txt
  Women/
    Tops/
      Blue/
        12.json
        12.txt
```

Each folder level filters on one `group_by` field, in order. Once every field
is bound, the folder lists each point's files, named by point id, or
`<name>__<id>` with `name_field`. Without `collection`, every collection is a
top-level folder. A value holding `/` renders as `∕`, and a blank or dot-led
value is led by `⁄`, so every value keeps its own folder that lists and opens.

- `<id>.txt` is the `text_field` value, the text the vector was built from.
- `<id>.json` is the full payload as compact JSON, without the vector and the
  blob.
- `<id>.<blob_ext>` is the raw bytes of `blob_field`, when it is set.

```text
$ cat /fashion/Men/Shoes/White/3.json
{"gender":"Men","articleType":"Shoes","baseColour":"White","productDisplayName":"Nike Men White Running Sneakers","id":3}
```

## Behavior

- **Read-only:** no command changes the collection.
- **Nested fields:** fields take Qdrant's dotted keys. For LangChain-style
  chunks, `group_by=["metadata.source"]`, `basename_fields=["metadata.source"]`,
  `name_field="metadata.page"` and `text_field="page_content"` show page `004`
  of `s3://docs/policies/refund-2026.pdf` as
  `refund-2026.pdf/004__<point-id>.txt`.
- **File names:** the point id stays in every name, so two equal labels never
  collide. Only the name a listing shows opens: another label in front of the
  same id reads as absent. A label that is not a string is written as compact
  JSON (`true`, `1`, `1e-7`).
- **Basenames:** `basename_fields` keeps only the last path or URL segment of a
  value. Two values with one basename under the same parent are refused rather
  than merged, and opening a basename folder checks every point of its parent,
  so a second source past `max_rows` is refused rather than hidden. A name over
  255 bytes is cut to fit and ends in `__` plus the md5 of the whole name.
- **Listing cap:** one folder listing scrolls at most `max_rows` (1,000)
  points; points past it are left out. Keep `group_by` to low-cardinality
  fields on a large collection.

### Semantic search

The `search` CLI runs Qdrant's vector query. Register it
on the workspace:

```python
from mirage.commands.cli.builtin.search import SEARCH

ws.register_cli("search", SEARCH)
```

Each hit prints the point's `.txt` path, or its `.json` without `text_field`,
with the similarity score, then the content:

```text
$ search "white running sneakers" /fashion
/fashion/Men/Shoes/White/3.txt:0.7421
Nike Men White Running Sneakers
```

`--top-k` defaults to `search_limit` (10). `--threshold` is the lowest score
kept. `--method` takes only `semantic`.

The query needs a vector. `embed`, an async `(text: str) -> list[float]`,
builds it in-process, so a self-hosted Qdrant works with any model.
Without it, `cloud_inference=True` sends the query text to the cluster, which
must have inference enabled (Qdrant Cloud) and store vectors from the same
`embedding_model`. With neither, `search` refuses the query. `embed` never
lands in a snapshot, so a restored mount needs a fresh `QdrantVFS`.
