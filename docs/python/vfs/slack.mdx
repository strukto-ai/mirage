`SlackVFS` mounts a Slack workspace as read-only files: channels and DMs as
one folder per day of messages and attachments, plus user profiles. The tokens
are set up on the [Slack page](/home/setup/slack).

## Install

```bash
pip install mirage-ai
```

## Configure

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.slack import SlackConfig, SlackVFS

config = SlackConfig(
    token=os.environ["SLACK_BOT_TOKEN"],
    search_token=os.environ["SLACK_USER_TOKEN"],
)
ws = Workspace({"/slack": SlackVFS(config)}, mode=MountMode.READ)

result = await ws.shell("ls /slack/channels && grep -rlw refund /slack/channels")
print(await result.stdout_str())
await ws.close()
```

`search_token` is optional: without it, `grep` reads the files. `start_time`
and `end_time` bound the mount to a time range.

## Authentication

`token` is a bot token (`xoxb-...`) with these bot scopes:

- `channels:read`, `channels:history`: public channels.
- `groups:read`, `groups:history`: private channels (optional).
- `im:read`, `im:history`: direct messages (optional).
- `mpim:read`, `mpim:history`: group DMs (optional).
- `users:read`: the `users/` folder.
- `files:read`: attachments under `files/`.

Invite the bot to each channel it should read with `/invite @Mirage`; a
channel it is not in answers `Permission denied`. The mount never posts.

Slack's search refuses bot tokens (`not_allowed_token_type`). The optional
`search_token` is a user token (`xoxp-...`) with `search:read`, used only for
Slack's search methods; the bot token still does every read. For `grep` and
`rg`, that user token also needs `channels:read`, `groups:read`, `im:read` and
`mpim:read`, so Mirage can tell which channels and DMs its search covers.

## Layout

```text
/slack/
  channels/
    general__C04KEPWF6V7/
      2026-11-16/
        chat.jsonl
        files/
          roadmap__F07AB12CD.pdf
  dms/
    alice__D0AQDJ5FP9V/
      2026-11-16/
        chat.jsonl
  users/
    alice__U12345678.json
```

- **Names:** a channel, DM or user is `<display-name>__<id>`, so the CLI's
  channel and user flags take the id from the path. Only `/` in a name
  becomes `∕` (U+2215); `ls` the parent for exact names and quote names with
  spaces.
- **Days:** each channel and DM lists one folder per day for the 90 days up
  to its newest message; a date glob finds earlier days.
- **`chat.jsonl`:** one message per line as Slack's API returns it (`.text`,
  `.user`, `.ts`, `.files`). `.user` is a user id, matched against
  `users/<name>__<user-id>.json`.
- **`files/`:** the attachments shared that day.
- **`users/`:** one file per user that is not deleted or a bot, holding the
  full profile from Slack.

## Behavior

- **Read only:** send messages, react, pin, look up members, search and upload
  files with the [`slack`](/python/cli/slack) CLI.
- **Time scope:** `start_time` and `end_time` bound the mount with RFC 3339
  timestamps that carry a timezone, at most to the millisecond. Start is
  inclusive, end exclusive, and an unset bound is open. Listings then cover
  that period instead of the recent window, day folders use UTC, messages are
  picked by creation time and attachments follow their messages. Direct
  paths, `stat`, date globs, `grep` and `rg` cannot leave the scope. Users and
  channel metadata stay visible. The scope applies to the mount, not to the
  `slack` CLI; rebuild the mount to change it.
- **Upstream changes:** a `read` mount refuses writes through Mirage; it does
  not freeze edits or deletions made in Slack.
- **Rate limits:** many reads of `chat.jsonl` can hit Slack's per-method rate
  limits, and history limits depend on how the app is distributed; see
  Slack's
  [`conversations.history` limits](https://docs.slack.dev/reference/methods/conversations.history/).

## Integration

Slack answers these commands through its own API, so fewer files are read.
See [Integration](/home/integration/overview).

- `grep -rw` and `rg -w`: with a user token, only the channel and DM days
  Slack search names are read, and the output matches reading every day.
  Search covers message text, file names and titles, and reactions
  (`has::name:`); a file hit names each day the file was shared. Users, file
  blobs and a day searched on its own are always read. Every day is read when
  the word is a key or fixed value of the message JSON, a file-type or URL
  word, a join or leave message word, or part of a user's name or of the
  workspace's domain, and when a search fails, returns more than 1,000
  messages or finds nothing. With a separate `search_token`, every day is also
  read when the scope holds a private channel or DM that token's user is not
  in (a bot's own DMs). Slack indexes a message some time after it is posted,
  and a word held only in another field (a bot's username, an unfurled link)
  is not searched; `walk_limit: -1` in the mount's `"@all"`
  [command limit](/home/core/output-limits) reads every file instead.
- `tail -f`: each new message as it is posted.
