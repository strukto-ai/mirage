`LanceDBVFS` mounts a LanceDB table, read-only, as nested folders, one level per
group-by column. Each row is a Markdown card plus an optional blob file, such
as its image. Set up local, object storage and LanceDB Cloud connections as in [LanceDB setup](/home/setup/lancedb).

## Install

```bash
pip install "mirage-ai[lancedb]"
```

## Configure

```python
from mirage import MountMode, Workspace
from mirage.vfs.lancedb import LanceDBConfig, LanceDBVFS

config = LanceDBConfig(
    uri="/data/fashion.lancedb",
    table="fashion",
    group_by=["gender", "articleType", "baseColour"],
    title_column="productDisplayName",
    blob_column="image_bytes",
    blob_ext="jpg",
    vector_column="vector",
)
ws = Workspace({"/fashion": LanceDBVFS(config)}, mode=MountMode.READ)

result = await ws.shell("ls /fashion/Men/Shoes/White && cat /fashion/Men/Shoes/White/3.md")
print(await result.stdout_str())
await ws.close()
```

`id_column` (default `id`) names each row's files. Without `table`, every table
is a top-level folder.

## Authentication

A local directory needs no credentials. LanceDB Cloud takes its `db://` URI
with `api_key` and `region` (default `us-east-1`); LanceDB Enterprise adds its
endpoint in `host_override`. An `s3://`, `gs://` or `az://` URI takes the
store's credentials or endpoint in `storage_options`.

```python
import os

config = LanceDBConfig(
    uri=os.environ["LANCEDB_URI"],
    api_key=os.environ["LANCEDB_API_KEY"],
    region=os.environ["LANCEDB_REGION"],
    table="fashion",
    group_by=["gender"],
)
```

## Layout

```text
/fashion/
  Men/
    Shoes/
      White/
        3.jpg
        3.md
    Watches/
      Silver/
        15.jpg
        15.md
  Women/
    Tops/
      Blue/
        12.jpg
        12.md
```

Each folder level filters on one `group_by` column, in order:
`/fashion/Men/Shoes/White/` lists the rows whose `gender` is `Men`,
`articleType` is `Shoes` and `baseColour` is `White`. Once every column is
bound, the folder lists each row's `<id>.md` and, with `blob_column`, its
`<id>.<blob_ext>`. A value
holding `/` renders as `∕`, and a blank or dot-led value is led by `⁄`, so
every value keeps its own folder that lists and opens.

A card lists the row's columns, headed by `title_column`, without the vector
and blob columns:

```text
# Nike Men White Running Sneakers

id: 3
gender: Men
articleType: Shoes
baseColour: White
productDisplayName: Nike Men White Running Sneakers
blob: 3.jpg
```

## Behavior

- **Read-only:** no command changes the table.
- **Listing cap:** one folder listing reads at most `max_rows` (1,000) rows;
  rows past it are left out. Keep `group_by` to low-cardinality columns on a
  large table.

### Semantic search

The `search` CLI runs LanceDB's vector search with the
table's embedding function, so the table needs one on a source column. Register
it on the workspace:

```python
from mirage.commands.cli.builtin.search import SEARCH

ws.register_cli("search", SEARCH)
```

Each hit prints its card's path with the vector distance, then the card, so
results work with `cat`, pipes and `wc`:

```text
$ search "white running sneakers" /fashion
/fashion/Men/Shoes/White/3.md:0.2679
# Nike Men White Running Sneakers
...
```

`--top-k` defaults to `search_limit` (10). `--threshold` is the largest
distance kept. `--method` takes only `semantic`.
