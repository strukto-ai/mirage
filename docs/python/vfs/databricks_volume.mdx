`DatabricksVolumeVFS` exposes files from a Unity Catalog volume through
Mirage's standard filesystem interface. Agents can list, stat, read, stream,
glob, and write files under the configured volume root.

For auth and environment setup, see [Databricks Volume Setup](/home/setup/databricks).

## Config

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.databricks_volume import (
	DatabricksVolumeConfig,
	DatabricksVolumeVFS,
)

vfs = DatabricksVolumeVFS(DatabricksVolumeConfig(
	catalog="main",
	schema="default",
	volume="agent_files",
	root_path="/reports",
	host=os.environ["DATABRICKS_HOST"],
	token=os.environ["DATABRICKS_TOKEN"],
))
ws = Workspace({"/dbx": vfs}, mode=MountMode.READ)
```

## Mount mode

`read` or `write`.

## Filesystem layout

Mirage maps the configured mount prefix onto the configured volume subtree.

Given:

```python
DatabricksVolumeConfig(
	catalog="main",
	schema="default",
	volume="agent_files",
	root_path="/reports/2026",
	host=os.environ["DATABRICKS_HOST"],
	token=os.environ["DATABRICKS_TOKEN"],
)
```

and mount prefix `/dbx/`, the volume path:

```text
/Volumes/main/default/agent_files/reports/2026/q1/summary.md
```

appears in Mirage as:

```text
/dbx/q1/summary.md
```

`root_path` is normalized before use, and Mirage rejects any virtual path that
would escape above that configured subtree.

## Supported operations

Reads: `readdir`, `stat`, `exists`, `read_bytes` (whole or a byte range),
`read_stream`, and glob resolution. Writes: `write`, `create`, `mkdir`,
`rmdir`, `unlink`, recursive `rm`, `cp`, and `mv`.

`mv` and `cp` download and upload the file. These operations are not atomic
because the Files API has no server-side rename.

## Shell Commands

The Databricks Volume VFS supports shell commands that operate on real
file content. Reads use the Files API with range requests, so commands like
`head -c BYTES` avoid downloading the whole object. The supported set is
scoped to commands that work over the volume API (no compression, encoding,
or local-only utilities).

## Rotating tokens

Pass a callback as `token` when your application refreshes access tokens:

```python
def current_token() -> str:
	return os.environ["DATABRICKS_TOKEN"]


config = DatabricksVolumeConfig(
	catalog="main",
	schema="default",
	volume="agent_files",
	host=os.environ["DATABRICKS_HOST"],
	token=current_token,
)
vfs = DatabricksVolumeVFS(config)
ws = Workspace({"/dbx/": vfs}, mode=MountMode.READ)
```

This callback reads the application's current token. Replace its body with your
credential broker or token store. The callback takes no arguments and returns
`str` or `SecretStr`. It can be synchronous or asynchronous. Mirage runs a
synchronous callback off the event loop and awaits any returned awaitable.

Mirage resolves the callback before each HTTP request, including each directory
page. A deferred read stream resolves its token when the stream opens. Cached
reads, construction, and snapshots do not invoke the callback. Tokens must be
nonblank and contain no carriage return or newline.

Your callback owns token refresh, caching, and coordination between concurrent
requests. Mirage propagates provider errors and authentication failures. It does
not replay a request after a 401 or fall back to profiles or default credentials.

Keep each VFS and workspace bound to one principal and permission scope. Isolate
file caches, indexes, and external cache prefixes across identities. If the
principal or permission scope changes, rebuild the workspace or invalidate its
caches. Token rotation for the same principal and scope can keep the existing
VFS.

## Snapshot behavior

Mirage redacts static tokens and token callbacks in VFS snapshots. Restore the
mount through `mounts=` when loading the workspace.

## Databricks Apps

Keep Mirage in-process and supply the workspace host and token explicitly.
Your application's OAuth or SDK integration can supply a token callback. This
does not require FUSE. The agent accesses the mounted workspace through Mirage's
backend adapters or `Workspace.shell(...)`.

## Integration

The most files one command reads on Databricks volumes. [Integration](/home/integration/overview) explains each command.

| Command | On Databricks volumes |
| --- | --- |
| Full scan | `grep -r`, `find`, `du` and other walks stop after [`full_scan_limit`](/home/integration/search#full_scan_limit) files (default 1000); a glob matching more, `tar -c`, `cp -r` and `rm -r` are refused. `-1` for no limit |

## Example

```python
import asyncio
import os

from mirage import MountMode, Workspace
from mirage.vfs.databricks_volume import (
	DatabricksVolumeConfig,
	DatabricksVolumeVFS,
)

vfs = DatabricksVolumeVFS(DatabricksVolumeConfig(
	catalog="main",
	schema="default",
	volume="agent_files",
	root_path="/reports",
	host=os.environ["DATABRICKS_HOST"],
	token=os.environ["DATABRICKS_TOKEN"],
))


async def main() -> None:
	ws = Workspace({"/dbx/": vfs}, mode=MountMode.READ)

	r = await ws.shell("ls /dbx/")
	print(await r.stdout_str())

	r = await ws.shell("find /dbx/ -name '*.md'")
	print(await r.stdout_str())

	r = await ws.shell('head -n 20 "/dbx/q1/summary.md"')
	print(await r.stdout_str())

	r = await ws.shell('stat "/dbx/q1/summary.md"')
	print(await r.stdout_str())


if __name__ == "__main__":
	asyncio.run(main())
```

## Use Cases

- **Agents in Databricks Apps**: mount a Unity Catalog volume in-process so an
  agent can read and write governed files without FUSE or hardcoded credentials.
- **Reading governed datasets**: expose a reports or dataset subtree through
  `root_path` and query it with shell commands.
- **Sandboxed volume access**: scope an agent to a single volume (and optional
  `root_path`) so it cannot read or write outside that subtree.
- **Writing agent outputs back**: persist generated files to the volume with
  `write`, `cp`, and `mv`.
