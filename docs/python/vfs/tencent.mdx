`TencentVFS` mounts one bucket: every object becomes a file and every `/` in
a key a folder. It is the [S3 VFS](/python/vfs/s3) pointed at Tencent COS's
endpoint, so commands behave as they do on S3. Set up credentials as in [Tencent COS setup](/home/setup/tencent).

## Install

```bash
pip install "mirage-ai[s3]"
```

## Configure

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.tencent import TencentConfig, TencentVFS

config = TencentConfig(
    bucket=os.environ["COS_BUCKET"],
    region=os.environ["COS_REGION"],
    access_key_id=os.environ["COS_SECRET_ID"],
    secret_access_key=os.environ["COS_SECRET_KEY"],
)
ws = Workspace({"/cos": TencentVFS(config)}, mode=MountMode.WRITE)

result = await ws.shell("ls /cos && find /cos -name '*.csv'")
print(await result.stdout_str())
await ws.close()
```

`region` also picks the endpoint, `https://cos.<region>.myqcloud.com`;
`endpoint_url` replaces it.
A mount takes `MountMode.READ`, `WRITE` or `EXEC`.

## Authentication

Credentials come from the first of:

1. `access_key_id` and `secret_access_key`, with `session_token` for temporary
   credentials.
2. `aws_profile`, a profile in `~/.aws/credentials`.
3. The AWS credential chain: environment variables, then the instance or
   container role.

`access_key_id` takes the CAM SecretId and `secret_access_key` the SecretKey. The
sub-user needs a COS policy: read-only for a read mount, read and write
for a write mount.
An object the key may not read or change answers `Permission denied`.

## Behavior

- **Key prefix:** `key_prefix="users/42/"` mounts only that part of the bucket,
  so `/cos/notes.md` is the key `users/42/notes.md`.
- **Bucket name:** a COS bucket name ends in the account's APPID, as in
  `my-bucket-1250000000`. `bucket` takes the full name, suffix included.
