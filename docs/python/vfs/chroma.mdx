`ChromaVFS` mounts one ChromaDB collection, read-only, as a tree of text files:
each file is its chunks joined in order. The collection's shape is set up on
the [Chroma page](/home/setup/chroma).

## Install

```bash
pip install "mirage-ai[chroma]"
```

## Configure

```python
from mirage import MountMode, Workspace
from mirage.vfs.chroma import ChromaConfig, ChromaVFS

config = ChromaConfig(host="localhost", port=8000, collection_name="knowledge")
ws = Workspace({"/knowledge": ChromaVFS(config)}, mode=MountMode.READ)

result = await ws.shell("tree /knowledge && grep -rn refund /knowledge")
print(await result.stdout_str())
await ws.close()
```

`ssl=True` reaches the server over HTTPS. A collection whose chunks name their
file and position with keys other than `page_slug` and `chunk_index` sets
`slug_field` and `chunk_index_field`.

## Layout

```text
/knowledge/
  README.md
  guides/
    api.md
    quickstart.md
  policies/
    refunds.md
```

Paths come from the collection's path tree document, the one with the ID
`__path_tree__`: a JSON object whose keys are file paths below the mount.
Folders come from the `/` in those paths, and the optional `size`,
`created_at` and `updated_at` values are used when present.
`/knowledge/guides/quickstart.md` is every chunk whose `page_slug` is
`guides/quickstart.md`.

## Behavior

- **Read-only:** no command changes the collection.
- **Pages:** a file is its chunks sorted by `chunk_index` and joined by line
  breaks.
- **Tree refresh:** the path tree is fetched on the first listing and reused
  until the index expires, so a change to `__path_tree__` shows up after that.
  File text is always read from Chroma.
- **Snapshots:** a snapshot keeps the config, and loading it needs the mount
  handed back through `mounts=`. A restored mount reads current content.

### Exact search with grep

`grep -r` and `rg` read only the pages with a chunk holding the text, which
Chroma's `$contains` answers, then match each page as `grep` does. No match can
span two chunks, so the answer is exact. `$contains` matches case, so `-i`
reads every page.

### Vector search

The `search` CLI ranks chunks by meaning with Chroma's
vector query. Register it on the workspace:

```python
from mirage.commands.cli.builtin.search import SEARCH

ws.register_cli("search", SEARCH)
```

```bash
search "how do I get started" /knowledge/
search --top-k 5 "billing policy" /knowledge/policies/
search --threshold 0.8 "billing policy" /knowledge/
```

The score is 1 minus Chroma's distance, and `--threshold` keeps the hits that
reach it. `--top-k` defaults to 10. `--method` takes only `semantic`. Each hit
prints its page and score, then the chunk:

```text
/knowledge/guides/quickstart.md:0.82
Use an API key to authenticate requests.
```

## Integration

Chroma answers this command through its own API, so fewer pages are read. See
[Integration](/home/integration/overview).

- `grep -r` and `rg`: Chroma's `$contains` picks the pages to read, for any
  text, and misses nothing; `-i` reads every page. See
  [Exact search with grep](#exact-search-with-grep).
