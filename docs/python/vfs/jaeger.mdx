`JaegerVFS` mounts an existing Jaeger query service as read-only JSON files:
each service becomes a folder with its operations and one file per trace. The
connection is set up on the [Jaeger page](/home/setup/jaeger).

## Install

```bash
pip install mirage-ai
```

## Configure

```python
from mirage import MountMode, Workspace
from mirage.vfs.jaeger import JaegerConfig, JaegerVFS

config = JaegerConfig(host="http://localhost:16686")
ws = Workspace({"/jaeger": JaegerVFS(config)}, mode=MountMode.READ)

result = await ws.shell("jq -r '.[].name' /jaeger/services/frontend/operations.json")
print(await result.stdout_str())
await ws.close()
```

`host` is the query service's base URL; it needs no credentials.
`default_trace_limit`, `default_from_timestamp` and `default_to_timestamp`
bound each trace listing.

## Layout

```text
/jaeger/
  services/
    <service>/
      operations.json
      traces/
        <trace-id>.json
```

- **`services/`:** one folder per service Jaeger reports, including Jaeger's
  own `jaeger` service when it traces itself.
- **`operations.json`:** the service's operation records, as Jaeger returns
  them.
- **`traces/<trace-id>.json`:** the trace document Jaeger returns, with
  `traceID`, `spans`, `processes` and `warnings`.

## Behavior

- **Read only:** the mount has no write operations.
- **Trace listing:** `traces/` shows the newest `default_trace_limit` traces
  (100) of the service between `default_from_timestamp` and
  `default_to_timestamp`; unset bounds search from the beginning up to now. A
  trace older than the listing is still readable by its id, as long as one of
  its spans comes from that service.
- **Missing paths:** a service Jaeger does not know, a trace id that is not 16
  or 32 hex digits, and a trace without a span from the addressed service are
  reported as missing.
- **Sizes:** every listed file has an exact size, so `ls -l`, `du` and `stat`
  work without reading the files.
