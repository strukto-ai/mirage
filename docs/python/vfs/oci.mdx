`OCIVFS` mounts one Oracle Cloud Infrastructure Object Storage bucket: every
object becomes a file and every `/` in a key a folder. It reaches OCI through
the Amazon S3 Compatibility API. Set up credentials as in [OCI setup](/home/setup/oci).

## Install

```bash
pip install "mirage-ai[oci]"
```

## Configure

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.oci import OCIConfig, OCIVFS

config = OCIConfig(
    bucket=os.environ["OCI_BUCKET"],
    namespace=os.environ["OCI_NAMESPACE"],
    region=os.environ["OCI_REGION"],
    access_key_id=os.environ["OCI_ACCESS_KEY_ID"],
    secret_access_key=os.environ["OCI_SECRET_ACCESS_KEY"],
)
ws = Workspace({"/oci": OCIVFS(config)}, mode=MountMode.WRITE)

result = await ws.shell("ls /oci && find /oci -name '*.csv'")
print(await result.stdout_str())
await ws.close()
```

`namespace` and `region` build the endpoint
`https://<namespace>.compat.objectstorage.<region>.oci.customer-oci.com`;
`endpoint_url` replaces it. A mount takes `MountMode.READ`, `WRITE` or `EXEC`.

## Authentication

Credentials come from the first of:

1. `access_key_id` and `secret_access_key`, a Customer Secret Key, with
   `session_token` for temporary credentials.
2. `aws_profile`, a profile in `~/.aws/credentials`.
3. The AWS credential chain: environment variables, then the instance or
   container role.

The user's group needs policies such as
`Allow group <group> to read buckets in compartment <compartment>` and
`Allow group <group> to manage objects in compartment <compartment>`
(`read objects` for a read-only mount). A request the credentials may not make
answers `Permission denied`.

## Behavior

- **Key prefix:** `key_prefix="users/42/"` mounts only that part of the bucket,
  so `/oci/notes.md` is the key `users/42/notes.md`.
- **Path style:** the S3 Compatibility API takes only path-style URLs, so
  `path_style` defaults to `True`.
