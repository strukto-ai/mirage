`HfModelsVFS` mounts one [Hugging Face model](https://huggingface.co/models)
repository, read-only: every file in the repo becomes a file, read lazily, so
configs, tokenizers and the model card open without downloading the weights.
Set up tokens for gated and private models as in [HF Models setup](/home/setup/hf_models).

## Install

```bash
pip install mirage-ai
```

## Configure

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.hf_models import HfModelsConfig, HfModelsVFS

config = HfModelsConfig(
    repo_id="sapientinc/HRM-Text-1B",
    token=os.environ.get("HF_TOKEN"),
)
ws = Workspace({"/model": HfModelsVFS(config)}, mode=MountMode.READ)

result = await ws.shell("ls -lh /model && jq .architectures /model/config.json")
print(await result.stdout_str())
await ws.close()
```

`revision` pins a branch, tag or commit (default `main`), and `key_prefix`
mounts one folder of the repo. `endpoint` points at a mirror or a self-hosted
Hub.

## Authentication

A public model needs no token. A gated or private one needs `token`: a `read`
token, or a fine-grained token with read access to that model; a gated model
also needs its conditions accepted on the Hub. A repository or revision
the token cannot see, or that does not exist, answers `Permission denied`.

## Layout

```text
/model/
  LICENSE
  README.md
  config.json
  model.safetensors
  tokenizer.json
  tokenizer_config.json
```

Files keep their repo paths: `/model/config.json` is `config.json` in the
repo. `repo_id` is `namespace/name`, or a
bare name under the token's owner.

## Behavior

- **Read-only:** a Hub write is a commit, and a file write cannot say where a
  commit ends, so `echo >`, `rm`, `cp` and `mv` are refused rather than making
  one commit per file. The [`hf` CLI](/python/cli/hf) is the write half:
  `hf download --local-dir` puts a copy on a writable mount, and `hf upload`
  sends it back as one commit.
- **Lazy reads:** `ls` and `stat` never download a file, so the weights'
  size shows without fetching them; they stream only when a command reads
  them.
- **Fresh reads:** under `read: fresh`, each command checks once which commit
  `revision` points at, even when `revision` is a full commit sha, since a
  branch or tag can carry the same name.

## Integration

The Hub answers this command through its own API, so fewer files are read. See
[Integration](/home/integration/overview).

- `sha256sum`: the LFS sha256 the Hub keeps; other files are read.
