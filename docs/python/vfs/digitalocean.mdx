`DigitalOceanVFS` mounts one bucket: every object becomes a file and every `/` in
a key a folder. It is the [S3 VFS](/python/vfs/s3) pointed at DigitalOcean Spaces's
endpoint, so commands behave as they do on S3. Set up credentials as in [DigitalOcean Spaces setup](/home/setup/digitalocean).

## Install

```bash
pip install "mirage-ai[s3]"
```

## Configure

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.digitalocean import DigitalOceanConfig, DigitalOceanVFS

config = DigitalOceanConfig(
    bucket=os.environ["DO_SPACE"],
    region=os.environ["DO_REGION"],
    access_key_id=os.environ["DO_ACCESS_KEY_ID"],
    secret_access_key=os.environ["DO_SECRET_ACCESS_KEY"],
)
ws = Workspace({"/spaces": DigitalOceanVFS(config)}, mode=MountMode.WRITE)

result = await ws.shell("ls /spaces && find /spaces -name '*.csv'")
print(await result.stdout_str())
await ws.close()
```

`region` also picks the endpoint, `https://<region>.digitaloceanspaces.com`;
`endpoint_url` replaces it.
A mount takes `MountMode.READ`, `WRITE` or `EXEC`.

## Authentication

Credentials come from the first of:

1. `access_key_id` and `secret_access_key`, with `session_token` for temporary
   credentials.
2. `aws_profile`, a profile in `~/.aws/credentials`.
3. The AWS credential chain: environment variables, then the instance or
   container role.

The Spaces key needs **Limited Access** with **Read** on the Space, or
**Read/Write/Delete** for a write mount. **Full Access** reaches every
Space.
An object the key may not read or change answers `Permission denied`.

## Behavior

- **Key prefix:** `key_prefix="users/42/"` mounts only that part of the bucket,
  so `/spaces/notes.md` is the key `users/42/notes.md`.
