`MinIOVFS` mounts one bucket on a self-hosted MinIO server: every object becomes
a file and every `/` in a key a folder. It reaches MinIO through its S3 API.
Set up credentials as in [MinIO setup](/home/setup/minio).

## Install

```bash
pip install "mirage-ai[s3]"
```

## Configure

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.minio import MinIOConfig, MinIOVFS

config = MinIOConfig(
    bucket=os.environ["MINIO_BUCKET"],
    endpoint_url=os.environ["MINIO_ENDPOINT"],
    access_key_id=os.environ["MINIO_ACCESS_KEY"],
    secret_access_key=os.environ["MINIO_SECRET_KEY"],
)
ws = Workspace({"/minio": MinIOVFS(config)}, mode=MountMode.WRITE)

result = await ws.shell("ls /minio && find /minio -name '*.csv'")
print(await result.stdout_str())
await ws.close()
```

`endpoint_url` is required, since the server is self-hosted. `region` defaults
to `us-east-1`. A mount takes `MountMode.READ`, `WRITE` or `EXEC`.

## Authentication

Credentials come from the first of:

1. `access_key_id` and `secret_access_key`, a MinIO access key, with
   `session_token` for temporary credentials.
2. `aws_profile`, a profile in `~/.aws/credentials`.
3. The AWS credential chain: environment variables, then the instance or
   container role.

The key inherits its user's policies: `readonly` to read, `readwrite` to write.
A request the credentials may not make answers `Permission denied`.

## Behavior

- **Key prefix:** `key_prefix="users/42/"` mounts only that part of the bucket,
  so `/minio/notes.md` is the key `users/42/notes.md`.
- **Conditional writes:** MinIO ignores copy and delete conditions, so under
  `write: conditional` Mirage refuses a `cp` or `mv` within the mount, a `mv`
  out of it, `rm` and `find -delete` (`ENOTSUP`); a `cp` or `mv` into it from
  another mount is a write and goes through. See
  [S3-compatible VFSes](/home/setup/s3#s3-compatible-vfses).
