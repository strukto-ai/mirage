`AirtableVFS` turns the bases a personal access token can reach into a
read-only tree: every table holds its field schema, its records as JSON lines
and one file per saved view. Writes go through the
[airtable CLI](/python/cli/airtable), which takes the same config. Set up the token as in [Airtable setup](/home/setup/airtable).

## Install

```bash
pip install mirage-ai
```

## Configure

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.airtable import AirtableConfig, AirtableVFS

config = AirtableConfig(token=os.environ["AIRTABLE_TOKEN"])
ws = Workspace({"/airtable": AirtableVFS(config)}, mode=MountMode.READ)

result = await ws.shell("ls /airtable/bases")
print(await result.stdout_str())
await ws.close()
```

`base_ids` limits the mount to those bases, and `max_read_records` bounds a full read
of one file. Unknown keys are refused, so a misspelled `base_ids` fails loudly
instead of widening the mount to every base.

## Authentication

The token needs the scopes `data.records:read` and `schema.bases:read`; without
`schema.bases:read` it cannot list tables. Only the bases (or workspaces) under
the token's **Access** are visible: a base left out reads as if it did not
exist. The [airtable CLI](/python/cli/airtable)'s writes also need `data.records:write`.

## Behavior

- **Read-only:** a record write is not a file write, so the mount refuses it.
  The [airtable CLI](/python/cli/airtable) names a base, a table and a record by the id after
  the last `__` of the mount's folder names, and a `records.jsonl` line is its
  stdin shape, so an edit pipes straight back:

  ```bash
  jq -c 'select(.fields.Status == "Todo") | .fields.Status = "Done"' \
    /airtable/bases/Product_Roadmap__appRoadmapBase001/Features__tblFeatures000001/records.jsonl \
    | airtable record update --base appRoadmapBase001 --table tblFeatures000001
  ```

  The CLI also reaches what a file cannot: server-side filters
  (`airtable record list --formula` or `--view`), one record by id
  (`airtable record get`) and comments.
- **Read limit:** a file holding more than `max_read_records` records ends with
  `File too large` (`cat: <path>: File too large`) instead of paging for
  minutes. `cat` and `grep` print each page as it arrives, so the first
  `max_read_records` records come before the error, and a reader that stops first
  (`head -c 100`, `grep -l`) never reaches it. Every command reports it per
  file and moves on, so `grep -l x a b` still answers for the files under the
  cap. Use `head`, a view, or raise the cap.
- **Order:** `records.jsonl` follows the API's own order, which Airtable calls
  arbitrary but keeps stable; a view file applies the view's sort.
- **Empty cells:** Airtable omits empty values from a record, a `false`
  checkbox included, so a missing key means empty.
- **Links and attachments:** a linked-record field is a list of record ids. An
  attachment URL expires two hours after it was read, so re-read the record
  before downloading.
- **Sizes:** `base.json` and `table.json` report their exact size. Record files
  have no size until read, which is what `ls -l` and `stat` show.
- **Freshness:** records are always read live; listings of bases, tables and
  views may be cached.
- **Rate limits:** requests are spaced to `requests_per_second` per base. A `429` that says
  `RATE_LIMIT_REACHED` is retried after Airtable's 30-second penalty; a `429`
  for an exhausted monthly quota is reported at once, since waiting cannot fix
  it.

## Integration

Airtable answers these commands through its own API, so fewer records are
read. See [Integration](/home/integration/overview).

- `grep` and `rg` on one file: a `filterByFormula` fetches only the records
  that may match.
- `head -n N`: fetches N records, through `maxRecords`, so the first lines of
  a large table cost one request.

For one plain text in a `records.jsonl` or a view's file, the formula searches
the record id and each text, select, email, url and phone cell, lowercased, in
the order a plain read lists them. Number, date and checkbox cells hold no word
to search. A link, AI text or attachment cell holds no space outside the text a
formula reads of it, so a table with one is searched for a text with a space
and read for a single word. The file is read as usual for a table with a
collaborator, lookup, rollup or formula field, for a text a field name holds,
or when more than `max_read_records` records match. A table too large to read
can still be searched when the output shows no line numbers or context.
