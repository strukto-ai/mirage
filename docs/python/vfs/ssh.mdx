`SSHVFS` mounts a directory of a remote server over SFTP: its folders and
files appear as they are on the server. Set up the key and server as in [SSH setup](/home/setup/ssh).

## Install

```bash
pip install "mirage-ai[ssh]"
```

## Configure

```python
from mirage import MountMode, Workspace
from mirage.vfs.ssh import SSHConfig, SSHVFS

config = SSHConfig(
    host="server.example.com",
    username="deploy",
    identity_file="~/.ssh/id_ed25519",
    root="/srv/data",
)
ws = Workspace({"/remote": SSHVFS(config)}, mode=MountMode.WRITE)

result = await ws.shell("ls /remote && tail -n 20 /remote/logs/app.log")
print(await result.stdout_str())
await ws.close()
```

`host` also matches a `~/.ssh/config` alias, and that entry's settings apply.
`known_hosts` turns on host-key checking. Use `MountMode.EXEC` when `python3`
or `js` should run scripts from the mount.

## Authentication

The mount offers, in order, the key at `identity_file`, then the key text in
`private_key`, which a [credential pointer](/home/service-credentials#pointer-fields)
can read from a secret store. Without either, it tries the SSH agent and the
default keys in `~/.ssh`. `passphrase` unlocks an encrypted key. `password`
works too, but a key is preferred.

The server needs SFTP turned on. Reads and writes go as far as the SSH
account's own file permissions allow.

## Behavior

- **Host keys:** checked only when `known_hosts` names a file; unset, any
  host key is accepted.
- **Caching:** listings are cached for 60 seconds by default. File bytes are
  served from cache without a check until the mount's `ttl:`; an SSH mount
  does not accept `read: fresh`.
- **Running programs:** this mount reads and writes files. To run programs on
  the server, use the [SSH machine](/home/setup/machine/ssh).
