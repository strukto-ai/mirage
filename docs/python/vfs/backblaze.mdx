`BackblazeVFS` mounts one bucket: every object becomes a file and every `/` in
a key a folder. It is the [S3 VFS](/python/vfs/s3) pointed at Backblaze B2's
endpoint, so commands behave as they do on S3. Credentials are set up on the
[Backblaze B2 page](/home/setup/backblaze).

## Install

```bash
pip install "mirage-ai[s3]"
```

## Configure

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.backblaze import BackblazeConfig, BackblazeVFS

config = BackblazeConfig(
    bucket=os.environ["B2_BUCKET"],
    region=os.environ["B2_REGION"],
    access_key_id=os.environ["B2_ACCESS_KEY_ID"],
    secret_access_key=os.environ["B2_SECRET_ACCESS_KEY"],
)
ws = Workspace({"/b2": BackblazeVFS(config)}, mode=MountMode.WRITE)

result = await ws.shell("ls /b2 && find /b2 -name '*.csv'")
print(await result.stdout_str())
await ws.close()
```

`region` also picks the endpoint, `https://s3.<region>.backblazeb2.com`,
as the bucket's **Endpoint** shows it in the Backblaze console; `endpoint_url`
replaces it.
A mount takes `MountMode.READ`, `WRITE` or `EXEC`.

## Authentication

Credentials come from the first of:

1. `access_key_id` and `secret_access_key`, with `session_token` for temporary
   credentials.
2. `aws_profile`, a profile in `~/.aws/credentials`.
3. The AWS credential chain: environment variables, then the instance or
   container role.

`access_key_id` takes the application key's keyID and `secret_access_key` its applicationKey.
The key needs **Read Only** on the bucket, or **Read and Write** for a
write mount, with **Allow List All Bucket Names** ticked. The master
application key does not work with the S3-compatible API, and neither
does a key created before May 4, 2020.
An object the key may not read or change answers `Permission denied`.

## Layout

```text
/b2/
  README.md
  logs/
    app-2026-11-15.log
    app-2026-11-16.log
  reports/
    2026-q3.csv
    2026-q4.csv
```

`/b2/reports/2026-q3.csv` is the key `reports/2026-q3.csv`. Folders come
from the `/` in keys.

## Behavior

- **Key prefix:** `key_prefix="users/42/"` mounts only that part of the bucket,
  so `/b2/notes.md` is the key `users/42/notes.md`. A leading `/` is dropped
  and a trailing `/` added.

## Integration

Backblaze B2 answers these commands through its own API, so fewer objects are
read. See [Integration](/home/integration/overview).

- `find`: one recursive listing.
- `du`: one recursive listing.
- `ls -R` and `tree`: one recursive listing.
