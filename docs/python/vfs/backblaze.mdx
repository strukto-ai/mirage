The Backblaze VFS is a thin wrapper over the [S3 VFS](/python/vfs/s3).
It maps a `BackblazeConfig` to an `S3Config` and reuses the exact same backend,
commands, and behavior as S3, it just derives the right B2 endpoint from
`region`. Uses aioboto3 against Backblaze B2's S3-compatible API.

The endpoint is computed from `region` as `s3.<region>.backblazeb2.com`. Pass
`endpoint_url` to override.

Install the extra:

```bash
pip install "mirage-ai[s3]"
```

## Config

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.backblaze import BackblazeConfig, BackblazeVFS

config = BackblazeConfig(
    bucket=os.environ["B2_BUCKET"],
    region=os.environ["B2_REGION"],          # e.g. us-west-004
    access_key_id=os.environ["B2_ACCESS_KEY_ID"],   # B2 application keyID
    secret_access_key=os.environ["B2_SECRET_ACCESS_KEY"],
    # Optional:
    # endpoint_url="https://s3.us-west-004.backblazeb2.com",
    # timeout=30,
    # proxy="http://proxy:8080",
)
vfs = BackblazeVFS(config)
ws = Workspace({"/data": vfs}, mode=MountMode.READ)
```

Both `READ` and `WRITE` modes are supported.

| Field | Required | Default | Description |
| --- | --- | --- | --- |
| `bucket` | yes |  | Name of the bucket to mount. |
| `region` | yes |  | Provider region every request is signed for. Most providers also build their endpoint URL from it unless `endpoint_url` is set. |
| `endpoint_url` | no |  | Endpoint URL that replaces the one the provider derives. |
| `access_key_id` | no |  | Access key ID, used only together with `secret_access_key`. Unset falls back to the AWS credential chain: `aws_profile`, the environment, the shared credentials file, then an instance role. Redacted in snapshots. |
| `secret_access_key` | no |  | Secret access key paired with `access_key_id`. Redacted in snapshots. |
| `session_token` | no |  | Session token for temporary credentials, sent with the access key pair. Redacted in snapshots. |
| `aws_profile` | no |  | Named profile in the shared AWS config and credentials files that supplies credentials when no access key pair is given. |
| `path_style` | no | `False` | Address the bucket in the URL path (`<endpoint>/<bucket>/<key>`) instead of as a subdomain of the endpoint. |
| `key_prefix` | no |  | Key prefix inside the bucket that the mount treats as its root; keys outside it are not visible. Leading slashes are dropped and a trailing `/` is added. |
| `timeout` | no | `30` | Seconds to wait to connect, and for each read of a response, before the request fails. |
| `proxy` | no |  | Proxy URL for every HTTP and HTTPS request to the endpoint. Redacted in snapshots. |

## Example

```python
import asyncio
import os

from dotenv import load_dotenv

from mirage import MountMode, Workspace
from mirage.vfs.backblaze import BackblazeConfig, BackblazeVFS

load_dotenv(".env.development")

config = BackblazeConfig(
    bucket=os.environ["B2_BUCKET"],
    region=os.environ["B2_REGION"],
    access_key_id=os.environ["B2_ACCESS_KEY_ID"],
    secret_access_key=os.environ["B2_SECRET_ACCESS_KEY"],
)
vfs = BackblazeVFS(config)


async def main() -> None:
    ws = Workspace({"/data/": vfs}, mode=MountMode.READ)

    r = await ws.shell("ls /data/")
    print(await r.stdout_str())

    r = await ws.shell("find /data/ -name '*.csv'")
    print(await r.stdout_str())


if __name__ == "__main__":
    asyncio.run(main())
```

## Notes

- Backblaze registers under its own `VFSName` and routes through the same `core/s3`
  implementation, so the full S3 shell-command set applies. See the
  [S3 VFS](/python/vfs/s3) for the complete command reference,
  range reads, streaming, and the index cache fast path.
- For credential setup, see [Backblaze B2 Setup](/home/setup/backblaze).
