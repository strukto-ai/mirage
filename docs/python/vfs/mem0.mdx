`Mem0VFS` mounts the memories of one Mem0 scope, a user, an agent or a run,
read-only. Each memory is one `<memory_id>.json` file. Set up the API key and the scope as in [Mem0 setup](/home/setup/mem0).

## Install

```bash
pip install "mirage-ai[mem0]"
```

## Configure

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.mem0 import Mem0Config, Mem0VFS

config = Mem0Config(
    api_key=os.environ["MEM0_API_KEY"],
    user_id=os.environ["MEM0_USER_ID"],
)
ws = Workspace({"/memory": Mem0VFS(config)}, mode=MountMode.READ)

result = await ws.shell("ls /memory && grep -rl allergic /memory")
print(await result.stdout_str())
await ws.close()
```

An agent or run scope sets `agent_id` or `run_id` instead of `user_id`. `host`
(default `https://api.mem0.ai`) points at another Mem0 API host.

## Authentication

The mount sends a Mem0 Platform API key, created on the dashboard's **API
Keys** page; the organization and project come from the key. Exactly one of
`user_id`, `agent_id` and `run_id` is set. A pair is refused: Mem0 splits a
memory added with both into separate memories, so a combined filter matches
nothing.

## Layout

```text
/memory/
  6d1ba0fc-1f0c-495b-b5b1-9141b2674b37.json
  b52e7a19-0c4d-4a8e-9f3b-2d6c1e8a7f40.json
```

The tree is flat: one file per memory in the scope, named by memory id. A file
holds the full record, `memory`, `categories`, `metadata`, `created_at`,
`updated_at`, `structured_attributes` and the rest:

```json
{
  "id": "6d1ba0fc-1f0c-495b-b5b1-9141b2674b37",
  "memory": "User's name is Alex, follows a vegetarian diet, allergic to nuts",
  "categories": ["personal_details"],
  "created_at": "2026-06-15T00:34:18-07:00",
  "updated_at": "2026-06-15T00:34:22-07:00"
}
```

## Behavior

- **Read-only:** no command changes the memories.
- **Times:** `stat` reports `updated_at`, or `created_at` when unset, as the
  modified time, and shows both.
- **grep:** `grep` and `rg` search the JSON that `cat` prints, so a match can
  come from metadata such as categories and timestamps. Plain `grep` needs `-r`
  or a glob on the mount; `rg` recurses by default.
- **Freshness:** the first `ls` fetches every memory in the scope, and reads
  reuse it until the cache expires. `search` always asks Mem0.
- **Snapshots:** a snapshot keeps the config, and loading it needs the mount
  handed back through `mounts=`.

### Search

The `search` CLI runs Mem0's semantic search in the same
scope. Register it on the workspace:

```python
from mirage.commands.cli.builtin.search import SEARCH

ws.register_cli("search", SEARCH)
```

```bash
search "what does the user eat for breakfast" /memory/
search --top-k 5 --threshold 0.4 "morning routine" /memory/
```

`--top-k` defaults to `default_search_limit` (10). `--threshold` is between 0
and 1. Each hit prints its file and score, then the memory, ranked by score:

```text
/memory/6d1ba0fc-1f0c-495b-b5b1-9141b2674b37.json:0.91
User asked for food recommendations to stay full in the morning
```
