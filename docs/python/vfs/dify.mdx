`DifyVFS` mounts a Dify Knowledge dataset, read-only, as a tree of text files.
Each document is one file, assembled from its segments. Set up the API key and the dataset as in [Dify setup](/home/setup/dify).

## Install

```bash
pip install mirage-ai
```

## Configure

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.dify import DifyConfig, DifyVFS

config = DifyConfig(
    api_key=os.environ["DIFY_API_KEY"],
    base_url=os.environ["DIFY_BASE_URL"],
    dataset_id=os.environ["DIFY_DATASET_ID"],
)
ws = Workspace({"/knowledge": DifyVFS(config)}, mode=MountMode.READ)

result = await ws.shell("find /knowledge -type f && grep -rn billing /knowledge")
print(await result.stdout_str())
await ws.close()
```

`slug_metadata_name` picks the document metadata field that holds each path
(default `slug`). `max_concurrency`, `retry_attempts` and `retry_max_delay`
bound the requests in flight and the retries after a 429, a 5xx or a
transport error.

## Authentication

The mount sends a Dify Knowledge API key, created under **Knowledge**,
**Service API**. The key reaches either every knowledge base or only the one
mounted, and that knowledge base keeps **API Access** on.

## Layout

```text
/knowledge/
  README.md
  guides/
    api.md
    quickstart.md
  policies/
    support.md
```

A document's path is the value of its `slug` metadata field; without one, the
file takes the document name.

| Dify document | Metadata | Mirage path |
| --- | --- | --- |
| `Quickstart` | `slug=guides/quickstart.md` | `/knowledge/guides/quickstart.md` |
| `README.md` | no slug | `/knowledge/README.md` |

- `/` makes folders. No empty segment, `.` or `..`.
- Each slug is unique across the dataset.
- A slug is never also a folder: `guides` and `guides/quickstart.md` cannot
  both be documents.
- Only enabled, fully indexed, unarchived documents appear.

## Behavior

- **Read-only:** no command changes the dataset.
- **Plain text:** a file is its completed, enabled segments joined by line
  breaks, whatever the original format.
- **Tree refresh:** listings are reused until the index expires, so a document
  edited in Dify can show its old path and metadata until then.
- **Snapshots:** a snapshot keeps the config, and loading it needs the mount
  handed back through `mounts=`.

### Search

The `search` CLI asks Dify's dataset retrieval API.
Register it on the workspace:

```python
from mirage.commands.cli.builtin.search import SEARCH

ws.register_cli("search", SEARCH)
```

```bash
search "how do I reset my password" /knowledge/
search --method hybrid --top-k 5 "billing policy" /knowledge/policies/
search --method semantic --threshold 0.4 "quickstart" /knowledge/guides/*.md
```

`--method` takes `semantic` (the default), `fulltext`, `hybrid` or `keyword`.
`--top-k` defaults to 10 and is capped at 100. `--threshold` is between 0 and
1; another value, or another method, exits 1 before Dify ranks anything. Each
hit prints its path and score, then the segment, and two hits in one document
stay two records:

```text
/knowledge/policies/refunds:0.82
Refunds are allowed within 30 days.
```

A search under a path filters retrieval by the slug field, or by
`document_name` for a document without a slug. That filter needs **Built-in
Fields** turned on in the dataset's metadata settings. Without it, a scoped
search on name-based files may return nothing while `ls`, `find`, `cat` and
`grep` still see them, so a slug on every document is the reliable choice.
