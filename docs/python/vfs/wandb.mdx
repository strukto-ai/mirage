`WandbVFS` mounts Weights & Biases (W&B) experiments as read-only files: each
run's metadata, config, summary, metric history and logged files. Set up the API key and entities as in [Weights & Biases setup](/home/setup/wandb).

## Install

```bash
pip install mirage-ai
```

## Configure

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.wandb import WandbConfig, WandbVFS

config = WandbConfig(
    entities=["my-team"],
    api_key=os.environ["WANDB_API_KEY"],
)
ws = Workspace({"/wandb": WandbVFS(config)}, mode=MountMode.READ)

result = await ws.shell("find /wandb/my-team -maxdepth 3 -name run.json")
print(await result.stdout_str())
await ws.close()
```

`page_size` and `max_pages` bound each listing, and `base_url` points at
another W&B server.

<ResponseField name="timeout" type={"float"} default={"30"}>
  Seconds a request may wait to connect, or between two reads of its answer, before it fails; a download that keeps flowing is never cut off.
</ResponseField>
<ResponseField name="entities" type={"list[str]"} required>
  W&B entities (users or teams) the mount shows as top-level directories; no other entity is reachable.
</ResponseField>
<ResponseField name="api_key" type={"str"} default={"SecretStr('')"} post={["secret"]}>
  W&B API key, sent as HTTP Basic auth. Empty sends no credentials.
</ResponseField>
<ResponseField name="base_url" type={"str"} default={"'https://api.wandb.ai'"}>
  W&B API root. Queries go to its `/graphql`, and only downloads from the same origin carry the key.
</ResponseField>
<ResponseField name="page_size" type={"int"} default={"100"}>
  Items per GraphQL page, and steps per window when reading `history.jsonl`.
</ResponseField>
<ResponseField name="max_pages" type={"int"} default={"10000"}>
  The most pages one listing or history read fetches. Past it the read fails rather than return a partial result.
</ResponseField>

Fields marked secret are redacted in snapshots.

    **VFS Layout**

    **`/<path>`**

    ```text
    /<path>
      <entity>/
        <project>/
          <run-id>/
            run.json
            config.json
            summary.json
            history.jsonl
            files/
    ```

    - Read only; only configured entities are visible. Run ids are stable,
      display names may repeat.
    - `run.json` holds identity, creator, sweep, group, tags, timestamps,
      notes and system metrics; its `read_only` is W&B's permission, not the
      mount mode.
    - `history.jsonl` is the full unsampled history in logged order and can
      be large; `head` streams a prefix.
    - `summary.json` holds stored values, not history maxima.
    - `files/` keeps run-relative paths; `files/wandb-metadata.json`
      describes the machine and environment.

    **Supported Unix Commands for VFS**

    Unix commands work on each path as on a local filesystem, as far as the path supports them:

    | Path | Supported |
    | --- | --- |
    | `/<path>` | Commands that read files (`ls`, `cat`, `grep`, `find`, `jq` and the rest). |

    **Limitations of Unix Commands for VFS**

    Where a path differs from a local filesystem:

    | Path | Limitations |
    | --- | --- |
    | `/<path>` | Read only: no command changes files. `grep -r`, `find` and `du` stop after 1000 files; a glob matching more, `tar -c`, `cp -r` and `rm -r` are refused. |

    Run `man <cmd>` or `<cmd> --help` for one command's usage.
