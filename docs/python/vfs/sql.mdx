The SQL VFS keeps a filesystem in a database's tables. It supports full read
and write operations and needs no extra for a SQLite file: it uses Python's
own `sqlite3`.

## Config

```python
from mirage import MountMode, Workspace
from mirage.vfs.sql import SqlVFS

vfs = SqlVFS("./workspace.db")
ws = Workspace({"/sql": vfs}, mode=MountMode.WRITE)
```

| Parameter  | Required | Default   | Description                                              |
| ---------- | -------- | --------- | -------------------------------------------------------- |
| `path`     | no       | in memory | The SQLite file, opened and closed with the mount        |
| `capacity` | no       | none      | The most bytes the files may hold, like `100MB`          |
| `driver`   | no       | none      | A `SqlDriver` to borrow instead of a file; you close it |

The tables are laid out as
[AgentFS](https://github.com/tursodatabase/agentfs)'s:

- `fs_inode`: one row per file and directory, with its size and mtime
- `fs_dentry`: each entry's name under its parent directory
- `fs_data`: a file's bytes, in rows of the database's chunk size (4 KiB unless the database says otherwise)
- `fs_config`: the chunk size

One database holds one filesystem. The TypeScript mount reads and writes the
same tables, so a Python and a Node process on one file serve one filesystem.

## Cache

Index TTL is `0`, so listings are read from the database every time. A
workspace `index:` block still applies its `ttl` to this mount.

## Example

```python
import asyncio

from mirage import MountMode, Workspace
from mirage.vfs.sql import SqlVFS


async def main():
    ws = Workspace({"/sql": SqlVFS("./workspace.db")}, mode=MountMode.WRITE)
    try:
        await ws.shell("mkdir -p /sql/data/")
        await ws.shell('echo "hello world" | tee /sql/data/hello.txt')
        r = await ws.shell("cat /sql/data/hello.txt")
        print(await r.stdout_str())
    finally:
        await ws.close()


if __name__ == "__main__":
    asyncio.run(main())
```
