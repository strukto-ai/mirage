`GSlidesVFS` mounts the Google Slides an account can see: each presentation
becomes a `.gslide.json` file holding the Slides API's JSON, split into the
presentations it owns and those shared with it. Credentials are set up on the
[Google Workspace page](/home/setup/google).

## Install

```bash
pip install mirage-ai
```

## Configure

```python
import os

from mirage import MountMode, Workspace
from mirage.vfs.gslides import GSlidesConfig, GSlidesVFS

config = GSlidesConfig(
    client_id=os.environ["GOOGLE_CLIENT_ID"],
    client_secret=os.environ["GOOGLE_CLIENT_SECRET"],
    refresh_token=os.environ["GOOGLE_REFRESH_TOKEN"],
)
ws = Workspace({"/gslides": GSlidesVFS(config)}, mode=MountMode.READ)

result = await ws.shell("ls /gslides/owned && jq '.slides | length' /gslides/owned/2026-*.gslide.json")
print(await result.stdout_str())
await ws.close()
```

`access_token` replaces the client and refresh token with a token or a
callable that returns one. A `MountMode.WRITE` mount also allows `mv` and `rm`.

## Authentication

Credentials come from the first of:

1. `access_token`, a token or a callable that returns one.
2. `client_id` and `refresh_token`, with `client_secret` unless the client
   uses PKCE. Mirage trades the refresh token for access tokens on its own.

The mount needs the Google Slides API with the
`https://www.googleapis.com/auth/presentations` scope, and the Drive API with the
`https://www.googleapis.com/auth/drive` scope, since the listing comes from
Drive. A read-only mount can use the `readonly` variants of both scopes.

## Layout

```text
/gslides/
  owned/
    2026-11-14_QBR_Deck__1Xk9rT2bQ.gslide.json
  shared/
    2026-10-02_Launch_Plan__1Pq7sV4mN.gslide.json
```

- `owned/` holds the presentations the account owns, shared or not;
  `shared/` holds those others shared with it.
- A file is named `<YYYY-MM-DD>_<title>__<presentation-id>.gslide.json`. The date
  is the last modified day and is left out when Drive gives none.
- A file holds the Slides API's JSON for the presentation: its slides,
  layouts and text.

## Behavior

- **Shared Drives:** a presentation in a Shared Drive has no owner, so it is
  listed under `shared/`, as on the `gdrive` mount.
- **Date globs:** a glob on the date prefix, such as `2026-05-*`, asks Drive
  only for the presentations modified on those days.
- **Incomplete listings:** Drive may skip part of the account's files and say
  so. The short listing is still shown, and the next `ls` lists again.
- **Rename:** on a `write` mount, `mv` to a new name in the same folder
  changes the title. The date and the id must stay, and the title is spelled
  as the listing spells it (spaces become `_`).
- **Delete:** on a `write` mount, `rm` deletes the presentation for good, not to
  the trash. `owned/` and `shared/` cannot be removed.
- **Edits:** creating presentations, batch updates and raw API calls go
  through the [`gws`](/python/cli/gws) CLI.

## Integration

Google Slides answers these commands through its own API, so fewer files are
read. See [Integration](/home/integration/overview).

- `grep -r` and `rg` with `-w`: Drive full-text search names the
  presentations to read. Every one is read when the search fails or finds
  nothing, and when the word may be in any presentation's JSON whatever the
  text says: a word with a digit, a Slides API name or value
  (`pageElements`, `SLIDE`), or a word every presentation carries (`https`,
  `arial`). Drive indexes a write some time after it lands and searches the
  presentation's text, so it can leave out one whose JSON holds the word only
  in another value (a font, a link or image address, a layout name, an id) or
  only inside a word that styling splits (`snow` in bold inside `snowman`). `walk_limit: -1` in the mount's
  `"@all"` [command limit](/home/core/output-limits) turns the search off and
  reads every file.
