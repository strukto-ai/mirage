## How To Read This Matrix

Watching splits into two halves, and they have different support stories:

- **Delivery** (`ws.watch()` + `ws.notify()`) works on **every mount** today.
  Delivery is notify-driven: any detection you run maps its signal to a
  `FileEvent` and injects it, and Mirage handles invalidation, scope matching,
  and the event stream. No per-backend code is involved.
- **Detection** is the provider's push, per backend. Where the push names
  the change, Mirage ships a **mapper** (`to_events`) that turns the payload
  into paths. Where the push is only a **ping**, the mount's `delta_hook()`
  answers it with one read of the provider's change feed.

| S3 / S3-compatible | S3 Event Notifications (SQS, SNS, EventBridge) | mapper `S3EventHook` | |

A mapper reads the payload and, at most, the backend for what the payload
leaves out (GridFS counts the revisions a name has left; MongoDB lists a
database's views). A ping handler reads the change feed from its cursor and
never walks the tree. Calendar issues a sync token only at the end of a full
sync, so it reads a calendar whole for its baseline and when its token
expires.

## What a ping handler keeps

The checkpoint `pull` hands back is opaque, but it is more than the feed's
cursor. A feed that names items by id (Drive, Graph, Box) says where an item
is now, not where it was, so the checkpoint keeps the path of each item a pull
has placed, and a later rename, move or delete leaves that path. An item seen
for the first time is a `create` when the provider says it is as it was made
(its created and modified times agree, or the feed says it was added) and an
`update` otherwise; where it was before is left to the index's expiry.

A cursor the provider no longer honors answers `unknown` on the watch root and
a fresh cursor: a Dropbox reset, a Graph `resyncRequired`, a Gmail history id
past what Gmail keeps, and a Box stream position older than two weeks, since
Box replays whatever it still has rather than refusing an old position.

## What "Delivery ✓" buys you without a mapper

Any backend is watchable end to end the moment you have a signal from
anywhere:

```python
async for event in ws.watch("/s3/exports/*.csv"):
    ...

await ws.notify(
    FileEvent(
        kind=FileChangeKind.CREATE,
        path=PathSpec.from_str_path("/s3/exports/jan.csv"),
        timestamp=datetime.now(timezone.utc),
    )
)
```

`watch()` is an async generator, so it subscribes on the first iteration, not at
the call: the loop and the `notify` call belong to different tasks (a request
handler, a queue consumer). Awaiting `notify` before anything consumes the
iterator drops the event.

The guarantee is identical on every backend: caches for the changed path and
its ancestor listings are invalidated before delivery, plus the cached subtree
of a removed folder that still has a listing cached at or under it, so reads
after an event are fresh within the limit [Watch](/python/watch) describes.

## The Dropbox longpoll example

The [Dropbox longpoll example](https://github.com/strukto-ai/mirage/blob/main/examples/python/dropbox/watch.py)
owns the loop in the embedding program: take a baseline with `pull`, wait for
`list_folder/longpoll`, then pull and `notify` each change. The example reads
the cursor from the checkpoint (`dropbox.cursor`) to longpoll on it, while
passing the entire checkpoint back to `pull`. This is Dropbox-specific example
code; other consumers should treat checkpoints as opaque. On a reset, pull with
the old checkpoint: the hook reports the watch root as `unknown` and takes a
fresh cursor. A missing watch root retries after 30 seconds.

Set `DROPBOX_APP_KEY`, `DROPBOX_APP_SECRET`, and `DROPBOX_REFRESH_TOKEN`;
optionally set `DROPBOX_ROOT_PATH`. From the repo root, run
`./python/.venv/bin/python examples/python/dropbox/watch.py`. Ctrl-C cancels
the current request and closes the HTTP session and workspace.

Dropbox's [longpoll endpoint](https://docs.dropboxapi.com/dropbox-api/api-reference/user-endpoints/files/list-folder-longpoll)
uses the notification host without an Authorization header. Its timeout is
30 to 480 seconds; the HTTP timeout must also allow up to 90 seconds of server
jitter. The returned `backoff` is a required minimum delay before the next
longpoll, including a response with no changes. The examples let transport or
unexpected API failures surface and close their resources on cancellation.
