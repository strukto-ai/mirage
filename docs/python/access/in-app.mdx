Call these when your agent runs in the same process as the workspace. The server, MCP, SSH and the CLI all call them underneath.

```text
Workspace  mounts, profiles, policies, the store
└── Session  one agent: its cwd, env, history and profile
    ├── shell   run a line
    ├── vfs     read and write files
    └── tools   the seven agent tools
```

```python
import asyncio

from mirage import MountMode, Workspace
from mirage.vfs.ram import RAMVFS

async def main() -> None:
    ws = Workspace({"/data": RAMVFS()}, mode=MountMode.WRITE)
    session = await ws.session("agent")
    await session.vfs.write("/data/notes.txt", b"one\ntwo\n")
    result = await session.shell("wc -l < /data/notes.txt")
    print(result.exit_code, await result.stdout_str())
    await ws.close()

asyncio.run(main())
```

## Workspace

```python
from mirage import Workspace
```

```python
class Workspace(
    mounts: dict[str, VFSMount],
    mode: MountMode = MountMode.READ,
    ...,
)
```

One virtual terminal over the VFS mounted at each path.

<ResponseField name="mounts" type="dict[str, VFSMount]" required>
  The VFS at each path, such as `{"/": RAMVFS(), "/s3": S3VFS(config)}`. Each value is a VFS, `(vfs, mode)`, `(vfs, mode, limits)` or `Mount(...)`.
</ResponseField>
<ResponseField name="mode" type="MountMode" default="MountMode.READ">
  The mode a mount gets when it sets none: `READ`, `WRITE` or `EXEC`.
</ResponseField>
<ResponseField name="profiles" type="dict[str, SessionProfile]">
  Named [profiles](/home/policy/overview) a session can be created under.
</ResponseField>
<ResponseField name="profile" type="str">
  The profile a session gets when it names none.
</ResponseField>
<ResponseField name="policies" type="list[Policy]">
  [Policies](/home/policy/overview) every line passes through.
</ResponseField>
<ResponseField name="on_ask" type="AskHandler">
  Resolves an approval request (ask) while the line waits. Without a handler, asks are recorded in [`ws.decisions`](#workspace-methods).
</ResponseField>
<ResponseField name="workspace_id" type="str">
  The workspace's id, generated when unset.
</ResponseField>
<ResponseField name="session_id" type="str">
  The default session's id.
</ResponseField>
<ResponseField name="store" type="WorkspaceStateStore">
  Where the workspace keeps its [state](/home/infrastructure/overview#workspace-state): symlinks and file attributes, command logs, sessions and background jobs. In memory when unset. A store passed in is borrowed: close it after `ws.close()`, or pass `owns_store=True`.
</ResponseField>

See [Workspace configuration](/home/configuration/workspace) for YAML settings.
Direct SDK construction defaults `mode` to `READ`; YAML defaults it to `write`.

```python
from mirage import MountMode, Workspace
from mirage.vfs.ram import RAMVFS

ws = Workspace({"/": RAMVFS()}, mode=MountMode.WRITE)
```

<Accordion title="Queue capacity and a shared store">
  Set the per-queue capacity when creating the workspace:

  ```python
  from mirage import IOConfig, Workspace
  from mirage.vfs.ram import RAMVFS

  ws = Workspace({"/": RAMVFS()}, io=IOConfig(buffer_bytes=262144))
  ```

  Every process that builds the workspace on one Redis store, under the same ids, shares its sessions and background jobs:

  ```python
  from mirage import MountMode, Workspace
  from mirage.vfs.ram import RAMVFS
  from mirage.workspace.store.redis import RedisWorkspaceStateStore

  store = RedisWorkspaceStateStore(url="redis://localhost:6379/0")
  ws = Workspace(
      {"/": RAMVFS()},
      mode=MountMode.WRITE,
      workspace_id="agent-ws",
      session_id="s1",
      store=store,
  )
  ```
</Accordion>

## Workspace methods

| Method | Does |
| --- | --- |
| `ws.session` | Create a session, or adopt one that exists. |
| `ws.set_profile`, `ws.set_session_profile` | Change a profile's rules, or move a session to another profile. |
| `ws.list_sessions`, `ws.close_session` | List the sessions, or close one. |
| `ws.cancel`, `ws.kill` | Stop running lines, or background jobs and the programs they started. |
| `ws.snapshot`, `Workspace.load` | Save the workspace to a tar, and rebuild it from one. |
| `ws.copy` | A deep copy of the workspace, without a tar in between. |
| `ws.decisions` | Answer the asks waiting for a host. |
| `ws.close` | Stop the jobs and close the mounts. |

Expand one for its signature and an example.

<AccordionGroup>
  <Accordion title="ws.session">
    ```python
    await ws.session(
        session_id, mounts=None, *, profile=None, permissions=None
    ) -> Session
    ```

    Returns the [`Session`](#session) for `session_id`, creating it if the id is new.

    - `profile`, `mounts` and `permissions` apply only when the session is created. Passing them for an existing session raises `ValueError`.
    - `permissions` adds rules for this session only, on top of its profile: a command tree, hides and weaker mount modes. The stricter of it and the profile wins, so it cannot allow what the profile refuses. It cannot add a policy.
    - `ws.create_session(...)` is the sync form. It returns a `SessionState`, not a `Session`.

    ```python
    session = await ws.session("agent")
    ```
  </Accordion>
  <Accordion title="ws.set_profile, ws.set_session_profile">
    ```python
    ws.set_profile(name, profile) -> None
    await ws.set_session_profile(session_id, profile) -> SessionState
    ```

    - `set_profile(name, profile)` adds or replaces a named profile. A profile no session could run under raises `PolicyError` and changes nothing.
    - Running sessions keep their old rules until you call `set_session_profile`.
    - `set_session_profile(session_id, profile)` takes a profile name, `None` (the workspace default) or a profile document. The session keeps its working directory, variables and history.
    - The profile name is the session's user: `whoami` prints it (uid 1000). A session with no profile is `root`. A profile document passed directly has uid 1000 and no name.

    ```python
    ws.set_profile(
        "user",
        {
            "commands": {"*": "deny", "ls": "allow", "cat": "allow"},
            "paths": {"hide": ["/data/secret"]},
        },
    )
    await ws.set_session_profile("agent", "user")
    ```
  </Accordion>
  <Accordion title="ws.list_sessions, ws.close_session">
    ```python
    ws.list_sessions() -> list[SessionState]
    await ws.close_session(session_id) -> None
    ```

    List the sessions, or close one: its lines are cancelled and its jobs end. The default session cannot be closed.

    <Expandable title="SessionState">
      <ResponseField name="session_id" type="str" />
      <ResponseField name="cwd" type="str">The working directory.</ResponseField>
      <ResponseField name="env" type="Mapping[str, str]">The exported variables.</ResponseField>
      <ResponseField name="profile" type="str | None">The profile it was created under.</ResponseField>
      <ResponseField name="mount_modes" type="dict[str, MountMode] | None">Its mount modes, when narrower than the workspace's.</ResponseField>
      <ResponseField name="last_exit_code" type="int">`$?`.</ResponseField>
      <ResponseField name="created_at" type="float">Unix time.</ResponseField>
    </Expandable>

    ```python
    print([s.session_id for s in ws.list_sessions()])
    await ws.close_session("agent")
    ```
  </Accordion>
  <Accordion title="ws.cancel, ws.kill">
    ```python
    await ws.cancel(session_id=None) -> int
    await ws.kill(session_id=None) -> int
    ```

    Stop a session's work, or every session's with no id, and leave the sessions open. `cancel` cancels the running and queued lines, whichever way they came in, and returns once they have ended; each ends with `MirageAbortError`. `kill` kills the background jobs (`cmd &`) and the programs machines started. Each answers how many it stopped.

    ```python
    await ws.cancel("agent")
    await ws.kill()
    ```
  </Accordion>
  <Accordion title="ws.snapshot, Workspace.load">
    ```python
    await ws.snapshot(target, *, compress=None, s3=None) -> int
    await Workspace.load(source, *, s3=None, ...) -> Workspace
    ```

    Save the workspace to a tar and rebuild it from one. `target` and `source` are a path, a file object, or an object key with `s3=`. `snapshot` returns the tar's size in bytes.

    - While it captures, new lines and file writes wait. Running ones get 30 seconds to end, else it raises `OSError` (`EBUSY`). Disk mount files are streamed, never held whole.
    - The tar keeps the profiles, the command limits and each store's `capacity`. Each session loads back under the restrictions it ran with.
    - An override brings its own `capacity`, or none.
    - The scratch root, the RAM root added when nothing is mounted at `/`, comes back as the scratch root, an override for it included.

    ```python
    await ws.snapshot("run.tar")
    restored = await Workspace.load("run.tar")
    ```
  </Accordion>
  <Accordion title="ws.copy">
    ```python
    await ws.copy() -> Workspace
    ```

    A deep copy, without a tar in between.

    | Part | In the copy |
    | --- | --- |
    | RAM and Disk mounts | Copied; a Disk mount to a new temporary directory. |
    | S3, Redis and other remote VFS | Shared: a write through the copy reaches the same bucket. |
    | Sessions, history, profiles, command limits, secrets declarations, CLIs | Copied. |
    | Policy objects, the route policy | Not copied. |

    ```python
    fork = await ws.copy()
    ```
  </Accordion>
  <Accordion title="ws.decisions">
    ```python
    ws.decisions.pending(session_id="") -> tuple[Decision, ...]
    await ws.decisions.answer(
        decision_id, outcome, scope=Scope.ONCE, note=""
    ) -> None
    ```

    The [asks](/home/policy/policies#asks) waiting for a host. Each one belongs to the session that ran the line: `pending()` lists every session's, `pending("agent")` one session's, and an answer never reaches another session. `outcome` is `Outcome.ALLOW` or `Outcome.DENY`. `Scope.ONCE` resolves the pending ask for this line, allowing its retry to run or be refused; `Scope.SESSION` allows every line the rule covers for the rest of that session.

    <Expandable title="Decision">
      <ResponseField name="id" type="str">The id to answer it by.</ResponseField>
      <ResponseField name="session_id" type="str">The session that ran the line.</ResponseField>
      <ResponseField name="command" type="str">The command name.</ResponseField>
      <ResponseField name="argv" type="tuple[str, ...]">The words after the name, expanded.</ResponseField>
      <ResponseField name="cwd" type="str" />
      <ResponseField name="paths" type="tuple[str, ...]">The paths the line names.</ResponseField>
      <ResponseField name="reason" type="str">The rule's reason.</ResponseField>
      <ResponseField name="outcome" type="Outcome | None">The answer; `None` while it waits.</ResponseField>
      <ResponseField name="scope" type="Scope" />
      <ResponseField name="note" type="str">What the host said when answering.</ResponseField>
    </Expandable>

    ```python
    from mirage import Outcome

    for ask in ws.decisions.pending():
        await ws.decisions.answer(ask.id, Outcome.ALLOW)
    ```
  </Accordion>
  <Accordion title="ws.close">
    ```python
    await ws.close() -> None
    ```

    Stops its jobs and closes its mounts. Sessions and history stay in the workspace's store.
  </Accordion>
</AccordionGroup>

## Session

```python
from mirage import Session
```

```python
class Session(ws: Workspace, session_id: str | None)
```

One session's handle, from [`ws.session`](#workspace-methods). Every call on it runs under the session's [profile](/home/policy/overview), working directory and environment. `ws.shell`, `ws.glob`, `ws.vfs` and `ws.tools` are the same calls as the workspace's default session.

<ResponseField name="session_id" type="str" />
<ResponseField name="state" type="SessionState">The session's record, as returned by [`ws.list_sessions`](#workspace-methods).</ResponseField>
<ResponseField name="vfs" type="Files">The file API, below.</ResponseField>
<ResponseField name="tools" type="MirageToolOperations">The agent tools, below.</ResponseField>
<ResponseField name="decisions" type="Decisions">The workspace's [asks](/home/policy/policies#asks) ledger, which records pending approval requests for this session.</ResponseField>

### session.shell

```python
await session.shell(
    command, stdin=None, cwd=None, env=None,
    cancel=None, record=True, *, stream=False, machine=None,
) -> IOResult | ShellExecution
```

Runs a shell line as the session. With `stream=False`, it collects the execution’s output and returns an `IOResult`. A non-zero exit is a result, not an exception. `ws.shell` has the same streaming option and accepts `session_id` to select the session.

<ResponseField name="stdin" type="bytes | AsyncIterator[bytes]">
  The line's stdin. An async iterator streams it.
</ResponseField>
<ResponseField name="cwd" type="str">
  A working directory for this line only. The line runs in a subshell of its own, beside the session's other lines rather than after them: a `cd` in it does not leak, and its jobs are its own.
</ResponseField>
<ResponseField name="env" type="dict[str, str]">
  Variables for this line only. Like `cwd`, they run the line in a subshell of its own.
</ResponseField>
<ResponseField name="cancel" type="asyncio.Event">
  Setting it stops the line and raises `MirageAbortError`.
</ResponseField>
<ResponseField name="record" type="bool" default="True">
  `False` keeps the line out of history.
</ResponseField>
<ResponseField name="machine" type="str">
  Run the commands this workspace [machine](/home/setup/machine/overview) captures on it, by name, instead of where routing puts them. Raises `ValueError` for a name the workspace does not have.
</ResponseField>

<Expandable title="IOResult">
  <ResponseField name="exit_code" type="int" />
  <ResponseField name="stdout_str()" type="async -> str">The output as text. `materialize_stdout()` returns the raw bytes.</ResponseField>
  <ResponseField name="stderr_str()" type="async -> str">The error output as text. `materialize_stderr()` returns the raw bytes.</ResponseField>
  <ResponseField name="decision" type="PolicyDecision | None">
    Why the line did not run, or `None`.
    <Expandable title="PolicyDecision">
      <ResponseField name="kind" type="str">`deny` for a refusal, `pending` for an ask nobody answered, `failed` for a policy that raised.</ResponseField>
      <ResponseField name="reason" type="str">The rule's or the policy's words.</ResponseField>
      <ResponseField name="policy" type="str">The policy class that refused; empty for an ask.</ResponseField>
      <ResponseField name="ask_id" type="str | None">The ask's id, for `pending`.</ResponseField>
    </Expandable>
  </ResponseField>
</Expandable>

```python
result = await session.shell("wc -l", stdin=b"a\nb\n")
print(result.exit_code, await result.stdout_str())
```

<Accordion title="Stream the output">
  `await session.shell(line, stream=True)` returns a running `ShellExecution`. Read `execution.events` (ordered `stdout` and `stderr` chunks, each with `stream` and `data` bytes), then await `execution.wait()` for the final `IOResult`: the exit code and refusal, with empty output fields.

  - Read the events before awaiting `wait()`. A full queue (64 KiB by default, set with `IOConfig`) blocks the line.
  - Use `async with execution:` (or `await execution.aclose()`) so stopping early cancels the line. `cancel()` stops it, and `wait()` then raises `MirageAbortError`.
  - `await execution.collect(on_event=callback)` returns the full result and awaits `callback` for each event.
  - A policy with `post_execute` holds output until the line finishes.

  In this example, `send_bytes` is the application's async output sink:

  ```python
  execution = await session.shell("echo ready; echo warning >&2", stream=True)
  async with execution:
      async for event in execution.events:
          await send_bytes(event.stream, event.data)
      result = await execution.wait()
  print(result.exit_code)
  ```
</Accordion>


  <Accordion title="session.explain">
    ```python
    await session.explain.shell(line) -> ShellExplanation
    await session.explain.vfs.<call>(...) -> VfsExplanation
    ```

    What `session.shell` or a `session.vfs` call would do, without running it: a line's verdict and parse tree, a VFS call's verdict and error, each with every policy's answer. See [Explain](/home/policy/explain).

    ```python
    from mirage import CommandExplanation

    shell_res = await session.explain.shell("rm /data/x")
    print(shell_res.exit_code, shell_res.reason)
    for node in shell_res.node.children:
        if isinstance(node, CommandExplanation):
            print(node.command, [a.policy for a in node.answers])
    vfs_res = await session.explain.vfs.write("/data/x", b"hi")
    print(vfs_res.error, [a.policy for a in vfs_res.answers])
    ```
  </Accordion>
</AccordionGroup>

### session.vfs

The file API, run as the session. Paths are absolute, bytes are `bytes`. A missing path raises `FileNotFoundError` and a refused one `PermissionError`.

| Call | Answers |
| --- | --- |
| `read(path, offset=0, size=None)` | The bytes, whole or a range. |
| `write(path, data)`, `append(path, data)` | `None` |
| `stat(path, nofollow=False, fresh=False)` | A `FileStat`. |
| `readdir(path)` | The full path of each entry. |
| `exists(path)` | `True` or `False`. |
| `mkdir(path)`, `rmdir(path)`, `unlink(path)` | `None` |
| `rename(src, dst)` | `None` |
| `truncate(path, length)` | `None` |

`stat` may answer from the mount's listing index. Pass `fresh=True` to ask the
service directly, for example after another client changed the file. Later
calls then see the new answer. `nofollow=True` reports a trailing symlink
itself.

```python
current = await session.vfs.stat("/s3/report.csv", fresh=True)
```

<Expandable title="FileStat">
  <ResponseField name="name" type="str" />
  <ResponseField name="type" type="FileType">`FILE`, `DIRECTORY`, `SYMLINK`, `CHAR_DEVICE` under `/dev`, or `FIFO` for a process substitution's `/dev/fd/N`. `BLOCK_DEVICE` and `SOCKET` exist in the enum but are never returned.</ResponseField>
  <ResponseField name="size" type="int | None">The bytes a read answers; `None` when unknown.</ResponseField>
  <ResponseField name="modified" type="str | None">ISO 8601.</ResponseField>
  <ResponseField name="content" type="ContentType | None">A file's content shape, such as `text`.</ResponseField>
  <ResponseField name="mode" type="int | None">The permission bits.</ResponseField>
  <ResponseField name="uid, gid" type="int | str | None" />
  <ResponseField name="atime, ctime, birthtime" type="str | None" />
  <ResponseField name="fingerprint, revision" type="str | None">The backend's ETag and version, when it has them.</ResponseField>
  <ResponseField name="extra" type="dict">Backend-specific fields.</ResponseField>
</Expandable>

```python
await session.vfs.write("/notes.txt", b"hello\n")
print(await session.vfs.read("/notes.txt"))
```

### session.tools

```python
await session.tools.shell(command) -> ToolResult
await session.tools.read(path, offset=0, limit=2000) -> ToolResult
await session.tools.write(path, content) -> ToolResult
await session.tools.edit(
    path, old_string, new_string, replace_all=False
) -> ToolResult
await session.tools.ls(path) -> ToolResult
await session.tools.grep(pattern, path, ignore_case=False, ...)
await session.tools.glob(pattern, path="/") -> ToolResult
await session.tools.call(name, arguments) -> ToolResult
session.tools.names() -> tuple[str, ...]
```

The seven agent tools, for a model rather than a program: every answer is text, and a failure is `is_error`, never an exception. `call` takes a tool's name and its JSON input, the form an agent loop gets from the model. `write` and `edit` refuse a file the session has not read in full, or one that changed since it was read. Every caller of the session shares that record. `names()` is the tools the session's [profile](/home/policy/explain#which-tools-the-agent-gets) leaves it, which MCP, RPC and the agent adapters offer: `shell` needs a command its `commands` lets run, `ls` and `grep` those commands, `write` and `edit` a mount the session may write.

| Tool | Answers |
| --- | --- |
| `shell` | The line's stdout, stderr and exit status as one text. |
| `read` | Numbered lines, `limit` of them from `offset`. |
| `write` | Writes a new file; an existing one only after a full `read`. |
| `edit` | Replaces `old_string` once, or everywhere with `replace_all`. |
| `ls`, `grep` | `ls` and `grep -rn`, as text. |
| `glob` | The files a pattern matches, one per line. |

<Expandable title="ToolResult">
  <ResponseField name="text" type="str">The text handed back to the agent.</ResponseField>
  <ResponseField name="is_error" type="bool">`True` when the call failed.</ResponseField>
</Expandable>

`mirage.workspace.tools.tool_descriptions` has each tool's description and JSON schema to hand the model, and the [agent adapters](/python/agents/index) wire the tools into each framework. `MirageToolOperations(session, stale_write_protection=False)`, from `mirage.workspace.tools.tool_operations`, turns the read guard off.

```python
await session.tools.call("read", {"path": "/notes.txt"})
result = await session.tools.call("edit", {
    "path": "/notes.txt",
    "old_string": "hello",
    "new_string": "hi",
})
print(result.text, result.is_error)
```
