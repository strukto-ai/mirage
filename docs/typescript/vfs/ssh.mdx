`SSHVFS` mounts a directory of a remote server over SFTP: its folders and
files appear as they are on the server. Set up the key and server as in [SSH setup](/home/setup/ssh). It ships in `@struktoai/mirage-node` only; the
browser package has no SSH client.

## Install

```bash
npm install @struktoai/mirage-node ssh2
```

`ssh2` is a peer package that only this mount needs.

## Configure

```ts
import { MountMode, SSHVFS, Workspace } from '@struktoai/mirage-node'

const ssh = new SSHVFS({
  host: 'server.example.com',
  username: 'deploy',
  identityFile: '~/.ssh/id_ed25519',
  root: '/srv/data',
})
const ws = new Workspace({ '/remote': ssh }, { mode: MountMode.WRITE })

const result = await ws.shell('ls /remote && tail -n 20 /remote/logs/app.log')
console.log(result.stdoutText)
await ws.close()
```

`hostname` connects to another address than `host`, and `port` to another
port. Use `MountMode.EXEC` when `python3` or `js` should run scripts from the
mount.

## Authentication

The mount offers, in order, the key at `identityFile`, then the key text in
`privateKey`, which a [credential pointer](/home/service-credentials#pointer-fields)
can read from a secret store. Without either, it tries the SSH agent and the
default keys in `~/.ssh`. `passphrase` unlocks an encrypted key. `password`
works too, but a key is preferred.

The server needs SFTP turned on. Reads and writes go as far as the SSH
account's own file permissions allow.

## Behavior

- **Host keys:** not verified. `knownHosts` is accepted but not applied, so
  any host key is accepted.
- **Caching:** listings are cached for 60 seconds by default. File bytes are
  served from cache without a check until the mount's `ttl:`; an SSH mount
  does not accept `read: fresh`.
- **Running programs:** this mount reads and writes files. To run programs on
  the server, use the [SSH machine](/home/setup/machine/ssh).
