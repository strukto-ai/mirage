`NotionVFS` mounts the Notion pages and databases shared with a connection as
read-only JSON files: pages with their content as Markdown, and databases with
their schema and rows. Set up the token as in [Notion setup](/home/setup/notion).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { MountMode, NotionVFS, Workspace } from '@struktoai/mirage-node'

const notion = new NotionVFS({ apiKey: process.env.NOTION_API_KEY! })
const ws = new Workspace({ '/notion': notion }, { mode: MountMode.READ })

const result = await ws.shell('tree -L 3 /notion && grep -r deadline /notion/pages')
console.log(result.stdoutText)
await ws.close()
```

`baseUrl` points at a proxy. `apiVersion` sets the `Notion-Version` header,
`2025-09-03` when unset.

## Authentication

The token is an internal connection's API token (`ntn_...`) with the read
content capability. The connection reaches only the pages and databases
shared with it; child pages inherit access, so sharing a top-level page
exposes its whole subtree. A personal access token with the **Notion API**
capability also works: it acts with its creator's permissions and needs no
sharing. The update and insert content capabilities are only for writes
through the `ntn` CLI.

## Behavior

- **Read only:** the mount cannot change pages. Use the [`ntn`](/typescript/cli/ntn)
  CLI, which takes the same token, to create, edit and trash pages, query data
  sources and reach every other route. Ids
  are positional: use the `<page-id>`, `<database-id>` or `<data-source-id>`
  from a path segment.
- **Rows in one file:** a query answers a hundred rows' cells in one call,
  while each row folder costs calls of its own, so rows are one file and
  `grep -r` or `find` over a large database stays cheap. Row folders are not
  listed; open one by the `path` on its line. Reading `rows.jsonl` costs one
  query call per hundred rows.

## Browser

The browser `NotionVFS` from `@struktoai/mirage-browser` talks to Notion's MCP
server through an OAuth client provider, so no token sits in the page.

```bash
npm install @struktoai/mirage-browser @modelcontextprotocol/client
```

```ts
import { MountMode, NotionVFS, Workspace } from '@struktoai/mirage-browser'

const notion = new NotionVFS({ authProvider })
const ws = new Workspace({ '/notion': notion }, { mode: MountMode.READ })
```

- `authProvider` is an `OAuthClientProvider` from `@modelcontextprotocol/client`.
- `serverUrl` routes MCP through another URL.


    - `page.json` holds the page's metadata, its body as Markdown and its raw
      blocks.
    - `database.json` lists a database's data sources, `data_source.json`
      holds the property schema and `rows.jsonl` one row per line, with its
      `path` below the data source directory. Row directories are not
      listed; open one by that `path`.
    - Titles are sanitized: `ls` the parent or take a row's `path` instead of
      building paths.
    - `ntn` takes ids as positional operands: `ntn pages get <page-id>`,
      `ntn datasources query <data-source-id>`,
      `ntn datasources resolve <database-id>`.

    **Supported Unix Commands for VFS**

    Unix commands work on each path as on a local filesystem, as far as the path supports them:

    | Path | Supported |
    | --- | --- |
    | `/<path>` | Commands that read files (`ls`, `cat`, `grep`, `find`, `jq` and the rest). `head` asks `notion` instead of reading a file. |

    **Limitations of Unix Commands for VFS**

    Where a path differs from a local filesystem:

    | Path | Limitations |
    | --- | --- |
    | `/<path>` | Read only: no command changes files. `grep -r`, `find` and `du` stop after 1000 files; a glob matching more, `tar -c`, `cp -r` and `rm -r` are refused. |

    Run `man <cmd>` or `<cmd> --help` for one command's usage.
