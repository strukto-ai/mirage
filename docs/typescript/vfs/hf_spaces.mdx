`HfSpacesVFS` mounts one [Hugging Face Space](https://huggingface.co/spaces)
repository as read-only files: its app code, README, config and requirements.
Set up a token for a private Space as in [HF Spaces setup](/home/setup/hf_spaces).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { HfSpacesVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const space = new HfSpacesVFS({
  repoId: process.env.HF_SPACE_REPO!,
  token: process.env.HF_TOKEN,
})
const ws = new Workspace({ '/space': space }, { mode: MountMode.READ })

const result = await ws.shell("ls /space && find /space -name '*.py'")
console.log(result.stdoutText)
await ws.close()
```

`revision` picks a branch, tag or commit (`main` when unset), `keyPrefix`
mounts one folder of the repository, and `endpoint` points at a mirror or a
self-hosted Hub. The class ships in `@struktoai/mirage-node` only.

## Layout

```text
/space/
  Dockerfile
  README.md
  app.py
  requirements.txt
  scripts/
    precompute.py
```

`repoId` is `namespace/space-name`, set at mount time, and the tree mirrors
the repository at `revision`: `/space/app.py` is `app.py`.

## Behavior

- **Read only:** a Hub write is a commit, and a POSIX write cannot say where a
  commit ends, so `echo >`, `rm`, `cp` and `mv` are refused rather than making
  one commit per file. The [`hf` CLI](/typescript/cli/hf) is the write half:
  `hf download --local-dir` puts a copy on a RAM or disk mount, and
  `hf upload` sends it back as one commit.
- **Fresh reads:** under `read: fresh`, each command checks the commit
  `revision` resolves to with one small request, also when `revision` is a
  full commit SHA, since a branch or tag could carry the same name.
