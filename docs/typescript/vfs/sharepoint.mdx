`SharePointVFS` mounts SharePoint Online: every site the token can reach
becomes a folder of its document libraries, each holding its real files as raw
bytes. Site and library names are resolved to Microsoft Graph IDs by the
mount, so no drive ID is needed. Set up the tokens as in [SharePoint setup](/home/setup/sharepoint).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { MountMode, SharePointVFS, Workspace } from '@struktoai/mirage-node'

const sharepoint = new SharePointVFS({
  accessToken: process.env.MS_GRAPH_DRIVE_TOKEN!,
  tenantHost: 'contoso.sharepoint.com',
})
const ws = new Workspace({ '/sharepoint': sharepoint }, { mode: MountMode.WRITE })

const result = await ws.shell('ls /sharepoint && ls /sharepoint/Engineering')
console.log(result.stdoutText)
await ws.close()
```

`tenantHost` and `siteFilter` narrow the sites listed. `site` and `drive`
together mount one library as the root, and `keyPrefix` one folder inside it.

## Authentication

`accessToken` is a Microsoft Graph bearer token, or a function (sync or async)
that returns one. A function is called for each request and again after a
`401`, so a long-running mount outlives one token; a plain string lasts about
an hour.

An app-only token works, since the mount reaches sites through `/sites` and
needs no signed-in user. Reads need `Sites.Read.All`; writes need
`Sites.ReadWrite.All`. A delegated token reaches only what its user can.

## Layout

```text
/sharepoint/
  Engineering/
    Documents/
      specs/
        api.md
    Design Reviews/
  Marketing/
    Documents/
```

Paths read `/<site>/<library>/<path>`, with the site's display name. The first
two levels are sites and libraries; everything below is a real driveItem.
`/sharepoint/Engineering/Documents/specs/api.md` is the driveItem
`/root:/specs/api.md` in the `Documents` library of the `Engineering` site.

With `site: 'Engineering'` and `drive: 'Documents'`, those two levels
disappear. Adding `keyPrefix: 'team/reports'` makes that folder the root, so
`/sharepoint/q1.csv` is the driveItem `/root:/team/reports/q1.csv`.

## Behavior

- **Scoping:** `drive` takes effect only with `site` set, and `keyPrefix`
  only with both. `..` segments in `keyPrefix` are rejected.
- **Service root:** mounts address `https://graph.microsoft.com/v1.0` unless
  `graphBaseUrl` names another root, given in full with its version segment,
  such as `https://graph.microsoft.us/v1.0`. A token minted for one sovereign
  cloud is rejected by the others, so a mount on the wrong root fails
  outright.
- **Raw bytes:** Office files stay as they are stored, with no conversion.
- **Snapshots:** a snapshot pins each file the agent read to its version, and
  replaying it reads those exact bytes. A file the agent wrote carries no
  version and is not checked on replay. Old versions read only while the
  library keeps them; an admin can cap or turn off versioning.
- **One drive instead:** for a single drive, such as a personal OneDrive or
  one known library, use [OneDrive](/typescript/vfs/onedrive).

## Browser

`@struktoai/mirage-browser` exports the same `SharePointVFS` with the same
fields.

```bash
npm install @struktoai/mirage-browser
```

```ts
import { MountMode, SharePointVFS, Workspace } from '@struktoai/mirage-browser'

const sharepoint = new SharePointVFS({ accessToken: () => getMicrosoftGraphToken() })
const ws = new Workspace({ '/sharepoint': sharepoint }, { mode: MountMode.READ })
```

- Pass a token function, such as one backed by the page's sign-in library, so
  a `401` fetches a fresh token and retries.
