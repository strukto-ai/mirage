`HfDatasetsVFS` mounts one [Hugging Face dataset](https://huggingface.co/datasets)
repository, read-only: every file in the repo becomes a file, read lazily, so
only the bytes a command reads are transferred. Set up the tokens for gated and private datasets as in [HF Datasets setup](/home/setup/hf_datasets).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { HfDatasetsVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const dataset = new HfDatasetsVFS({
  repoId: 'AlienKevin/SWE-ZERO-12M-trajectories',
  token: process.env.HF_TOKEN,
})
const ws = new Workspace({ '/data': dataset }, { mode: MountMode.READ })

const result = await ws.shell("ls /data && find /data -name '*.parquet' | head -n 5")
console.log(result.stdoutText)
await ws.close()
```

`revision` pins a branch, tag or commit (default `main`), and `keyPrefix`
mounts one folder of the repo. `endpoint` points at a mirror or a self-hosted
Hub.

## Layout

```text
/data/
  README.md
  assets/
    marin8b_swe_bench_scaling.png
  data/
    train-00000.parquet
    train-00001.parquet
```

Files keep their repo paths: `/data/data/train-00000.parquet` is
`data/train-00000.parquet` in the repo. `repoId` is `namespace/name`, or a
bare name under the token's owner.

## Behavior

- **Read-only:** a Hub write is a commit, and a file write cannot say where a
  commit ends, so `echo >`, `rm`, `cp` and `mv` are refused rather than making
  one commit per file. The [`hf` CLI](/typescript/cli/hf) is the write half:
  `hf download --local-dir` puts a copy on a writable mount, and `hf upload`
  sends it back as one commit.
- **Lazy reads:** `ls` and `stat` never download a file, and `head` on a large
  shard reads only its first bytes.
- **Fresh reads:** under `read: fresh`, each command checks once which commit
  `revision` points at, even when `revision` is a full commit sha, since a
  branch or tag can carry the same name.
