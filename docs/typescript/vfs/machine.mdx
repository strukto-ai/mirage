</Note>

`MachineVFS` shows the files of the workspace's machines at a prefix, reached
through the exec each machine's handle already holds. A workspace with
machines mounts `/tmp` and `/dev/shm` this way, and `'@<machine>'` picks one
machine's; see [Machine Files](/home/setup/machine/machine_files).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { MachineVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const ws = new Workspace(
  { '/tmp': new MachineVFS({ machines: ['gpu'], root: '/tmp' }) },
  {
    mode: MountMode.WRITE,
    machines: {
      cpu: { provider: 'docker', container: 'my-sandbox' },
      gpu: { provider: 'ssh', host: 'gpu.example.com' },
    },
  },
)
const result = await ws.shell('ls /tmp')
console.log(result.stdoutText)
await ws.close()
```

`'/tmp': '@gpu'` is the same mount, written short. A machine mount needs a
workspace with machines, and a name in `machines` or `defaultMachine` that
is none of them is refused when the workspace is built.

## Behavior

- **Caching:** none; every read and listing asks the machine.
- **Placement:** several machines show as one tree. A name several hold is
  the copy written last, a removal reaches every machine, and a new name
  lands where its folder is. See
  [Several machines](/home/setup/machine/machine_files#several-machines).
- **Commands:** a command whose every path is one machine's own runs on that
  machine whole. See
  [Where a command runs](/home/setup/machine/machine_files#where-a-command-runs).
- **Browser:** a page has no machines, so `@struktoai/mirage-browser` mounts
  none of this.
