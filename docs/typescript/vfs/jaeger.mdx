`JaegerVFS` mounts an existing Jaeger query service as read-only JSON files:
each service becomes a folder with its operations and one file per trace. Set up the connection as in [Jaeger setup](/home/setup/jaeger).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { JaegerVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const jaeger = new JaegerVFS({ host: 'http://localhost:16686' })
const ws = new Workspace({ '/jaeger': jaeger }, { mode: MountMode.READ })

const result = await ws.shell("jq -r '.[].name' /jaeger/services/frontend/operations.json")
console.log(result.stdoutText)
await ws.close()
```

`host` is the query service's base URL; it needs no credentials.
`defaultTraceLimit`, `defaultFromTimestamp` and `defaultToTimestamp` bound
each trace listing. The class ships in `@struktoai/mirage-node` only. In a
YAML config or `buildVfs('jaeger', ...)`, the same fields are snake_case
(`default_trace_limit`).

## Behavior

- **Read only:** the mount has no write operations.
- **Trace listing:** `traces/` shows the newest `defaultTraceLimit` traces
  (100) of the service between `defaultFromTimestamp` and
  `defaultToTimestamp`; unset bounds search from the beginning up to now. A
  trace older than the listing is still readable by its id, as long as one of
  its spans comes from that service.
- **Missing paths:** a service Jaeger does not know, a trace id that is not 16
  or 32 hex digits, and a trace without a span from the addressed service are
  reported as missing.
- **Sizes:** every listed file has an exact size, so `ls -l`, `du` and `stat`
  work without reading the files.
