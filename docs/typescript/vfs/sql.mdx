`SqlVFS` keeps a filesystem in a database's tables: a SQLite file, a Postgres
server, a Durable Object's storage or a D1 database. Every command that writes
works, and the files persist with the database. Setup is on the
[SQL page](/home/setup/sql).

## Install

```bash
npm install @struktoai/mirage-node
```

Postgres also needs the `pg` peer package.

## Configure

```ts
import { MountMode, SqlVFS, Workspace } from '@struktoai/mirage-node'

const sql = new SqlVFS({ path: './workspace.db' })
const ws = new Workspace({ '/sql': sql }, { mode: MountMode.WRITE })

const result = await ws.shell('echo hello > /sql/note.txt && ls /sql')
console.log(result.stdoutText)
await ws.close()
```

Leave out `path` to keep the database in memory. `capacity: '100MB'` caps the
bytes the database's files hold; see [capacity](/home/setup/vfs#mount-capacity).
To keep the tables in Postgres, pass its driver:

```ts
import { PostgresSqlDriver, SqlVFS } from '@struktoai/mirage-node'

const driver = new PostgresSqlDriver(process.env.DATABASE_URL!)
const sql = new SqlVFS({ driver })
```

### Fields

| Field | Default | Notes |
| --- | --- | --- |
| `path` | `:memory:` | The SQLite file, opened and closed with the mount. |
| `driver` | none | A database to borrow instead of a file: `SqliteDriver` or `PostgresSqlDriver`. The caller closes it. Not with `path`. |
| `capacity` | none | The most bytes the database's files may hold, like `100MB`. |
| `root` | `/` | The folder of the database the mount serves, made if missing. |

## Behavior

- **One filesystem, both runtimes:** the Python mount reads and writes the
  same tables, so the two runtimes on one file serve one filesystem.
- **Several mounts on one database:** a mount serves one folder of its
  database, `/` by default. Hand two mounts one driver to serve the whole
  database and one folder as a mount of its own:

  ```ts
  import { MountMode, SqliteDriver, SqlVFS, Workspace } from '@struktoai/mirage-node'

  const driver = new SqliteDriver('./workspace.db')
  const ws = new Workspace(
    {
      '/': new SqlVFS({ driver, capacity: '1GB' }),
      '/workspace': new SqlVFS({ driver, root: '/workspace', capacity: '1GB' }),
    },
    { mode: MountMode.WRITE },
  )
  ```

- **Capacity:** `capacity` counts every file in the database, whichever mount
  wrote it. Mounts on one driver with the same `capacity` share one count, so
  their writes together stay within it. Mounts on separate drivers count apart,
  even on one file, and together they can pass it.
- **Snapshots:** a snapshot keeps the mount's own folder, and loading it
  replaces that folder. The rest of the database stays as it was.

## Cloudflare

`@struktoai/mirage-cloudflare` takes a driver as the first argument and the
same `root` and `capacity` after it: `DurableObjectSqlDriver` over a Durable
Object's storage, or `D1SqlDriver` over a D1 database.

```ts
import { DurableObjectSqlDriver, MountMode, SqlVFS, Workspace } from '@struktoai/mirage-cloudflare'

const sql = new SqlVFS(new DurableObjectSqlDriver(ctx.storage), { root: '/workspace' })
const ws = new Workspace({ '/sql': sql }, { mode: MountMode.WRITE })
```
