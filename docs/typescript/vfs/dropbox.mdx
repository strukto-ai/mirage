`DropboxVFS` mounts a Dropbox account, or one folder of it: files keep their
names and bytes, and folders stay folders. Set up the app key, app secret and refresh token as in [Dropbox setup](/home/setup/dropbox).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { DropboxVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const dropbox = new DropboxVFS({
  clientId: process.env.DROPBOX_APP_KEY!,
  clientSecret: process.env.DROPBOX_APP_SECRET!,
  refreshToken: process.env.DROPBOX_REFRESH_TOKEN!,
})
const ws = new Workspace({ '/dropbox': dropbox }, { mode: MountMode.WRITE })

const result = await ws.shell('ls /dropbox && grep -rl report /dropbox/Projects')
console.log(result.stdoutText)
await ws.close()
```

`rootPath`, such as `/Team/data`, mounts one folder instead of the whole
account.

## Authentication

Mirage mints short-lived access tokens from the long-lived `refreshToken` and
renews each one 5 minutes before it expires. The refresh token lasts until the
user disconnects the app or the app is deleted.

The app needs these scopes, checked on its **Permissions** tab:

- `files.metadata.read` to list folders and read metadata.
- `files.content.read` to download files.
- `files.content.write` for writes on a `write` mount.
- `account_info.read` for `df` (optional).

Dropbox leaves unchecked scopes out of tokens, and a call that needs one fails
with `missing_scope`.

## Layout

```text
/dropbox/
  Photos/
  Projects/
    data.csv
    report.pdf
  notes.txt
```

`/dropbox/Projects/data.csv` is the Dropbox path `/Projects/data.csv`, or
`<rootPath>/Projects/data.csv` with `rootPath` set. An App folder app sees
only its own folder.

## Behavior

- **Folder root:** `rootPath` accepts `Team/data`, `/Team/data` or
  `/Team/data/`, all the same; `..` segments are rejected. Paths outside it
  are unreachable.
- **Folders:** `rmdir` fails with `ENOTEMPTY` on a non-empty folder; `rm -r`
  removes it.
- **Files from other clients:** a name missing from a cached listing is looked
  up on Dropbox before the mount answers that it does not exist, so a file
  another client created is found, and `>>`, `touch` and `sed -i` act on it
  instead of replacing it. A listing the running command fetched itself is
  trusted for the whole command, so one long-running command, such as a
  program a runtime runs, does not see a file created after it listed the
  folder.
- **Space:** `df` reports the account's space usage, with the
  `account_info.read` scope.

## Browser

`@struktoai/mirage-browser` exports the same `DropboxVFS`. It signs in with
PKCE, so the page holds the app key and a refresh token but no app secret.

```bash
npm install @struktoai/mirage-browser
```

```ts
import { DropboxVFS, MountMode, Workspace } from '@struktoai/mirage-browser'

const dropbox = new DropboxVFS({
  clientId: import.meta.env.VITE_DROPBOX_APP_KEY,
  refreshToken: refreshTokenFromLocalStorage,
})
const ws = new Workspace({ '/dropbox': dropbox }, { mode: MountMode.READ })
```

- Add the page's URL to the app's **Redirect URIs** on its **Settings** tab,
  such as `http://localhost:5173/vfs/dropbox/dropbox_pkce.html`. It must match
  exactly.
- [`examples/browser/vfs/dropbox/dropbox_pkce.ts`](https://github.com/strukto-ai/mirage/blob/main/examples/browser/vfs/dropbox/dropbox_pkce.ts)
  runs the whole PKCE sign-in and keeps the refresh token in `localStorage`.
- To keep a secret on a backend instead, pass `refreshFn`: it takes the
  refresh token and returns `{ accessToken, expiresIn }`.
