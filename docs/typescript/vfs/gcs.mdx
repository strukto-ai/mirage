`GCSVFS` mounts one Google Cloud Storage bucket: every object becomes a file and
every `/` in a key a folder. It reaches GCS through the S3-compatible XML API at
`https://storage.googleapis.com`, signed with an HMAC key. Set up credentials as in [GCS setup](/home/setup/gcs).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { GCSVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const gcs = new GCSVFS({
  bucket: process.env.GCS_BUCKET!,
  accessKeyId: process.env.GCS_ACCESS_KEY_ID!,
  secretAccessKey: process.env.GCS_SECRET_ACCESS_KEY!,
})
const ws = new Workspace({ '/gcs': gcs }, { mode: MountMode.WRITE })

const result = await ws.shell("ls /gcs && find /gcs -name '*.csv'")
console.log(result.stdoutText)
await ws.close()
```

`endpoint` defaults to `https://storage.googleapis.com` and `region` to `auto`:
one host serves every region. A mount takes `MountMode.READ`, `WRITE` or `EXEC`.

## Authentication

Credentials come from `accessKeyId` and `secretAccessKey`, a service account's
HMAC key, with `sessionToken` for temporary credentials. Without them, the AWS
SDK reads its own chain: environment variables, `~/.aws/credentials`, then the
instance or container role.

The service account needs **Storage Object Viewer** on the bucket, or **Storage
Object User** (or **Storage Object Admin**) to write. A new key can take up to a
minute to work. A request the credentials may not make answers
`Permission denied`.

## Behavior

- **Key prefix:** `keyPrefix: 'users/42/'` mounts only that part of the bucket,
  so `/gcs/notes.md` is the key `users/42/notes.md`.

## Browser

The browser `GCSVFS` from `@struktoai/mirage-browser` keeps credentials off the
page: a server signs a URL for each S3 call with the GCS keys, and the browser
fetches it.

```bash
npm install @struktoai/mirage-browser
```

```ts
import { GCSVFS, MountMode, Workspace } from '@struktoai/mirage-browser'

const gcs = new GCSVFS({
  bucket: 'my-bucket',
  presignedUrlProvider: async (path, op, opts) => {
    const r = await fetch('/presign', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ path, op, opts }),
    })
    return ((await r.json()) as { url: string }).url
  },
})
const ws = new Workspace({ '/gcs': gcs }, { mode: MountMode.READ })
```

- The bucket's CORS rules must allow the page's origin, exactly as served.
- A browser mount cannot declare `write: conditional`, and any HTTP 403 from a
  signed URL, an expired one included, answers `Permission denied`.
- `keyPrefix` set in the browser is no security boundary: enforce the prefix in
  the signing server.
- `endpoint` only names the mount's storage location: requests go to the host
  each signed URL names.

An Express route that signs URLs:

```ts
import {
  CopyObjectCommand,
  DeleteObjectCommand,
  GetObjectCommand,
  HeadObjectCommand,
  ListObjectsV2Command,
  PutObjectCommand,
  S3Client,
} from '@aws-sdk/client-s3'
import { getSignedUrl } from '@aws-sdk/s3-request-presigner'

const client = new S3Client({
  region: 'auto',
  endpoint: 'https://storage.googleapis.com',
  credentials: {
    accessKeyId: process.env.GCS_ACCESS_KEY_ID!,
    secretAccessKey: process.env.GCS_SECRET_ACCESS_KEY!,
  },
})
const BUCKET = process.env.GCS_BUCKET!

app.post('/presign', async (req, res) => {
  const { path, op, opts } = req.body as {
    path: string
    op: 'GET' | 'PUT' | 'HEAD' | 'DELETE' | 'LIST' | 'COPY'
    opts?: Record<string, unknown>
  }
  const key = path.replace(/^\/+/, '')
  const ttl = typeof opts?.ttlSec === 'number' ? opts.ttlSec : 300
  let cmd
  switch (op) {
    case 'GET':    cmd = new GetObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'PUT':    cmd = new PutObjectCommand({ Bucket: BUCKET, Key: key, ContentType: opts?.contentType as string | undefined }); break
    case 'HEAD':   cmd = new HeadObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'DELETE': cmd = new DeleteObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'LIST':   cmd = new ListObjectsV2Command({
      Bucket: BUCKET,
      Prefix: opts?.listPrefix as string | undefined,
      Delimiter: opts?.listDelimiter as string | undefined,
      ContinuationToken: opts?.listContinuationToken as string | undefined,
    }); break
    case 'COPY':   cmd = new CopyObjectCommand({
      Bucket: BUCKET,
      Key: key,
      CopySource: `${BUCKET}/${opts?.copySource as string}`,
    }); break
  }
  const url = await getSignedUrl(client, cmd, { expiresIn: ttl })
  res.json({ url })
})
```

Google's own signer (`getSignedUrl` in `@google-cloud/storage`) works too: the
mount only needs a URL that `fetch()` accepts, and native signing needs no HMAC
key on the server.

Sign only the operations the app needs: a viewer needs `GET`, `HEAD` and `LIST`.

  <Accordion title="Bucket CORS rules">

GCS refuses the S3 `PutBucketCors` call, since its CORS schema differs. Set the
rules with `gsutil`:

```json
[
  {
    "origin": ["http://localhost:5173", "https://app.example.com"],
    "method": ["GET", "PUT", "HEAD", "DELETE", "POST"],
    "responseHeader": ["Content-Type", "ETag", "Last-Modified"],
    "maxAgeSeconds": 3000
  }
]
```

```bash
gsutil cors set cors.json gs://$GCS_BUCKET
```

GCS lets every request header through, so the rules name none.
