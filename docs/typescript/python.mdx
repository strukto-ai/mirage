Mirage TypeScript implements `python3` as a shell builtin, backed by [Pyodide](https://pyodide.org/) (CPython compiled to WebAssembly). Behavior matches Python Mirage's reference, with a few WASM-runtime divergences noted below. The same code path runs in Node and in the browser.

## What works

<Tabs>
  <Tab title="-c inline code">
    ```ts
    const r = await ws.shell(`python3 -c "print(sum(range(1, 11)))"`)
    r.stdout          // "55\n"
    r.exitCode        // 0
    ```
  </Tab>
  <Tab title="Script file from any mount">
    ```ts
    // Script can live on any Mirage mount (RAM, disk, S3, Redis, ...).
    await ws.shell(`cat > /ram/hello.py <<'PYEOF'
    import sys
    print(f"args: {sys.argv[1:]}")
    PYEOF`)
    const r = await ws.shell('python3 /ram/hello.py alice bob')
    r.stdout          // "args: ['alice', 'bob']\n"
    ```
  </Tab>
  <Tab title="Piped stdin code">
    ```ts
    const r = await ws.shell(`echo 'print(1+1)' | python3`)
    r.stdout          // "2\n"

    // Heredocs (quoted, unquoted, dash-stripped) all work:
    await ws.shell(`python3 << 'PYEOF'
    for i in range(3):
        print(f"item-{i}")
    PYEOF`)
    ```
  </Tab>
</Tabs>

Also: `export FOO=bar` is visible via `os.environ`, `sys.argv[1:]` reflects shell args, `sys.exit(n)` is honored, uncaught exceptions return `exit 1` with traceback on stderr, missing script returns `exit 1` with `python3: <path>: No such file`.

## Setup

Pyodide is an optional peer dependency of `@struktoai/mirage-core`. Workspaces that never call `python3` never load it.

<CodeGroup>
```bash Node
pnpm add @struktoai/mirage-node @struktoai/mirage-core pyodide
```
```bash Browser
pnpm add @struktoai/mirage-browser pyodide
```
</CodeGroup>

`npm install` and `yarn add` work too.

If `pyodide` isn't installed, `python3` returns `exit=127` with a helpful stderr message, and the workspace keeps running.

## Limitations

Pyodide runs CPython in WebAssembly, using a worker when workers and `SharedArrayBuffer` are available. That creates these divergences from Python Mirage's subprocess model:

### 1. Interpreter startup per command

Each `python3` command starts a fresh Pyodide interpreter. Imported modules,
builtins, and other interpreter state belong to that invocation, so editing
a module and running another command loads it again. Files written to
workspace mounts remain available to later commands.

Initialization and package imports run for each command. Explicit console
evaluation sessions retain their own interpreter until the runtime closes;
one-shot evaluations and other sessions do not share that state.

### 2. Concurrency is bounded and defaults to one

Set `maxConcurrency` in the Pyodide runtime's config to allow independent
top-level commands, one-shot evaluations, and different named console
sessions to run concurrently. It must be a positive safe integer and
defaults to `1`. Additional calls wait for a slot; feeds to the same named
console always run one at a time. Each command still receives a fresh
interpreter. Nested subprocess calls bypass this limit so a parent waiting
for its child cannot deadlock.

Shell calls in the same session stay ordered, including calls using the
default session. Create distinct sessions and pass their `sessionId` to
run independent shell calls concurrently:

```ts
import { MountMode, RAMVFS, Workspace } from '@struktoai/mirage-node'
import { PyodideRuntime } from '@struktoai/mirage-core/runtime/python/pyodide'

const ws = new Workspace(
  { '/data': new RAMVFS() },
  {
    mode: MountMode.EXEC,
    runtimes: [new PyodideRuntime({ config: { maxConcurrency: 2 } }), 'workspace'],
  },
)

for (const sessionId of ['python-one', 'python-two', 'python-three']) {
  ws.createSession(sessionId)
}

await Promise.all([
  ws.shell(`python3 -c "print(sum(range(1_000_000)))"`, { sessionId: 'python-one' }),
  ws.shell(`python3 -c "print(sum(range(2_000_000)))"`, { sessionId: 'python-two' }),
  ws.shell(`python3 -c "print(sum(range(3_000_000)))"`, { sessionId: 'python-three' }),
])
```

The YAML key is `max_concurrency`, inside the runtime's `config` block:

```yaml
runtimes:
  - name: pyodide
    config:
      max_concurrency: 2
  - workspace
mounts:
  /data:
    vfs: ram
```

Hosts that cannot isolate asynchronous task context use an effective limit
of `1`. CPU parallelism also requires workers and `SharedArrayBuffer`;
without them, Python executes on the host thread. Each active call has its
own interpreter, so raising the limit increases memory use and does not
remove interpreter startup cost.

### 3. No real OS file descriptors

`sys.stdin`, `sys.stdout`, `sys.stderr` are Python-level wrappers over in-memory buffers. Byte-level IO works:

```ts
// works
await ws.shell(`python3 -c "import sys; sys.stdout.buffer.write(sys.stdin.buffer.read())"`)

// needs a real fd
await ws.shell(`python3 -c "import select; select.select([0], [], [])"`)
```

Anything through `sys.stdin.read()`, `input()`, `print()`, `.buffer.read/write()` works. `select`, `poll`, `fcntl`, and `os.read(fd, ...)` on fd 0/1/2 don't apply in WASM.

## Reading and writing Mirage mounts from Python

Python code under `python3` can `open()` paths inside any Mirage-mounted prefix. Reads and writes route through the workspace's mount layer (RAM, S3, OPFS, Slack, anything you've registered).

```ts
import { MountMode, RAMVFS } from '@struktoai/mirage-core'

const ram = new RAMVFS()
ws.addMount('/ram', ram, MountMode.WRITE)

await ws.vfs.write('/ram/in.txt', 'hello')
const r = await ws.shell(`python3 -c 'print(open("/ram/in.txt").read())'`)
r.stdoutText // "hello\n"

// Writes flush back through the bridge:
await ws.shell(`python3 -c 'open("/ram/out.txt","w").write("from python")'`)
await ws.vfs.cat('/ram/out.txt') // "from python"
```

PIL and other native-extension libs that go through Python's `open()` work too:

```ts
await ws.shell(`python3 -c '
from PIL import Image
img = Image.new("RGB", (4, 4), color="red")
img.save("/ram/icon.png")
'`)
const png = await ws.vfs.read('/ram/icon.png')
// PNG bytes, ws.vfs sees what Python wrote
```

See [Pyodide workspace file access](/typescript/runtime/python#workspace-file-access)
for worker requirements, caching, write behavior, and mount limitations.

## What you cannot do

### `pip install` at runtime

Pre-bundle what you need. Pyodide's [`micropip`](https://pyodide.org/en/stable/usage/loading-packages.html) isn't wired into the `python3` builtin yet.

### Native CPython fallback

Mirage TS always uses Pyodide, never `child_process.spawn('python3', ...)`, so behavior is identical in Node and in the browser.

## Shell parser quirk (not python3-specific)

The tree-sitter-bash grammar strips newlines inside `"..."`. For multi-line `-c`, use single quotes or a heredoc:

```ts
// Newlines collapse, SyntaxError
await ws.shell(`python3 -c "x = 2
print(x * 3)"`)

// Single quotes preserve newlines
await ws.shell(`python3 -c 'x = 2
print(x * 3)'`)

// Heredocs read more naturally
await ws.shell(`python3 << 'PYEOF'
x = 2
print(x * 3)
PYEOF`)
```

## Quick reference

| Feature | Status |
|---|---|
| `python3 -c "..."` | matches Python Mirage |
| `python3 -c` multi-line | use single quotes or heredoc |
| `python3 /path/script.py` (any mount) | matches Python Mirage |
| `echo code \| python3` | matches Python Mirage |
| `python3 << EOF ... EOF` (all variants) | matches Python Mirage |
| `os.environ` reads `session.env` | matches Python Mirage |
| `sys.argv[1:]` reflects shell args | matches Python Mirage |
| `sys.exit(n)` | matches Python Mirage |
| `os.getcwd()` reflects `session.cwd` | matches Python Mirage |
| Cross-workspace env isolation | fresh interpreter per command |
| Cross-call env isolation | fresh interpreter per command |
| `sys.modules` fresh per call | fresh interpreter with configured initialization |
| True CPU parallelism within one workspace | opt in with `maxConcurrency`; requires workers, shared memory, and isolated task context |
| `select()` / `poll()` / `fcntl()` on stdin | no real fds in WASM |
| `open('/<mount>/...')` inside Python | via Mirage's own filesystem, collected before the run + replayed after |
| `pip install` at runtime | pre-bundle instead |
| Native CPython fallback | always Pyodide |
| Browser support | any engine (no JSPI, no V8 flag) |
