[Sandlock](https://github.com/multikernel/sandlock) runs native commands,
including Python and Node.js, confined on the local Linux host.
`SandlockRuntime` ships in `@struktoai/mirage-node`. Install the Sandlock CLI
on `PATH`; its full ruleset needs Linux 6.12+ (Landlock ABI v6).

```yaml
runtimes:
  - name: sandlock
    config:
      fs_readable: ["/opt/data"]
      fs_writable: ["/mnt/workspace"]
      max_memory: "512M"
      env:
        PATH: /usr/local/bin:/usr/bin:/bin
  - workspace
```

```ts
import { SandlockRuntime } from '@struktoai/mirage-node'

const runtime = new SandlockRuntime({
  config: { fsReadable: ['/opt/data'], fsWritable: ['/mnt/workspace'], maxMemory: '512M' },
})
```

- Sandlock defaults to `captures: ["@external"]`: unresolved program names
  run confined, and Mirage keeps its commands, pipes and redirects. Use
  `captures: ["python3", "node", "@external"]` to send the interpreters too.
- A direct `runtime.execute({ kind: 'process', argv, ... })` takes an argv
  with no shell. Name the interpreter in argv; there is no `home` setting.
- Reads are granted on the common system paths that exist (`/usr`, `/lib`,
  `/lib64`, `/bin`, `/etc`, `/proc`, `/dev`) plus `fsReadable`. An interpreter
  installed elsewhere needs a grant.
- The child gets the config `env` and the execution's `env` (which wins);
  host credentials are not inherited.

## Workspace access

Sandlock has `process` reach: its file calls see real paths only. To reach
Mirage's files, grant an existing [FUSE mount](/typescript/setup/fuse)
through `fsReadable` or `fsWritable`. The runtime neither creates that mount
nor binds it to the line's session, and paths outside it skip Mirage's
policy and observation.
