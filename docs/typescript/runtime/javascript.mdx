`node` and `js` are two names for one command, run by the `quickjs` runtime
(the default): [quickjs-emscripten](https://github.com/justjake/quickjs-emscripten),
QuickJS compiled to WebAssembly, in Node and browsers. It sees the workspace
mounts, and no host files or network.

It is for **small scripts and pipe transforms**: compute, JSON, regex text
processing, code generation. It is a bare ES2023 engine (ES modules, `JSON`,
`Promise`, top-level await), **not** Node: no `require`, npm, `process`,
`fs` or `fetch`.

```bash
js -e "console.log(6 * 7)"                 # inline
node /data/transform.mjs arg1 arg2         # a mounted script, args in scriptArgs
cat data.json | node -e "const d = JSON.parse(std.in.readAsString()); console.log(d.length)"
```

## Programs

- `-e <code>` runs the argument, a file runs a mounted script, and with
  neither, piped stdin is the program.
- A `.mjs` file runs as an ES module; `.js` and `-e` run as classic scripts.
  `-m` (`--module`) forces module mode:
  `js -m -e "const x = await Promise.resolve(41); console.log(x + 1)"`.
- `scriptArgs` holds the words after the code or script, and
  `std.in.readAsString()` reads stdin.
- Output follows the real engine: `console.log` and `print` add a newline,
  `std.out.puts`/`std.err.puts` write raw, `std.out.printf`/`std.err.printf`
  return the characters written, and there is no `console.error`.
- A run starts in the session's cwd (a direct `run()` can pass
  `RunArgs.cwd`). `os.getcwd()` returns `[directory, 0]`, and
  `os.chdir(path)` returns `0` or a negative WASI errno; a change lasts for
  the run only.

Scripts behave the same in the Python `quickjs` runtime.

## Files

- `std.open('/data/f.txt', 'r')` reads the mount, `os.readdir('/data')` lists
  it, and `os.stat`, `os.mkdir`, `os.rename`, `os.remove` and `os.utimes`
  change it (0 or a negative WASI errno). A write shows to every command once
  the file is closed.
- File calls get the same cache and write modes as `cat`. On a read-only
  mount, or a session narrowed to read, `std.open` returns `null`.
- There are no extended-attribute calls; use `getfattr` and `setfattr`.

The engine is capability-isolated: it cannot reach host files or the
network, but only soft engine caps and `command_limits` bound its CPU and
memory. Run untrusted or heavy code in a
[sandbox runtime](/typescript/runtime/sandbox).

## Setup

`quickjs-emscripten` is an optional peer dependency that bundles its own
WebAssembly:

```bash
pnpm add quickjs-emscripten
```

`quickjs` is in the default runtimes. To list it explicitly:

```ts
const ws = new Workspace(mounts, {
  mode: MountMode.EXEC,
  runtimes: ['quickjs', 'workspace'],
})
```

```yaml
runtimes:
  - quickjs
  - workspace
mounts:
  /data:
    vfs: ram
    command_limits:
      js:
        timeout_seconds: 30
```

## Resource limits

`command_limits` apply to `node` and `js` as to any command: past
`timeout_seconds` a run exits 124, and `max_bytes` and `max_lines` cap its
output. The deadline bounds the answer, not the engine, so give untrusted
code a finite workload.

## Route policy

`quickjs` can evaluate expressions, so it can run a
[route policy](/home/policy/route-policy): `route_policy: ./policy.js` runs per line
with `ctx` as a global, and the last expression names the runtime.
