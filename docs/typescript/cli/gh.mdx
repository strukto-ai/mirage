Work with GitHub repositories, issues, pull requests, releases and Actions, or call REST and GraphQL directly. Mirage implements the supported subset below of the [GitHub CLI (`gh`)](https://github.com/cli/cli), with workspace files and configured account credentials.

## Setup

Use [GitHub setup](/home/setup/github) for token permissions. No GitHub mount
or local checkout is required.

```typescript
import { GH, Workspace } from '@struktoai/mirage-node'

const ws = new Workspace({})
ws.registerCli('gh', GH, { token: 'ghp_...', repo: 'acme/tools' })
```

`repo` is the default repository and `branch` supplies the API's `{branch}`
placeholder. `base_url` (`baseUrl` in TypeScript) selects an API host. An
Enterprise REST base ending in `/api/v3` uses `/api/graphql` for GraphQL;
other bases use `/graphql` beneath that base.

For YAML and multiple accounts, see [registration](/typescript/cli/index#register-a-cli).

## Issues, pull requests and Actions

```bash
gh auth status
gh issue list --state open --label bug --limit 20
gh issue view 42 --json number,title,labels,url --jq '.url'
gh pr view 17 --json files,commits,reviews --jq '.files[].path'
gh pr checks 17 --json name,bucket,state
gh run list --workflow ci.yml --json databaseId,status,conclusion
gh run view 123456 --log-failed
gh workflow view ci.yml --yaml --ref release
```

Use `-R/--repo [HOST/]OWNER/REPO` where supported to override the configured
repository. Typed `--jq` requires `--json`. List commands paginate up to
`-L/--limit`; issue, pull-request and repository JSON fields follow the
supported upstream field sets. Other typed groups expose smaller REST-backed
field sets; use `gh api` for additional data.

```bash
gh issue create --title 'Broken build' --body-file /work/issue.md --label bug
gh issue comment 42 --body-file - < /work/comment.md
gh issue edit 42 --add-label confirmed --remove-assignee octocat
gh pr create --title 'Fix build' --head fix-build --base main --body-file /work/pr.md
gh pr merge 17 --squash --subject 'Fix build'
gh release create v1.2.0 --title '1.2.0' --notes-file /work/notes.md
gh workflow run ci.yml --ref main -f mode=full
gh run rerun 123456 --failed
```

Commands are noninteractive: supply titles, bodies, branches and confirmation
flags explicitly. Body/notes files and `--input` files use the workspace VFS;
`-` selects stdin. Workflow YAML is read at the selected ref. Run logs are
available only after completion; `--log-failed` selects failed steps.

## Repositories

```bash
gh repo view --json nameWithOwner,defaultBranchRef,url
gh repo list acme --limit 50
gh repo clone acme/tools /work/tools -- --branch dev
gh repo create acme/tools-next --private --add-readme
gh repo fork acme/tools --fork-name tools-patched
gh repo rename tools-v2 -R acme/tools
gh repo edit acme/tools --enable-wiki=false --add-topic cli,agents
gh repo edit acme/tools --visibility private --accept-visibility-change-consequences
gh repo delete acme/tools-old --yes
```

`repo clone` uses Mirage's Git implementation and needs a writable destination
mount. The token travels in the HTTP authorization header, not in the command
line, output or `.git/config`. Fork clones do not add an `upstream` remote.

`repo rename` takes the **new name** as its operand; `-R` selects the repository
to rename. `repo edit` changes only the named settings, and bare boolean
settings can be disabled with `=false`. Deletion needs both a repository name
and `--yes`. Repository URLs and `[HOST/]OWNER/REPO` are accepted, but the host
must match the configured API host; use a separate install for another host.

## REST and GraphQL API

```bash
gh api /user
gh api 'repos/{owner}/{repo}/issues' -f title='Bug' -f body='Steps to reproduce'
gh api repos/acme/tools/issues -F 'labels[]=bug' -F 'metadata[agent]=worker'
gh api repos/acme/tools/issues --input /work/issue.json --silent
gh api 'repos/acme/tools/issues?per_page=50' --paginate --slurp
gh api repos/acme/tools/pulls/17 -H 'Accept: application/vnd.github.v3.diff'
gh api graphql -f query='{viewer{login}}'
```

| Option or input | Behavior |
| --- | --- |
| No fields | GET by default; no request body |
| `-f` / `--raw-field` | String field; supplying fields selects POST unless `-X` overrides it |
| `-F` / `--field` | Typed booleans, null and integers; `@FILE` reads a workspace file and `@-` reads stdin |
| `-X` / `--method` | Explicit method; GET fields become query parameters, other methods use JSON |
| `key[nested]`, `key[]` | Nested objects and arrays |
| `--input FILE` | JSON body from a file or `-`; additional fields move to the query string |
| `-H` / `--header` | Add or replace a header |
| `--paginate` | Follow REST Link headers; array pages are joined |
| `--slurp` | Wrap pages in an array; Mirage also permits `--jq` on that array |
| `-i` / `--include` | Print status and headers for each response, including failures |
| `--silent` | Suppress the response body; `--include` still prints headers |
| `-q` / `--jq` | Filter API output in process; unlike typed commands, needs no `--json` |

Quote endpoints containing `{owner}`, `{repo}` or `{branch}`. These expand
from config in endpoints and `-F` values, but not `-f` values. Other brace
pairs remain unchanged. A leading endpoint slash is optional.

Unfiltered output preserves the server's response bytes. Typed `--json`
output is compact JSON followed by a newline. `--jq` prints strings raw,
null as an empty line, and objects/arrays as compact JSON. A jq error exits 1
and can leave earlier output on stdout. Connection failures and HTTP 500
responses are not retried.

## VFS and limits

A [GitHub VFS](/typescript/setup/github) can expose the same remote repository
as files, independently of the CLI. The configured `repo` and `branch` supply
context that a host `gh` would infer from a checkout. CLI service writes
invalidate mounted caches; read API methods leave them intact.

| Boundary | Mirage behavior |
| --- | --- |
| Authentication | `auth status` checks the token; `auth token` refuses to print it. No login/logout flow. |
| Interactive tools | No editor, browser, extension manager, codespace or host-checkout workflow. |
| Pull-request creation | Requires explicit title, head, base and body/body-file. |
| Forks | `--clone` is refused; `--remote` without a repository is refused. |
| Repository operations | No archive, unarchive, sync, deploy-key, autolink, gitignore, license or set-default verbs. |
| Release assets and live runs | Asset upload and `run watch` are absent. |
| Raw API | JSON `--input` only; REST pagination only; no verbose or cache flags. |
| Help topics | `environment` and `exit-codes` are supported, alongside command help. |
| HTTP display | `--include` prints HTTP/1.1 rather than upstream's HTTP/2.0 display. |
| jq compatibility | Uses jq rather than gojq: builtin error wording and floating-point edge cases can differ. Numbers above 2^53 can lose precision; NaN, infinities and negative zero follow jq's values. |
