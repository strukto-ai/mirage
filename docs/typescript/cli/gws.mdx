Use Google Drive, Sheets, Docs, Slides, Calendar, Forms and Gmail through one command tree. Mirage implements a subset of the [Google Workspace CLI (`gws`)](https://github.com/googleworkspace/cli), with selected API methods and helpers for mail, spreadsheet ranges and document text.

## Setup

Use [Google Workspace setup](/home/setup/google) to obtain OAuth credentials and the scopes needed by each service.

```typescript
import { GWS, Workspace } from '@struktoai/mirage-node'

const config = { clientId: '...', clientSecret: '...', refreshToken: '...' }
const ws = new Workspace({})
ws.registerCli('gws', GWS, config)
```

No service mount is required. For YAML and multiple accounts, see the
[CLI overview](/typescript/cli/index#register-a-cli).

## Call an API method

```bash
gws drive files list --params '{"pageSize":10}'
gws gmail users messages get --params '{"userId":"me","id":"MESSAGE_ID"}'
gws drive permissions create --params '{"fileId":"FILE_ID"}' --json '{"role":"reader","type":"anyone"}'
gws sheets spreadsheets create --json '{"properties":{"title":"Q3 planning"}}'
```

The form is `gws SERVICE RESOURCE METHOD`. `--params` supplies URL path and
query parameters; `--json` supplies the body. Methods return the API response
as compact JSON. Lists follow `nextPageToken` by default and print multiple
pages as NDJSON. Use `--page-limit N` to stop early. Export methods can return
raw bytes instead of JSON.

The supported methods are the registered subset above, not every method in
Google's Discovery documents.

## Use helpers

```bash
gws gmail triage --query 'is:unread' --max 10
gws gmail read --id MESSAGE_ID
gws gmail send --to user@example.com --subject Hello --body 'Hi there'
gws gmail reply --message-id MESSAGE_ID --body 'Thanks'
gws sheets read --spreadsheet SHEET_ID --range 'Sheet1!A1:C10'
gws sheets append --spreadsheet SHEET_ID --values 'alice,42'
gws docs write --document DOC_ID --text 'New paragraph'
gws docs write --document DOC_ID --tab TAB_ID --text 'Into this tab'
```

Helpers omit the upstream CLI's `+` prefix: use `gws docs write`, not
`gws docs +write`. `--tab` is Mirage's addition for document tabs.

## Choose a document tab

`gws docs documents get --params '{"documentId":"DOC_ID"}'` returns the
legacy body of the first tab. Add `"includeTabsContent":true` to receive
`tabs[].documentTab`, including nested `childTabs`, instead of that flat body.
Mounted `.gdoc.json` files always use the tab-aware shape.

`docs write` appends to the first tab unless `--tab` selects another one.
A raw `batchUpdate` follows the API's defaults: `replaceAllText` without a
tab restriction can affect every tab.

## VFS, folder placement and limits

The CLI can share `GoogleConfig` with Google's VFS adapters. Each registration
owns its config and requires no mount. Setting `folder_id` (`folderId` in
TypeScript) changes **creation placement**, not which files the CLI may read:

- Drive `files create` and `copy` default `parents` to that folder.
- An explicit `parents` array wins, including an empty array.
- Docs, Sheets and Slides creation is followed by a Drive move into the folder.
  These are separate requests, so a failed move can leave the new file created.
- Injected placement requests include Shared Drive support.

Reads still reach the whole account allowed by the credential. Use command
policy to restrict operations; a mounted folder is not a CLI access boundary.

Mirage registers a fixed command subset; upstream builds commands from
Google Discovery at runtime. Folder placement and helper spelling also differ,
and the host config supplies credentials instead of an interactive login.
Mirage paginates list methods by default; upstream requires `--page-all`.
Parser refusals use Mirage's declared command style, so upstream exit codes
and diagnostics are not a blanket compatibility promise.
