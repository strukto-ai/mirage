`@struktoai/mirage-cloudflare` runs a workspace inside a Worker's isolate: the
shell, the commands and, when a workspace names it, `python3` on
[Monty](/typescript/runtime/monty), with no machine to start.

## Install

```bash
npm install @struktoai/mirage-cloudflare
npm install -D wrangler
```

```toml wrangler.toml
name = "mirage"
main = "src/worker.ts"
compatibility_date = "2026-10-01"
compatibility_flags = ["nodejs_compat", "no_handle_cross_request_promise_resolution"]

[alias]
"cpu-features" = "@struktoai/mirage-cloudflare/cpu_features"
```

- `nodejs_compat` gives Mirage Node's `buffer`, `crypto`, `path`, `process`
  and `util`.
- `no_handle_cross_request_promise_resolution` lets a later request finish
  work an earlier one started, which the server API needs.
- The alias hands `ssh2` a stub for the native `cpu-features` addon, which a
  Worker cannot load.

## Run a workspace

```ts src/worker.ts
import { MountMode, RAMVFS, Workspace } from '@struktoai/mirage-cloudflare'

export default {
  async fetch(request: Request): Promise<Response> {
    const { command } = (await request.json()) as { command: string }
    const ws = new Workspace(
      { '/data': new RAMVFS() },
      {
        mode: MountMode.EXEC,
        machines: { py: { provider: 'in_process', runtime: 'monty' } },
        maxMemory: '32MB',
      },
    )
    try {
      const result = await ws.shell(command)
      return Response.json({ exit: result.exitCode, stdout: result.stdoutText })
    } finally {
      await ws.close()
    }
  },
}
```

```bash
npx wrangler dev
curl -s localhost:8787 -d '{"command": "seq 1 100 | sort -rn | head -3"}'
```

```json
{"exit":0,"stdout":"100\n99\n98\n"}
```

- `python3` runs on Monty in the isolate's one thread. Monty's own clock
  stops a run at the line's time limit (exit 124) or after 30 seconds, so a
  loop that never ends leaves the isolate free for the next line.
- `node` does not run on Workers: QuickJS would hold the isolate's one thread
  until Cloudflare's CPU limit, so a config whose machines run `quickjs` is
  refused.
- Import anything else from core by subpath
  (`@struktoai/mirage-core/vfs/registry`): the package root pulls in optional
  packages, such as Pyodide, that a Worker bundle cannot resolve.

## Serve the server API

`createApp` answers the [HTTP](/home/access/http) routes, [MCP](/home/access/mcp)
and [RPC](/home/access/rpc) as the [server](/typescript/access/server) does,
over the workspaces the isolate holds:

```ts src/worker.ts
import { createApp } from '@struktoai/mirage-cloudflare'

export default createApp({ maxWorkspaces: 8 })
```

A Worker's URL is public, so it serves nothing without a token or a JWT
issuer, set through the server's `MIRAGE_AUTH_*` and `MIRAGE_JWT_*`
[variables](/home/access/http#configure-authentication):

```toml wrangler.toml
[vars]
MIRAGE_AUTH_MODE = "token"
```

```bash
npx wrangler secret put MIRAGE_AUTH_TOKEN
curl -s localhost:8787/v1/workspaces -H "Authorization: Bearer $MIRAGE_AUTH_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"id": "demo", "config": {"mounts": {"/": {"vfs": "ram"}}, "machines": {"py": {"provider": "in_process", "runtime": "monty"}}}}'
curl -s localhost:8787/v1/workspaces/demo/shell -H "Authorization: Bearer $MIRAGE_AUTH_TOKEN" \
  -H 'content-type: application/json' -d '{"command": "python3 -c \"print(6 * 7)\""}'
```

`/v1/workspaces/:id/codex-exec` serves Codex's exec-server over a WebSocket,
so `codex exec-server forward` runs its tools in a workspace on the Worker.

<Accordion title="createApp options">
  | Option | Meaning |
  | --- | --- |
  | `auth` | An `AuthConfig` in place of the variables: `{ mode: 'token', bearerToken }` or `{ mode: 'jwt', jwt }`. |
  | `maxWorkspaces` | The most workspaces the isolate holds at once. A create past it answers 503. |
  | `maxSessions` | The most sessions each workspace holds, `4` unless set. A new session past it answers 429. |
  | `maxMemory` | The most any workspace's `max_memory` reaches, as a [size](/home/configuration/workspace#sizes). |
  | `maxProcesses` | The most any session's `processes.max` reaches. |
  | `maxLineSeconds` | The most seconds any line runs, whatever a config or profile sets. |
  | `maxEnv` | The most any workspace's `max_env` reaches, as a [size](/home/configuration/workspace#sizes). |
  | `policies` | The server's own [policies](/home/access/http#server-policies). |
  | `snapshotStore` | An `S3Config`: the store a snapshot request may name a key in. |
</Accordion>

## Keep files and sessions

A Worker's memory goes with its isolate. To keep files and sessions, store
them in SQL: [`SqlVFS`](/typescript/setup/sql) over a Durable Object's storage
or a D1 database, and `SqlWorkspaceStateStore` over the same driver for each
session's directory, variables, functions, jobs and history:

```ts
import { DurableObjectSqlDriver, SqlVFS, SqlWorkspaceStateStore, Workspace } from '@struktoai/mirage-cloudflare'

const driver = new DurableObjectSqlDriver(this.ctx.storage)
const ws = new Workspace(
  { '/work': new SqlVFS(driver) },
  {
    workspaceId: 'w1',
    store: new SqlWorkspaceStateStore(driver),
    ownsStore: true,
    daemonId: this.ctx.id.toString(),
  },
)
```

`daemonId` set to the Durable Object's id lets a woken Durable Object take its
workspace back at once. A Durable Object per workspace gives each workspace
its own database, but not its own memory: Cloudflare may run several of one
class in one isolate, sharing its 128 MB.

## Secrets

A [pointer](/home/service-credentials) reads `aws-sm` and `1password` in a
Worker as on the server. There is no `env` source: the Worker's environment
holds its own secrets, so the Worker's code passes a source its keys from its
bindings.

<AccordionGroup>
  <Accordion title="AWS Secrets Manager">
    `aws-sm` is registered when the package loads. The Worker signs each
    request itself and has no credentials file or default chain, so the
    source's config gives `region`, `aws_access_key_id` and
    `aws_secret_access_key`, with `aws_session_token` for temporary keys.
    `aws_profile` is refused.
  </Accordion>
  <Accordion title="1Password">
    1Password's SDK core is about 13 MiB of WebAssembly, so it is its own
    import. Install the SDK version the package is built against, alias its
    core to the package's build, and minify to stay under Cloudflare's 64 MiB
    limit:

    ```bash
    npm install @1password/sdk@0.5.0
    ```

    ```toml wrangler.toml
    minify = true

    [alias]
    "cpu-features" = "@struktoai/mirage-cloudflare/cpu_features"
    "@1password/sdk-core" = "@struktoai/mirage-cloudflare/onepassword_core"
    ```

    ```ts src/worker.ts
    import '@struktoai/mirage-cloudflare/onepassword'
    ```

    The token is the source config's `token`, or `OP_SERVICE_ACCOUNT_TOKEN`
    among the Worker's secrets.
  </Accordion>
</AccordionGroup>

## VFS and CLIs

| Runs on Workers | Names |
| --- | --- |
| VFS in memory | `ram` |
| VFS over HTTP | `github`, `gdrive`, `gdocs`, `gsheets`, `gslides`, `gcal`, `gmail`, `onedrive`, `sharepoint`, `box`, `airtable`, `linear`, `trello`, `langfuse`, `wandb`, `mem0`, `dify`, `slack`, `discord`, `notion`, `dropbox`, `jaeger`, `databricks_volume`, `tidb_filesystem`, `hf_models`, `hf_datasets`, `hf_spaces` |
| Object store VFS, without `proxy` | `s3`, `r2`, `gcs`, `minio`, `ceph`, `seaweedfs`, `wasabi`, `backblaze`, `digitalocean`, `tencent`, `aliyun`, `scaleway`, `qingstor`, `oci`, `supabase` |
| VFS with a peer installed | `qdrant` (`@qdrant/js-client-rest`), `postgres` (`pg`), `email` (`imapflow`, `mailparser`, `nodemailer`) |
| VFS over TCP | `redis`, any Redis at a `redis://` or `rediss://` URL, Upstash included, through Cloudflare's `connect()` |
| CLIs | `airtable`, `discord`, `gh`, `git`, `gws`, `hf`, `himalaya`, `linear`, `mcp`, `ntn`, `search`, `slack`, `trello` |

The `chroma` VFS does not run on Workers.

## Limits

- An isolate has 128 MB and no disk, shared by every workspace in it. Set
  `max_memory` on each workspace, so a large write fails with
  `Disk quota exceeded` before the isolate runs out.
- The server API's workspaces live in one isolate's memory: a request routed
  to another isolate does not see them, and eviction drops them. `store.type`
  must be `ram`; a workspace built in code keeps its state in SQL, as
  [above](#keep-files-and-sessions).
- Network rules judge a request by host name, since the isolate never sees
  the address a name reaches, so a `denied_domains` entry naming an address or
  a range is refused, and jwt mode's block on cloud metadata addresses
  covers only a request made to the address itself.
- SSH, FUSE, policy and script files read by path, and runtimes or CLIs loaded
  by a `source:Class` reference run only on the Node server.
