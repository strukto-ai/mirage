## Installation

Install the Node runtime:

```bash
pnpm add @struktoai/mirage-node
pnpm add -D tsx typescript
```

`npm install @struktoai/mirage-node` and `yarn add @struktoai/mirage-node` work too.

## Create a Workspace

Start with the RAM VFS so you can try Mirage without credentials.

```ts
import { MountMode, RAMVFS, Workspace } from '@struktoai/mirage-node'

async function main(): Promise<void> {
  const ws = new Workspace({ '/data': new RAMVFS() }, { mode: MountMode.WRITE })

  await ws.shell('echo "hello mirage" | tee /data/hello.txt')
  const result = await ws.shell('cat /data/hello.txt')
  process.stdout.write(result.stdoutText)

  await ws.close()
}

main()
```

Run it:

```bash
pnpm tsx quickstart.ts
```

## Run Commands

Once a VFS is mounted, you can use Mirage like a shell over your virtual filesystem:

```ts
import { MountMode, RAMVFS, Workspace } from '@struktoai/mirage-node'

async function main(): Promise<void> {
  const ws = new Workspace({ '/data': new RAMVFS() }, { mode: MountMode.WRITE })

  await ws.shell(`echo '{"name": "alice"}' | tee /data/user.json`)

  const files = await ws.shell('ls /data/')
  process.stdout.write(files.stdoutText)

  const name = await ws.shell('jq ".name" /data/user.json')
  process.stdout.write(name.stdoutText)

  const match = await ws.shell('grep alice /data/user.json')
  process.stdout.write(match.stdoutText)

  await ws.close()
}

main()
```

## Estimate Before You Run

`execute(..., { provision: true })` returns a `ProvisionResult` instead
of running the command: network/cache bytes, read ops, and a
`precision` telling you how much to trust the numbers (`exact`,
`range`, `unknown` -- totals under `unknown` are floors). Pipelines,
`&&`/`||`, `if`/`case`, loops, and subshells aggregate automatically.

```ts
const plan = await ws.shell('cat /data/user.json | wc -l', { provision: true })
console.log(plan.networkRead, plan.readOps, plan.precision)
```

Read commands are estimated out of the box on every backend. When you
register your own command, pass `provision:` to `command({...})`
(reuse a helper like `makeFileReadProvision(myStat)` or
`defaultProvision(name, myStat)`, or wrap a bespoke command list with
`withDefaultProvisions(commands, myStat)`), or omit it and the planner
reports `unknown`. Full semantics live in the
[CLI provision docs](/home/cli#5-dry-run-with-provision).

## Output Limits

To keep huge reads from flooding an agent, `cat`, `grep`, `rg`, `head`,
and `tail` cap their **final** output at 2000 lines by default. When a
cap fires, the agent sees the truncated bytes plus a stderr notice
(`output truncated at limit (2000 lines); ...`); the exit code
stays 0.

Caps fire only on the **terminal** command of a pipeline, so
`cat big.txt | head -n 30` still shows 30 lines.

### Workspace, profile, and mount limits

```ts
import { Limit, Mount, MountMode, OnExceed, RAMVFS, Workspace } from '@struktoai/mirage-node'

const ws = new Workspace(
  {
    '/data': new Mount(new RAMVFS(), {
      mode: MountMode.WRITE,
      commandLimits: { cat: new Limit({ maxLines: 1000, onExceed: OnExceed.ERROR }) },
    }),
  },
  {
    commandLimits: { head: new Limit({ maxLines: 2000 }) },
    profiles: {
      researcher: { commandLimits: { head: new Limit({ maxLines: 10000 }) } },
    },
  },
)
ws.createSession('research', { profile: 'researcher' })
const result = await ws.shell('cat /data/n.txt | head -n 3000', { sessionId: 'research' })
```

The workspace `commandLimits` option is keyed by command name. Per-mount
settings belong on `Mount` (or its tuple form). The precedence is profile,
mount, workspace, command-declared default, then built-in default. A selected
entry replaces the whole limit; omitted commands inherit. `null` removes a
bound and zero permits no output.

A pipe-only reader uses the profile or workspace setting, without inheriting
upstream mount limits. Each terminal command is capped separately, so
`cat big.txt; echo end` preserves `end`. Pipe input, file redirects, and
captured substitutions retain full data.

`Limit` accepts `maxLines`, `maxBytes`, `timeoutSeconds`, and `onExceed`.
`TRUNCATE` retains bounded output and adds a notice without changing status;
`ERROR` discards that command's stdout and sets exit 1 before shell control
flow decides the next command. Exact-fit output produces no notice.
The same configuration uses `command_limits` and snake_case fields in YAML.
Independent whole-response policy ceilings still constrain the result.
