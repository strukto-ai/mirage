`@struktoai/mirage-edge` runs Mirage on an edge runtime: a host with web `Request`/`Response`, no Node and no threads. A workspace runs in the runtime's own isolate: the shell, the commands built on Rust, and `python3` on [Monty](/typescript/runtime/python), all in one thread.

The runtime needs:

- Node's `buffer`, `crypto`, `path`, `process` and `util` modules.
- A bundler that loads a `.wasm` import as a compiled `WebAssembly.Module`. Mirage's Rust module and Monty both load this way.

The examples below run on Cloudflare Workers.

## Install

```bash
npm install @struktoai/mirage-edge
npm install -D wrangler
```

```toml wrangler.toml
name = "mirage"
main = "src/worker.ts"
compatibility_date = "2026-10-01"
compatibility_flags = ["nodejs_compat"]
```

## Run a workspace

```ts src/worker.ts
import { MountMode, RAMVFS, Workspace } from '@struktoai/mirage-edge'

export default {
  async fetch(request: Request): Promise<Response> {
    const { command } = (await request.json()) as { command: string }
    const ws = new Workspace(
      { '/data': new RAMVFS() },
      { mode: MountMode.EXEC, runtimes: ['workspace', 'monty'], maxMemory: '32MB' },
    )
    try {
      const result = await ws.shell(command)
      return Response.json({ exit: result.exitCode, stdout: result.stdoutText })
    } finally {
      await ws.close()
    }
  },
}
```

```bash
npx wrangler dev
curl -s localhost:8787 -d '{"command": "seq 1 100 | sort -rn | head -3"}'
```

`python3` runs on Monty in the isolate's own thread. A run stops after 30 seconds with `TimeoutError`, so a loop that never ends leaves the isolate free for the next line.

For anything else from core, import its subpaths (`@struktoai/mirage-core/vfs/registry`), not its package root: the root also imports optional packages, such as Pyodide, that an edge bundle cannot resolve.

## Serve the server API

`createApp` answers the [HTTP](/home/access/http) routes, [MCP](/home/access/mcp) and [RPC](/home/access/rpc) as the [server](/typescript/access/server) does, over the workspaces the isolate holds:

```ts src/worker.ts
import { createApp } from '@struktoai/mirage-edge'

export default createApp({ maxWorkspaces: 8 })
```

It checks each request the way the server does, from the same `MIRAGE_AUTH_MODE`, `MIRAGE_AUTH_TOKEN` and `MIRAGE_JWT_*` [variables](/home/access/http#configure-authentication). Without a token or a JWT issuer it serves nothing, since an edge app's URL is public.

```toml wrangler.toml
[vars]
MIRAGE_AUTH_MODE = "token"
```

```bash
npx wrangler secret put MIRAGE_AUTH_TOKEN
curl -s localhost:8787/v1/workspaces -H "Authorization: Bearer $MIRAGE_AUTH_TOKEN" \
  -H 'content-type: application/json' \
  -d '{"id": "demo", "config": {"mounts": {"/": {"vfs": "ram"}}, "runtimes": ["workspace", "monty"]}}'
curl -s localhost:8787/v1/workspaces/demo/shell -H "Authorization: Bearer $MIRAGE_AUTH_TOKEN" \
  -H 'content-type: application/json' -d '{"command": "python3 -c \"print(6 * 7)\""}'
```

| Option | Meaning |
| --- | --- |
| `auth` | An `AuthConfig` in place of the env variables: `{ mode: 'token', bearerToken }`, or `{ mode: 'jwt', jwt }`. |
| `maxWorkspaces` | The most workspaces the isolate holds at once. A create past it answers 503. |
| `maxSessions` | The most sessions each workspace holds. A new session past it answers 429. |
| `policies` | The server's own [policies](/home/access/http#server-policies). |
| `snapshotStore` | An `S3Config`: the store a snapshot request may name a key in. |

## Limits

- An edge isolate has little memory and no disk; a Cloudflare Worker has 128 MB. Set `max_memory` on each workspace so a large write fails with `Disk quota exceeded` before the isolate runs out.
- Workspaces live in the isolate's memory. A request routed to another isolate does not see them, and they are gone when the isolate is evicted. `store.type` must be `ram`.
- A config's mounts come from core's VFS table: `ram`, `github`, `gdrive`, `gdocs`, `gsheets`, `gslides`, `gcal`, `gmail`, `onedrive`, `sharepoint`, `box`, `airtable`, `linear`, `trello`, `langfuse`, `wandb`, `mem0`, `chroma`, `qdrant` and `dify`.
- SSH, FUSE, policy and script files read by path, and runtimes or CLIs loaded by a `source:Class` reference are the Node server's alone.
- A workspace's `network` setting is not enforced. The runtime's own outbound rules apply.
