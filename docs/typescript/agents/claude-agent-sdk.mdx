The [Claude Agent SDK](https://code.claude.com/docs/en/agent-sdk/) builds agents on Claude. Mirage exposes any `Workspace` to the SDK as an in-process MCP server, so every file and shell operation the agent runs is routed through Mirage instead of the host filesystem.

This is distinct from [Claude Code](/home/agents/claude-code), the `claude` CLI run as it is on a workspace. Use this SDK integration when you build your own agent with the SDK's `query()` and want Mirage tools rather than the built-in file tools.

## Install

Use this integration from Node. The Claude Agent SDK launches the native Claude Code runtime, so the complete `query()` workflow does not run in a browser.

```bash
pnpm add @struktoai/mirage-claude-agent-sdk @struktoai/mirage-node @anthropic-ai/claude-agent-sdk
```

## Usage

`buildOptions` adds and preapproves Mirage tools, turns off the SDK's built-in tools, and describes the mounted paths in the system prompt.

```ts
import { MountMode, RAMVFS, Workspace } from '@struktoai/mirage-node'
import { query } from '@anthropic-ai/claude-agent-sdk'
import { buildOptions } from '@struktoai/mirage-claude-agent-sdk'

const ws = new Workspace({ '/': new RAMVFS() }, { mode: MountMode.WRITE })

for await (const msg of query({
  prompt: "Write /hello.txt with 'hi from mirage', then cat it.",
  options: await buildOptions(ws),
})) {
  console.log(msg)
}
```

## Composing with other MCP servers

Use `MirageServer` directly to combine Mirage with other servers:

```ts
import { MirageServer, buildSystemPrompt } from '@struktoai/mirage-claude-agent-sdk'

const options = {
  mcpServers: { mirage: MirageServer(ws), github: githubServer },
  allowedTools: ['mcp__mirage__*', 'mcp__github__*'],
  tools: [],
  systemPrompt: await buildSystemPrompt({ workspace: ws }),
}
```

## Shell

To keep Claude's own tools and run its Bash tool in a workspace instead, point the SDK at `mirage-bash`, as for [Claude Code](/home/agents/claude-code#shell). The workspace is one the Mirage daemon serves:

```bash
mirage workspace create workspace.yaml --id demo
```

```ts
import type { Options } from '@anthropic-ai/claude-agent-sdk'

const options: Options = {
  cwd: '/Users/me/project',
  env: {
    ...process.env,
    CLAUDE_CODE_SHELL: '/Users/me/.local/bin/mirage-bash',
    MIRAGE_WORKSPACE: 'demo',
    MIRAGE_SESSION: 'agent',
  },
}
```

`env` replaces the environment Claude Code starts with, so keep `process.env` in it. `command -v mirage-bash` prints the path.

- `MIRAGE_SESSION` is optional; without it commands run as the workspace's default session.
- Mount the project and `/tmp` at their own paths, as the [Claude Code page](/home/agents/claude-code#shell) shows, so `cd` carries over and Claude's Read and Edit see the same files.
- Claude's Read, Edit, Write, Glob and Grep still run on the host.

## Tools

The server serves the session's seven tools, [`session.tools`](/typescript/access/in-app#session-tools): `shell`, `read`, `write`, `edit`, `ls`, `grep` and `glob`, named `mcp__mirage__<tool>` in the SDK. It carries the ones the session's profile leaves it (`session.tools.names()`).
