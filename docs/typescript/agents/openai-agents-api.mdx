OpenAI's [Agents API](https://developers.openai.com/api/docs/guides/agents-api/overview) runs the agent on OpenAI's servers. With a `self_hosted` environment, its shell commands, file reads and patches run in a Mirage workspace, under the workspace's profile and mount modes. No sandbox holds the files.

The workspace connects through Codex's exec-server relay, set up on the [Codex page](/typescript/agents/codex#exec-server-forward).

## Install

```bash
npm install -g @struktoai/mirage-cli redis
npm install openai
```

## Workspace

`/workspace`, where OpenAI's examples work, is scratch space in memory. `/redis` keeps what the agent saves there after the workspace closes:

```yaml workspace.yaml
mode: write
mounts:
  /workspace:
    vfs: ram
  /redis:
    vfs: redis
    config:
      url: redis://localhost:6379/0
```

```bash
docker run -d -p 6379:6379 redis
mirage workspace create workspace.yaml --id demo
```

## Create a session

```ts
import OpenAI from 'openai'

const client = new OpenAI()
const session = await client.beta.agents.sessions.create({
  agent: { model: 'gpt-6-astra' },
  environment: { type: 'self_hosted', workspace_directory: '/workspace' },
})
console.log(session.environment.id, session.environment.remote_url)
```

## Connect the workspace

Hand the session's `environment.id` and `environment.remote_url`, with an [environment key](https://developers.openai.com/api/docs/guides/agents-api/environments/self-hosted#authentication), to [`codex exec-server forward`](/typescript/agents/codex#exec-server-forward) pointed at workspace `demo`. Then [send input](https://developers.openai.com/api/docs/guides/agents-api/sessions#send-input) to the session. The agent's commands run in the workspace, and what it writes lands in its mounts.

The Agents API is in beta.
