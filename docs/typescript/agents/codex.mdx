| Way | Codex gets | Needs |
| --- | --- | --- |
| [CLI](#cli) | Mirage's seven tools, beside its own | the `mirage` CLI |
| [SSH](#ssh) | its own tools, run in the workspace | the daemon's [SSH server](/home/access/ssh) |
| [Exec-server forward](#exec-server-forward) | its own tools, run in the workspace, for a remote harness | `codex exec-server forward` |
| [FUSE](#fuse) | its own tools, on the workspace as a folder | a [FUSE driver](/home/setup/fuse) |

## Install

```bash
npm install -g @struktoai/mirage-cli
```

Install [Codex](https://github.com/openai/codex) separately.

## Workspace

```yaml workspace.yaml
mode: write
mounts:
  /:
    vfs: ram
```

```bash
mirage workspace create workspace.yaml --id demo
```

## CLI

```bash
codex mcp add mirage -- mirage mcp -w demo
```

Codex gets `shell`, `read`, `write`, `edit`, `ls`, `grep` and `glob` from the workspace's [MCP server](/home/access/mcp).

Or install the Mirage plugin, which adds a skill and reads `.mirage/workspace.yaml` from your project instead:

```bash
codex plugin marketplace add strukto-ai/mirage
codex plugin add mirage@mirage
```

## SSH

Turn on the daemon's [SSH server](/home/access/ssh#set-up), then add it as a Codex environment:

```toml ~/.codex/environments.toml
default = "mirage"
include_local = false

[[environments]]
id = "mirage"
program = "ssh"
args = ["-T", "-p", "2222", "demo@127.0.0.1", "-s", "codex-exec"]
```

```bash
codex -C /
```

Codex's shell commands, file reads and patches run in the workspace, under the SSH key's profile. This works in the Codex CLI, not the app. The protocol is experimental and follows Codex 0.147.

## Exec-server forward

`codex exec-server forward` carries the tool calls of a remote harness, such as an [OpenAI Agents API](/typescript/agents/openai-agents-api) session, to an exec server. `mirage codex-exec` makes the workspace that exec server: it listens on a local port and relays each connection to the server's codex-exec route with the CLI's token, which forward cannot send itself.

```bash
npm install -g @openai/codex@alpha
mirage codex-exec demo --listen 127.0.0.1:8790
```

```bash
CODEX_API_KEY="$OPENAI_EXECUTOR_API_KEY" codex exec-server forward \
  --connect ws://127.0.0.1:8790 \
  --remote "$REMOTE_URL" \
  --environment-id "$ENVIRONMENT_ID"
```

The remote URL and environment id come from the harness's session, and `CODEX_API_KEY` is its environment key.

- Each connection runs in a fresh session under the workspace's default profile, closed when the connection ends. A reconnect starts a new session; the files stay.
- `mirage codex-exec` lets in any connection on its port, as you, and refuses one from a browser page. Keep it on loopback.
- On a hosted server, run [`mirage login`](/home/access/cli#log-in) first; the relay asks for its token on every connection.

## FUSE

Install your platform's [FUSE driver](/home/setup/fuse). On macOS, also follow the [macFUSE 4 workaround](/typescript/setup/fuse#macos-4-symlink-workaround). Then expose the RAM mount at a local folder:

```yaml workspace-fuse.yaml
mode: write
mounts:
  /:
    vfs: ram
    backend: fuse
    mountpoint: /tmp/mirage-demo
```

```bash
mirage workspace create workspace-fuse.yaml --id demo-fuse
cd /tmp/mirage-demo && codex
```

File operations inside `/tmp/mirage-demo` go through Mirage. The mount does not restrict the agent’s access to other host paths. In the Codex app, open the mountpoint as the project folder. `mirage workspace delete demo-fuse` unmounts it. On macOS the daemon holds one FUSE mount at a time.
