| Way | Grok Build gets | Needs |
| --- | --- | --- |
| [CLI](#cli) | Mirage's seven tools, beside its own | a [supported Node release](/typescript/install#quick-install) |
| [FUSE](#fuse) | its own tools, on the workspace as a folder | a [FUSE driver](/home/setup/fuse) |

## Install

```bash
npm install -g @struktoai/mirage-cli
```

Install [Grok Build](https://x.ai/cli) separately; its command is `grok`.

## Workspace

```yaml .mirage/workspace.yaml
mode: write
mounts:
  /:
    vfs: ram
```

## CLI

```bash
grok plugin install strukto-ai/mirage
```

The plugin runs `mirage mcp` through `npx` on your project's `.mirage/workspace.yaml`, so Grok gets `shell`, `read`, `write`, `edit`, `ls`, `grep` and `glob`, and a skill on how to use them. Open `/plugins` in `grok` to check that it is on.

## FUSE

Install your platform's [FUSE driver](/home/setup/fuse). On macOS, also follow the [macFUSE 4 workaround](/typescript/setup/fuse#macfuse-4-symlink-workaround). For this route, add the kernel backend and local mountpoint to `.mirage/workspace.yaml`:

```yaml .mirage/workspace.yaml
mode: write
mounts:
  /:
    vfs: ram
    backend: fuse
    mountpoint: /tmp/mirage-demo
```

```bash
mirage workspace create .mirage/workspace.yaml --id demo
cd /tmp/mirage-demo && grok
```

File operations inside `/tmp/mirage-demo` go through Mirage. The mount does not restrict the agent’s access to other host paths. `mirage workspace delete demo` unmounts it. On macOS the daemon holds one FUSE mount at a time.
