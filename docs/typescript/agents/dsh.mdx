[DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) (`dsh`) is a plugin-based agent harness on Cordis. `@struktoai/mirage-dsh` gives dsh one Mirage workspace as its filesystem and shell, so its tools work on whatever the workspace mounts: S3, Slack, Gmail, Postgres, disk.

## Install

```bash
npm install @struktoai/mirage-dsh @struktoai/mirage-node @deepseek-ai/cordis @deepseek-ai/dsh-fs @deepseek-ai/dsh-fs-patch @deepseek-ai/dsh-shell @deepseek-ai/dsh-spill @deepseek-ai/dsh-subprocess
```

## What is wired to what

| Mirage plugin | dsh service | Used by |
| --- | --- | --- |
| `MirageService` | `ctx.mirage` | The one workspace the plugins below share |
| `MirageFileSystem` | `ctx.fs` | `read`, `write`, `edit`, `apply_patch` and the working directory |
| `MirageShellExecutor` | `ctx.shell` | `bash` |
| `MirageSubprocess` | `ctx.subprocess` | Tools that start a program by argv |
| `MirageSpillStore` | `ctx.spillStore` | Large tool results, saved as workspace files the agent can read back |

- The agent starts in the disk mount that holds the directory dsh was launched from, or in `/`. The `working_directory` tool moves between mounts.
- Each `bash` call is a fresh shell. Give `MirageShellExecutor` a `sessionId` to keep exports and functions between calls.
- Mount modes and [session profiles](/home/configuration/session) apply to every tool. `DSH_PERMISSION_MODE=read-only` makes every mount read-only.
- An [ask](/home/policy/policies#asks) rule shows in dsh's approval prompt. With no prompt, the line is refused and the question stays pending: answer it through `ctx.mirage.decisions`, then run the line again.

## Example

```ts
import { Context } from '@deepseek-ai/cordis'
import { DiskVFS, MountMode, RAMVFS, SlackVFS, Workspace } from '@struktoai/mirage-node'
import {
  MirageFileSystem,
  MirageService,
  MirageShellExecutor,
  MirageSpillStore,
  MirageSubprocess,
} from '@struktoai/mirage-dsh'

const ws = new Workspace({
  '/project': [new DiskVFS({ root: process.cwd() }), MountMode.WRITE],
  '/slack': [new SlackVFS({ token: process.env.SLACK_BOT_TOKEN ?? '' }), MountMode.READ],
  '/tmp': [new RAMVFS(), MountMode.WRITE],
})

const ctx = new Context()
await ctx.plugin(MirageService, { workspace: ws }).await()
await ctx.plugin(MirageFileSystem).await()
await ctx.plugin(MirageShellExecutor).await()
await ctx.plugin(MirageSubprocess).await()
await ctx.plugin(MirageSpillStore).await()

const run = await ctx.shell.execute(ctx.shell.resolve({ command: 'grep -rl invoice /slack /project' }))
console.log((await run.result()).stdout.text)
```

[`examples/typescript/agents/dsh/dsh.ts`](https://github.com/strukto-ai/mirage/blob/main/examples/typescript/agents/dsh/dsh.ts) is a longer runnable version, with Python and permissions.

## Use with the dsh CLI

The package is also a dsh bundle. Added to a profile, it replaces dsh's filesystem, shell, subprocess and spill providers with the Mirage ones:

```bash
dsh plugin --profile web add @struktoai/mirage-dsh
dsh --profile web
```

The bundle mounts one RAM disk at `/tmp`. Set your own mounts, [Python](/typescript/runtime/python) and permissions in the profile's `cordis.patch.yml`. Python runs only on an `exec` mount:

```yaml
- id: mirage
  config:
    mounts:
      /tmp: { vfs: ram, mode: exec }
      /project: { vfs: disk, mode: exec, config: { root: . } }
      /slack: { vfs: slack, mode: read, config: { token: !!js process.env.SLACK_BOT_TOKEN } }
    machines:
      py: { provider: worker, captures: [python, python3] }
    profiles:
      agent:
        commands:
          ask:
            - { commands: [rm], reason: deletes are reviewed }
          deny:
            - { commands: [git push], reason: no publishing }
    profile: agent
```

PowerShell and the `glob` and `grep` tools stay off, since they start programs on the host. The agent searches with `rg`, `grep` and `find` in `bash`.
