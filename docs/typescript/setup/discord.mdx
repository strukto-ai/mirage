`DiscordVFS` mounts the Discord servers a bot is in as read-only files: each
channel as one folder per day of messages and attachments, plus members. Set up the bot token as in [Discord setup](/home/setup/discord).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { DiscordVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const discord = new DiscordVFS({ token: process.env.DISCORD_BOT_TOKEN! })
const ws = new Workspace({ '/discord': discord }, { mode: MountMode.READ })

const result = await ws.shell('ls /discord && tree -L 2 /discord')
console.log(result.stdoutText)
await ws.close()
```

`startTime` and `endTime` bound the mount to a time range.

## Authentication

`token` is a bot token, sent with Discord's `Bot <token>` scheme. The bot
needs:

- **Message Content Intent**: without it, message text and attachments come
  back empty.
- **Server Members Intent**: for the `members/` folder; without it, `members/`
  is empty.
- The **View Channels** and **Read Message History** permissions in each
  server it reads. The mount never posts.

A channel the bot cannot read answers `Permission denied`: `ls` names it and
fails, `find` reports it and walks on. A channel deleted since it was listed
answers `No such file or directory`.

## Layout

```text
/discord/
  Acme Labs__1098765432101234567/
    channels/
      general__1098765432101234570/
        2026-11-16/
          chat.jsonl
          files/
            diagram__1174567890123456789.png
    members/
      alice__1012345678901234567.json
```

- **Names:** a server, channel, member or attachment is
  `<display-name>__<id>`, so the CLI's flags take the snowflake id from the
  path and two entities with one name never collide. Spaces, apostrophes and
  emoji are kept; only `/` becomes `∕` (U+2215). Quote names with spaces.
  `stat` also shows the id.
- **Servers:** the root lists one folder per server the bot is in.
- **`channels/`:** text channels (types 0, 5 and 15), each with one folder per
  day for the 30 days up to its newest message, so an inactive channel shows
  days around its last activity, not today.
- **`chat.jsonl`:** one message per line as Discord's API returns it, with
  `.id`, `.content`, `.author.username` and `.attachments`.
- **`files/`:** the attachments posted that day, named
  `<stem>__<attachment-id>.<ext>`. `cat` downloads one from Discord's CDN.
- **`members/`:** one file per member, holding the member as Discord's API
  returns it.

## Behavior

- **Read only:** the mount cannot send or change messages. Use the
  [`discord`](/typescript/cli/discord) CLI to send, edit, react, open threads and
  polls, look up members and servers, and search.
- **Search:** `grep -r` and `rg` read every day's `chat.jsonl` under the folder
  they walk, one history fetch per day, so name a day folder or a date glob
  for a large channel. Discord's own search is not used: it cannot say which
  days hold a word, since a reply carries the message it answers
  (`referenced_message`).
- **Time scope:** `startTime` and `endTime` bound the mount with RFC 3339
  timestamps that carry a timezone, at most to the millisecond. Start is
  inclusive, end exclusive, and an unset bound is open. Listings then cover
  that period instead of the recent window, day folders use UTC, messages are
  picked by creation time and attachments follow their messages. Direct
  paths, `stat`, date globs, `grep` and `rg` cannot leave the scope. Members
  and server metadata stay visible. The scope applies to the mount, not to
  the `discord` CLI; rebuild the mount to change it.
- **Upstream changes:** a `read` mount refuses writes through Mirage; it does
  not freeze edits or deletions made in Discord.
- **Rate limits:** many reads of `chat.jsonl` can hit Discord's per-route rate
  limits. A read that gets a 429 waits the `retry_after` Discord sends and
  retries; one that outlasts the retries fails, so slow down or name specific
  channels.

## Browser

The browser `DiscordVFS` from `@struktoai/mirage-browser` never sees the
token: a proxy on the backend holds it and forwards `/api/discord/*` to
`https://discord.com/api/v10/*`.

```bash
npm install @struktoai/mirage-browser
```

```ts
import { DiscordVFS, MountMode, Workspace } from '@struktoai/mirage-browser'

const discord = new DiscordVFS({ proxyUrl: '/api/discord' })
const ws = new Workspace({ '/discord': discord }, { mode: MountMode.READ })
```

- The proxy is required: Discord sets no permissive CORS headers for the bot
  API, so a call to `https://discord.com/api/v10/*` from the page fails.
- The proxy sends `Authorization: Bot <token>`, not `Bearer`; `Bearer` answers
  `401 Unauthorized`.
- `getHeaders` returns extra headers for each request to the proxy, such as a
  per-user session credential.

```ts
import { createServer } from 'node:http'

const TOKEN = process.env.DISCORD_BOT_TOKEN!
const PREFIX = '/api/discord/'

createServer(async (req, res) => {
  const url = new URL(req.url ?? '/', 'http://localhost')
  if (!url.pathname.startsWith(PREFIX)) {
    res.statusCode = 404
    res.end()
    return
  }
  const upstream = new URL(`https://discord.com/api/v10/${url.pathname.slice(PREFIX.length)}`)
  upstream.search = url.search

  const method = (req.method ?? 'GET').toUpperCase()
  const chunks: Buffer[] = []
  if (method !== 'GET' && method !== 'HEAD') {
    for await (const chunk of req) chunks.push(chunk as Buffer)
  }
  const body = chunks.length > 0 ? Buffer.concat(chunks).toString('utf-8') : undefined

  const headers: Record<string, string> = { Authorization: `Bot ${TOKEN}` }
  const ct = req.headers['content-type']
  if (typeof ct === 'string') headers['content-type'] = ct

  const upstreamRes = await fetch(upstream, { method, headers, ...(body !== undefined ? { body } : {}) })
  const text = await upstreamRes.text()
  res.statusCode = upstreamRes.status
  const upstreamCt = upstreamRes.headers.get('content-type')
  if (upstreamCt !== null) res.setHeader('content-type', upstreamCt)
  res.end(text)
}).listen(8902, '127.0.0.1')
```

## Integration

Discord answers these commands through its own API, so less is read. See
[Integration](/home/integration/overview).

- `head` and `tail`: on a `chat.jsonl` file, the messages API answers instead
  of a download of the whole day.
- `tail -f`: each new message as it is posted.
