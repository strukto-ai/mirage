`RedisVFS` keeps a filesystem in Redis: every file is one key under
`keyPrefix`, and the tree is whatever commands write. Files persist across
processes, and every workspace pointed at the same URL and prefix sees them.
Set up the server as in [Redis setup](/home/setup/redis).

## Install

```bash
npm install @struktoai/mirage-node redis
```

## Configure

```ts
import { MountMode, RedisVFS, Workspace } from '@struktoai/mirage-node'

const redis = new RedisVFS({
  url: process.env.REDIS_URL!,
  keyPrefix: 'mirage:fs:',
})
const ws = new Workspace({ '/redis': redis }, { mode: MountMode.WRITE })

const result = await ws.shell('echo hello > /redis/note.txt && ls /redis')
console.log(result.stdoutText)
await ws.close()
```

Node speaks the Redis protocol over a socket and needs the `redis@^5` peer
package. `capacity: '100MB'` caps the bytes the files hold; see
[capacity](/home/setup/vfs#mount-capacity). A mount takes `MountMode.READ`,
`WRITE` or `EXEC`.

### Fields

| Field | Default | Notes |
| --- | --- | --- |
| `url` | `redis://localhost:6379/0` | Redis connection URL. Redacted in snapshots. |
| `keyPrefix` | `mirage:fs:` | Prefix of every key the mount reads and writes. |
| `capacity` | none | The most bytes the files may hold, a size like `100MB` or a count of bytes. |

## Authentication

The password goes in the URL, `redis://:<password>@<host>:6379/0`, or
`rediss://` for TLS. An [Upstash](/typescript/setup/upstash) database works with
the `rediss://` URL its console prints.

## Layout

```text
/redis/
  config.json
  logs/
    app.log
  cache/
    session-abc.json
```

`/redis/logs/app.log` is the key `<prefix>file:/logs/app.log`. Folders live in
the set `<prefix>dir`, and modified times in `<prefix>modified:<path>`.

## Behavior

- **Key prefix:** a different `keyPrefix` keeps one workspace's files apart
  from another's, and from other data in the same database.
- **Shared database:** the Python, Node, browser and Cloudflare mounts use the
  same key layout, and the browser store keeps every value byte-identical, so
  all of them can mount one database at the same time.

## Browser

A page cannot open a socket, so `@struktoai/mirage-browser` reaches Redis
through the [Upstash REST API](https://upstash.com/docs/redis/features/restapi).
It takes the same redis URL the Upstash console prints: its password is also
the REST token. [Upstash Redis](/typescript/setup/upstash) covers that database
on its own page.

```bash
npm install @struktoai/mirage-browser
```

```ts
import { MountMode, RedisVFS, Workspace } from '@struktoai/mirage-browser'

const redis = new RedisVFS({
  url: 'rediss://default:<token>@<name>.upstash.io:6379',
  keyPrefix: 'mirage:fs:',
})
const ws = new Workspace({ '/redis': redis }, { mode: MountMode.WRITE })
```

- A read-only token cannot `SCAN`, which listings need, so mount with the full
  token.
- Upstash bills the free and pay-as-you-go tiers per command, and one shell
  command is several Redis commands (a listing costs a few per entry).

<AccordionGroup>

| --- | --- | --- |
| `url` | required | The database's redis URL, password included; or its REST URL (`https://<name>.upstash.io`) with `token` beside it. Redacted in snapshots. |
| `token` | from the URL | The REST token. Needed only with a REST URL, as for a self-hosted [serverless-redis-http](https://github.com/hiett/serverless-redis-http) front, whose token is not a redis password. |
| `keyPrefix` | `mirage:fs:` | Prefix of every key the mount reads and writes. |
| `maxRequestBytes` | `8388608` | Upstash caps a request at 10 MB; a larger file is written as one `SET` plus `APPEND`s of this size. |

## Cloudflare

`@struktoai/mirage-cloudflare` speaks the Redis protocol over the Workers socket
API, with a client of its own. It takes the same `url`, `keyPrefix` and
`capacity`, so it reaches any Redis, Upstash included, at its `redis://` or
`rediss://` URL.

```ts
import { MountMode, RedisVFS, Workspace } from '@struktoai/mirage-cloudflare'

const redis = new RedisVFS({ url: env.REDIS_URL, keyPrefix: 'mirage:fs:' })
const ws = new Workspace({ '/redis': redis }, { mode: MountMode.WRITE })
```

- A Worker cannot keep a socket past the request that opened it, so each
  request opens its own connection; a later command in the same request reuses
  it.
- Workers refuse connections to Cloudflare's own IP ranges.

## Integration

Redis answers these commands through its own API, so fewer keys are read. See
[Integration](/home/integration/overview).

- `find`: one recursive listing.
- `du`: one recursive listing.
- `ls -R` and `tree`: one recursive listing.
