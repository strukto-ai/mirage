`DifyVFS` mounts a Dify Knowledge dataset, read-only, as a tree of text files.
Each document is one file, assembled from its segments. The API key and the
dataset are set up on the [Dify page](/home/setup/dify).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { DifyVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const knowledge = new DifyVFS({
  apiKey: process.env.DIFY_API_KEY!,
  baseUrl: process.env.DIFY_BASE_URL!,
  datasetId: process.env.DIFY_DATASET_ID!,
})
const ws = new Workspace({ '/knowledge': knowledge }, { mode: MountMode.READ })

const result = await ws.shell('find /knowledge -type f && grep -rn billing /knowledge')
console.log(result.stdoutText)
```

`slugMetadataName` picks the document metadata field that holds each path
(default `slug`). `maxConcurrency`, `retryAttempts` and `retryMaxDelay` bound
the requests in flight and the retries after a 429, a 5xx or a transport
error.

## Authentication

The mount sends a Dify Knowledge API key, created under **Knowledge**,
**Service API**. The key reaches either every knowledge base or only the one
mounted, and that knowledge base keeps **API Access** on.

## Layout

```text
/knowledge/
  README.md
  guides/
    api.md
    quickstart.md
  policies/
    support.md
```

A document's path is the value of its `slug` metadata field; without one, the
file takes the document name.

| Dify document | Metadata | Mirage path |
| --- | --- | --- |
| `Quickstart` | `slug=guides/quickstart.md` | `/knowledge/guides/quickstart.md` |
| `README.md` | no slug | `/knowledge/README.md` |

- `/` makes folders. No empty segment, `.` or `..`.
- Each slug is unique across the dataset.
- A slug is never also a folder: `guides` and `guides/quickstart.md` cannot
  both be documents.
- Only enabled, fully indexed, unarchived documents appear.

## Behavior

- **Read-only:** no command changes the dataset.
- **Plain text:** a file is its completed, enabled segments joined by line
  breaks, whatever the original format.
- **Tree refresh:** listings are reused until the index expires, so a document
  edited in Dify can show its old path and metadata until then.
- **Snapshots:** a snapshot leaves out the API key, so `Workspace.load` takes a
  live `DifyVFS` in its third argument:
  `Workspace.load(snapshot, {}, { '/knowledge': knowledge })`.

### Search

The [`search` CLI](/typescript/cli/search) asks Dify's dataset retrieval API.
Register it on the workspace:

```ts
import { SEARCH } from '@struktoai/mirage-node'

ws.registerCli('search', SEARCH)
```

```bash
search "how do I reset my password" /knowledge/
search --method hybrid --top-k 5 "billing policy" /knowledge/policies/
```

`--method` takes `semantic` (the default), `fulltext`, `hybrid` or `keyword`.
`--top-k` defaults to 10 and is capped at 100. `--threshold` is between 0 and
1. A search under a path filters retrieval by the slug field, or by
`document_name` for a document without a slug, which needs **Built-in Fields**
turned on in the dataset's metadata settings.

## Browser

The same `DifyVFS` runs in the browser from `@struktoai/mirage-browser`.

```bash
npm install @struktoai/mirage-browser
```

```ts
import { DifyVFS, MountMode, Workspace } from '@struktoai/mirage-browser'

const knowledge = new DifyVFS({
  apiKey: DIFY_API_KEY,
  baseUrl: 'https://api.dify.ai/v1',
  datasetId: DIFY_DATASET_ID,
})
const ws = new Workspace({ '/knowledge': knowledge }, { mode: MountMode.READ })
```

- The page calls the Dify API directly, so it must accept requests from the
  page's origin.
- The API key is visible to anyone who loads the page: give it access to the
  mounted knowledge base only.
