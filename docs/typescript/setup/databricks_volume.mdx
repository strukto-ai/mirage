`DatabricksVolumeVFS` mounts one Unity Catalog volume, or one folder of it:
its files and folders appear with their own names and bytes. Set up the host, token and volume grants as in [Databricks setup](/home/setup/databricks).
It ships in `@struktoai/mirage-node` only: Databricks refuses cross-origin
browser requests, so there is no browser variant.

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { DatabricksVolumeVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const dbx = await DatabricksVolumeVFS.create({
  catalog: 'main',
  schema: 'default',
  volume: 'agent_files',
  host: process.env.DATABRICKS_HOST!,
  token: process.env.DATABRICKS_TOKEN!,
})
const ws = new Workspace({ '/dbx': dbx }, { mode: MountMode.WRITE })

const result = await ws.shell("ls /dbx && find /dbx -name '*.md'")
console.log(result.stdoutText)
await ws.close()
```

`rootPath`, such as `/reports`, mounts one folder of the volume. Use
`MountMode.EXEC` when `python3` or `js` should run scripts from the mount.

## Authentication

Pass `host` and `token` explicitly: Mirage reads no environment variables, SDK
profiles or default credentials. `token` is a personal access token or an
OAuth access token, or a function, sync or async, that returns the current
one, or a promise of one. A function is called before each request,
including each listing page; it owns refresh, caching and concurrent
refreshes.

```ts
const dbx = await DatabricksVolumeVFS.create({
  catalog: 'main',
  schema: 'default',
  volume: 'agent_files',
  host: process.env.DATABRICKS_HOST!,
  token: async () => broker.getAccessToken(),
})
```

The token's principal needs `USE CATALOG`, `USE SCHEMA` and `READ VOLUME`,
plus `WRITE VOLUME` for a write mount; a scoped token needs the `files` API
scope. A refused request fails as Databricks answered it: Mirage never replays
it after a `401` or tries another credential.

Bind each VFS and workspace to one principal. Keep file caches, indexes and
external cache prefixes apart across identities, and rebuild the workspace or
drop its caches when the principal or its permissions change. A token refresh
for the same principal keeps the VFS.

## Layout

```text
/dbx/
  reports/
    2026/
      q1/
        summary.md
  datasets/
    orders.csv
```

`/dbx/reports/2026/q1/summary.md` is
`/Volumes/main/default/agent_files/reports/2026/q1/summary.md`. With
`rootPath: '/reports/2026'`, the same file is `/dbx/q1/summary.md`.

## Behavior

- **Folder root:** `rootPath` is normalized, `..` segments are refused, and
  no path can reach above it.
- **Partial reads:** reads use range requests, so `head -c` does not download
  the whole file.
- **Copy and move:** the Files API has no server-side rename, so `cp` and
  `mv` download and upload the file and are not atomic. A directory `mv`
  removes only what it copied: a file written into the source after the copy
  listed it stays there, and `mv` fails with `Directory not empty`.
- **Snapshots:** a snapshot never stores the token or calls a token function.
  Loading it needs a live mount with fresh credentials.
