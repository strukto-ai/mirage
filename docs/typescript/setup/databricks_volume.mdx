`DatabricksVolumeVFS` exposes files from a Unity Catalog volume through
MIRAGE's standard filesystem interface. Agents can list, stat, read, stream,
glob, and write files under the configured volume root.

MIRAGE ships it in `@struktoai/mirage-node` only. The TypeScript client calls
the Databricks Files REST API directly with `fetch`; the Databricks API does
not allow cross-origin browser requests, so there is no browser runtime.

For auth and environment setup, see [Databricks Volume Setup](/home/setup/databricks).

## Node

```bash
pnpm add @struktoai/mirage-node
```

```ts
import {
  DatabricksVolumeVFS,
  MountMode,
  Workspace,
  normalizeDatabricksVolumeConfig,
} from '@struktoai/mirage-node'

const vfs = await DatabricksVolumeVFS.create(
  normalizeDatabricksVolumeConfig({
    catalog: 'main',
    schema: 'default',
    volume: 'agent_files',
    root_path: '/reports',
    host: process.env.DATABRICKS_HOST,
    token: process.env.DATABRICKS_TOKEN,
  }),
)
const ws = new Workspace({ '/dbx/': vfs }, { mode: MountMode.READ })
const res = await ws.shell('ls /dbx/')
console.log(res.stdoutText)
```

| `token` | yes |  | Bearer token as a string, or a function, synchronous or asynchronous, that returns one for each request. Redacted in snapshots. |
| `timeout` | no | `30` | Seconds one request may take before it fails. |

Pass `host` and `token` explicitly. Mirage does not discover environment
variables, SDK profiles, or default credentials. An application can read its
environment as shown above or use its own credential broker.

For rotating credentials, pass a callback that returns a token or a promise
of one. Mirage resolves it once for each outbound request, including listing
pages and metadata probes. A stream resolves it when iteration starts. The
provider owns token caching, refresh, and concurrent refresh coordination.
Authentication failures propagate without a fallback or automatic replay.

```ts
const rotating = await DatabricksVolumeVFS.create(
  normalizeDatabricksVolumeConfig({
    catalog: 'main',
    schema: 'default',
    volume: 'agent_files',
    host: process.env.DATABRICKS_HOST,
    token: async () => broker.getAccessToken(),
  }),
)
```

Keep the principal and permission scope fixed for a VFS and its workspace.
Different identities require isolated workspaces, file caches, indexes, and
external cache prefixes. If permissions change, rebuild or invalidate those
caches before further access.

## Filesystem layout

MIRAGE maps the configured mount prefix onto the configured volume subtree.
With `root_path: '/reports/2026'` and mount prefix `/dbx/`, the volume path

```text
/Volumes/main/default/agent_files/reports/2026/q1/summary.md
```

appears in MIRAGE as

```text
/dbx/q1/summary.md
```

`root_path` is normalized before use, and MIRAGE rejects any virtual path that
would escape above that configured subtree.

## Supported operations

Reads: `readdir`, `stat`, `exists`, `read_bytes` (whole or a byte range),
`read_stream`, and glob resolution. Writes: `write`, `create`, `mkdir`, `rmdir`, `unlink`,
recursive `rm`, `cp`, and `mv`.

Standard shell commands like `ls`, `cat`, `head`, `tail`, `grep`, `rg`,
`find`, `tree`, `touch`, `mkdir`, `rm`, `cp`, and `mv` work through those
primitives. `mv`/`cp` are non-atomic download + upload — the Files API has no
server-side rename.

## Snapshot behavior

`token` is redacted in VFS state. A callback is never called or serialized
during a snapshot. Loading the snapshot requires a live VFS override with
fresh credentials.
