`DatabricksVolumeResource` exposes files from a Unity Catalog volume through
MIRAGE's standard filesystem interface. Agents can list, stat, read, stream,
glob, and write files under the configured volume root.

MIRAGE ships it in `@struktoai/mirage-node` only. The TypeScript client calls
the Databricks Files REST API directly with `fetch`; the Databricks API does
not allow cross-origin browser requests, so there is no browser runtime.

The workspace **host** and the bearer **token** are both config.

For auth and environment setup, see [Databricks Volume Setup](/home/setup/databricks).

## Node

```bash
pnpm add @struktoai/mirage-node
```

```ts
import {
  DatabricksVolumeResource,
  MountMode,
  Workspace,
  normalizeDatabricksVolumeConfig,
} from '@struktoai/mirage-node'

const resource = new DatabricksVolumeResource(
  normalizeDatabricksVolumeConfig({
    host: process.env.DATABRICKS_HOST!,
    token: process.env.DATABRICKS_TOKEN!,
    catalog: 'main',
    schema: 'default',
    volume: 'agent_files',
    root_path: '/reports',
  }),
)
const ws = new Workspace({ '/dbx/': resource }, { mode: MountMode.READ })
const res = await ws.execute('ls /dbx/')
console.log(res.stdoutText)
```

| Field | Default | Notes |
| --- | --- | --- |
| `host` | required | Databricks workspace URL. Trailing slashes are stripped. |
| `catalog` | required | Unity Catalog catalog name. |
| `token` | required | Bearer token, redacted in snapshots. |
| `schema` | required | Unity Catalog schema name. |
| `volume` | required | Unity Catalog volume name. |
| `root_path` | `/` | Subdirectory inside the volume to expose. |
| `timeout` | `30` | Request timeout in seconds. |

There is no `profile` field, and no environment or `~/.databrickscfg`
fallback. A mount described as data works like any other:

```yaml
mounts:
  /dbx/:
    resource: databricks_volume
    config:
      host: https://dbc-xxxxxxxx-xxxx.cloud.databricks.com
      token: dapi...
      catalog: main
      schema: default
      volume: agent_files
```

## Where the token comes from

Any credential your program can turn into a bearer token works: a personal
access token, OAuth machine-to-machine for a service principal, the token of a
signed-in user, or one read from a secret manager. Mint it your own way and
pass the string as `token`.

## When a token expires

MIRAGE sends the configured token on every Files API call and never refreshes
or retries it: a retry would send the same refused credential again and, for a
write, would send the write twice. A refusal throws
`DatabricksVolumeAuthError`, a subclass of `DatabricksVolumeApiError`:

```ts
import { DatabricksVolumeAuthError } from '@struktoai/mirage-core'

try {
  await ws.execute('ls /dbx/')
} catch (err) {
  if (err instanceof DatabricksVolumeAuthError) {
    // mint a new token and build a new resource
  }
}
```

## Filesystem layout

MIRAGE maps the configured mount prefix onto the configured volume subtree.
With `root_path: '/reports/2026'` and mount prefix `/dbx/`, the volume path

```text
/Volumes/main/default/agent_files/reports/2026/q1/summary.md
```

appears in MIRAGE as

```text
/dbx/q1/summary.md
```

`root_path` is normalized before use, and MIRAGE rejects any virtual path that
would escape above that configured subtree.

## Supported operations

Reads: `readdir`, `stat`, `exists`, `read_bytes`, `read_stream`, `range_read`,
and glob resolution. Writes: `write`, `create`, `mkdir`, `rmdir`, `unlink`,
recursive `rm`, `cp`, and `mv`.

Standard shell commands like `ls`, `cat`, `head`, `tail`, `grep`, `rg`,
`find`, `tree`, `touch`, `mkdir`, `rm`, `cp`, and `mv` work through those
primitives. `mv`/`cp` are non-atomic download + upload — the Files API has no
server-side rename.

## Snapshot behavior

Resource state records the config with the token as `<REDACTED>`, so
`Workspace.load` asks for a fresh resource rather than restoring one that
cannot authenticate.
