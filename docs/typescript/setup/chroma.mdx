`ChromaVFS` mounts one ChromaDB collection, read-only, as a tree of text files:
each file is its chunks joined in order. The collection's shape is set up on
the [Chroma page](/home/setup/chroma).

## Install

```bash
npm install @struktoai/mirage-node chromadb
```

## Configure

```ts
import { ChromaVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const knowledge = new ChromaVFS({
  host: 'localhost',
  port: 8000,
  collectionName: 'knowledge',
})
const ws = new Workspace({ '/knowledge': knowledge }, { mode: MountMode.READ })

const result = await ws.shell('tree /knowledge && grep -rn refund /knowledge')
console.log(result.stdoutText)
```

`ssl: true` reaches the server over HTTPS. A collection whose chunks name their
file and position with keys other than `page_slug` and `chunk_index` sets
`slugField` and `chunkIndexField`.

## Layout

```text
/knowledge/
  README.md
  guides/
    api.md
    quickstart.md
  policies/
    refunds.md
```

Paths come from the collection's path tree document, the one with the ID
`__path_tree__`: a JSON object whose keys are file paths below the mount.
Folders come from the `/` in those paths. `/knowledge/guides/quickstart.md` is
every chunk whose `page_slug` is `guides/quickstart.md`.

## Behavior

- **Read-only:** no command changes the collection.
- **Pages:** a file is its chunks sorted by chunk index and joined by line
  breaks.
- **Tree refresh:** the path tree is fetched on the first listing and reused
  until the index expires, so a change to `__path_tree__` shows up after that.
  File text is always read from Chroma.

### Vector search

The [`search` CLI](/typescript/cli/search) ranks chunks by meaning with
Chroma's vector query. Register it on the workspace:

```ts
import { SEARCH } from '@struktoai/mirage-node'

ws.registerCli('search', SEARCH)
```

```bash
search "how do I get started" /knowledge/
search --top-k 5 "billing policy" /knowledge/policies/
search --threshold 0.8 "billing policy" /knowledge/
```

The score is 1 minus Chroma's distance, and `--threshold` keeps the hits that
reach it. `--top-k` defaults to 10. `--method` takes only `semantic`. Each hit
prints its page and score, then the chunk.

## Browser

The same `ChromaVFS` runs in the browser from `@struktoai/mirage-browser`.

```bash
npm install @struktoai/mirage-browser chromadb
```

```ts
import { ChromaVFS, MountMode, Workspace } from '@struktoai/mirage-browser'

const knowledge = new ChromaVFS({
  host: 'chroma.example.com',
  port: 443,
  ssl: true,
  collectionName: 'knowledge',
})
const ws = new Workspace({ '/knowledge': knowledge }, { mode: MountMode.READ })
```

- The page calls the Chroma server directly, so the server must accept requests
  from the page's origin.

## Integration

Chroma answers this command through its own API, so fewer pages are read. See
[Integration](/home/integration/overview).

- `grep -r` and `rg`: read only the pages with a chunk holding the text,
  which Chroma's `$contains` answers, then match each page as `grep` does. No
  match can span two chunks, so it misses nothing. `$contains` matches case,
  so `-i` reads every page.
