`GSlidesVFS` exposes Slides decks as `.gslide.json` files containing the deck structure, slides, and text content.

Setup steps for OAuth credentials live at [Google Workspace Credentials](/home/setup/google).

## Node

```bash
pnpm add @struktoai/mirage-node
```

```ts
import { GSlidesVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const slides = new GSlidesVFS({
  clientId: process.env.GOOGLE_CLIENT_ID!,
  clientSecret: process.env.GOOGLE_CLIENT_SECRET!,
  refreshToken: process.env.GOOGLE_REFRESH_TOKEN!,
})

const ws = new Workspace({ '/slides': slides }, { mode: MountMode.READ })
await ws.shell('ls /slides/owned/')
```

## Browser

```bash
pnpm add @struktoai/mirage-browser
```

```ts
import { GSlidesVFS, MountMode, Workspace } from '@struktoai/mirage-browser'

const slides = new GSlidesVFS({
  clientId: GOOGLE_CLIENT_ID,
  clientSecret: GOOGLE_CLIENT_SECRET,
  refreshToken: localStorage.getItem('gslides.refresh_token')!,
})
```

## Mount mode

`read`. A `MountMode.WRITE` mount also allows `mv` (retitle) and `rm` (delete). Edit a deck with the [gws CLI](/typescript/cli/gws).

For the JSON structure (slides, layouts, text frames) see the [Python Slides docs](/python/vfs/gslides).

    ### Virtual Filesystem

    | Path | Description |
    | --- | --- |
    | `/<path>` | `gslides`, write |

    #### VFS Layout

    ##### `/<path>`

    ```text
    /<path>
      owned/     # presentations you created
        <YYYY-MM-DD>_<title>__<presentation-id>.gslide.json
      shared/    # presentations others shared with you
        <YYYY-MM-DD>_<title>__<presentation-id>.gslide.json
    ```

    - `<YYYY-MM-DD>` is the file's `modifiedTime`, so a date glob such as
      `2026-05-*` narrows by it.
    - `<title>` is sanitized: spaces and any character outside
      `[A-Za-z0-9_.-]` become `_`, at most 100 characters.
    - `<presentation-id>` is the Google Slides presentation id.
    - `shared/` holds presentations shared with you by others, not presentations you
      own and shared with others; those are still in `owned/`.

    A `.gslide.json` matches the Google Slides API `presentations.get`
    response:

    ```jsonc
    {
      "presentationId": "...",
      "title": "...",
      "pageSize": { "width": {...}, "height": {...} },
      "slides": [
        {                                      // one element per slide
          "objectId": "...",
          "pageElements": [
            {
              "objectId": "...",
              "shape": {
                "shapeType": "TEXT_BOX",
                "text": {
                  "textElements": [
                    { "textRun": { "content": "the actual text\n",
                                   "style": {...} } }
                  ]
                }
              }
            },
            { "image": {...} },
            { "table": {...} }
          ]
        }
      ],
      "masters": [...],
      "layouts": [...]
    }
    ```

    Useful `jq` paths:

    ```jq
    .title
    .slides | length                                                    # slide count
    .slides[].pageElements[].shape.text.textElements[].textRun.content  # all text
    .slides[0].objectId
    ```

    Delete, on a `write` path:

    ```sh
    rm /<path>/owned/<file>.gslide.json   # deletes it from Drive for good
    rm -f <path>                       # ignores a missing file
    ```

    Only `.gslide.json` files can be removed; `owned/` and `shared/` cannot.

    Rename to a new title, on a `write` path:

    ```sh
    mv /<path>/owned/<date>_<old>__<id>.gslide.json \
       /<path>/owned/<date>_<new>__<id>.gslide.json
    ```

    Keep the folder, the date and the id, and spell the title the way the
    listing does (spaces become `_`); any other name is refused.

    #### Supported Unix Commands for VFS

    Unix commands work on each path as on a local filesystem, as far as the path supports them:

    | Path | Supported |
    | --- | --- |
    | `/<path>` | Commands that read files (`ls`, `cat`, `grep`, `find`, `jq` and the rest), and `mv`, `rm` and `unlink`. `grep -r` and `rg` with `-w` ask `gslides` which files may match. |

    #### Limitations of Unix Commands for VFS

    Where a path differs from a local filesystem:

    | Path | Limitations |
    | --- | --- |
    | `/<path>` | Not supported: `>`, `>>`, `tee`, `tee -a`, `touch` of a new file, `cp`, `cp -r`, `mkdir`, `rm -r`, `rmdir`, `truncate`, `sed -i`. Without `-w`, `grep -r` and `rg` read every file. `grep -r`, `find` and `du` stop after 1000 files; a glob matching more, `tar -c`, `cp -r` and `rm -r` are refused. |

    Run `man <cmd>` or `<cmd> --help` for one command's usage.

## Integration

What Google Slides answers through its own API, so fewer files are read. [Integration](/home/integration/overview) explains each command.

| Command | On Google Slides |
| --- | --- |
| `grep -r`, `rg` | Drive full-text search, for whole words. It can miss words only in non-text values (fonts, links, layout names and ids) or split by styling. |

The [Python Google Slides docs](/python/vfs/gslides#integration) list when each search answers and what it can miss.
