`OneDriveVFS` mounts one Microsoft Graph drive: a personal OneDrive, OneDrive
for Business or one SharePoint document library. Its files and folders become
a folder tree of raw bytes. Tokens and drive IDs are set up on the
[OneDrive page](/home/setup/onedrive).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { MountMode, OneDriveVFS, Workspace } from '@struktoai/mirage-node'

const drive = new OneDriveVFS({
  accessToken: process.env.MS_GRAPH_DRIVE_TOKEN!,
})
const ws = new Workspace({ '/onedrive': drive }, { mode: MountMode.WRITE })

const result = await ws.shell("ls /onedrive && find /onedrive -name '*.xlsx'")
console.log(result.stdoutText)
```

With no drive named, the mount is the signed-in user's own drive. Set one of
`driveId`, `siteId`, `groupId` or `userId` to mount another drive, and
`keyPrefix` to mount one folder.

## Authentication

`accessToken` is a Microsoft Graph bearer token, or a function (sync or async)
that returns one. A function is called for each request and again after a
`401`, so a long-running mount outlives one token; a plain string lasts about
an hour.

A delegated token reaches the signed-in user's drive with no drive named. An
app-only token cannot use `/me/drive`, so it must set one of `driveId`,
`siteId`, `groupId` or `userId`, and have the permission to read that target.
Reads need `Files.Read`; writes need `Files.ReadWrite` or a wider write
permission. Other drives and SharePoint may need `Files.Read.All`,
`Files.ReadWrite.All` or a `Sites.*` permission.

## Layout

```text
/onedrive/
  Documents/
    file.txt
    config.json
  Reports/
    q1.csv
    q2.csv
```

`/onedrive/Documents/file.txt` is the driveItem at `/root:/Documents/file.txt`.
Folders are real driveItems, so the tree matches what OneDrive shows.

## Behavior

- **Naming the drive:** `driveId`, `siteId`, `groupId` and `userId` are four
  ways to name the drive, so set at most one. Setting two throws at
  construction rather than addressing whichever came first.
- **Folder scope:** `keyPrefix: 'users/42'` mounts only that folder, so
  `/onedrive/data/notes.md` is the driveItem `users/42/data/notes.md`.
  Slashes at either end are ignored.
- **Service root:** mounts address `https://graph.microsoft.com/v1.0` unless
  `graphBaseUrl` names another root, given in full with its version segment,
  such as `https://graph.microsoft.us/v1.0`. Sovereign clouds are separate
  instances, so a token minted for one is rejected by the others and a mount
  on the wrong root fails outright. Take the root from Microsoft's national
  cloud documentation for the tenant.
- **Raw bytes:** Office files stay as they are stored, with no conversion.
- **Snapshots:** a snapshot pins each file the agent read to its version, and
  replaying it reads those exact bytes. A file the agent wrote carries no
  version and is not checked on replay. Old versions read only while the
  library keeps them; an admin can cap or turn off versioning.

## Browser

`@struktoai/mirage-browser` exports the same `OneDriveVFS` with the same
fields.

```bash
npm install @struktoai/mirage-browser
```

```ts
import { MountMode, OneDriveVFS, Workspace } from '@struktoai/mirage-browser'

const drive = new OneDriveVFS({ accessToken: () => getMicrosoftGraphToken() })
const ws = new Workspace({ '/onedrive': drive }, { mode: MountMode.READ })
```

- Pass a token function, such as one backed by the page's sign-in library, so
  a `401` fetches a fresh token and retries.

## Integration

OneDrive answers these commands through its own API, so fewer files are read.
See [Integration](/home/integration/overview).

- `grep -rw` and `rg -w`: Microsoft Graph search names the files to read,
  for whole words. Every file is read when the search fails or finds nothing.
  Graph searches the text it extracted, not the bytes, and indexes a write
  some time after it lands, so it can miss Office files, PDFs, archives, the
  end of a large file, a word Graph splits differently (`foo.bar`) and recent
  writes. `walk_limit: -1` in the mount's `"@all"`
  [command limit](/home/core/output-limits) reads every file instead.
- `grep -r` and `rg` without `-w`: every file is read.
- `find`: one recursive listing.
- `du`: one recursive listing.
- `ls -R` and `tree`: one recursive listing.
