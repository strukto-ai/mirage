`GDocsVFS` mounts the Google Docs an account can see: each document becomes a
`.gdoc.json` file holding the Docs API's JSON, split into the documents it owns
and those shared with it. Credentials are set up on the
[Google Workspace page](/home/setup/google).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { GDocsVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const docs = new GDocsVFS({
  clientId: process.env.GOOGLE_CLIENT_ID!,
  clientSecret: process.env.GOOGLE_CLIENT_SECRET!,
  refreshToken: process.env.GOOGLE_REFRESH_TOKEN!,
})
const ws = new Workspace({ '/gdocs': docs }, { mode: MountMode.READ })

const result = await ws.shell("ls /gdocs/owned && jq -r '.title' /gdocs/owned/2026-*.gdoc.json")
console.log(result.stdoutText)
await ws.close()
```

`accessToken` replaces the client and refresh token with a token or a
function that returns one. A `MountMode.WRITE` mount also allows `mv` and `rm`.

## Authentication

Credentials come from the first of:

1. `accessToken`, a token or a function, sync or async, that returns one.
2. `clientId` and `refreshToken`, with `clientSecret` unless the client uses
   PKCE. Mirage trades the refresh token for access tokens on its own, or
   hands it to `refreshFn` when set, so the secret can stay on a backend.

The mount needs the Google Docs API with the
`https://www.googleapis.com/auth/documents` scope, and the Drive API with the
`https://www.googleapis.com/auth/drive` scope, since the listing comes from
Drive. A read-only mount can use the `readonly` variants of both scopes.

## Layout

```text
/gdocs/
  owned/
    2026-11-14_Meeting_Notes__1Xk9rT2bQ.gdoc.json
  shared/
    2026-10-02_Design_Review__1Pq7sV4mN.gdoc.json
```

- `owned/` holds the documents the account owns, shared or not; `shared/`
  holds those others shared with it.
- A file is named `<YYYY-MM-DD>_<title>__<document-id>.gdoc.json`. The date
  is the last modified day and is left out when Drive gives none.
- A file holds the Docs API's JSON for the document, with every tab.

## Behavior

- **Shared Drives:** a document in a Shared Drive has no owner, so it is
  listed under `shared/`, as on the `gdrive` mount.
- **Date globs:** a glob on the date prefix, such as `2026-05-*`, asks Drive
  only for the documents modified on those days.
- **Incomplete listings:** Drive may skip part of the account's files and say
  so. The short listing is still shown, and the next `ls` lists again.
- **Rename:** on a `write` mount, `mv` to a new name in the same folder
  changes the title. The date and the id must stay, and the title is spelled
  as the listing spells it (spaces become `_`).
- **Delete:** on a `write` mount, `rm` deletes the document for good, not to
  the trash. `owned/` and `shared/` cannot be removed.
- **Edits:** writing text into a document, and raw API calls, go through the
  [`gws`](/typescript/cli/gws) CLI.

## Browser

The same `GDocsVFS` comes from `@struktoai/mirage-browser`. In a page, an
`accessToken` function fetches a fresh token from a backend, so the client
secret never reaches the browser.

```bash
npm install @struktoai/mirage-browser
```

```ts
import { GDocsVFS, MountMode, Workspace } from '@struktoai/mirage-browser'

const docs = new GDocsVFS({
  accessToken: async () => (await fetch('/api/google-token')).text(),
})
const ws = new Workspace({ '/gdocs': docs }, { mode: MountMode.READ })
```

- `/api/google-token` stands for a backend endpoint that returns an access
  token.
- A PKCE OAuth client needs no secret: `clientId` and `refreshToken` alone
  mount it. `examples/browser/vfs/gdocs/gdocs_pkce.ts` shows the sign-in
  flow.
- `refreshFn` sends each refresh to a backend instead of Google's token
  endpoint.

## Integration

Google Docs answers these commands through its own API, so fewer files are
read. See [Integration](/home/integration/overview).

- `grep -r` and `rg` with `-w`: Drive full-text search names the documents to
  read. Every one is read when the search fails or finds nothing, and when
  the word may be in any document's JSON whatever the text says: a word with
  a digit, a Docs API name or value (`paragraph`, `NORMAL_TEXT`), or a word
  every document carries (`https`, `arial`). Drive indexes a write some time
  after it lands and searches the document's text, so it can leave out one
  whose JSON holds the word only in another value (a font, a link or image
  address, a tab title, an id) or only inside a word that styling splits
  (`snow` in bold inside `snowman`). `walkLimit: -1` in the mount's
  `"@all"` [command limit](/home/core/output-limits) turns the search off and
  reads every file.
