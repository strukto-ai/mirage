`GDocsVFS` exposes Google Docs as `.gdoc.json` files. Reads return the document's structured content.

Setup steps for OAuth credentials live at [Google Workspace Credentials](/home/setup/google).

## Node

```bash
pnpm add @struktoai/mirage-node
```

```ts
import { GDocsVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const docs = new GDocsVFS({
  clientId: process.env.GOOGLE_CLIENT_ID!,
  clientSecret: process.env.GOOGLE_CLIENT_SECRET!,
  refreshToken: process.env.GOOGLE_REFRESH_TOKEN!,
})

const ws = new Workspace({ '/docs': docs }, { mode: MountMode.WRITE })
await ws.shell('cat /docs/owned/MyDoc.gdoc.json')
```

## Browser

```bash
pnpm add @struktoai/mirage-browser
```

```ts
import { GDocsVFS, MountMode, Workspace } from '@struktoai/mirage-browser'

const docs = new GDocsVFS({
  clientId: GOOGLE_CLIENT_ID,
  clientSecret: GOOGLE_CLIENT_SECRET,
  refreshToken: localStorage.getItem('gdocs.refresh_token')!,
})

const ws = new Workspace({ '/docs': docs }, { mode: MountMode.WRITE })
```

A PKCE example lives at `examples/browser/vfs/gdocs/gdocs_pkce.ts`.

| <code style={{ whiteSpace: 'nowrap' }}>refreshToken</code><br />secret | User's OAuth refresh token. Required with `clientId` when `accessToken` is unset. |
| <code style={{ whiteSpace: 'nowrap' }}>refreshFn</code><br />secret | Function that exchanges the refresh token for `{ accessToken, expiresIn }` instead of Google's token endpoint, so the client secret can stay on a backend. Still needs `clientId` and `refreshToken`. |
| <code style={{ whiteSpace: 'nowrap' }}>apiBase</code> | One base URL that replaces every Google API host and the OAuth token endpoint, such as a test server. Unset uses Google's hosts. |

## Mount mode

`read`. A `MountMode.WRITE` mount also allows `mv` (retitle) and `rm` (delete). Append text with the [gws CLI](/typescript/cli/gws).

For the JSON shape see the [Python Google Docs docs](/python/vfs/gdocs).

    #### `/<path>` layout

    ```text
    /<path>
      owned/
        <date>_<title>__<doc-id>.gdoc.json
      shared/
        <date>_<title>__<doc-id>.gdoc.json

      Filename: <YYYY-MM-DD>_<title>__<doc-id>.gdoc.json
        <YYYY-MM-DD>  modifiedTime, used for date-glob (e.g. 2026-05-*)
        <title>       sanitized: spaces->_, non-[A-Za-z0-9_.-]->_, <=100 chars
        <doc-id>      Google Docs document ID

      Buckets:
        owned/   docs you created
        shared/  docs shared with you by others
                 - does NOT include docs you own and shared with others;
                   those are still in owned/.

      gdoc.json structure (the Google Docs API documents.get response, read
      with includeTabsContent=true so every tab is present):
        {
          "documentId": "...",
          "title": "...",
          "tabs": [                          # one entry per top-level tab
            {
              "tabProperties": {
                "tabId": "t.0",              # names a tab for gws docs write
                "title": "Tab 1",
                "index": 0
              },
              "documentTab": {
                "body": {
                  "content": [
                    {                          # one element per block
                      "paragraph": {
                        "elements": [
                          { "textRun": { "content": "the actual text\n",
                                         "textStyle": {...} } }
                        ],
                        "paragraphStyle": {...}
                      }
                    },
                    { "table": {...} },
                    { "sectionBreak": {...} }
                  ]
                },
                "documentStyle": {...},
                "namedStyles": {...}
              },
              "childTabs": [ { ...same shape, nested to any depth... } ]
                                           # a NESTED tab additionally carries
                                           # parentTabId and nestingLevel; a
                                           # root tab carries neither
            }
          ],
          "revisionId": "..."
        }

      There is no top-level .body. A tab-aware response leaves the singleton
      fields (.body, .documentStyle, .namedStyles) empty and hangs every
      tab's content off .tabs[].documentTab instead. Tabs also nest, so text
      can sit at any depth under .childTabs; the recursive recipes below read
      a one-tab and a fifty-tab document alike.

      Useful jq paths:
        .title
        [.. | .tabProperties? // empty | .title]             # every tab name
        [.. | .textRun? // empty | .content] | add           # all text, any depth
        [.. | .tabProperties? // empty] | length             # tab count
        [.tabs[0].documentTab.body.content[]
          | .paragraph?.elements[]?.textRun.content] | add   # first tab only
        .revisionId

      The first block of a body is always a sectionBreak, which carries no
      .paragraph, so a path through .paragraph needs the `?` or it fails with
      "Cannot iterate over null".

      Delete, on a `write` path:
        rm /<path>/owned/<file>.gdoc.json      # permanent delete from Drive
        rm -f <path>                            # ignore if missing
        Only operates on .gdoc.json files; owned/ and shared/ themselves
        cannot be removed.

      Rename to a new title, on a `write` path:
        mv /<path>/owned/<date>_<old>__<id>.gdoc.json \
           /<path>/owned/<date>_<new>__<id>.gdoc.json
        Keep the folder, the date and the id, and spell the title the way
        the listing does (spaces->_); any other name is refused.
    ```

    #### Supported Unix Commands for VFS

    Unix commands work on each path as on a local filesystem, as far as the path supports them:

    | Path | Supported |
    | --- | --- |
    | `/<path>` | Commands that read files (`ls`, `cat`, `grep`, `find`, `jq` and the rest), and `mv`, `rm` and `unlink`. `grep -r` and `rg` with `-w` ask `gdocs` which files may match. |

    #### Limitations of Unix Commands for VFS

    Where a path differs from a local filesystem:

    | Path | Limitations |
    | --- | --- |
    | `/<path>` | Not supported: `>`, `>>`, `tee`, `tee -a`, `touch` of a new file, `cp`, `cp -r`, `mkdir`, `rm -r`, `rmdir`, `truncate`, `sed -i`. Without `-w`, `grep -r` and `rg` read every file. `grep -r`, `find` and `du` stop after 1000 files; a glob matching more, `tar -c`, `cp -r` and `rm -r` are refused. |

    Run `man` to list every command, and `man <cmd>` or `<cmd> --help` for one command's usage.

## Integration

What Google Docs answers through its own API, so fewer files are read. [Integration](/home/integration/overview) explains each command.

| Command | On Google Docs |
| --- | --- |
| `grep -r`, `rg` | Drive full-text search, for whole words. It can miss words only in non-text values (fonts, links and ids) or split by styling. |

The [Python Google Docs docs](/python/vfs/gdocs#integration) list when each search answers and what it can miss.
