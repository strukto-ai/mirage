title: Google Calendar

description: Mount Google Calendar calendars and events as JSON files from Node or the browser.
---

`GCalVFS` exposes every calendar the account can see as a directory of date
buckets, with one `.gcal.json` file per event.

Setup steps for OAuth credentials live at [Google Workspace Credentials](/home/setup/google).
For the Python SDK, see [Google Calendar (Python)](/python/vfs/gcal).

## Node

```bash
pnpm add @struktoai/mirage-node
```

```ts
import { GCalVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const gcal = new GCalVFS({
  clientId: process.env.GOOGLE_CLIENT_ID!,
  clientSecret: process.env.GOOGLE_CLIENT_SECRET!,
  refreshToken: process.env.GOOGLE_REFRESH_TOKEN!,
})

const ws = new Workspace({ '/gcal': gcal }, { mode: MountMode.READ })
const res = await ws.shell('ls /gcal/primary')
console.log(res.stdoutText)
```

## Browser

```bash
pnpm add @struktoai/mirage-browser
```

```ts
import { GCalVFS, MountMode, Workspace } from '@struktoai/mirage-browser'

const gcal = new GCalVFS({
  accessToken: async () => (await fetch('/api/google-token')).text(),
})

const ws = new Workspace({ '/gcal': gcal }, { mode: MountMode.READ })
```

In the browser, get the access token from your backend so the client secret never reaches the page.
`/api/google-token` stands for that endpoint.

    #### `/<path>` layout

    ```text
    Google Calendar is mounted as one directory per calendar, one
    directory per date bucket, and one JSON file per event.

        /<mount>/primary/calendar.json
        /<mount>/primary/2026-08-11/<eventId>__0900-1030_Team_Standup.gcal.json
        /<mount>/Engineering__team@group.calendar.google.com/2026-08-11/...

    Reading the tree:

    - `ls <mount>/` lists the calendars. The primary one is always spelled
      `primary`; every other directory ends in `__<calendarId>`.
    - `ls <mount>/primary/` lists buckets with events from all available history
      through today +90 days unless end_time is configured. start_time/end_time
      restrict this mount, including direct paths, date globs and event reads.
      A date glob such as `ls <mount>/primary/2027-03-*` selects its own
      listing range within that scope, beyond the default future horizon.
    - A bucket is one local day, named by its date. A well-formed date inside
      the configured scope is a directory even when it holds no events. Dates
      outside the scope are absent.
    - A file name is `<eventId>__<HHMM-HHMM>_<Title>.gcal.json`. The times are
      clamped to that day, so an event running through it reads `0000-2400`.
      A multi-day event appears under every day it covers.
    - `cat` an event for the unmodified Calendar API payload, including
      attendees, description, location and the original start/end with offsets.
    - `calendar.json` carries the calendar's accessRole and, in
      `bucketTimeZone`, the zone the buckets are cut in. That zone is
      mount-wide, so every calendar's `2026-08-11/` covers the same hours.
    - On a calendar shared as free/busy only, Google returns no titles at all,
      so events render as `busy`.

    Acting on it:

    - On a `write` path, `rm` an event file to delete that event for every
      attendee.
    - Everything else goes through the `gws calendar` CLI, which takes the ids
      the tree renders.
    - A written event must carry an explicit UTC offset or timeZone; an
      ambiguous local time is not interpreted for you.

      Time scope: start_time=unbounded (inclusive), end_time=unbounded (exclusive). Explicit paths and globs cannot escape this scope.
    ```

    #### Supported Unix Commands for VFS

    Unix commands work on each path as on a local filesystem, as far as the path supports them:

    | Path | Supported |
    | --- | --- |
    | `/<path>` | Commands that read files (`ls`, `cat`, `grep`, `find`, `jq` and the rest), and `rm` and `unlink`. `grep -r` and `rg` with `-w` ask `gcal` which files may match. |

    #### Limitations of Unix Commands for VFS

    Where a path differs from a local filesystem:

    | Path | Limitations |
    | --- | --- |
    | `/<path>` | Not supported: `>`, `>>`, `tee`, `tee -a`, `touch` of a new file, `cp`, `cp -r`, `mkdir`, `mv`, `rm -r`, `rmdir`, `truncate`, `sed -i`. Without `-w`, `grep -r` and `rg` read every file. `gcal` answers only for `*/*/*.gcal.json`; `grep -r` and `rg` read every other file. `grep -r`, `find` and `du` stop after 1000 files; a glob matching more, `tar -c`, `cp -r` and `rm -r` are refused. |

    Run `man <cmd>` or `<cmd> --help` for one command's usage.

## Write Support

The only write is `rm` on an event file, on a mount in `MountMode.WRITE`. It
deletes the event on its calendar, for every attendee. The account needs the
`owner` or `writer` role on that calendar; otherwise `rm` fails with
permission denied. Creating, editing and moving events go through the
[`gws calendar`](/home/setup/cli/gws) CLI, which takes the calendar and event
ids the tree shows.
