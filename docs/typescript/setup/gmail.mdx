`GmailVFS` browses messages, threads, and labels via the Gmail API.

Both runtimes share the same OAuth config: a Google Cloud `clientId` / `clientSecret` plus a long-lived `refreshToken` for the user. Setup steps live at [Google Workspace Credentials](/home/setup/google).

## Node

```bash
pnpm add @struktoai/mirage-node
```

```ts
import { GmailVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const gmail = new GmailVFS({
  clientId: process.env.GOOGLE_CLIENT_ID!,
  clientSecret: process.env.GOOGLE_CLIENT_SECRET!,
  refreshToken: process.env.GOOGLE_REFRESH_TOKEN!,
})

const ws = new Workspace({ '/mail': gmail }, { mode: MountMode.READ })
await ws.shell('ls /mail/INBOX/')
```

## Browser

```bash
pnpm add @struktoai/mirage-browser
```

```ts
import { GmailVFS, MountMode, Workspace } from '@struktoai/mirage-browser'

const gmail = new GmailVFS({
  clientId: GOOGLE_CLIENT_ID,
  clientSecret: GOOGLE_CLIENT_SECRET,
  refreshToken: localStorage.getItem('gmail.refresh_token')!,
})

const ws = new Workspace({ '/mail': gmail }, { mode: MountMode.READ })
```

For OAuth in a browser, prefer PKCE so secrets stay off the page; the [Google setup guide](/home/setup/google) shows the flow.

## Config

| Field | Default | Notes |
| --- | --- | --- |
| `clientId` | required | Google OAuth client ID. |
| `clientSecret` | required | Google OAuth client secret. Redacted in snapshots. |
| `refreshToken` | required | User's refresh token. Redacted in snapshots. |
| `refreshFn` | built-in | Optional override for the access-token refresh callback. |
| `contentSearch` | `false` | Narrow `grep -rw` and `rg -w` with Gmail search ([below](#grep-and-rg)). |

## grep and rg

With `contentSearch: true` (YAML `content_search: true`), `grep -rw` and `rg -w` read only
the messages Gmail search names, and print what reading every message would.
Search covers the From, To, Cc and Subject headers, the body and, through
`filename:`, attachment names. Each label is searched on its own, since an
account-wide search leaves out spam and trash. Listing a label already fetches
its messages, so this saves the second fetch of each message it rules out.
Attachments are always read.

Every message is read when the word is a key of the message JSON, a system
label, a Date header or MIME type word, and when a search fails, reaches 500
messages or finds nothing. It is off by default: Gmail indexes a message some
time after it arrives.

## Mount mode

`read`. Partial write (drafts, labels) is exposed via Python and may land in TS in a future release.

For the mounted layout (labels, dates, attachments) see the [Python Gmail docs](/python/vfs/gmail).
