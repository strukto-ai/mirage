`GmailVFS` browses labels, messages, and attachments via the Gmail API.

Both runtimes share the same OAuth config: a Google Cloud `clientId` / `clientSecret` plus a long-lived `refreshToken` for the user. Setup steps live at [Google Workspace Credentials](/home/setup/google).

## Node

```bash
pnpm add @struktoai/mirage-node
```

```ts
import { GmailVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const gmail = new GmailVFS({
  clientId: process.env.GOOGLE_CLIENT_ID!,
  clientSecret: process.env.GOOGLE_CLIENT_SECRET!,
  refreshToken: process.env.GOOGLE_REFRESH_TOKEN!,
})

const ws = new Workspace({ '/mail': gmail }, { mode: MountMode.READ })
await ws.shell('ls /mail/INBOX/')
```

## Browser

```bash
pnpm add @struktoai/mirage-browser
```

```ts
import { GmailVFS, MountMode, Workspace } from '@struktoai/mirage-browser'

const gmail = new GmailVFS({
  clientId: GOOGLE_CLIENT_ID,
  clientSecret: GOOGLE_CLIENT_SECRET,
  refreshToken: localStorage.getItem('gmail.refresh_token')!,
})

const ws = new Workspace({ '/mail': gmail }, { mode: MountMode.READ })
```

For OAuth in a browser, prefer PKCE so secrets stay off the page; the [Google setup guide](/home/setup/google) shows the flow.

| <code style={{ whiteSpace: 'nowrap' }}>refreshFn</code><br />secret | Function that exchanges the refresh token for `{ accessToken, expiresIn }` instead of Google's token endpoint, so the client secret can stay on a backend. Still needs `clientId` and `refreshToken`. |

## Integration

What Gmail answers through its own API, so fewer files are read. [Integration](/home/integration/overview) explains each command.

| Command | On Gmail |
| --- | --- |
| `grep -r`, `rg` | The message text the listing keeps, for ASCII text. It misses nothing. |

The [Python Gmail docs](/python/vfs/gmail#integration) list when each search answers and what it can miss.

## Mount mode

`read`.

For the mounted layout (labels, dates, attachments) see the [Python Gmail docs](/python/vfs/gmail).
