`LanceDBVFS` mounts a LanceDB table, read-only, as nested folders, one level per
group-by column. Each row is a Markdown card plus an optional blob file, such
as its image. Local, object storage and LanceDB Cloud connections are set up on
the [LanceDB page](/home/setup/lancedb).

## Install

```bash
npm install @struktoai/mirage-node @lancedb/lancedb
```

## Configure

```ts
import { LanceDBVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const fashion = new LanceDBVFS({
  uri: '/data/fashion.lancedb',
  table: 'fashion',
  groupBy: ['gender', 'articleType', 'baseColour'],
  titleColumn: 'productDisplayName',
  blobColumn: 'image_bytes',
  blobExt: 'jpg',
  vectorColumn: 'vector',
})
const ws = new Workspace({ '/fashion': fashion }, { mode: MountMode.READ })

const result = await ws.shell('ls /fashion/Men/Shoes/White && cat /fashion/Men/Shoes/White/3.md')
console.log(result.stdoutText)
await ws.close()
```

`idColumn` (default `id`) names each row's files. Without `table`, every table
is a top-level folder.

## Authentication

A local directory needs no credentials. LanceDB Cloud takes its `db://` URI
with `apiKey` and `region` (default `us-east-1`); LanceDB Enterprise adds its
endpoint in `hostOverride`. An `s3://`, `gs://` or `az://` URI takes the
store's credentials or endpoint in `storageOptions`.

```ts
const fashion = new LanceDBVFS({
  uri: process.env.LANCEDB_URI!,
  apiKey: process.env.LANCEDB_API_KEY!,
  region: process.env.LANCEDB_REGION!,
  table: 'fashion',
  groupBy: ['gender'],
})
```

## Layout

```text
/fashion/
  Men/
    Shoes/
      White/
        3.jpg
        3.md
    Watches/
      Silver/
        15.jpg
        15.md
  Women/
    Tops/
      Blue/
        12.jpg
        12.md
```

Each folder level filters on one `groupBy` column, in order:
`/fashion/Men/Shoes/White/` lists the rows whose `gender` is `Men`,
`articleType` is `Shoes` and `baseColour` is `White`. Once every column is
bound, the folder lists each row's `<id>.md` and, with `blobColumn`, its
`<id>.<blobExt>`. A value holding `/` renders as `∕`, and a blank or dot-led
value is led by `⁄`, so every value keeps its own folder that lists and opens.

A card lists the row's columns, headed by `titleColumn`, without the vector and
blob columns.

## Behavior

- **Read-only:** no command changes the table.
- **Listing cap:** one folder listing reads at most `maxRows` (1,000) rows; rows
  past it are left out. Keep `groupBy` to low-cardinality columns on a large
  table.

### Semantic search

The `search` CLI runs LanceDB's vector search with
the table's embedding function, so the table needs one on a source column.
Register it on the workspace:

```ts
import { SEARCH } from '@struktoai/mirage-node'

ws.registerCli('search', SEARCH)
```

Each hit prints its card's path with the vector distance, then the card, so
results work with `cat`, pipes and `wc`:

```text
$ search "white running sneakers" /fashion
/fashion/Men/Shoes/White/3.md:0.2679
# Nike Men White Running Sneakers
...
```

`--top-k` defaults to `searchLimit` (10). `--threshold` is the largest distance
kept. `--method` takes only `semantic`.

## Integration

LanceDB answers this command through its own API, so fewer cards are read. See
[Integration](/home/integration/overview).

- `grep -r` and `rg`: a `LIKE` query over each row's string columns picks the
  cards to read, for any text, and misses nothing. A text that could match a
  column's name, a boolean or `null`, or the `column: ` prefix reads every
  card, as does a table that renders a list, struct or bytes column.
