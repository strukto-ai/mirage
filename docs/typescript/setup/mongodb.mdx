`MongoDBVFS` exposes databases containing `collections/` and `views/` directories.
Each collection or view contains `schema.json` and `documents.jsonl`.

Setup steps for the connection URI live at [MongoDB Credentials](/home/setup/mongodb).

## Node

```bash
pnpm add @struktoai/mirage-node mongodb
```

```ts
import { MongoDBVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const mongo = new MongoDBVFS({
  uri: process.env.MONGODB_URI!,
  databases: ['app', 'analytics'],
})

const ws = new Workspace({ '/mongo': mongo }, { mode: MountMode.READ })
try {
  const result = await ws.shell('ls /mongo/app/collections/users/')
  console.log(result.stdoutText)
} finally {
  await ws.close()
}
```

## Browser

```bash
pnpm add @struktoai/mirage-browser
```

The browser VFS sends HTTP requests to a backend route, which keeps the MongoDB
connection URI on the server. This example expects `/api/mongo` on the same origin.
The repository's [Vite middleware](https://github.com/strukto-ai/mirage/blob/main/examples/browser/scripts/mongo_proxy.ts)
supports the database listing below for local development.

```ts
import { MongoDBVFS, MountMode, Workspace } from '@struktoai/mirage-browser'

const mongo = new MongoDBVFS({ uri: '/api/mongo' })
const ws = new Workspace({ '/mongo': mongo }, { mode: MountMode.READ })

try {
  const result = await ws.shell('ls /mongo/')
  console.log(result.stdoutText)
} finally {
  await ws.close()
}
```

The development proxy does not yet support document streaming or schema reads.

## Config

| Field | Description |
| --- | --- |
| <code style={{ whiteSpace: 'nowrap' }}>uri</code><br />required, secret | MongoDB connection URI in Node; in the browser, the URL of a backend route that holds the connection URI. |
| <code style={{ whiteSpace: 'nowrap' }}>databases</code> | Databases to mount; others are hidden. Unset or empty mounts every database except `admin`, `config` and `local`. |
| <code style={{ whiteSpace: 'nowrap' }}>maxDocLimit</code><br />default `5000` | Most documents one `tail -n` read of `documents.jsonl` fetches; a larger count on a collection that holds more is refused (`File too large`). |
| <code style={{ whiteSpace: 'nowrap' }}>elideFields</code><br />default `{}` | Fields dropped from `documents.jsonl`, keyed by `<database>.<collection>` (a view's name works too); a dotted path such as `nested.path` drops a nested field. |
| <code style={{ whiteSpace: 'nowrap' }}>walkLimit</code><br />default `1000` | Most files one command walks under a folder: `grep -r`, `find` and other walks stop there, and a larger glob, `tar -c`, `cp -r` or `rm -r` is refused. `-1` lifts the limit. |

## `/<path>` layout

```text
/<path>
  <database>/
    database.json                  collection and view names
    collections/<collection>/
      schema.json                  sampled field types, validator, indexes
      documents.jsonl              streamed BSON Extended JSON documents
    views/<view>/
      schema.json
      documents.jsonl
  Read database.json first to discover entities. Use schema.json before
  reading large document streams; head, tail, wc, grep, rg, and jq understand
  documents.jsonl; grep and rg fetch only the documents that may match.
  Unknown stat sizes display as -; wc -c measures bytes and wc -l counts
  documents on demand. These counts may scan the collection.
```

## Supported Unix Commands for VFS

Unix commands work on each path as on a local filesystem, as far as the path supports them:

| Path | Supported |
| --- | --- |
| `/<path>` | Commands that read files (`ls`, `cat`, `grep`, `find`, `jq` and the rest). `grep` and `rg` ask `mongodb` for the matching lines. `tail` and `wc -l` ask `mongodb` instead of reading a file. |

## Limitations of Unix Commands for VFS

Where a path differs from a local filesystem:

| Path | Limitations |
| --- | --- |
| `/<path>` | Read only: no command changes files. `grep -r`, `find` and `du` stop after 1000 files; a glob matching more, `tar -c`, `cp -r` and `rm -r` are refused. |

Run `man` to list every command, and `man <cmd>` or `<cmd> --help` for one command's usage.

## Integration

What MongoDB answers through its own API, so fewer files are read. [Integration](/home/integration/overview) explains each command.

| Command | On MongoDB |
| --- | --- |
| `grep`, `rg` on one file | A filter on the server sends only the documents that may match |
| `tail -n N` | The last N documents by `_id` |
| `wc -l` | `countDocuments()` on the server |
| `tail -f` | A change stream yields each new insert |

The [Python MongoDB docs](/python/vfs/mongodb#integration) list when each search answers and what it can miss.
