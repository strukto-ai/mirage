`LinearVFS` exposes a Linear workspace as a tree of teams, projects, and issues. Reads route through the Linear GraphQL API.

Setup steps for the API key live at [Linear Credentials](/home/setup/linear).

## Node

```bash
pnpm add @struktoai/mirage-node
```

```ts
import { LinearVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const linear = new LinearVFS({
  apiKey: process.env.LINEAR_API_KEY!,
})

const ws = new Workspace({ '/linear': linear }, { mode: MountMode.READ })
await ws.shell('ls /linear/teams/')
```

## Supported Unix Commands for VFS

Unix commands work on each path as on a local filesystem, as far as the path supports them:

| Path | Supported |
| --- | --- |
| `/<path>` | Commands that read files (`ls`, `cat`, `grep`, `find`, `jq` and the rest). `grep -r` and `rg` use `linear` search. |

## Limitations of Unix Commands for VFS

Where a path differs from a local filesystem:

| Path | Limitations |
| --- | --- |
| `/<path>` | No command changes files. `linear` search covers only `teams/*/issues/*/issue.json`, `teams/*/members/*`, `teams/*/projects/*`, `teams/*/cycles/*` and `teams/*/documents/*`; `grep -r` and `rg` read every other file. `grep -r`, `find` and `du` stop after 1000 files; a glob matching more, `tar -c`, `cp -r` and `rm -r` are refused. |

Run `man` to list every command, and `man <cmd>` or `<cmd> --help` for one command's usage.

## Integration

What Linear answers through its own API, so fewer files are read. [Integration](/home/integration/overview) explains each command.

| Command | On Linear |
| --- | --- |
| `grep -r`, `rg` | Issues: Linear search, for whole words. Other files: the text the listing keeps. It can miss recent issue writes. |

The [Python Linear docs](/python/vfs/linear#integration) list when each search answers and what it can miss.
