`TencentVFS` mounts one bucket: every object becomes a file and every `/` in a key
a folder. It is the [S3 VFS](/typescript/setup/s3) pointed at Tencent COS's
endpoint, so commands behave as they do on S3. Credentials are set up on the
[Tencent COS page](/home/setup/tencent).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { MountMode, TencentVFS, Workspace } from '@struktoai/mirage-node'

const cos = new TencentVFS({
  bucket: process.env.COS_BUCKET!,
  region: process.env.COS_REGION!,
  accessKeyId: process.env.COS_SECRET_ID!,
  secretAccessKey: process.env.COS_SECRET_KEY!,
})
const ws = new Workspace({ '/cos': cos }, { mode: MountMode.WRITE })

const result = await ws.shell("ls /cos && find /cos -name '*.csv'")
console.log(result.stdoutText)
await ws.close()
```

`region` also picks the endpoint, `https://cos.<region>.myqcloud.com`;
`endpoint` replaces it.
A mount takes `MountMode.READ`, `WRITE` or `EXEC`.

## Authentication

Credentials come from the first of:

1. `accessKeyId` and `secretAccessKey`, with `sessionToken` for temporary
   credentials.
2. `profile`, a profile in `~/.aws/credentials`.
3. The AWS SDK credential chain: environment variables, then the instance or
   container role.

`accessKeyId` takes the CAM SecretId and `secretAccessKey` the SecretKey. The
sub-user needs a COS policy: read-only for a read mount, read and write
for a write mount.
An object the key may not read or change answers `Permission denied`.

## Layout

```text
/cos/
  README.md
  logs/
    app-2026-11-15.log
    app-2026-11-16.log
  reports/
    2026-q3.csv
    2026-q4.csv
```

`/cos/reports/2026-q3.csv` is the key `reports/2026-q3.csv`. Folders come
from the `/` in keys.

## Behavior

- **Key prefix:** `keyPrefix: 'users/42/'` mounts only that part of the bucket,
  so `/cos/notes.md` is the key `users/42/notes.md`. A leading `/` is dropped
  and a trailing `/` added.
- **Bucket name:** a COS bucket name ends in the account's APPID, as in
  `my-bucket-1250000000`. `bucket` takes the full name, suffix included.

## Browser

The browser `TencentVFS` from `@struktoai/mirage-browser` keeps the keys off the
page: a server signs a URL for each S3 call with the Tencent COS keys, and the
browser fetches it.

```bash
npm install @struktoai/mirage-browser
```

```ts
import { MountMode, TencentVFS, Workspace } from '@struktoai/mirage-browser'

const cos = new TencentVFS({
  bucket: 'my-bucket-1250000000',
  region: 'ap-guangzhou',
  presignedUrlProvider: async (path, op, opts) => {
    const r = await fetch('/presign', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ path, op, opts }),
    })
    return ((await r.json()) as { url: string }).url
  },
})
const ws = new Workspace({ '/cos': cos }, { mode: MountMode.READ })
```

- Requests go to the host each signed URL names; `region` and `endpoint` only
  name the mount's storage location.
- The bucket's CORS rules must allow the page's origin, exactly as served.
- A browser mount cannot declare `write: conditional`, and any HTTP 403 from a
  signed URL, an expired one included, answers `Permission denied`.
- `keyPrefix` set in the browser is no security boundary: enforce the prefix in
  the signing server and the key's permissions.

```ts
import {
  CopyObjectCommand,
  DeleteObjectCommand,
  GetObjectCommand,
  HeadObjectCommand,
  ListObjectsV2Command,
  PutObjectCommand,
  S3Client,
} from '@aws-sdk/client-s3'
import { getSignedUrl } from '@aws-sdk/s3-request-presigner'

const REGION = process.env.COS_REGION!
const BUCKET = process.env.COS_BUCKET!
const client = new S3Client({
  region: REGION,
  endpoint: `https://cos.${REGION}.myqcloud.com`,
  credentials: {
    accessKeyId: process.env.COS_SECRET_ID!,
    secretAccessKey: process.env.COS_SECRET_KEY!,
  },
})

app.post('/presign', async (req, res) => {
  const { path, op, opts } = req.body as {
    path: string
    op: 'GET' | 'PUT' | 'HEAD' | 'DELETE' | 'LIST' | 'COPY'
    opts?: Record<string, unknown>
  }
  const key = path.replace(/^\/+/, '')
  const ttl = typeof opts?.ttlSec === 'number' ? opts.ttlSec : 300
  let cmd
  switch (op) {
    case 'GET':    cmd = new GetObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'PUT':    cmd = new PutObjectCommand({ Bucket: BUCKET, Key: key, ContentType: opts?.contentType as string | undefined }); break
    case 'HEAD':   cmd = new HeadObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'DELETE': cmd = new DeleteObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'LIST':   cmd = new ListObjectsV2Command({
      Bucket: BUCKET,
      Prefix: opts?.listPrefix as string | undefined,
      Delimiter: opts?.listDelimiter as string | undefined,
      ContinuationToken: opts?.listContinuationToken as string | undefined,
    }); break
    case 'COPY':   cmd = new CopyObjectCommand({
      Bucket: BUCKET,
      Key: key,
      CopySource: `${BUCKET}/${opts?.copySource as string}`,
    }); break
  }
  const url = await getSignedUrl(client, cmd, { expiresIn: ttl })
  res.json({ url })
})
```

Sign only the operations the app needs: a viewer needs `GET`, `HEAD` and `LIST`.

## Integration

Tencent COS answers these commands through its own API, so fewer objects are
read. See [Integration](/home/integration/overview).

- `find`: one recursive listing.
- `du`: one recursive listing.
- `ls -R` and `tree`: one recursive listing.
