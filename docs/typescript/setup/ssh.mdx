`SSHVFS` opens an SFTP session and mounts the remote root as a filesystem.

<Note>
  Node only. Requires the `ssh2` peer dependency. The browser SDK doesn't ship an SSH client.
</Note>

## Install

```bash
pnpm add @struktoai/mirage-node ssh2
```

## Config

```ts
import { MountMode, SSHVFS, Workspace } from '@struktoai/mirage-node'

const ssh = new SSHVFS({
  host: 'jump.example.com',
  username: 'me',
  identityFile: '~/.ssh/id_ed25519',
  root: '/srv/data',
})

const ws = new Workspace({ '/remote': ssh }, { mode: MountMode.READ })
await ws.shell('ls /remote')
```

## Mount mode

`read`, `write`, `exec`. Writes flush via SFTP put. Use `MountMode.EXEC` if `python3` or `js` should run scripts from the mount.

For the full set of supported shell commands see the [Python SSH docs](/python/vfs/ssh).

## Integration

What SSH answers through its own API, so fewer files are read. [Integration](/home/integration/overview) explains each command.

| Command | On SSH |
| --- | --- |
| `grep -r`, `rg` | `grep` on the server, for any text. It misses nothing. |
| `wc -l` | `wc -l` on the server |
| `tail -f` | `tail -f` on the server |
| `md5sum`, `sha256sum` and the other hash commands | The matching sum tool on the server |
| `find`, `du`, `ls -R`, `tree` | One `find` on the server |

The [Python SSH docs](/python/vfs/ssh#integration) list when each search answers and what it can miss.
