`SharePointVFS` shares its file-operation backend with OneDrive. Its additional resolver maps SharePoint sites and document libraries onto the virtual tree.

```ts
import { MountMode, SharePointVFS, Workspace } from '@struktoai/mirage-node'

const sharepoint = new SharePointVFS({
  accessToken: () => getMicrosoftGraphToken(),
  tenantHost: 'contoso.sharepoint.com',
})

const ws = new Workspace({ '/sharepoint': sharepoint }, { mode: MountMode.WRITE })
await ws.shell('ls /sharepoint/')
await ws.shell('ls /sharepoint/Engineering/Documents/')
```

An unscoped mount uses `/site/library/path`. To hide the site and library levels, configure `site` and `drive` together; `keyPrefix` can narrow that drive further.

```ts
new SharePointVFS({
  accessToken,
  site: 'Engineering',
  drive: 'Documents',
  keyPrefix: 'Reports/2026',
})
```

## Integration

What SharePoint answers through its own API, so fewer files are read. [Integration](/home/integration/overview) explains each command.

| Command | On SharePoint |
| --- | --- |
| `grep -r`, `rg` | Microsoft Graph search within one document library, for whole words. It can miss Office files, PDFs, archives, the end of large files, words Graph splits differently (`foo.bar`) and recent writes. |
| `find`, `du`, `ls -R`, `tree` | One recursive listing |

The [Python SharePoint docs](/python/vfs/sharepoint#integration) list when each search answers and what it can miss.
