`SupabaseVFS` mounts one Supabase Storage bucket: every object becomes a file
and every `/` in a key a folder. It reaches Supabase through the Storage S3 API.
Credentials are set up on the [Supabase page](/home/setup/supabase).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { MountMode, SupabaseVFS, Workspace } from '@struktoai/mirage-node'

const supabase = new SupabaseVFS({
  bucket: process.env.SUPABASE_BUCKET!,
  region: process.env.SUPABASE_REGION!,
  projectRef: process.env.SUPABASE_PROJECT_REF!,
  accessKeyId: process.env.SUPABASE_ACCESS_KEY_ID!,
  secretAccessKey: process.env.SUPABASE_SECRET_ACCESS_KEY!,
})
const ws = new Workspace({ '/supabase': supabase }, { mode: MountMode.WRITE })

const result = await ws.shell("ls /supabase && find /supabase -name '*.csv'")
console.log(result.stdoutText)
await ws.close()
```

`projectRef` builds the endpoint
`https://<projectRef>.storage.supabase.co/storage/v1/s3`; `endpoint` replaces
it. `region` is required to sign requests: use the one on the project's Storage
settings page. A mount takes `MountMode.READ`, `WRITE` or `EXEC`.

## Authentication

Credentials come from `accessKeyId` and `secretAccessKey`, a Storage S3 access
key, with `sessionToken` for temporary credentials. Without them, the AWS SDK
reads its own chain: environment variables, `~/.aws/credentials`, then the
instance or container role.

Use an S3 access key, not the project's `anon` or `service_role` key. An S3
access key reaches every bucket in the project and bypasses Row Level Security,
so keep it on a server. A request the credentials may not make answers
`Permission denied`.

## Layout

```text
/supabase/
  data/
    config.json
    file.txt
  reports/
    q1.csv
    q2.csv
```

`/supabase/data/file.txt` is the key `data/file.txt`. Folders come from the `/`
in keys; Supabase stores no folder objects.

## Behavior

- **Key prefix:** `keyPrefix: 'users/42/'` mounts only that part of the bucket,
  so `/supabase/notes.md` is the key `users/42/notes.md`. A leading `/` is
  dropped and a trailing `/` added.
- **Path style:** Supabase takes only path-style URLs, so `forcePathStyle`
  defaults to `true`.

## Browser

The browser `SupabaseVFS` from `@struktoai/mirage-browser` keeps credentials off
the page: a server signs a URL for each S3 call with the Supabase keys, and the
browser fetches it.

```bash
npm install @struktoai/mirage-browser
```

```ts
import { MountMode, SupabaseVFS, Workspace } from '@struktoai/mirage-browser'

const supabase = new SupabaseVFS({
  bucket: 'my-bucket',
  presignedUrlProvider: async (path, op, opts) => {
    const r = await fetch('/presign', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ path, op, opts }),
    })
    return ((await r.json()) as { url: string }).url
  },
})
const ws = new Workspace({ '/supabase': supabase }, { mode: MountMode.READ })
```

- The bucket's CORS rules must allow the page's origin, exactly as served.
- A browser mount cannot declare `write: conditional`, and any HTTP 403 from a
  signed URL, an expired one included, answers `Permission denied`.
- `keyPrefix` set in the browser is no security boundary: enforce the prefix in
  the signing server.
- `projectRef` and `endpoint` only name the mount's storage location: requests
  go to the host each signed URL names.

```ts
import {
  CopyObjectCommand,
  DeleteObjectCommand,
  GetObjectCommand,
  HeadObjectCommand,
  ListObjectsV2Command,
  PutObjectCommand,
  S3Client,
} from '@aws-sdk/client-s3'
import { getSignedUrl } from '@aws-sdk/s3-request-presigner'

const PROJECT_REF = process.env.SUPABASE_PROJECT_REF!
const REGION = process.env.SUPABASE_REGION!

const client = new S3Client({
  region: REGION,
  endpoint: `https://${PROJECT_REF}.storage.supabase.co/storage/v1/s3`,
  forcePathStyle: true,
  credentials: {
    accessKeyId: process.env.SUPABASE_ACCESS_KEY_ID!,
    secretAccessKey: process.env.SUPABASE_SECRET_ACCESS_KEY!,
  },
})
const BUCKET = process.env.SUPABASE_BUCKET!

app.post('/presign', async (req, res) => {
  const { path, op, opts } = req.body as {
    path: string
    op: 'GET' | 'PUT' | 'HEAD' | 'DELETE' | 'LIST' | 'COPY'
    opts?: Record<string, unknown>
  }
  const key = path.replace(/^\/+/, '')
  const ttl = typeof opts?.ttlSec === 'number' ? opts.ttlSec : 300
  let cmd
  switch (op) {
    case 'GET':    cmd = new GetObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'PUT':    cmd = new PutObjectCommand({ Bucket: BUCKET, Key: key, ContentType: opts?.contentType as string | undefined }); break
    case 'HEAD':   cmd = new HeadObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'DELETE': cmd = new DeleteObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'LIST':   cmd = new ListObjectsV2Command({
      Bucket: BUCKET,
      Prefix: opts?.listPrefix as string | undefined,
      Delimiter: opts?.listDelimiter as string | undefined,
      ContinuationToken: opts?.listContinuationToken as string | undefined,
    }); break
    case 'COPY':   cmd = new CopyObjectCommand({
      Bucket: BUCKET,
      Key: key,
      CopySource: `${BUCKET}/${opts?.copySource as string}`,
    }); break
  }
  const url = await getSignedUrl(client, cmd, { expiresIn: ttl })
  res.json({ url })
})
```

Sign only the operations the app needs: a viewer needs `GET`, `HEAD` and `LIST`.

Supabase Storage's S3 API follows the bucket's CORS configuration, set in the
Supabase dashboard under the project's **Storage** > **Settings**:

1. Add the page's origins, such as `http://localhost:5173`.
2. Allow the methods `GET, PUT, HEAD, DELETE, POST` and the headers `*`.
3. Expose the headers `ETag, Content-Length, Content-Type, Last-Modified`.

## Integration

Supabase answers these commands through its own API, so fewer objects are read.
See [Integration](/home/integration/overview).

- `find`: one recursive listing.
- `du`: one recursive listing.
- `ls -R` and `tree`: one recursive listing.
