`SeaweedFSVFS` mounts one bucket on a SeaweedFS S3 gateway: every object becomes
a file and every `/` in a key a folder. It reaches the gateway (port `8333` by
default) through its S3 API. Create the bucket and credentials as in [SeaweedFS setup](/home/setup/seaweedfs).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { MountMode, SeaweedFSVFS, Workspace } from '@struktoai/mirage-node'

const seaweedfs = new SeaweedFSVFS({
  bucket: process.env.SEAWEEDFS_BUCKET!,
  endpoint: process.env.SEAWEEDFS_ENDPOINT!,
  accessKeyId: process.env.SEAWEEDFS_ACCESS_KEY!,
  secretAccessKey: process.env.SEAWEEDFS_SECRET_KEY!,
})
const ws = new Workspace({ '/seaweedfs': seaweedfs }, { mode: MountMode.WRITE })

const result = await ws.shell("ls /seaweedfs && find /seaweedfs -name '*.csv'")
console.log(result.stdoutText)
await ws.close()
```

`endpoint` is required, since the server is self-hosted. `region` defaults to
`us-east-1`. A mount takes `MountMode.READ`, `WRITE` or `EXEC`.

## Authentication

Credentials come from `accessKeyId` and `secretAccessKey`, an identity's key
pair from the gateway's S3 config, with `sessionToken` for temporary
credentials. Without them, the AWS SDK reads its own chain: environment
variables, `~/.aws/credentials`, then the instance or container role.

The identity needs the `Read` and `List` actions on the bucket, and `Write` to
write. A gateway with no identities accepts any key pair. A request the
credentials may not make answers `Permission denied`.

## Layout

```text
/seaweedfs/
  data/
    config.json
    file.txt
  reports/
    q1.csv
    q2.csv
```

`/seaweedfs/data/file.txt` is the key `data/file.txt`. Folders come from the `/`
in keys; SeaweedFS stores no folder objects.

## Behavior

- **Key prefix:** `keyPrefix: 'users/42/'` mounts only that part of the bucket,
  so `/seaweedfs/notes.md` is the key `users/42/notes.md`.
- **Blaxel Agent Drive:** a drive is backed by SeaweedFS. Set `endpoint` to the
  drive's `s3Url` and use a drive access token's credentials as the key pair.

## Browser

The browser `SeaweedFSVFS` from `@struktoai/mirage-browser` keeps credentials
off the page: a server signs a URL for each S3 call with the SeaweedFS keys, and
the browser fetches it.

```bash
npm install @struktoai/mirage-browser
```

```ts
import { MountMode, SeaweedFSVFS, Workspace } from '@struktoai/mirage-browser'

const seaweedfs = new SeaweedFSVFS({
  bucket: 'my-bucket',
  presignedUrlProvider: async (path, op, opts) => {
    const r = await fetch('/presign', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ path, op, opts }),
    })
    return ((await r.json()) as { url: string }).url
  },
})
const ws = new Workspace({ '/seaweedfs': seaweedfs }, { mode: MountMode.READ })
```

- The gateway's CORS rules must allow the page's origin, exactly as served.
- A browser mount cannot declare `write: conditional`, and any HTTP 403 from a
  signed URL, an expired one included, answers `Permission denied`.
- `keyPrefix` set in the browser is no security boundary: enforce the prefix in
  the signing server.
- `endpoint` only names the mount's storage location: requests go to the host
  each signed URL names.

An Express route that signs URLs:

```ts
import {
  CopyObjectCommand,
  DeleteObjectCommand,
  GetObjectCommand,
  HeadObjectCommand,
  ListObjectsV2Command,
  PutObjectCommand,
  S3Client,
} from '@aws-sdk/client-s3'
import { getSignedUrl } from '@aws-sdk/s3-request-presigner'

const client = new S3Client({
  region: 'us-east-1',
  endpoint: process.env.SEAWEEDFS_ENDPOINT,
  forcePathStyle: true,
  credentials: {
    accessKeyId: process.env.SEAWEEDFS_ACCESS_KEY!,
    secretAccessKey: process.env.SEAWEEDFS_SECRET_KEY!,
  },
})
const BUCKET = process.env.SEAWEEDFS_BUCKET!

app.post('/presign', async (req, res) => {
  const { path, op, opts } = req.body as {
    path: string
    op: 'GET' | 'PUT' | 'HEAD' | 'DELETE' | 'LIST' | 'COPY'
    opts?: Record<string, unknown>
  }
  const key = path.replace(/^\/+/, '')
  const ttl = typeof opts?.ttlSec === 'number' ? opts.ttlSec : 300
  let cmd
  switch (op) {
    case 'GET':    cmd = new GetObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'PUT':    cmd = new PutObjectCommand({ Bucket: BUCKET, Key: key, ContentType: opts?.contentType as string | undefined }); break
    case 'HEAD':   cmd = new HeadObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'DELETE': cmd = new DeleteObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'LIST':   cmd = new ListObjectsV2Command({
      Bucket: BUCKET,
      Prefix: opts?.listPrefix as string | undefined,
      Delimiter: opts?.listDelimiter as string | undefined,
      ContinuationToken: opts?.listContinuationToken as string | undefined,
    }); break
    case 'COPY':   cmd = new CopyObjectCommand({
      Bucket: BUCKET,
      Key: key,
      CopySource: `${BUCKET}/${opts?.copySource as string}`,
    }); break
  }
  const url = await getSignedUrl(client, cmd, { expiresIn: ttl })
  res.json({ url })
})
```

Sign only the operations the app needs: a viewer needs `GET`, `HEAD` and `LIST`.

## Integration

SeaweedFS answers these commands through its own API, so fewer objects are read.
See [Integration](/home/integration/overview).

- `find`: one recursive listing.
- `du`: one recursive listing.
- `ls -R` and `tree`: one recursive listing.
