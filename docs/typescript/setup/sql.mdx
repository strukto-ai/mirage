`SqlVFS` keeps a filesystem in a database's tables: a SQLite file, a Postgres
server, a Durable Object's storage or a D1 database.

## Install

```bash
pnpm add @struktoai/mirage-node
```

## Config

```ts
import { MountMode, SqlVFS, Workspace } from '@struktoai/mirage-node'

const sql = new SqlVFS({ path: './workspace.db' })

const ws = new Workspace({ '/sql': sql }, { mode: MountMode.WRITE })
await ws.shell('echo "hello" | tee /sql/greet')
await ws.shell('cat /sql/greet')
```

| Field | Default | Notes |
| --- | --- | --- |
| `path` | `:memory:` | The SQLite file, opened and closed with the mount. |
| `driver` | none | A database to borrow instead of a file; you close it. |
| `capacity` | none | The most bytes the files may hold, like `100MB`. |

To mount Postgres, install `pg` and pass its driver:

```ts
import { PostgresSqlDriver, SqlVFS } from '@struktoai/mirage-node'

const driver = new PostgresSqlDriver('postgres://user:pass@localhost:5432/app')
const sql = new SqlVFS({ driver })
```

The tables are [AgentFS](https://github.com/tursodatabase/agentfs)'s, so a
database AgentFS made mounts here and AgentFS reads one this mount made:

- `fs_inode`: one row per file and directory, with its mode, owner, size and times
- `fs_dentry`: each entry's name under its parent directory
- `fs_data`: a file's bytes, in rows of the database's chunk size (4 KiB unless the database says otherwise)
- `fs_symlink` and `fs_config`: link targets, and the chunk size and schema version

One database holds one filesystem. The Python mount reads and writes the same
tables, so the two runtimes on one file serve one filesystem.
