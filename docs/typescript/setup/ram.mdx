`RAMVFS` keeps files in process memory, for scratch work, tests and trying
Mirage. The mount starts empty and its files are gone when the process exits.
It needs no service and no credentials; see the [RAM page](/home/setup/ram).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { MountMode, RAMVFS, Workspace } from '@struktoai/mirage-node'

const ws = new Workspace({ '/data': new RAMVFS() }, { mode: MountMode.WRITE })

const result = await ws.shell('echo hello > /data/note.txt && cat /data/note.txt')
console.log(result.stdoutText)
```

`new RAMVFS()` takes no config. `new RAMVFS({ capacity: '100MB' })` caps the
bytes the store holds; a write past it fails with "Disk quota exceeded". See
[capacity](/home/setup/vfs#mount-capacity).

## Layout

```text
/data/
  note.txt
  reports/
    status.json
```

The mount starts empty. Files and folders exist once a command such as
`touch`, `mkdir`, `tee` or `cp` writes them. The root `/` always exists.

## Browser

`@struktoai/mirage-browser` exports the same `RAMVFS`, with the same options.

```bash
npm install @struktoai/mirage-browser
```

```ts
import { MountMode, RAMVFS, Workspace } from '@struktoai/mirage-browser'

const ws = new Workspace({ '/data': new RAMVFS() }, { mode: MountMode.WRITE })
```

## Integration

RAM answers these commands from its own tree, so fewer files are read. See
[Integration](/home/integration/overview).

- `find`: one recursive listing.
- `du`: one recursive listing.
- `ls -R` and `tree`: one recursive listing.
