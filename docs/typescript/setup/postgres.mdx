`PostgresVFS` connects to Postgres via a DSN and exposes its schemas and tables as a tree.

Setup steps for the DSN and required permissions live at [Postgres Credentials](/home/setup/postgres).

## Node

```bash
pnpm add @struktoai/mirage-node pg
```

```ts
import { MountMode, PostgresVFS, Workspace } from '@struktoai/mirage-node'

const pg = new PostgresVFS({
  dsn: process.env.DATABASE_URL!,
  schemas: ['public', 'analytics'],
})

const ws = new Workspace({ '/pg': pg }, { mode: MountMode.READ })
try {
  const result = await ws.shell('ls /pg/public/')
  console.log(result.stdoutText)
} finally {
  await ws.close()
}
```

## Browser

```bash
pnpm add @struktoai/mirage-browser
```

The default browser driver uses Neon's HTTP transport. Replace the connection
string below with one for a read-only demo role on Neon. Browser users can inspect
this credential. Keep private database credentials in a Node backend.

```ts
import { MountMode, PostgresVFS, Workspace } from '@struktoai/mirage-browser'

const pg = new PostgresVFS({
  dsn: 'postgresql://mirage_reader:password@your-endpoint.neon.tech/app?sslmode=require',
  schemas: ['public'],
})
const ws = new Workspace({ '/pg': pg }, { mode: MountMode.READ })

try {
  const result = await ws.shell('ls /pg/public/')
  console.log(result.stdoutText)
} finally {
  await ws.close()
}
```

| <code style={{ whiteSpace: 'nowrap' }}>dsn</code><br />required, secret | Postgres connection string. The default browser driver connects over Neon's HTTP transport, so a browser mount needs a Neon connection string. |

| <code style={{ whiteSpace: 'nowrap' }}>defaultRowLimit</code><br />default `1000` | Rows a windowed read returns when it passes an offset but no limit, and the rows one page of a streamed `rows.jsonl` fetches. |
| <code style={{ whiteSpace: 'nowrap' }}>maxReadRows</code><br />default `10000` | Most rows one read returns. A whole read past it is refused, and so is a `head -n` / `tail -n` count past it on a table that long (`File too large`); `wc -l` counts past it. |
| <code style={{ whiteSpace: 'nowrap' }}>maxReadBytes</code><br />default `10485760` (10 MiB) | Most bytes of `rows.jsonl` one read returns; a whole read past it is refused (`File too large`). |
| <code style={{ whiteSpace: 'nowrap' }}>fullScanLimit</code><br />default `1000` | Most files one command walks under a folder: `grep -r`, `find` and other walks stop there, and a larger glob, `tar -c`, `cp -r` or `rm -r` is refused. `-1` lifts the limit. |

## Mount mode

`read` only. Postgres mounts are read-only at the VFS level.

## Snapshot behavior

The DSN is redacted on snapshot. Hand the mount back at load (the third argument of `Workspace.load`, or a config over the server and CLI).

## Integration

What PostgreSQL answers through its own API, so fewer files are read, and the most files one command reads. [Integration](/home/integration/overview) explains each command.

| Command | On PostgreSQL |
| --- | --- |
| `grep`, `rg` on one file | `LIKE` (`ILIKE` for `-i`) fetches only the rows that may match |
| Full scan | `grep -r`, `find`, `du` and other walks stop after [`fullScanLimit`](/home/integration/search#full_scan_limit) files (default 1000); a glob matching more, `tar -c`, `cp -r` and `rm -r` are refused. `-1` for no limit |
| `head -n N` | `LIMIT N` |
| `tail -n N` | The last N rows by one query |
| `wc -l` | `COUNT(*)` |
| `tail -f` | Polls for rows past the last key, on a table with a primary key |

The [Python PostgreSQL docs](/python/vfs/postgres#integration) list when each search answers and what it can miss.
