`GoogleDriveVFS` mounts a Google Drive account: every folder becomes a
directory, every file a file, and Docs, Sheets and Slides read as JSON. My
Drive and every Shared Drive the account can see are included. Credentials are
set up on the [Google Workspace page](/home/setup/google).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { GoogleDriveVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const drive = new GoogleDriveVFS({
  clientId: process.env.GOOGLE_CLIENT_ID!,
  clientSecret: process.env.GOOGLE_CLIENT_SECRET!,
  refreshToken: process.env.GOOGLE_REFRESH_TOKEN!,
})
const ws = new Workspace({ '/gdrive': drive }, { mode: MountMode.WRITE })

const result = await ws.shell("ls /gdrive && find /gdrive -maxdepth 2 -name '*.gsheet.json'")
console.log(result.stdoutText)
```

`folderId` mounts one folder instead of the whole Drive. A mount takes
`MountMode.READ`, `WRITE` or `EXEC`; `EXEC` lets `python3` and `js` run
scripts from the mount.

## Authentication

Credentials come from the first of:

1. `accessToken`, a token or a function, sync or async, that returns one.
2. `clientId` and `refreshToken`, with `clientSecret` unless the client uses
   PKCE. Mirage trades the refresh token for access tokens on its own, or
   hands it to `refreshFn` when set, so the secret can stay on a backend.

The mount needs the Drive API and the `https://www.googleapis.com/auth/drive`
scope, or `drive.readonly` for a read-only mount. Drive grants access per
item, so a write mount can still hold files the account may not change. A
change Drive refuses fails with `Permission denied` on that operand, and the
rest of the mount keeps working.

## Layout

```text
/gdrive/
  Projects/
    roadmap.gsheet.json
    spec.pdf
  Notes/
    meeting.gdoc.json
  Engineering/
    ...
```

- The root holds My Drive's folders and files plus one folder per Shared
  Drive. A Shared Drive whose name clashes gets a `[Shared Drive]` suffix and,
  if needed, a number.
- Regular files (PDFs, images, CSVs) keep their names and read as their
  bytes.
- Docs, Sheets and Slides cannot be downloaded as bytes, so they read as the
  JSON of their own API: `.gdoc.json`, `.gsheet.json` and `.gslide.json`.

## Behavior

- **Folder scope:** `folderId: '1AbCdEf...'` makes that folder the mount
  root. It may sit in My Drive, be shared with the account, sit in a Shared
  Drive, or be a Shared Drive's id. A scoped mount shows no other Shared
  Drive.
- **Writes:** on a `write` mount, `tee`, `cp`, `mv`, `rm`, `mkdir`, `rmdir`,
  `touch`, `truncate` and `sed -i` work on regular files and folders.
  `mkdir` over an existing name fails with `File exists`, `mv` onto a
  non-empty directory with `Directory not empty`, and `cp -r` merges. `rm`
  deletes for good, not to the trash.
- **Docs, Sheets and Slides:** read only as bytes; a write to one fails with
  `Permission denied`. Change them with the [`gws`](/typescript/cli/gws) CLI,
  which also acts on any Drive item by id.
- **Shared Drives:** writable on the same terms as My Drive. The account's
  role on that drive decides what it may change, and some organizations
  restrict deleting or moving content out of a drive. `MountMode.READ` makes
  a mount that cannot write at all.

## Browser

The same `GoogleDriveVFS` comes from `@struktoai/mirage-browser`. In a page, an
`accessToken` function fetches a fresh token from a backend, so the client
secret never reaches the browser.

```bash
npm install @struktoai/mirage-browser
```

```ts
import { GoogleDriveVFS, MountMode, Workspace } from '@struktoai/mirage-browser'

const drive = new GoogleDriveVFS({
  accessToken: async () => (await fetch('/api/google-token')).text(),
})
const ws = new Workspace({ '/gdrive': drive }, { mode: MountMode.READ })
```

- `/api/google-token` stands for a backend endpoint that returns an access
  token.
- A PKCE OAuth client needs no secret: `clientId` and `refreshToken` alone
  mount it. `examples/browser/vfs/gdrive/gdrive_pkce.ts` shows the sign-in
  flow.
- `refreshFn` sends each refresh to a backend instead of Google's token
  endpoint.

## Integration

Drive answers these commands through its own API, so fewer files are read.
See [Integration](/home/integration/overview).

- `grep -r` and `rg` with `-w` or `-x`: Drive full-text search names the
  files to read. Every file is read when the search fails or finds nothing.
  Drive searches the text it extracted, not the bytes `grep` reads, and
  indexes a write some time after it lands, so it can leave out a file that
  holds the word: a Docs, Sheets or Slides file (its JSON keys and ids), an
  office file, PDF or archive, the end of a large file, or a word Drive
  splits differently (`foo.bar`). `walkLimit: -1` in the mount's `"@all"`
  [command limit](/home/core/output-limits) turns the search off and reads
  every file.
- `md5sum`, `sha1sum` and `sha256sum`: the digest Drive keeps. A Docs, Sheets
  or Slides file is read.
- `find`, `du`, `ls -R` and `tree`: one recursive listing.
