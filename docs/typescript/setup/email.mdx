`EmailVFS` reads the mailbox over IMAP as a tree of folders and messages. The [himalaya CLI](/typescript/cli/himalaya) sends mail.

<Note>
  Node only. Requires `imapflow`, `mailparser`, and `nodemailer` peers. The browser cannot speak raw TCP for IMAP/SMTP.
</Note>

## Install

```bash
pnpm add @struktoai/mirage-node imapflow mailparser nodemailer
```

## Config

```ts
import { EmailVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const email = new EmailVFS({
  imapHost: 'imap.example.com',
  smtpHost: 'smtp.example.com',
  username: process.env.EMAIL_USERNAME!,
  password: process.env.EMAIL_PASSWORD!,
})

const ws = new Workspace({ '/mail': email }, { mode: MountMode.READ })
await ws.shell('ls /mail/INBOX/')
```

    Unix commands work on each path as on a local filesystem, as far as the path supports them:

## Integration

What Email answers through its own API, so fewer files are read. [Integration](/home/integration/overview) explains each command.

| Command | On Email |
| --- | --- |
| `grep -r`, `rg` | IMAP `SEARCH TEXT`, for any text. It can miss on a server that searches words rather than substrings (Dovecot with full-text search). |

The [Python Email docs](/python/vfs/email#integration) list when each search answers and what it can miss.

## Mount mode

`read`. Send mail through the [himalaya CLI](/typescript/cli/himalaya).

For mailbox layout, search behavior, and synthesized date directories see the [Python Email docs](/python/vfs/email).
