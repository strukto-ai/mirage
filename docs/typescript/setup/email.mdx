`EmailVFS` mounts an IMAP mailbox as read-only files: each folder holds one
folder per day of messages as JSON, with their attachments. The
[`himalaya`](/typescript/cli/himalaya) CLI sends mail over SMTP. Set up the credentials as in [Email setup](/home/setup/email).

## Install

```bash
npm install @struktoai/mirage-node imapflow mailparser nodemailer
```

`imapflow`, `mailparser` and `nodemailer` are peer packages. The class ships
in `@struktoai/mirage-node` only: a browser cannot open the raw TCP
connections IMAP and SMTP need.

## Configure

```ts
import { EmailVFS, MountMode, Workspace } from '@struktoai/mirage-node'

const email = new EmailVFS({
  imapHost: process.env.IMAP_HOST!,
  smtpHost: process.env.SMTP_HOST!,
  username: process.env.EMAIL_USERNAME!,
  password: process.env.EMAIL_PASSWORD!,
})
const ws = new Workspace({ '/email': email }, { mode: MountMode.READ })

const result = await ws.shell('ls /email && rg -l quarterly /email/INBOX')
console.log(result.stdoutText)
await ws.close()
```

`imapPort` (993) and `smtpPort` (587) change the ports, and `maxMessages` how
many messages each folder lists. `saveCopy`, `sentFolder` and `trashFolder`
shape what `himalaya` does after a send or delete.

## Authentication

The mount logs in to IMAP with `username` and `password`; sending through
`himalaya` uses the same pair on SMTP. Most providers want an app password
instead of the account password. Microsoft 365 is unsupported: it requires
OAuth for IMAP, and the mount accepts only passwords.

| Provider | IMAP host | SMTP host | Notes |
| --- | --- | --- | --- |
| Yahoo | `imap.mail.yahoo.com` | `smtp.mail.yahoo.com` | App password |
| Fastmail | `imap.fastmail.com` | `smtp.fastmail.com` | App password |
| iCloud | `imap.mail.me.com` | `smtp.mail.me.com` | App password |
| ProtonMail | `127.0.0.1` | `127.0.0.1` | Proton Mail Bridge |
| Self-hosted | the server's hostname | the server's hostname | The server's own login |

## Layout

```text
/email/
  INBOX/
    2026-11-16/
      Meeting_Notes__12345.email.json
      Meeting_Notes__12345/
        report.pdf
        screenshot.png
  Sent/
    2026-11-16/
      ...
```

- **Folders:** the root lists the IMAP folders under their own names
  (`INBOX`, `Sent`, `Drafts`).
- **Days:** inside a folder, messages are grouped by the `YYYY-MM-DD` of their
  `Date` header.
- **Messages:** each message is `<subject>__<uid>.email.json`, with a
  sanitized subject, so `ls` the day rather than build the name. The UID
  after `__` is what `himalaya` takes.
- **Attachments:** a message with attachments gets a folder of the same base
  name holding them.

## Behavior

- **Read only:** the mount cannot send or change mail. Use the
  [`himalaya`](/typescript/cli/himalaya) CLI, which uses the SMTP settings, to
  list, read, send, reply and forward.
- **Newest messages:** each folder lists its newest `maxMessages` messages
  (200).
- **TLS:** IMAP speaks TLS from the first byte (IMAPS) by default. `useSsl: false`
  connects in plaintext with no STARTTLS upgrade. SMTP follows its port.

## Integration

The IMAP server answers this command, so fewer messages are read. See
[Integration](/home/integration/overview).

- `grep -r` and `rg`: IMAP `SEARCH TEXT` names the messages to read in each
  folder or day they walk (from the mount root, in every folder), and the
  output matches reading every message. IMAP matches headers and body in any
  case. Attachments are always read. Every message is read when the text is a
  key of the message JSON or a flag name, holds anything but ASCII letters and
  spaces, matches more than `maxMessages` messages in a folder, or the search
  fails. A server that answers `SEARCH` from a full-text index (Dovecot with
  an FTS plugin, for one) matches words rather than substrings, so a narrowed
  scan can miss a message there; `walk_limit: -1` in the mount's `"@all"`
  [command limit](/home/limits#command-output) reads every file instead.
