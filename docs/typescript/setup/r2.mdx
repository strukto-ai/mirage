`R2VFS` mounts one Cloudflare R2 bucket: every object becomes a file and every
`/` in a key a folder. It reaches R2 through its S3-compatible API at
`https://<accountId>.r2.cloudflarestorage.com`. Credentials are set up on the
[R2 page](/home/setup/r2).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { MountMode, R2VFS, Workspace } from '@struktoai/mirage-node'

const r2 = new R2VFS({
  bucket: process.env.R2_BUCKET!,
  accountId: process.env.R2_ACCOUNT_ID!,
  accessKeyId: process.env.R2_ACCESS_KEY_ID!,
  secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
})
const ws = new Workspace({ '/r2': r2 }, { mode: MountMode.WRITE })

const result = await ws.shell("ls /r2 && find /r2 -name '*.csv'")
console.log(result.stdoutText)
```

A bucket in a jurisdiction has its own endpoint, such as
`https://<accountId>.eu.r2.cloudflarestorage.com`; set `endpoint` to it. A mount
takes `MountMode.READ`, `WRITE` or `EXEC`.

## Authentication

Credentials come from `accessKeyId` and `secretAccessKey`, an R2 API token's key
pair, with `sessionToken` for temporary credentials. Without them, the AWS SDK
reads its own chain: environment variables, `~/.aws/credentials`, then the
instance or container role.

The token needs **Object Read only** on the bucket, or **Object Read & Write**
to write. A request the credentials may not make answers `Permission denied`.

## Layout

```text
/r2/
  data/
    config.json
    file.txt
  reports/
    q1.csv
    q2.csv
```

`/r2/data/file.txt` is the key `data/file.txt`. Folders come from the `/` in
keys; R2 stores no folder objects.

## Behavior

- **Key prefix:** `keyPrefix: 'users/42/'` mounts only that part of the bucket,
  so `/r2/notes.md` is the key `users/42/notes.md`. A leading `/` is dropped and
  a trailing `/` added.

## Browser

The browser `R2VFS` from `@struktoai/mirage-browser` keeps credentials off the
page: a server signs a URL for each S3 call with the R2 keys, and the browser
fetches it.

```bash
npm install @struktoai/mirage-browser
```

```ts
import { MountMode, R2VFS, Workspace } from '@struktoai/mirage-browser'

const r2 = new R2VFS({
  bucket: 'my-bucket',
  presignedUrlProvider: async (path, op, opts) => {
    const r = await fetch('/presign', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ path, op, opts }),
    })
    return ((await r.json()) as { url: string }).url
  },
})
const ws = new Workspace({ '/r2': r2 }, { mode: MountMode.READ })
```

- The bucket's CORS rules must allow the page's origin, exactly as served.
- A browser mount cannot declare `write: conditional`, and any HTTP 403 from a
  signed URL, an expired one included, answers `Permission denied`.
- `keyPrefix` set in the browser is no security boundary: enforce the prefix in
  the signing server.
- `accountId` and `endpoint` only name the mount's storage location: requests go
  to the host each signed URL names.

```ts
import {
  CopyObjectCommand,
  DeleteObjectCommand,
  GetObjectCommand,
  HeadObjectCommand,
  ListObjectsV2Command,
  PutObjectCommand,
  S3Client,
} from '@aws-sdk/client-s3'
import { getSignedUrl } from '@aws-sdk/s3-request-presigner'

const client = new S3Client({
  region: 'auto',
  endpoint: `https://${process.env.R2_ACCOUNT_ID}.r2.cloudflarestorage.com`,
  credentials: {
    accessKeyId: process.env.R2_ACCESS_KEY_ID!,
    secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
  },
})
const BUCKET = process.env.R2_BUCKET!

app.post('/presign', async (req, res) => {
  const { path, op, opts } = req.body as {
    path: string
    op: 'GET' | 'PUT' | 'HEAD' | 'DELETE' | 'LIST' | 'COPY'
    opts?: Record<string, unknown>
  }
  const key = path.replace(/^\/+/, '')
  const ttl = typeof opts?.ttlSec === 'number' ? opts.ttlSec : 300
  let cmd
  switch (op) {
    case 'GET':    cmd = new GetObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'PUT':    cmd = new PutObjectCommand({ Bucket: BUCKET, Key: key, ContentType: opts?.contentType as string | undefined }); break
    case 'HEAD':   cmd = new HeadObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'DELETE': cmd = new DeleteObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'LIST':   cmd = new ListObjectsV2Command({
      Bucket: BUCKET,
      Prefix: opts?.listPrefix as string | undefined,
      Delimiter: opts?.listDelimiter as string | undefined,
      ContinuationToken: opts?.listContinuationToken as string | undefined,
    }); break
    case 'COPY':   cmd = new CopyObjectCommand({
      Bucket: BUCKET,
      Key: key,
      CopySource: `${BUCKET}/${opts?.copySource as string}`,
    }); break
  }
  const url = await getSignedUrl(client, cmd, { expiresIn: ttl })
  res.json({ url })
})
```

Sign only the operations the app needs: a viewer needs `GET`, `HEAD` and `LIST`.

  <Accordion title="Bucket CORS rules">

R2 accepts the S3 CORS call only from a token with **Admin Read & Write** on the
bucket; an object token gets `Access Denied`. Without one, set the policy in the
[Cloudflare dashboard](https://dash.cloudflare.com/): **R2**, the bucket,
**Settings** > **CORS Policy**, with the page's origins, methods
`GET,PUT,HEAD,DELETE,POST` and allowed headers `*`. With an admin token:

```json
{
  "CORSRules": [
    {
      "AllowedOrigins": ["http://localhost:5173", "https://app.example.com"],
      "AllowedMethods": ["GET", "PUT", "HEAD", "DELETE", "POST"],
      "AllowedHeaders": ["*"],
      "ExposeHeaders": ["ETag", "Content-Length", "Content-Type", "Last-Modified"]
    }
  ]
}
```

```bash
aws s3api put-bucket-cors --bucket $R2_BUCKET \

  --cors-configuration file://cors.json
```

## Integration

R2 answers these commands through its own API, so fewer objects are read. See
[Integration](/home/integration/overview).

- `md5sum`: the object's ETag, when it is the MD5 (a single-part upload,
  unencrypted or under SSE-S3).
- `find`: one recursive listing.
- `du`: one recursive listing.
- `ls -R` and `tree`: one recursive listing.
