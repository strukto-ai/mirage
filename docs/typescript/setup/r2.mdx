R2 uses the S3 API with AWS Signature V4 against `https://<account-id>.r2.cloudflarestorage.com`. MIRAGE derives this endpoint from your account ID automatically.

Credentials (R2 API token with object read/write scopes) are created the same way in both runtimes, see [R2 Credentials](/home/setup/r2).

## Node (server-side)

```bash
pnpm add @struktoai/mirage-node
```

```ts
import { MountMode, R2VFS, Workspace } from '@struktoai/mirage-node'

const r2 = new R2VFS({
  bucket: process.env.R2_BUCKET!,
  accountId: process.env.R2_ACCOUNT_ID!,
  accessKeyId: process.env.R2_ACCESS_KEY_ID!,
  secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
})

const ws = new Workspace({ '/bucket/': r2 }, { mode: MountMode.READ })
const res = await ws.shell('ls /bucket/')
console.log(res.stdoutText)
```

### Config

{/* generated: config-table r2 start */}
| Field | Required | Default | Description |
| --- | --- | --- | --- |
| `bucket` | yes |  | Name of the bucket to mount. |
| `accessKeyId` | no |  | Access key ID, used only together with `secretAccessKey`. Unset falls back to the AWS SDK credential chain: `profile`, the environment, the shared credentials file, then an instance role. Redacted in snapshots. |
| `secretAccessKey` | no |  | Secret access key paired with `accessKeyId`. Redacted in snapshots. |
| `sessionToken` | no |  | Session token for temporary credentials, sent with the access key pair. Redacted in snapshots. |
| `profile` | no |  | Named profile in the shared AWS config and credentials files that supplies credentials when no access key pair is given. |
| `forcePathStyle` | no |  | Address the bucket in the URL path (`<endpoint>/<bucket>/<key>`) instead of as a subdomain of the endpoint. |
| `keyPrefix` | no |  | Key prefix inside the bucket that the mount treats as its root; keys outside it are not visible. Leading slashes are dropped and a trailing `/` is added. |
| `timeoutMs` | no |  | Milliseconds to wait to connect, and for each read of a response, before the request fails. Unset leaves the AWS SDK's own timeouts. |
| `proxy` | no |  | Proxy URL for every HTTP and HTTPS request to the endpoint. Redacted in snapshots. |
| `region` | no | `'auto'` | Region requests are signed for; R2 addresses a bucket by account, not by region. |
| `endpoint` | no |  | Endpoint URL that replaces the one the provider derives. |
| `accountId` | no |  | Cloudflare account ID. It builds the endpoint `https://<accountId>.r2.cloudflarestorage.com` unless `endpoint` is set; one of the two is required. |
{/* generated: config-table r2 end */}

## Browser (presigned URLs)

```bash
pnpm add @struktoai/mirage-browser
```

The browser `R2VFS` is secret-free, your backend signs each operation using your R2 keys and returns a URL. R2 accepts AWS Signature V4, so `@aws-sdk/s3-request-presigner` works with `region: 'auto'` pointed at R2's endpoint.

### Config

{/* generated: config-table browser/r2 start */}
| Field | Required | Default | Description |
| --- | --- | --- | --- |
| `bucket` | yes |  | Name of the bucket to mount. |
| `presignedUrlProvider` | yes |  | Function `(path, operation, options)` that returns a signed URL for one S3 operation (`GET`, `PUT`, `HEAD`, `DELETE`, `LIST` or `COPY`). Your server signs it with the provider's keys, so the browser holds none. Redacted in snapshots. |
| `region` | no | `'auto'` | Region of the bucket; R2 addresses a bucket by account, not by region. |
| `endpoint` | no |  | Endpoint URL that replaces the one the provider derives. Requests go to the host each presigned URL names; the mount uses it to name its storage location. |
| `defaultContentType` | no | `'application/octet-stream'` | `Content-Type` stored with every object the mount writes. |
| `keyPrefix` | no |  | Key prefix inside the bucket that the mount treats as its root; keys outside it are not visible. Leading slashes are dropped and a trailing `/` is added. The browser can change it before a URL is signed, so enforce the prefix on the signing server. |
| `accountId` | no |  | Cloudflare account ID. It builds the endpoint `https://<accountId>.r2.cloudflarestorage.com` unless `endpoint` is set. |
{/* generated: config-table browser/r2 end */}

### 1. Server: sign URLs with the R2 endpoint

```ts
import {
  CopyObjectCommand,
  DeleteObjectCommand,
  GetObjectCommand,
  HeadObjectCommand,
  ListObjectsV2Command,
  PutObjectCommand,
  S3Client,
} from '@aws-sdk/client-s3'
import { getSignedUrl } from '@aws-sdk/s3-request-presigner'

const client = new S3Client({
  region: 'auto',
  endpoint: `https://${process.env.R2_ACCOUNT_ID}.r2.cloudflarestorage.com`,
  credentials: {
    accessKeyId: process.env.R2_ACCESS_KEY_ID!,
    secretAccessKey: process.env.R2_SECRET_ACCESS_KEY!,
  },
})
const BUCKET = process.env.R2_BUCKET!

app.post('/presign/r2', async (req, res) => {
  const { path, op, opts } = req.body
  const key = path.replace(/^\/+/, '')
  const ttl = typeof opts?.ttlSec === 'number' ? opts.ttlSec : 300
  let cmd
  switch (op) {
    case 'GET':    cmd = new GetObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'PUT':    cmd = new PutObjectCommand({ Bucket: BUCKET, Key: key, ContentType: opts?.contentType }); break
    case 'HEAD':   cmd = new HeadObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'DELETE': cmd = new DeleteObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'LIST':   cmd = new ListObjectsV2Command({
      Bucket: BUCKET,
      Prefix: opts?.listPrefix,
      Delimiter: opts?.listDelimiter,
      ContinuationToken: opts?.listContinuationToken,
    }); break
    case 'COPY':   cmd = new CopyObjectCommand({
      Bucket: BUCKET,
      Key: key,
      CopySource: `${BUCKET}/${opts?.copySource}`,
    }); break
  }
  res.json({ url: await getSignedUrl(client, cmd, { expiresIn: ttl }) })
})
```

### 2. Browser: wire it up

```ts
import { MountMode, R2VFS, Workspace } from '@struktoai/mirage-browser'

const r2 = new R2VFS({
  bucket: 'my-r2-bucket',
  accountId: 'abc123...',
  presignedUrlProvider: async (path, op, opts) => {
    const r = await fetch('/presign/r2', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ path, op, opts }),
    })
    const { url } = await r.json()
    return url
  },
})

const ws = new Workspace({ '/bucket/': r2 }, { mode: MountMode.READ })
```

<Tip>
`accountId` on the browser config is only used for display/logging; the actual endpoint is baked into the presigned URLs your backend returns.
</Tip>

### 3. Configure CORS on the bucket

R2 does accept S3-flavored `PutBucketCors`, but your token needs **"Admin Read & Write"** permissions on the bucket, object-scoped tokens will get `Access Denied`. Two paths:

**Option A, Cloudflare Dashboard (fastest, no new token):**

1. Open https://dash.cloudflare.com → **R2** → your bucket
2. **Settings** tab → **CORS Policy** → **Add CORS policy**
3. Origin: `http://localhost:5173` (and any production origins), methods `GET,PUT,HEAD,DELETE,POST`, allowed headers `*`

**Option B, admin-scoped R2 API token + the helper script:**

1. Cloudflare Dashboard → **R2** → **Manage R2 API Tokens** → **Create API token**
2. Permissions: **Admin Read & Write** on your bucket
3. Update `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` in `.env.development`
4. Run the same helper used for S3:

```bash
cd examples/browser
npx tsx scripts/configure-cors.ts http://localhost:5173 https://app.example.com
```

<Warning>
Object-scoped tokens (`Object Read & Write`) cannot edit CORS. If the script returns `Access Denied` on R2, you're almost certainly using an object token.
</Warning>

See the [R2 VFS](/python/vfs/r2) docs for the equivalent Python wiring.
