`OCIVFS` mounts one Oracle Cloud Infrastructure Object Storage bucket: every
object becomes a file and every `/` in a key a folder. It reaches OCI through
the Amazon S3 Compatibility API. Create the bucket and credentials as in [OCI setup](/home/setup/oci).

## Install

```bash
npm install @struktoai/mirage-node
```

## Configure

```ts
import { MountMode, OCIVFS, Workspace } from '@struktoai/mirage-node'

const oci = new OCIVFS({
  bucket: process.env.OCI_BUCKET!,
  namespace: process.env.OCI_NAMESPACE!,
  region: process.env.OCI_REGION!,
  accessKeyId: process.env.OCI_ACCESS_KEY_ID!,
  secretAccessKey: process.env.OCI_SECRET_ACCESS_KEY!,
})
const ws = new Workspace({ '/oci': oci }, { mode: MountMode.WRITE })

const result = await ws.shell("ls /oci && find /oci -name '*.csv'")
console.log(result.stdoutText)
await ws.close()
```

`namespace` and `region` build the endpoint
`https://<namespace>.compat.objectstorage.<region>.oci.customer-oci.com`;
`endpoint` replaces it. A mount takes `MountMode.READ`, `WRITE` or `EXEC`.

## Authentication

Credentials come from `accessKeyId` and `secretAccessKey`, a Customer Secret
Key, with `sessionToken` for temporary credentials. Without them, the AWS SDK
reads its own chain: environment variables, `~/.aws/credentials`, then the
instance or container role.

The user's group needs policies such as
`Allow group <group> to read buckets in compartment <compartment>` and
`Allow group <group> to manage objects in compartment <compartment>`
(`read objects` for a read-only mount). A request the credentials may not make
answers `Permission denied`.

## Layout

```text
/oci/
  data/
    config.json
    file.txt
  reports/
    q1.csv
    q2.csv
```

`/oci/data/file.txt` is the key `data/file.txt`. Folders come from the `/` in
keys; OCI stores no folder objects.

## Behavior

- **Key prefix:** `keyPrefix: 'users/42/'` mounts only that part of the bucket,
  so `/oci/notes.md` is the key `users/42/notes.md`.
- **Path style:** the S3 Compatibility API takes only path-style URLs, so
  `forcePathStyle` defaults to `true`.

## Browser

The browser `OCIVFS` from `@struktoai/mirage-browser` keeps credentials off the
page: a server signs a URL for each S3 call with the OCI keys, and the browser
fetches it.

```bash
npm install @struktoai/mirage-browser
```

```ts
import { MountMode, OCIVFS, Workspace } from '@struktoai/mirage-browser'

const oci = new OCIVFS({
  bucket: 'my-bucket',
  presignedUrlProvider: async (path, op, opts) => {
    const r = await fetch('/presign', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ path, op, opts }),
    })
    return ((await r.json()) as { url: string }).url
  },
})
const ws = new Workspace({ '/oci': oci }, { mode: MountMode.READ })
```

- The S3 Compatibility API answers CORS for any origin by default. Its CORS
  rules cannot be set through the S3 `PutBucketCors` call.
- A browser mount cannot declare `write: conditional`, and any HTTP 403 from a
  signed URL, an expired one included, answers `Permission denied`.
- `keyPrefix` set in the browser is no security boundary: enforce the prefix in
  the signing server.
- `namespace`, `region` and `endpoint` only name the mount's storage location:
  requests go to the host each signed URL names.

An Express route that signs URLs:

```ts
import {
  CopyObjectCommand,
  DeleteObjectCommand,
  GetObjectCommand,
  HeadObjectCommand,
  ListObjectsV2Command,
  PutObjectCommand,
  S3Client,
} from '@aws-sdk/client-s3'
import { getSignedUrl } from '@aws-sdk/s3-request-presigner'

const NAMESPACE = process.env.OCI_NAMESPACE!
const REGION = process.env.OCI_REGION!

const client = new S3Client({
  region: REGION,
  endpoint: `https://${NAMESPACE}.compat.objectstorage.${REGION}.oci.customer-oci.com`,
  forcePathStyle: true,
  credentials: {
    accessKeyId: process.env.OCI_ACCESS_KEY_ID!,
    secretAccessKey: process.env.OCI_SECRET_ACCESS_KEY!,
  },
})
const BUCKET = process.env.OCI_BUCKET!

app.post('/presign', async (req, res) => {
  const { path, op, opts } = req.body as {
    path: string
    op: 'GET' | 'PUT' | 'HEAD' | 'DELETE' | 'LIST' | 'COPY'
    opts?: Record<string, unknown>
  }
  const key = path.replace(/^\/+/, '')
  const ttl = typeof opts?.ttlSec === 'number' ? opts.ttlSec : 300
  let cmd
  switch (op) {
    case 'GET':    cmd = new GetObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'PUT':    cmd = new PutObjectCommand({ Bucket: BUCKET, Key: key, ContentType: opts?.contentType as string | undefined }); break
    case 'HEAD':   cmd = new HeadObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'DELETE': cmd = new DeleteObjectCommand({ Bucket: BUCKET, Key: key }); break
    case 'LIST':   cmd = new ListObjectsV2Command({
      Bucket: BUCKET,
      Prefix: opts?.listPrefix as string | undefined,
      Delimiter: opts?.listDelimiter as string | undefined,
      ContinuationToken: opts?.listContinuationToken as string | undefined,
    }); break
    case 'COPY':   cmd = new CopyObjectCommand({
      Bucket: BUCKET,
      Key: key,
      CopySource: `${BUCKET}/${opts?.copySource as string}`,
    }); break
  }
  const url = await getSignedUrl(client, cmd, { expiresIn: ttl })
  res.json({ url })
})
```

Sign only the operations the app needs: a viewer needs `GET`, `HEAD` and `LIST`.

## Integration

OCI answers these commands through its own API, so fewer objects are read. See
[Integration](/home/integration/overview).

- `find`: one recursive listing.
- `du`: one recursive listing.
- `ls -R` and `tree`: one recursive listing.
