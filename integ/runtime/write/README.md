# write

Writes that reach a mount. Runs on monty and quickjs on both hosts, wasi on the python host and pyodide on the typescript host. A case with a `backends` list also
runs over RAM, disk, ssh, S3 and redis.

| File            | Pins                                                                                                                                                                                | Differs                                                                                                                                                                                                                                                                                         |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `write.json`    | `write_text`, `write_bytes` and `write` reach the mount; a loop of small writes reaches it as one op; a read-only mount refuses with EROFS; a mount at `/` is served like any other | monty: each write is its own op, since the engine gives the entry point no close to gather a file's writes at, so on S3 a write loop rewrites the object once per write. pyodide: a mount at `/` is not served. host: the ledger records the ops the entry point asked for, on S3 and redis too |
| `pwrite.json`   | `os.pwrite` writes at an offset, and a write past the end leaves zeros in the gap                                                                                                   | monty: no `os.pwrite`. On S3 and redis a `pwrite` is a read and a whole write                                                                                                                                                                                                                   |
| `truncate.json` | `truncate` cuts a file, a write past the cut leaves zeros, `os.truncate` needs no handle, and `os.truncate` of a missing file is ENOENT                                             | monty: no `os.truncate`                                                                                                                                                                                                                                                                         |
| `exit.json`     | a file still open when the program exits lands on the mount, and an `os._exit` the program catches still ends it: nothing after reaches the mount or the output                     |                                                                                                                                                                                                                                                                                                 |
| `parallel.json` | four sessions writing one file at once: their offset writes and their appends all land, on stores that write in place and on those that read and write back the whole file          | monty: no `os.pwrite`                                                                                                                                                                                                                                                                           |
