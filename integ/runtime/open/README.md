# open

What `open()` in Python and `std.open` in QuickJS do in each mode. Runs on monty and quickjs on both hosts, wasi on the python host and pyodide on the typescript host.
A case with a `backends` list also runs over RAM, disk, ssh, S3 and redis.

| File        | Pins                                                                                                                                                         | Differs                                                                                                                                              |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `r.json`    | `r` refuses a missing file without creating it and opens an existing one without writing; a missing file raises a typed error with `strerror` and `filename` | monty: the error has no `strerror` or `filename`                                                                                                     |
| `r+.json`   | `r+` refuses a missing file, sends an edit in place as one `pwrite`, and two handles on one file keep both edits                                             | monty: no `+` modes. On S3 and redis a `pwrite` is a read and a whole write. The host door's ledger records the `pwrite` it asked for on every store |
| `w.json`    | `w` refuses a directory, creates a missing file, truncates an existing one, and its handle has a `stat`                                                      | monty: no `fileno()`. host: a mounted file has no descriptor, so `fileno()` raises `UnsupportedOperation`                                            |
| `w+.json`   | `w+` reads back what it wrote before the close, and keeps an edit another handle made after the open                                                         |                                                                                                                                                      |
| `a.json`    | `a` appends without truncating, creates and then appends, and appends from three opens all land                                                              | On S3 an append is a whole write: S3 has no append. The host door's ledger records the append it asked for, on S3 too                                |
| `a+.json`   | `a+` writes land at the end even after a seek                                                                                                                | On S3 an append is a whole write. The host door's ledger records the append it asked for, on S3 too                                                  |
| `x.json`    | `x` refuses an existing file and a dangling link, and creates a missing file                                                                                 | monty: no `x` mode. pyodide: `x` on a dangling link creates the link's target, because Emscripten follows the link before it checks `O_EXCL`         |
| `mode.json` | a malformed mode string is refused                                                                                                                           | monty and quickjs: their own wording. quickjs: reads a mode as C's fopen does: `rr` opens as `r`                                                     |
| `view.json` | paths outside the mounts (`/.bash_history`, `/tmp`, `/etc`) are refused                                                                                      | pyodide: a write outside the view lands in its own in-memory file system                                                                             |
